【フォルダの並び】
  このフォルダ(リポジトリ直下)で、あなたが触るのは次のものです:
    start.bat(Mac は start.command)   起動。ダブルクリック(start-background.bat は画面なしで裏で動かす)
    push.bat                            変更を GitHub に保存する
    setup\                              最初のインストールと片付け(bootstrap.bat・install.bat など)
    README.txt                          このファイル(全体の使い方)
  ふだん開かないもの:
    src\                動くコード。ツール本体(home・studio・editor・cut2resolve。録画の部品 recorder は pipeline\ingest)・共通部品(ytt = 基盤)と、役割の層(pipeline = 自動の流れ・human = 人の操作・manage = データの管理・eval = 検証)が入っている。部品は少しずつ役割の層へ移していて、RS4 まで済み
    friend-apps\        友人に渡す Windows のアプリ(holo-colors = ホロカラー・launcher = 友人のアプリの窓 FriendApp.exe。C#)
    codemap\            コードの地図(AI が探す用。dev\code_map.py が作る)
    dev\                開発の道具(テストの補助・push.bat の検査・消すファイルの一覧 removals.txt。精度を測る道具 eval_*.py は src\eval\tools\ にある = 使い方は py -3.12 src\eval\tools\eval_asr.py のように)
  計画・仕様・作業の記録などの資料は Obsidian の保管庫 D:\Obsidian保管庫\youtube-tools にあります(入口は ホーム.md)。
  AGENTS.md・CLAUDE.md は AI 向けの決まりです。以下の説明にある「home」「studio」「editor」などのツールのフォルダは src\ の中にあります。

【これは何?】
  配信から見どころを探して切り抜き、字幕を作り、DaVinci Resolve(以下 Resolve)で仕上げられる形にするまでを手伝うツールです。
  このパソコンの中だけで動き、動画・音声を外部のサービスへ送りません
  (YouTube からの動画・チャットの取得と、ランキング検索の YouTube Data API は使います)。

  画面は 4 つです。
    ホーム(/)                          処理の状況・配信ごとの依頼と結果(案件の一覧)・新しい案件(配信を探す・URL や動画ファイルから入れる)・運用(受付・バックアップなど)
    案件の画面(/cases)                 1 つの配信(案件)の作業。左に候補と切り抜き、右に 3 つのタブ:
                                         候補 … 見どころの候補を確認して採用 → mp4 に書き出す
                                         校正 … 文字起こしの字幕を聞きながら直す(話者の判別も)
                                         カット・パック … 残す区間を決めて、Resolve 用のパック(Text+ の字幕つき)を作る
    確かめる(/check)                   人が答えると自動の精度が上がる、軽い確認を 1 枚ずつ(下の「確かめる」)
    設定(/settings)                    すべての設定を 1 つの画面で
  中で動く部品(フォルダは src\ の中): studio(解析・書き出し)・editor(文字起こし・校正)・cut2resolve(パックを作る。コマンドでも使える)

    別のツール: ホロカラー(holo-colors)  ホロライブのメンバーカラーを Ctrl+Alt+H で呼び出してコピーする Windows のアプリ。
                                         主に友人用。上のツールとは別に動く(Python は要らない)。使い方と作り方は friend-apps\holo-colors\README.txt

【準備(最初に1回)】
  Windows を入れ直したあとなど、まとめて入れたいとき: setup フォルダの bootstrap.bat をダブルクリック(下の 1〜4 を winget で入れ、続けて install.bat も流します。
    入っているものは飛ばします。winget の同意を代わりに受け入れるので、最初の表示を読んでから進めてください。
    Visual Studio Build Tools と Vulkan SDK(GPU 用の whisper.cpp を作るときだけ)は同意が要るので入れず、入れ方の案内だけ出します。
    入れたあとの ffmpeg などは、新しい黒い画面から使えます)
  1. Python 3.12(https://www.python.org/downloads/ 。Windows はインストール時に「Add python.exe to PATH」にチェック。
       winget なら Windows: winget install Python.Python.3.12 。入れたあとは py -3.12 で動かせます)
       部品の版は 3.12 で確かめています(setup\requirements.txt)。install.bat は 3.12 があればそれを使います。start.bat は 3.12 に部品が入っていればそれを、無ければ 3.10(前の版。しばらく残す)→ ほかの Python 3 の順に使います
  2. ffmpeg     Windows: winget install Gyan.FFmpeg   / Mac: brew install ffmpeg
  3. yt-dlp     Windows: winget install yt-dlp.yt-dlp / Mac: brew install yt-dlp
     Deno       Windows: winget install DenoLand.Deno  / Mac: brew install deno
       (今の yt-dlp は YouTube の取得に JavaScript の実行環境として Deno を使います。yt-dlp と一緒に入ることもあります)
     (入れたら黒い画面を開き直してください)
  4. 文字起こしの部品: setup フォルダの install.bat をダブルクリック(Mac は install.command)
       話者の自動判別を使うなら install-diarize.bat も。NVIDIA の GPU がある人だけ install-gpu.bat
       (AMD Radeon・Intel の GPU では使えず、CPU で処理します)
  5. YouTube Data API のキー(配信を探すのに使います。無くても解析・書き出しはできます):
       ホームの「新しい案件」を開き、いちばん下の「探す設定」で入れます(事務所の登録・コラボも同じ所)

【起動と終了】
  起動: このフォルダの start.bat をダブルクリック(Mac は start.command)。
        黒い画面が1つ開き、ブラウザでホームの画面 http://localhost:8700/ が開きます。
        案件の画面は /cases、確かめるは /check、設定の画面は /settings です(ヘッダー左の「ホーム / 案件 / 確かめる / 設定」で行き来します)。
        以前の /studio/・/transcribe/・/cases.html のリンクやブックマークは使えません(ホームか案件の画面から開き直してください)。
        ※ 127.0.0.1 ではなく localhost で開いてください(YouTube の埋め込みプレーヤーのため)
  終了: ホームの下の「詳しく」を開いて「すべて終了」(誤操作を防ぐため2回押し)か、黒い画面を閉じる。
  ※ 各ツールのフォルダの start.bat での単独起動はできません。起動は start.bat だけです。
  ※ 新しいコードを取り込んだら(push.bat の後など)、「すべて終了」→ start.bat で起動し直してください。
    古いまま動いていると、画面の上に「版が違います」の赤い帯が出ます。

  専用の窓(既定): start.bat で起動すると、ブラウザのタブではなく Microsoft Edge の専用の窓(アドレス欄もタブも無い窓)で開きます。
    いつものブラウザのタブで開きたいときは、ホームの「詳しく」の中の「窓で開く」をオフにします(次の起動から)。Edge が無いときはブラウザで開きます。
    - 窓の中のリンク(「開く」「編集で開く」など)も窓で開きます。YouTube などの外のサイトは、いつものブラウザで開きます
    - 窓の設定・拡張機能・ログインは、いつものブラウザと別です(専用のプロファイル: %LOCALAPPDATA%\youtube-tools\app\browser-profile)。
      そのため、会員限定・年齢制限のある配信は、窓の中の埋め込みプレーヤーで再生できないことがあります
    - 窓を閉じてもツールは止まりません。終わるときは今までどおり「すべて終了」
    - 合わなければスイッチをオフに戻すだけで、元のブラウザのタブに戻ります

【作業の流れ】
  1. ホームの「新しい案件」: 配信を探す(配信ランキング)か、URL・動画ファイルを入れて解析(見どころの候補を自動で選ぶ)
  2. 案件の画面の「候補」: マークを見て「採用」→ 書き出す
       書き出すときに、切り抜きごとにバラバラな聞こえ方の音量(ラウドネス)を、既定で -14 LUFS(YouTube の目安)にそろえます。
       設定の画面の「音量のそろえ方」で変えられます(「そろえない」なら以前と同じ音量 %)。
  3. 案件の画面の「校正」: 書き出した切り抜きを文字起こし → 画面で聞きながら直す(校正)。左の一覧で切り抜きを選び、
       「次の未校正の切り抜き」(Shift+N)で順に進めます。直した字幕は、候補でも書き出したマークの下に「セリフ」として見られます。
  4. 案件の画面の「カット・パック」: 残す区間をタイムライン(映像・波形・字幕)で決める(たたき台 = 行から・無音・時刻リスト・スタジオ から始めて手で直せます。
       削った所を飛ばしてプレビューできます)→ 下の「パックを作る」。カット・字幕を直したら「作り直し」をお知らせします
  5. パックの「Resolve での手順を見る」の手順で Resolve に取り込む(パックのフォルダの bat で登録 → Resolve でスクリプトを実行)。
  評価用の文字起こしは、ホームの案件の一覧の末尾の「評価用」の案件から開きます。精度(評価の一括・精度の表)と置換の提案(学習)はホームの運用の中です。

  画面の共通の決まり(言葉・ボタン・一覧の見せ方)は notes:docs/spec/ui.md。画面の左上の「ホーム / 案件 / 確かめる / 設定」で行き来できます。

  確かめる(/check): ホームの「確かめる」の [始める] か、案件の画面の上の「確かめると効く物 n 件」から開きます。
    機械が自信を持てなかった所を、案件をまたいで 1 枚ずつ聞きます。答えるとすぐ次のカードが出ます。
      切り抜く価値があるか … 自動でできた切り抜きを [送る](友人へ届ける)か [要らない]、まだ選んでいない候補を [採用] か [不採用]
      どちらの読みが正しいか … 後処理や別のエンジンが直した字幕と、認識のままの字幕を比べて 1 / 2、どちらも違えば 3 で打ち直す
      これは誰の声? … 行を聞いて話す人を選ぶ(再生が終わると Enter で機械の予想どおりに答えられます)。名前で答えた行がたまると、その人の声を覚え直します
      行の時刻が合っているか … 波形の印を見て、字幕の出る・消える時刻がずれていれば ← → で直す
    Z で 1 つ前の答えを取り消せます。自動でできた切り抜きの [送る]・[要らない] は戻せないので、次のカードに答えた(か画面を離れた)ときに確定します(1 枚遅れ)。
    N で今日は後ろへ回します。上の帯には「今日答えた数」と「この確認で何が決まるか・目標まであと何件か」が出ます。
    開いただけでは何も変わりません(答えたときだけ字幕・採用を直します)。評価用の文字起こしは出ません。
    答えの記録は作業データの app\check\answers.jsonl に残ります(精度の自動測定が「確かめた数」として数えます)。

  ホームを開くと、上に「処理の状況」(動いている処理の今の段と進み具合・待っている処理・失敗。押すとその案件へ)、
  下に「案件(配信ごと)の一覧」が出ます。配信1本ごとに、書き出した切り抜き・文字起こし(校正の進み具合)・パックの有無が並びます。
  作業中・投稿済み・見送りの「状態」と「メモ」も付けられます。どの配信にも紐づかない文字起こし(手元の動画ファイルなど)は
  「単体の文字起こし」のまとまりに入り、検索して選ぶとまとめて文字起こし・パックを進められます。

  「まとめて実行」(案件の一覧の各配信): 押すと、残りの作業を順に自動で進めます。形は「解析から全部」だけです(2026-10-19):
    未解析なら解析 → 人が採用したマーク + 自動マークの点数の高いものを指定の数まで採用 → 書き出し → 文字起こし → パック(→ 友人へ自動で送るかの判定)
    人が選んだ 1 本だけ進めるときは、案件の画面の候補のマークの行の「この後を」を使います(書き出しから全部)
  まだ無いものだけを作るので、途中で止めても、もう一度押せば続きから進みます。
  「配信者(字幕の色)」に名前を入れると、パックの字幕の文字をその人のメンバーカラーにします(ホロカラーの色の一覧。空なら黒い文字)。
  同じ「まとめて実行」は、作業の各段階からも始められます: 新しい案件の「配信を探す」(配信をチェックして「まとめて実行」= 解析から全部)、
  案件の画面の候補(「まとめて実行 ▾」)とマークの行(「この後を ▸」= そのマークだけ)、校正の題名の行(「まとめて実行 ▾」= 今の文書)。

  出力先のフォルダ(配信ごと)の直下には、書き出した切り抜き(mp4)とパック(_pack)だけが並びます。受け渡しの途中のファイル
  (.clip.json・編集用素材・文字起こしの .transcript.json など)は、その下の「作業用」フォルダに入ります。
  パックは、「編集」でカットを決めてあればそのとおりに、無ければ文字起こしの行だけを残して作ります。
  自動で作ったパックの字幕は校正前です。案件の画面の校正で直したら、カット・パックのタブで作り直してください(「作り直し」の知らせが出ます)。
  「解析から全部」の解析は、設定の画面のスタジオの節の「解析」で保存した値を使います。

  重い処理(解析・書き出し・文字起こし・パック作り・音の波形)は、ツールを合わせて同時に2つまでです。
  3つ目からは「他のツールの処理が終わるのを待っています」と出て、順番に進みます。

【作業データの置き場所】
  文字起こし・マーク・設定・API キー・キャッシュ・ログは、このフォルダではなく
  %LOCALAPPDATA%\youtube-tools\(例 C:\Users\<名前>\AppData\Local\youtube-tools\)にあります。
  ホームの「詳しく」の「作業データの置き場所」にパスが出ます(隠しフォルダなので、パスをコピーしてエクスプローラーに貼ります)。
  詳しくは notes:docs/spec/data.md。書き出した切り抜き・パックは、設定の画面の出力先と、動画の隣です。
  作業データはリポジトリの外にあるので、git にも GitHub にも入りません。Windows を入れ直すと消えます(実際に失ったことがあります)。
  ときどき別のドライブへコピーしておき、入れ直す前には必ずコピーしてください(特に transcribe と studio。notes:docs/spec/data.md の「バックアップ」)。

【変更を GitHub に保存する(push.bat)】
  push.bat をダブルクリックすると、変更をまとめてコミットして GitHub に送ります。途中で次のことを自動で行います:
    - dev\removals.txt に書いてあるファイルを消す(AI が PC のファイルを消せないため。git の履歴には残ります)
    - これから送るファイルに、API キー・個人データ(文字起こし・data.json・設定など)・動画・大きすぎるファイルが混じっていないか調べ、
      あれば送らずに止まる(リポジトリは公開する方針のため)。止まったら、その表示を Claude に見せてください

【困ったとき】
  - 画面の上に赤い帯(版が違います): ホームの「詳しく」の「すべて終了」→ start.bat
  - 動かない・エラー: ホームの「詳しく」の各カードの「ログ」、または %LOCALAPPDATA%\youtube-tools\app\logs\ の中の .log
  - 画面がおかしい・ボタンが効かない: 画面で起きたエラーは同じフォルダの client-errors.jsonl に自動で残ります(Claude に見せてください)
  - 表示や操作について: 各ツールの README.txt
