  文字起こしツール  v0.57.0  はじめに読んでください
==========================================================

【これは何?】
  動画・音声ファイルの話し声を文字にして、字幕ファイル(SRT / VTT)やテキストとして
  書き出すツールです。文字起こしは、自分のパソコンの中だけで行います
  (動画や音声はインターネットに送られません)。
  ・認識のあとで、画面上で誤変換を直せます(再生しながら1行ずつ聞き直せます)
  ・文字を検索して、その場面へジャンプできます
  ・「切り抜きマーカー」で記録したポイントの範囲だけを文字起こしできます
  ・v0.16.0 から、入口では「編集」という名前で出ます。文字起こし・カット・Resolve へのパックを1つの画面の
    3つのタブ(1 文字起こし / 2 カット / 3 パック)で行います(以前の cut2resolve の画面はここに統合しました)

  ※ v0.3.1 では「話者の自動判別」(誰が話しているかの色分け・名前付け)が入りました。
  ※ これは初期の版です。実際の音声での認識精度は、使いながら調整していきます。


----------------------------------------------------------
 ① 最初の準備(1回だけ)
----------------------------------------------------------
  1. Python 3.10 をインストール(無料)   https://www.python.org/downloads/
       Windows: インストーラーで「Add python.exe to PATH」に必ずチェック(winget なら winget install Python.Python.3.10)
       ※ 部品の版は 3.10 で固定しています(setup\requirements.txt)
  2. ffmpeg をインストール(無料。音声を取り出すのに使います)
       Windows: スタートメニューから PowerShell を開いて
                  winget install Gyan.FFmpeg
                (終わったら、開いている黒い画面は一度閉じる)
       Mac:     ターミナルで  brew install ffmpeg
  3. リポジトリ直下の setup フォルダの install.bat をダブルクリック(Mac は setup の install.command)
       → 文字起こしのエンジン(faster-whisper)が入ります。数分かかります

  4. (NVIDIA の GPU がある人だけ) setup フォルダの install-gpu.bat をダブルクリック
       → GPU を使えるようになり、処理がかなり速くなります(RTX 3060 など)
       ※ 対応するのは NVIDIA(GeForce / RTX)だけです。AMD(Radeon)・Intel の GPU と、
         Mac の GPU は使えず、CPU で処理します。
       ※ 入れたあとは、ツールを起動し直してください。画面の左上に、GPU を使えるかどうかが出ます。

  5. (話者の自動判別を使う人だけ) setup フォルダの install-diarize.bat をダブルクリック(Mac は setup の install-diarize.command)
       → 判別に使う部品(sherpa-onnx)が入ります。GPU は不要で、どのパソコンでも CPU で動きます。
       ※ 判別用のモデル(約46MB)は、初めて使うときに自動でダウンロードされます。
       ※ Mac で .command が使えないときは、ターミナルで  python3 -m pip install -U sherpa-onnx numpy
         (先に install.command を実行済みなら  .venv/bin/python -m pip install -U sherpa-onnx numpy)

  ※ 切り抜きマーカーで ffmpeg をすでに入れている人は、2 は不要です。
  ※ zip は「展開(解凍)」してから使ってください。


----------------------------------------------------------
 ② 起動のしかた
----------------------------------------------------------
  リポジトリ直下(youtube-tools フォルダ)の start.bat をダブルクリック(Mac は start.command)。
  入口の画面(http://localhost:8700/)の「編集」の「開く」で http://localhost:8700/transcribe/ が開きます。
  使い終わったら入口の「すべて終了」か、黒い画面を閉じてください。
  ※ このフォルダの start.bat・start.command での単独起動は 2026-09-26 にやめました。準備と起動の全体はリポジトリ直下の README.txt


----------------------------------------------------------
 ③ 基本の使い方
----------------------------------------------------------
  1. 左の「新しく文字起こしする」で、動画・音声ファイルのパスを貼る
       Windows: ファイルを Shift+右クリック →「パスのコピー」
       Mac:     Finder でファイルを option+右クリック →「"…"のパス名をコピー」
     (範囲を入れると、その部分だけ処理します。空欄なら全体です)
  2. 「文字起こしを開始」。左の「処理状況」に進み具合が出ます
       ・初めてのモデルを使うときは、ダウンロードのため最初に時間がかかります
       ・何本でも追加できます(順番に1本ずつ処理します)
  3. 終わると右側に文字起こしが開きます。再生しながら直します
  4. 上の 2 カット のタブで残す区間を決め、3 パック のタブで「パックを作る」(DaVinci Resolve へ渡すフォルダ。入口から開いたとき)。
     字幕だけなら「書き出し」で SRT など(下の「■ 「編集」の3つのタブ」)

  ■ 「編集」の3つのタブ(v0.16.0)
     画面の上に 1 文字起こし / 2 カット / 3 パック のタブがあります(Alt+1 / Alt+2 / Alt+3。アドレスの #tx / #cut / #pack でも開けます)。
     どのタブにも、題名の行(長さ・校正の進み具合・カットの状態)が出ます。保存の状態はヘッダーの右に出ます。
     ・1 文字起こし … 今までの校正の画面。行の右の「残す/カット済」は、2 カット のタブの区間と同じもの(どちらで変えても両方に出ます)
     ・2 カット … 残す区間をタイムライン(目盛り・区間(中に波形)・字幕の3段)で決めます。上のミニマップ(全体を縮めた帯)の
         枠をドラッグすると見る範囲が動き、枠の端をドラッグすると拡大縮小します。ホイールでも拡大縮小(マウスの位置が中心。Ctrl は不要)、
         Shift+ホイールで横に移動します
         ・区間を押して選ぶ・端をドラッグ(見た目より少し外側までつかめます。字幕の行の端・無音の境目・再生位置に吸い付く。Alt を押している間は吸い付かない)
         ・S 分割 / Del 削る・戻す / I・O で範囲を決めて X で削る / , . 選んだ端を1コマ(Shift で10コマ)/ Ctrl+Z 元に戻す / + − ズーム
         ・Space・J K L・← →(1秒。Shift で5秒)で再生(他のタブと共通のキーです)。プレビューは削った所を飛ばして再生し、字幕も重ねて出ます
         ・たたき台: 「行から」(文字起こしの行を残す)・「無音 ▾」(しゃべっていない所を削る)・「時刻リスト ▾」(残す区間を時刻で貼る)・
           「スタジオ」(スタジオの残す区間があるとき)。たたき台は出発点で、そのあと手で直せます
         ・「行から」は、語頭・語尾が切れないように、区間の端を声の止まる所(無音)まで広げます(終わりは 0.5 秒先・始まりは 0.3 秒前まで。
           BGM などで無音が見つからないときは 前 0.1 秒・後 0.2 秒。カット済の行は越えません。字幕の時刻は変えません)。
           「行から」の右の ▾ で、広げない・上限の秒を変えられます(zip・まとめて実行のカットの無い文書にも同じ設定を使います)。
           行を「削る」と、その行の前後に広げた分も一緒に削ります(ほかの残す行と重ならない切れ端だけ)
         ・変えると自動で保存します。別の画面・別の窓で同じ文書を直していたときは「読み直す / こちらで上書き」を聞きます
     ・3 パック … 画面には「前回の設定」の要約(fps・大きさ・入れるもの・出力先。配信者の色を入れていれば色の丸も)と、
         大きな「パックを作る」ボタン・字幕の見本(いつも見えます)だけが出ます。置き先のプロジェクト(30/60 fps・縦/横)・入れるもの
         (粗編集の動画など)・出力先を変えるときは「設定を変える」で開く欄で行います(変えると、次からそれが「前回の設定」になります)
         「これから作るパック」に、カット後の長さ・区間の数・Text+ 字幕の数・字幕の見本と、作る前の注意(とても短い区間・
         60fps の動画を 30fps のプロジェクトに入れるときなど)が出ます。前に作ったパックがあれば上書きしてよいか聞きます。
         作ったあとでカット・字幕を直すと「作り直しが要る」をお知らせします。「前回のパック」から、フォルダを開く・Resolve での手順を見る・パスのコピー
     ・文字起こしをしていない動画も、左の「新しく文字起こしする」の「文字起こしせずに開く」で開いて、カットとパックができます
       (あとから同じ文書に文字起こしを入れられます。そのときカットはそのまま)
     ・パックの中身は cut2resolve(隣のフォルダ)が作ります。入口から開いていないとき・cut2resolve が動いていないときは、
       パックは作れません(見積もりと zip は使えます)

  ■ 保存済みの文字起こし(左のメニューの「履歴」。v0.15.0 で見やすくしました)
     ・既定は「配信ごと」にまとめます(見出し = 配信の題名・配信者・最終更新)。今開いている文書のまとまりだけ開きます。
       「配信者ごと」「まとめない」にも切り替えられます
     ・1件の行には、題名(配信ごとのときは、配信の題名を省いてマークの名前など違う部分)・いつ(「3日前」など)・
       元の配信のどこか・長さ・校正の進み具合(棒と「12/30」)・状態の札(未校正・パック済み・評価用・動画なし)が出ます。
       「→ パックを作る」「→ 作り直す」は、次にやることの案内です
     ・検索(題名・配信の題名・配信者・ファイル名)・状態(未校正・校正中・校正済み)・種類(切り抜き・それ以外・評価用)・
       並び替え(更新が新しい順・作った順・未校正が多い順・題名順)。選んだ条件はこのブラウザに覚えます
     ・行の右の「⋮」で、題名の全文・ファイル名・削除(「動画なし」の文書は「動画を選び直す」も)

  ■ 動画を選び直す(動画を移した・名前を変えたとき。v0.25.0)
     ・動画が見つからない文書を開くと、映像の下に「元の動画が見つかりません: <元のパス>」と「動画を選び直す」が出ます
       (2 カット のタブの案内・履歴の「⋮」にも同じボタン)。mkv など形式のせいで再生できないときは出ません
     ・「参照…」で動画を選ぶ(選ぶとすぐ確かめます)か、新しいパスを貼り付けて「確かめる」→ 名前・長さ(元/新)・fps・注意を見てから「付け替える」。
       パスは、エクスプローラーで動画を Shift+右クリック →「パスとしてコピー」でも取れます(v0.31.0 から「参照…」)
     ・まとめて付け替える(v0.31.0): 動画が見つからない文書があると、履歴の一覧の上に「元の動画が見つからない文書が N 件」と
       「まとめて付け替える」が出ます。動画を移したフォルダを「フォルダを選ぶ…」で選ぶ(かパスを入れて「探す」)と、その中(下のフォルダも)から
       同じファイル名の動画を探して入れ、1件ずつ長さを確かめます。見つからないものは行の「参照…」で選べます。
       長さが同じものだけ最初から選ばれます(長さが違うものは、確かめてから自分で選ぶと付け替えます)。「付け替える」で選んだものを1件ずつ付け替えます。
       探すのは 6 段下のフォルダまで・8 秒まで(ドライブ全体のような大きなフォルダは途中まで。動画のあるフォルダを選ぶと確実です)
     ・「参照…」の窓はパソコンの画面に開きます(ブラウザの後ろに隠れたらタスクバーを見てください)。窓が開かないときはパスを貼り付けてください
     ・行・校正・話者・カットはそのまま残ります。パックを作ってあれば「作り直す」になります(Resolve に新しいパスで入れ直すため)
     ・長さが元の動画と違う(別の動画の可能性)ときは、「長さが違うのを分かったうえで付け替える」にチェックするまで付け替えません
     ・選べるのはこのパソコンのドライブの動画だけです(ネットワーク上のファイル・このツールの作業データの中は選べません)。
       Dropbox の「オンラインのみ」のファイルは、確かめるときにダウンロードが始まるので時間がかかります
     ・付け替える前の状態は「以前の版に戻す」で戻せます(作業データの transcripts\.bak にも1つ残します)
     ・切り抜きスタジオの書き出しの記録・保管したデータの中の名前は古いままです(案件の紐づけは元の配信で取れるので切れません)
     ・配信者は、切り抜きスタジオの data.json から読みます(読むだけ。スタジオで文字起こしした切り抜きのとき)

  ■ 切り抜きマーカーのポイントを文字起こしする
     「切り抜きマーカーのポイント」タブを開くと、隣の clip-marker フォルダの
     data.json を自動で読みます(なければ「data.json を選ぶ」から選ぶ)。
     動画と元ファイルのパスを確認し、対象のポイントにチェックを入れて開始します。
     ・「前後の余裕」は、ポイントの前後に足す秒数です(話の頭が欠けるのを防ぎます)
     ・パスは、切り抜きマーカーの書き出し設定に入力済みなら自動で入ります

  ■ 直すときの操作
     ・行の文字をクリックして直す(自動で保存されます)
     ・行の ▶ = その行だけ再生(行の終わりで必ず止まります。R でも可)。
       続けて全体を流すときは、映像そのものの再生ボタン(または Space)を使います
     ・行をクリックして選ぶと、その行の下に操作のボタンが出ます:
       開始・終了の −/＋/再生位置、＋前に行・＋後に行(行の追加)、分割、次と結合、削除
     ・分割 = 文字の途中にカーソルを置いて押すと、2行に分けます
     ・行の追加(v0.9.8) = 認識で抜けたセリフを書き足します。「＋前に行」「＋後に行」(N キー)、
       または映像の下の「＋再生位置に行」。前後の行のすき間に置かれます。すき間が無いときは
       仮の長さ(1.5秒)で置かれ、時刻の欄が赤くなります(前後と重なっている印)。「再生位置」ボタンで、
       聞きながら開始・終了を合わせてください
     ・「要確認」の印は、認識が怪しい行です(押すと確認済みになります)。
       「要確認だけ」にチェックすると、その行だけ表示されます
     ・「元に戻す」ボタン(文字の入力中以外は Ctrl+Z でも可)で、分割・結合・削除・置換を戻せます
     ・話者: 自動判別は下の「■ 話者を自動で判別する」。手動なら
       「話者を追加」→ 行の左のチェックで行を選ぶ →「適用」
     ・一括置換: 「誤=>正」の辞書を作っておくと、どの文字起こしにも使えます

  ■ 話者を自動で判別する(誰が話しているかを、行ごとに色分けする)
     1. 文字起こしを開き、映像の下の「話者」のカード(「道具 ▾」→「話者」でも開けます)の
     「話者の自動判別」を使う
     2. 人数が分かっていれば「人数」を選ぶ(コラボなら人数を指定するのがおすすめ)
     3. 「話者を自動で判別」。処理中は編集できません(終わると自動で読み込み直します)
     4. 各話者の「▶ 聞く」で発言を聞いて、「話者1」を本人の名前に直す
     5. 間違った行は、行の話者欄で直す。
        「要確認: 声が混ざっている可能性」の行は、1つの行に2人以上の声が入っています。
        その行は「分割」して、それぞれに話者を付けてください
     ・すでに付けた話者は、判別すると置き換わります(直前の状態は transcripts/.bak に
       1つだけ残ります)。手直しは、判別の「あと」にしてください
     ・字幕に話者名を出したいときは、書き出しの「話者名を付ける」にチェック
     ・文字起こしのモデルとは無関係に使えます(どのモデルで作った文字起こしにも使えます)
     ・CPU で処理するので、長い音声は時間がかかります。まず短い範囲で、かかる時間を
       確かめてください。判別できるのは、1回3時間の範囲までです

  ■ 校正済み・認識精度の測定(v0.7.0)
     「校正済み」= 聞いて確認して、その行の文字が正しいと判断した印です。
     ・各行の「校正済み」ボタン(または Shift+Space。付けると次の行へ進みます。入力中は Alt+Enter)
     ・「選択行を校正済みに」「全行を校正済みに」(全行は、聞いて確認した文字起こしだけ)
     ・「絞り込み」で、校正済み/未校正の行だけを表示できます
     ・置換辞書・修正の提案の採用・再認識で、聞かずに書き換わった行は、校正済みが外れます
     左の「認識精度の測定」に、校正済みの行を正解とした文字誤り率(CER)が出ます。
     ・内訳は 置換(別の字に間違い)/ 脱落(聞き逃し)/ 挿入(余計な字。幻覚など)。
       機械が出した行を人が消した数、用語(用語集・辞書)が正しく出た率も出ます
     ・「印のない旧データも含める(仮)」で、v0.6 までに直した分を仮計算できます
     ・「設定の比較(A/B)」…開いている文字起こしの校正済みの行の音声を、モデル・用語集の
       有無の違う設定で認識し直して、正解との差を比べます(文字起こしは書き換えません)。
       結果は evals フォルダに残ります。重いモデルほど時間がかかります
       (v0.8.1)設定ごとに用語集を変えられます。「用語集」にチェックを入れた設定の下の欄が
       空なら、左の共通の用語集(+自動追加)を使います。書くと、その設定だけ、その語だけを
       使います(自動追加はしません)。例: なし / 共通 / その動画に出る人だけ、の3つを比べる。
       注意: 認識に渡る用語は、実際には先頭約150字(プロンプト)・300字(ホットワード)までです。
       長い用語集は後ろが切れるので、多く入れるほど良いとは限りません
     ・修正データの書き出しで「校正済みの行すべて(学習用)」を選ぶと、直していない行も
       入ります(将来の追加学習では、正しく認識できた行も必要です)
     ・日本語の文字起こしで、英字が目立つ行(英語の幻覚のことが多い)は「要確認」になります。
     ・長い区間に文字が少ない行(4 秒より長くて、1 秒あたり 1.5 文字未満)は「要確認: 長い区間に文字が少ない(抜けの可能性)」になります。
       BGM などで、しゃべっている所がまとめて抜けていることがあります(v0.17.0。範囲を選んで再認識すると取り直せることがあります)
       用語集に入れた英字の語(Apex など)は数えません

  ■ 長時間の校正作業向けの機能(v0.7.1 / キー操作は v0.8.0 で左手だけに変更)
     ・左のメニューの開閉(v0.9.8。左上の「☰」、メニュー内の「◀ 閉じる」、または G)…
       メニューを閉じると、映像と一覧を広く使えます(開閉の状態は覚えています)。処理中の件数は、右上に出ます。
       画面が狭いときは、文字起こしを開いた時点で自動で閉じます
     ・⚙ 設定(ヘッダーの右)…文字の大きさ・行の間隔・動画の大きさ(「音声だけ聞く」で映像を隠せます)・「移動したら自動で再生」・
       画面の色(明るい/暗い/OS に合わせる)・文字の大きさ・下のキーの帯の表示。画面の色・文字の大きさ・キーの帯は全体の設定(どのツール・
       どの画面で変えても共通)、それ以外はこのブラウザだけに保存されます
     ・左手だけで校正できます(v0.8.0)。v0.9.7 からは「キー単体」で操作します(Shift 不要。一覧は右上の「キー操作」か ?。
       行の一覧の上と画面の下の帯にも、主なキーの手がかりが出ます)

     ・Text+ 字幕の見た目を、フォント「けいふぉんと」・黒い文字・白いふち・外側の黒いふちにしました(縦・横とも)。けいふぉんと はパックに入れないので、

----------------------------------------------------------
 ④ モデルの選び方・速さについて
----------------------------------------------------------
  ・GPU(NVIDIA)がなくても動きますが、CPU だけだと遅くなります。
    長い動画は、動画の長さ以上の時間がかかることもあります。
    まずは短い範囲で試して、時間を確かめてください。
  ・「処理方式」は「自動」のままで大丈夫です(GPU が使えれば GPU、だめなら CPU)。
    処理中の表示に、実際に使っている方式(GPU / CPU)が出ます。
  ・small … 軽い。精度はそこそこ
  ・medium … バランス型(迷ったらこれ)
  ・large-v3 … 高精度。重いので GPU 推奨
  ・large-v3-turbo … large-v3 に近い精度で、より速い(迷ったらこれも候補)
  ・kotoba-whisper … 日本語向けの高速モデル。速い代わりに、声が重なる・BGM が大きい
    ・聞き取りにくい音声では、抜けや誤変換が増えることがあります
  ・「品質」を「速度優先」にすると速くなりますが、精度は少し下がります
  ・初回のダウンロードは数百MB〜数GB。以降はインターネットなしで使えます


----------------------------------------------------------
 ④-2 精度が低いときの試し方
----------------------------------------------------------
  まず、1〜2分の短い範囲だけで、設定を変えて比べてください
  (「範囲」を入れて何回か実行すると、結果が別々に保存されます)。
  ・全体的に間違いが多い → モデルを large-v3 か large-v3-turbo にする
  ・声が抜ける・途中がまるごとない → 「無音・BGMの扱い」を「弱め」か「使わない」に
  ・話していない文(「ご視聴ありがとうございました」など)が出る → 「標準」に
  ・声が小さい・人によって音量が違う → 「小さい声を持ち上げる」をオンに
  ・名前や用語が違う → 「用語集」に入れる。直らないものは「置換辞書」で直す
  ・品質は「精度優先」にしておく(「速度優先」は精度が下がります)
  ・複数人の声が重なる場面は、どの設定でも間違いやすい部分です。
    その場面は「要確認」の行や、聞き直しながらの修正で直してください

----------------------------------------------------------
 ⑤ 精度についての注意(必ずお読みください)
----------------------------------------------------------
  ・BGM や歌、ゲーム音が大きいところ、複数人が同時に話すところでは、誤認識や
    抜けが増えます。「無音・BGMの扱い」は、無音部分での
    でたらめな文(「ご視聴ありがとうございました」など)と、声の抜けの、
    どちらを減らすかの調整です(標準の「弱め」は、声を抜かない側です)。
  ・それでも出る誤認識は、「要確認」の印を付けます。印がない行にも
    間違いはあるので、公開する字幕は必ず聞いて確認してください。
  ・固有名詞(名前・グループ名)は誤変換されやすいです。用語集に入れるか、
    置換辞書で直してください。
  ・話者の自動判別も間違えます。特に、声が似た人、同時にしゃべる場面、笑い声や短い
    相づち、BGM の大きい場面は苦手です。人数を「自動」にすると、声が似た人を1人に
    まとめたり、1人を複数人に分けたりします。人数が分かるなら指定してください。
    重なって話している場面は、片方の人にしか割り当てられません。
  ・BGM と声を分ける処理(ボーカル分離)は入っていません。


----------------------------------------------------------
 ⑥ データについて
----------------------------------------------------------
  ・文字起こしは、作業データの %LOCALAPPDATA%\youtube-tools\transcribe\transcripts\ に保存されます(1件1ファイル。2026-09-26 からリポジトリの外)。
    バックアップは %LOCALAPPDATA%\youtube-tools\transcribe\ をコピーしてください(transcripts\.hist に、自動の履歴も残ります)。
    Windows を入れ直すと作業データは消えます(2026-10-03 に実際に失いました)。入れ直す前には必ず別のドライブへコピーしてください(docs\spec\data-location.md の「バックアップ」)。
  ・ホロライブの名簿(v0.8.2): 設定の「用語集」の下の「ホロライブの名簿から追加」で、所属(期・ユニット
    など)にチェックして「用語集に追加」を押すと、その名前が用語集に入ります。設定の比較(A/B)の
    設定別の用語集にも、「名簿から足す」で入れられます。名簿は hololive-roster.json(公式サイトで
    確認、2026-09-22 時点)。メンバーの増減があったら、このファイルを直せます(形式は見ればわかります)。
    ★用語集のうち、認識に効くのは先頭の約150字だけです(画面に「先頭N語まで」と出ます)。
    全員を入れると後ろが切れるので、その動画に出る人・ユニットだけに絞ってください
  ・用語集・置換辞書は settings.json に保存されます。
  ・話者判別のモデルは models/ フォルダに保存されます(消しても、次回また自動でダウンロードされます)。
    ダウンロードしたファイルは、配布元と同じものか(ハッシュ)を確認してから使います。
  ・元の動画・音声ファイルは、移動や削除をしないでください
    (聞き直しの再生に使います。なくても文字の編集は可能です)。
  ・更新するときは、フォルダの中の .py ファイル(serve.py・pipeline_io.py・resolve_export.py)と
    index.html・app.js・ui-kit.js をまとめて上書きします(serve.py と app.js の片方だけだと、画面の上に赤い帯が出ます。
    pipeline_io.py・resolve_export.py が無いと「動画の隣に保存」「パック(zip)」が使えません。
    パックは隣の cut2resolve フォルダの部品で作るので、cut2resolve も一緒に更新してください。
    app.js・ui-kit.js が無いと画面が真っ白になります)。
  ・動画の隣に保存した .transcript.json / .srt / .cut-plan.json には、文字起こしの文章と元の動画のパスが入ります。
  ・他の人に作業データのフォルダを渡すときは、transcripts/ と settings.json と dataset/ を抜いてください(serve.log には動画名が入っています)。

 ⑦ 困ったとき
----------------------------------------------------------
  ・「準備が必要です」と出る → 表示された内容(ffmpeg / faster-whisper)を実行
  ・NVIDIA の GPU があるのに CPU で動く → setup\install-gpu.bat を実行して、ツールを起動し直す。
    それでも GPU にならない場合は、NVIDIA のドライバを最新にしてください
  ・「話者判別の部品(sherpa-onnx)が入っていません」と出る → setup\install-diarize.bat を実行して、
    ツールを起動し直す。入らないときは、Python のバージョンが新しすぎる可能性があります
    (Python 3.10 にしてください。部品の版を 3.10 で固定しています)
  ・話者判別のモデルをダウンロードできない → インターネット接続を確認(初回のみ必要)
  ・話者が多すぎる・少なすぎる → 「人数」を指定してやり直す
  ・「モデルを読み込めませんでした」 → インターネット接続を確認(初回のみ必要)。
    ディスクの空き容量も確認してください
  ・「音声を取り出せませんでした」 → 動画に音声がない、またはファイルが壊れて
    います。別の形式(mp4 など)に変換して試してください
  ・動画が再生されない → mkv など、ブラウザで再生できない形式です。
    文字の編集と書き出しは、再生できなくても使えます
  ・画面の上に赤い帯が出る → 古い版の黒い画面が残っています。閉じてから
    start を起動し直してください
  ・Python が見つからない → Python を入れ直し、「Add python.exe to PATH」に
    チェックを入れる
  ・ポート番号が使用中と出る → 自動で次の番号を使います。表示されたアドレスを開く
  ・「動画のフォルダに書き込めません」 → 動画が読み取り専用の場所(DVD・共有フォルダなど)にあるか、
    同じ名前のファイルを他のアプリで開いています。動画を書き込めるフォルダへ移すか、ダウンロードを使ってください
  ・「元の動画が見つかりません」 → 文字起こしのあとで動画を移動・削除・改名しています。元の場所に戻すか、
    「動画を選び直す」(下の ■ 動画を選び直す)で新しい場所を選んでください
  ・起動時に「※ …」と出る → 書いてある準備をしてから、黒い画面を閉じて起動し直してください

DaVinci Resolve連携(2 カット・3 パック のタブ。v0.16.0)
-------------------
- 2 カット のタブで残す区間を決めます(上の「■ 「編集」の3つのタブ」)。1 文字起こし のタブの各行の「残す/カット済」や、
  行の左端のチェックで選んで「まとめて ▾」の「選んだ行をカット/残す」で変えても、同じカットが変わります。
- 3 パック のタブで、Resolve で作るプロジェクトの fps(Text+ の fps)と画面の大きさ(縦・横)を選んで「パックを作る」。動画の隣の「動画の名前_pack」フォルダに
  できます(前に作ったものがあると、上書きの確認が出ます)。できたら「前回のパック」の「Resolve での手順を見る」の手順で取り込みます。
  カット・字幕を直したあとは「作り直し」の知らせが出ます。
- パック作りは cut2resolve が行います(入口 start.bat から開いたとき、同じ入口の中の cut2resolve を使います。
  そのため、入口の外で開いたときや cut2resolve が起動していないときは「パックを作る」は使えず、理由が出ます)。
  字幕の元として、動画の隣に「動画の名前.transcript.json」を書き出します(「書き出し」の「動画の隣に保存」と同じファイル)。
  「これから作るパック」の見積もりは、ファイルを作らずに計算します。
- 人に送るときは「詳しい設定」の「zip でダウンロード」(中身は同じパック。入口の外でも使えます)。
  「残す区間(.cut-plan.json)」だけの保存も「詳しい設定」にあります。
- パックの中身(v0.17.0 から最小限): 動画(v0.17.1 からフォルダの直下)、Text+ 字幕を作るスクリプト(.lua)と字幕の雛形(.drb)、登録用の bat と ps1。
  手順書は入れません(v0.17.1。「Resolve での手順を見る」で出ます)。
  「予備も入れる」をオンにしたときだけ、予備の EDL と手順書(予備_EDLで開く手順.txt)・字幕(SRT)も入ります。
  カットの記録(以前の cut-plan.json)はパックに入れず、このパソコンの作業データに残します(一覧の「パック済み」・前回のパックはこれを見ます)。
- 取り込み: プロジェクトは手で作る → bat で登録 →「ワークスペース」→「スクリプト」→「cut2resolve TextPlus Import Lua」。
- CUT_TextPlusは再編集用、SOURCE_WITH_HANDLESは削除区間の復旧用です。
- 切り抜きスタジオで新しく書き出した素材には前後10秒の編集余白があります。
