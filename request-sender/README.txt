==========================================================
  切り抜き依頼(RequestSender) v1.4.0
==========================================================
切り抜いてほしい配信の URL や、切り抜いた動画を「送る」ボタンで送るだけのアプリです。
「① 全自動」で送ったものは、できあがったパックを「受け取る」のタブで受け取れます。
送り先は、このアプリを渡してくれた人の Dropbox です(あなたの Dropbox のアカウントやお金は要りません)。
インストールは要りません(Windows 10 / 11 にはじめから入っている .NET Framework で動きます)。

【はじめに(最初に1回)】
  1. 受け取った RequestSender.zip を右クリック →「すべて展開」。できた RequestSender フォルダを、消さない場所(例: ドキュメント)に置く
     (RequestSender.exe・config.json・members.json は、同じフォルダに入れたままにしてください)
  2. RequestSender.exe をダブルクリック
     「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」
     (インターネットで受け取った、署名の無いアプリに出る確認です。最初の1回だけ)
  3. 「右クリックの『送る』でも送れるようにしますか?」と聞かれます。「はい」にすると、
     動画のファイルを右クリック →「送る」→「切り抜き依頼」で、その動画を入れた状態で開きます
     (Windows 11 は右クリック →「その他のオプションを確認」の中の「送る」)

【使い方】
  ■ 切り抜いた動画を送る
    - 動画のファイル(.mp4 .mov .mkv .webm .m4v)を「動画を送る」の欄へドラッグ(いくつでも)。「ファイルを選ぶ…」でもよい
    - 「配信者」を選ぶと、字幕がその人の色になります(選ばなくてもよい)
    - 「話す人の数」を選ぶと、その人数分の名前の欄が出ます(選ばなくてもよい。名前は空でもよい)。
      人数を入れると、PC が話者を分けて名前を付けます(名前は覚えている声と照らし合わせます。分からない人は「話者1」などのまま)。
      名前はメンバー一覧から選ぶか、そのまま打ちます。動画と URL の両方にかかります
    - 「送る」を押す。大きな動画は時間がかかります。下の棒が右まで進んで「送りました ✓」と出たら終わり
  ■ 配信を切り抜いてもらう
    - YouTube の配信・動画の URL を「配信を切り抜いてもらう」の欄に貼る(1行に1本。何本でも)
      使える形: https://www.youtube.com/watch?v=… / https://youtu.be/… / …/live/… / …/shorts/…
    - 「1本の配信から切り抜く数」(1〜10。はじめは 3)を決めて「送る」
  ■ 両方いっぺんに入れて送っても大丈夫です(中で2つの依頼に分けて送ります)
  ■ メモ: 送り先の人へのひとこと(自動の処理には使いません)
  ■ PC でどこまでやるか(送るたびに選ぶ。その回の動画と URL の両方にかかります。アプリを開いたときはいつも ①)
    - ① 全自動(パックまで作って届ける): PC が DaVinci Resolve のパックまで作ります。
        字幕の校正前のパックが「受け取る」のタブに届きます(配信の長さによっては何時間もかかります)
    - ② 軽く確認(文字起こしまで): 送り先の人が字幕を直してから仕上げます
    - ③ 全部人が行う(解析まで): 送り先の人が切り抜く所から決めます
    選ぶと、その下に1行で説明が出ます

  - 送っている途中で窓を閉じると、送るのをやめます(もう一度送り直してください)
  - 「送りました ✓」が出れば届いています。② ③ は送り先の人から返事は来ません

  ■ 受け取る(① で送ったもの)
    - 上の「受け取る」のタブを開くと、届いたものの一覧が出ます(新しいものが上)。「更新」で見直します
      種類「パック」= できあがったもの / 「失敗」= 自動でうまくいかなかった知らせ(選ぶと下に理由が出ます)
    - パックを選んで「受け取る」(ダブルクリックでもよい)。数 GB のことがあるので時間がかかります
      保存先ははじめ「ダウンロード\切り抜き依頼」。「変える…」で選び直せます(次からも使います)
    - パックは、できた順に1本ずつ届きます(1つの依頼で何本も出ることがあります)
    - 「受け取りました ✓」が出たら「フォルダを開く」。受け取ったパックは、ちゃんと保存できたことを確かめたあと、
      送り先の Dropbox と一覧から消えます(一覧に残るのは、まだ受け取っていないものだけ。もう一度は受け取れません)
    - 「受け取りましたが、Dropbox から消せませんでした」と出たら、保存はできています。「更新」で見直すとまた出るので、
      そのときにもう一度「受け取る」を押せば消えます
    - 「失敗」は、選んで理由を読んだあと「消す」を押すと一覧から消えます(消す前に確認が出ます)
    - 「まだ届いたものはありません」: まだできていません。しばらくしてから「更新」

【うまくいかないとき】
  - 「config.json が見つかりません」: RequestSender.exe と同じフォルダに config.json があるか確かめる
  - 「鍵が使えなくなっています」: 送り先の人に新しい config.json をもらって、今のものと入れ替える
  - 「インターネットにつながりません」: つながっているか確かめて、もう一度「送る」
  - 「Dropbox の空きが足りません」: 送り先の人に伝えてください
  - 途中で失敗したときは、送れたものが画面に出ます。残りだけもう一度送ってください
  - 「受け取るには新しい鍵が要ります」: 前の版の鍵(config.json)は送るだけの鍵です。送り先の人に新しい config.json をもらって入れ替える
  - 「保存先の空きが足りません」: ディスクを空けるか、「変える…」で別のドライブを選ぶ
  - 記録: %LOCALAPPDATA%\RequestSender\request-sender.log(困ったらこのファイルを送り先の人に見せる。鍵は書いていません)

【config.json について(大事)】
  config.json は、送り先の Dropbox の「このアプリ専用のフォルダ」にだけファイルを置いたり読んだりできる鍵です。
  他の人に渡したり、ネットに上げたりしないでください。なくしたり漏れたりしたら、送り先の人に伝えてください(鍵を無効にして作り直します)。

【やめるとき】
  RequestSender フォルダを消すだけです。右クリックの「送る」に出したときは、
  エクスプローラーのアドレス欄に shell:sendto と入れて開き、「切り抜き依頼」を消してください。


==========================================================
  ここから下は、アプリを渡す人(PC で受け取る人)向け
==========================================================
友人の PC → Dropbox の API → 自分の Dropbox の「アプリ」フォルダ → 同期 → PC のホームが見て自動で文字起こし、という流れです。
設計: docs/design/friend-intake.md

【鍵を作る(最初に1回)】
  1. https://www.dropbox.com/developers/apps →「Create app」
     - Choose an API: Scoped access
     - Choose the type of access: App folder(アプリ専用のフォルダだけ。Dropbox の他のファイルは読めない・書けない)
     - Name: 例「切り抜き依頼」(この名前がフォルダの名前になる。Dropbox 全体で重ならない名前が必要)
  2. できたアプリの「Permissions」タブで次の3つにチェック →「Submit」(ほかは付けない)
       files.content.write(送る・受け取ったあとに消す)・files.content.read(受け取る)・files.metadata.read(受け取るものの一覧)
     権限を変えたら、鍵は作り直す(前に作った鍵には新しい権限は付かない)
  3. 「Settings」タブの App key を控える。App secret は使わない(PKCE という方式なので secret なしで鍵を作れる)
  4. リポジトリ直下で:  python dev\dropbox_auth.py <App key>
     表示された URL をブラウザで開いて「許可」→ 出てきたコードを貼る → request-sender\config.json ができる
     (URL で上の3つの権限を頼む。足りない・余計な権限が付いたら [注意] が出るので、Permissions を直して作り直す)
     (鍵の値は画面に出しません。config.json は .gitignore と push.bat の検査でコミットされないようにしてある)
  5. request-sender\build.bat → dist\RequestSender.zip(exe・README.txt・members.json・config.json)を友人に渡す
     zip には鍵が入っているので、人に見られない方法で渡す

【届く場所】
  自分の Dropbox の「アプリ\<アプリの名前>\」(英語の Dropbox では「Apps\<アプリの名前>\」)。
  PC のホームがこのフォルダを見張る(Dropbox のデスクトップアプリで同期しておく)。
  - 動画: <id>__<元の名前>.mp4 など(名前がぶつかると Dropbox が「 (1)」などを付ける。依頼の JSON の files には実際の名前が入る)
  - 依頼: <id>.request.json(いつも最後に送る。これが届いた = そろった、の合図)
    id は yyyyMMdd-HHmmss-<16進 6 桁>。形:
      {"v":1,"kind":"video","id":"…","flow":"auto","files":["…__名前.mp4"],"streamer":"さくらみこ","memo":"…","sentAt":"2026-10-01T12:00:00+09:00"}
      {"v":1,"kind":"url","id":"…","flow":"auto","items":[{"url":"https://www.youtube.com/watch?v=xxxxxxxxxxx","top":3}],"memo":"…","sentAt":"…"}
    speakers(v1.3.0 から。人数を選んだときだけ。選ばないとキーごと無い): "speakers":{"count":3,"names":["名前","名前"]}
      count = 話す人の数(1〜10)。names = 友人が入れた名前(空は除く・前後の空白なし・重複なし・1つ60文字まで・count 以下。0 個のこともある)。
      動画・URL のどちらの依頼にも、memo と sentAt の間に入る。PC はこれで話者を count 人に分け、names を覚えている声と照らして名前を付ける
    videoTracks(v1.4.0 から。① 全自動のときだけ。1〜5・既定 1。②③ はキーごと無い): "videoTracks":3(speakers の後・sentAt の前)。
      PC が作る Resolve のパックの映像トラックの数(V1〜V数 に同じ動画(V2 から上は映像だけ)・字幕はいちばん上)
    flow(v1.1.0 から): "auto" = ① 全自動(パックまで)/ "check" = ② 文字起こしまで / "manual" = ③ 解析まで。
      1回の「送る」の動画と URL の両方に同じ値が付く。v1.0.0 の依頼には flow が無い
    動画と URL を一度に送ると、依頼は2つ(id も2つ)になる
  - 返すもの(PC が置く。友人のプログラムの「受け取る」が一覧にする): アプリのフォルダの「出力\」
      <依頼の id>__<題>.zip        … DaVinci Resolve のパック(① で作ったもの)
      <依頼の id>__<題>.失敗.txt   … ① の自動の処理が失敗した理由(UTF-8・BOM つき・短く。64KB を超えた分は読まない)
    友人のプログラムは、受け取り終えたパックと、読み終えて「消す」を押された失敗の知らせを、ここから消す(v1.2.0 から。files/delete_v2)。
    そのため 出力\ は友人が受け取るたびに空いていく(自分では消さなくてよい)。1つの依頼のパックは、できた順に1本ずつ置いてよい。.zip と .失敗.txt 以外(フォルダ・途中のファイル)は一覧に出さない。
    書き終えてから置く(途中の名前で書いて最後に名前を変える)と、書きかけのものが一覧に出ない。
    同じ名前で置き直すと、友人の側でまた一覧に出る(消えていれば新しいものとして出る)

【v1.0.0 から上げるとき(鍵の作り直しが要る)】
  v1.0.0 の鍵は files.content.write だけなので、「受け取る」が使えない(画面に「新しい鍵が要ります」と出る)。
  1. App console の Permissions で files.content.read・files.metadata.read にもチェック →「Submit」
  2. python dev\dropbox_auth.py <App key> をやり直す(config.json を作り直す)
  3. request-sender\build.bat → dist\RequestSender.zip を友人に渡し直す(友人は exe と config.json を入れ替える)
  古い鍵は https://www.dropbox.com/account/connected_apps で切ってよい(新しい鍵は同じアプリなので、切ると新しい鍵も無効になる点に注意。
  切るなら先に切ってから 2 をやる)

【鍵を無効にする(漏れた・友人に使わせるのをやめる)】
  https://www.dropbox.com/account/connected_apps でアプリの接続を切る(Disconnect)。
  またはアプリの設定(developers/apps)でアプリごと消す。新しく渡すときは「鍵を作る」の 4〜5 をやり直す。

【開発】
  - C# 5・WinForms。Windows に入っている .NET Framework 4 の csc で作る(ホロカラーと同じ形。build.bat)
  - src\Core.cs(URL の読み取り・id・JSON・分け方・「出力」の名前の読み取り・手元の記録)/ Dropbox.cs(API)/ Sending.cs(1回の送信)/
    Receiving.cs(一覧と受け取り)/ MainForm.cs(画面・送る)/ MainForm.Receive.cs(画面・受け取る)/ Program.cs(起動・「送る」のショートカット)
  - 手元の記録: %LOCALAPPDATA%\RequestSender\ の settings.json(保存先)・request-sender.log
  - テスト: build.bat が tests\CoreTests.cs を作って流す(通信はしない)
  - メンバーの一覧は holo-colors\members.json を写す(build.bat)
