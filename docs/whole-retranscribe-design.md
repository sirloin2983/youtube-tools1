# 動画全体の再認識(設計メモ)

2026-09-28 Cowork(Claude)が作成。実装は Claude Code(PC。文字起こしツールの担当)に任せる。**コードはまだ変えていない**。

## 1. ユーザーの要望と決まったこと
- 要望: 「文字起こしの再認識に、動画全体を再認識させる機能が欲しい」。あわせて「複数人(声が重なる所)だと全く認識しない(0文字)ことがある」
- ユーザーが決めたこと(2026-09-28、質問への回答):
  1. 動き = **動画全体を「範囲をまとめて」と同じやり方で認識し直す**(行は新しく作り直す。抜けも拾う。15分の上限は外す)
  2. **校正済み(proofed)の行は残す**。それ以外の所だけ新しい結果で埋める
  3. 実装は Claude Code に任せる(この文書が依頼書)

## 2. 今の再認識との違い
| 対象 | 行の区切り | 抜け | 上限 | 校正済み |
| --- | --- | --- | --- | --- |
| 文字の要確認の行 / 選択 / すべての行(`mode: each`) | そのまま・1行ずつ | 直らない | 2000行 | 上書き(proofed を外す) |
| 範囲をまとめて(`mode: range`) | 作り直す | 拾う | 15分(`MAX_RANGE_SEC`) | 範囲内は全部差し替え |
| **動画全体(新・`mode: whole`)** | 作り直す | 拾う | 新規の文字起こしと同じ6時間 | **残す** |

## 3. 仕様

### 3-1 画面(編集 1 文字起こし →「文字をまとめて直す」→ 再認識)
- 「対象」の選択肢に **「動画全体(校正済みの行は残す)」** を足す(`rtTarget` の `whole`)。行の選択は要らない
- ヒント(`#rtHint`): `動画全体 0:00〜1:02:10 を認識し直します。校正済みの 42 行は残し、残り 380 行を新しい行に差し替えます(行の数は変わります)。目安 約23分(CPU・large-v3)`
  - 目安は段0 の実測(large-v3・CPU で実時間の約 0.37 倍)から出す。GPU・他のモデルは「目安なし」でよい(でたらめな数字を出さない)
- 押すのは今と同じ2度押し(`armDelete`)。文字を大量に書き換えるので、1回目の表示に「校正済み以外の行が書き換わります」を出す
- 評価用の文書では、今と同じく選べない(サーバーも `eval_set` で断る)
- 画面の変更は選択肢1つとヒントだけ。NN/g の原則で確かめる点: 状態の見える化(目安・進み具合・取り消し)、誤りの予防(2度押し・評価用は不可)、戻せること(以前の版に戻す)

### 3-2 API
- 既存の `POST /api/retranscribe` に `mode: "whole"` を足す(新しい API は作らない。排他・ジョブの表示・読み込み直しをそのまま使える)
- `validate_retranscribe`: `whole` のとき
  - `range = [doc.start, doc.end]`(文書の範囲全体)。`ids` は画面から受け取らず、サーバーが「校正済みでない全行」を入れる
  - 上限は `MAX_RANGE_SEC` ではなく新規の文字起こしと同じ6時間(1752 行目付近の `too_long` と同じ値を共通の定数にする)
  - `vadMode` は既定「弱め」(4-2 の 5)。捨てすぎたら自動で緩める(4-2 の 1)。`wordSplit` も range と同じ
  - タイトル: `全体を再認識: <文書名>`
- ジョブの種類は `retranscribe` のまま(排他 `EXCLUSIVE` は変えなくてよい)

### 3-3 認識
- 音声の取り出し・認識は `range` と同じ流れ(`audio_span` → `extract_audio` → `range_lines_real`)。音声は新規の文字起こしと同じく全体を読むので、メモリも新規の文字起こしと同程度(6時間で float32 約1.4GB)。新しい分割の仕組みは作らない
- 進み具合・取り消し・GPU 失敗時の CPU へのやり直しは `range` の実装をそのまま使う

### 3-4 結果の反映(`apply_range` を拡張 or `apply_whole` を新設)
1. **校正済みの行は残す**: 校正済みの行の時間(前後 0.05 秒)を「守る区間」とする。
   新しい行のうち、真ん中が守る区間に入るものは捨てる。一部だけ重なるものは、守る区間の外側に切り詰め、0.3 秒未満になったら捨てる
2. **文字が出なかった所は元の行を残す(0文字対策の安全装置)**: 差し替え対象の元の行ごとに、新しい行と時間が重なる割合を見て、
   **重なりが 30% 未満(= 新しい認識でその所がほぼ空)なら元の行を残し**、印「再認識で文字が出なかった」を付ける。
   → 今の `range` は範囲内の元の行を全部消すので、声が重なって 0 文字になった所の字幕がそのまま消える。`range` にも同じ安全装置を入れる(下の 4)
3. 話者: 今の `apply_range` と同じ(時間が最も重なった元の行から引き継ぐ)。残した行は元の話者のまま
4. 機械の出力の記録 `original`: 守る区間(校正済み)の分は**古いまま残す**(人が直した元の機械の出力なので、学習の対応を壊さない)。それ以外を新しい出力に差し替える(`replace_original_multi` を「区間の一覧」を受け取れるようにする)
5. 単語の時刻 `replace_words`: 守る区間を除いた所だけ差し替える
6. 保存の前に `.bak/<id>.pre-retranscribe.json` と `hist_snapshot(force=True)`(今と同じ)。`apply_edit_cuts` でカット済を付け直す
7. `doc.retranscribed = {model, lines, range, whole: true, kept: 校正済みで残した行数, emptyKept: 0文字で残した行数, at}`。
   `docInfo` の表示と、完了の知らせに「校正済み n 行と、文字が出なかった m 行は元のまま」を出す
8. 全体で1文字も出なかったら今と同じ `no_speech` のエラー(元の文書は変えない)

## 4. 「複数人だと 0 文字」について(調べたことと対策)

### 4-1 実際の例で分かったこと(2026-09-28。教師データ＿白上フブキ02)
- 文書 `8e89d529ae24`(40 秒・評価用・large-v3・CPU・**声の検出: 標準**・音量補正あり)は行が 0。認識の記録 `recognition.runs` の `wallSec` が **0.08 秒**(40 秒の音声を large-v3 の CPU で認識したら普通は十数秒)
- worker.log(19:14:02): **`VAD filter removed 00:40.000 of audio`** = 声の検出(Silero VAD)が40秒すべてを「声ではない」と判断して捨て、認識のモデルには何も渡っていなかった
- 同じ時に作った 03(`855b1f53aa87`、30 秒)も 22.4 秒が捨てられ、残りから「ご視聴ありがとうございました」(よくある誤認識の文)だけが出ている
- 話者判別用に PC にある pyannote の区切りのモデル(`models/diar/segmentation.onnx`)で同じ音声を見ると、**40 秒のうち約 85% に声があり、16〜21 秒・39 秒は2人の声の重なりが多い**。声は確かにある
- 音量は普通(平均 -17dB・最大 -2.5dB)。音声が壊れている・無音、ではない
- → **原因は「捨てる判定(no_speech)」ではなく、声の検出(Silero VAD。「標準」= しきい値 0.5)**。声が重なる・BGM がある所を声と見なさないことがある。
  「弱め」(しきい値 0.3)で通るかは、まだ試していない(Silero のモデルをクラウドで動かせなかった)
- 設定(settings.json)の `vadMode` が `normal`(標準)になっている。コラボの文字起こしでは「弱め」の方が安全(画面の説明にもそう書いてある)

### 4-2 対策(今回の実装に入れる)
1. **声の検出が捨てすぎたら、自動で緩めてやり直す**(新規の文字起こし・範囲・全体の全部):
   声の検出が捨てた割合を取り(faster-whisper の戻り値 `info.duration_after_vad` / `info.duration`。ログの "VAD filter removed" と同じもの)、
   **残りが 20% 未満、または文字が 0** のときは、「弱め」→「なし」の順でやり直す。やり直したことを文書の `recognition.runs` に残し、
   画面に「声の検出で大部分が声ではないと判断されたので、検出を緩めて認識しました」と出す(何が起きたか見えるように)
2. 3-4 の 2 の安全装置(範囲・全体。再認識で文字が出なかった所は元の行を残す)
3. **空いた所だけ条件を緩めてもう一度**: 3-4 の 2 で「ほぼ空」になった元の行の区間を集め(前後 0.5 秒)、
   `vad_filter=False`・`no_speech_threshold=None` でその区間だけ認識し直す。文字が出たら新しい行として入れ、印「要確認: 声が重なる所を緩い条件で認識」。
   緩い条件は無音で幻覚を出しやすいので、**元の行があった所(= 声があった所)にだけ**使う
4. 記録: 声の検出が捨てた秒数を `recognition.runs` に `vadRemovedSec` として残す(今はログにしか出ていない)。精度の道具 `tools/eval_asr.py` でも見られるように
5. 「全体を再認識」の声の検出は、画面の設定に関係なく**既定「弱め」**にする(やり直しの目的が抜けを拾うことなので)

### 4-3 後で検討(設計の変更なのでユーザーに確認してから)
- 声の検出を Silero から **pyannote の区切りのモデル**(話者判別のために PC にすでにある。重なった声を「2人」として見つけられる)に替える、または両方の「どちらかが声」を使う。
  `docs/transcription-overhaul-plan.md` の段3(抜け)・段5(重なり声)とまとめて、評価用のデータで比べてから決める

### 4-4 すぐにできる回避(実装の前)
- 0 文字になった文書は、設定の「声の検出」を「弱め」か「なし」にして文字起こしし直す(評価用の文書は、評価用を外すか新しく文字起こしする)
