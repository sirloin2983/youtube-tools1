## 1. 出力先に途中のファイルを並べない
- 要望: 「出力先が汚くなるから途中出力のものをまとめて新たな下層のフォルダに入れる」
- **決定(ユーザー): パックと元動画(書き出した切り抜きの mp4)以外を下のフォルダへ**
- 下のフォルダの名前: `作業用`(`ytt_core` の1か所で決める)。入るもの: `<名前>.clip.json`・`<名前>.edit.json`・`<名前>_edit.mp4`・`<名前>_edit.clip.json`・
  `<名前>.transcript.json`(「編集」がパックの前に書く・「作業用フォルダに保存」)・`.srt`・`.cut-plan.json`(「編集」の書き出し)・`.studio-id`(フォルダの持ち主の印)
- 直下に残るもの: `<名前>.mp4`・`<名前>_pack\`・ユーザーが自分で置いたもの
- 以前の置き方(動画の隣)のファイルは**動かさない**(読む側が両方を見る。データの移し替えはしない = コピーも削除もしない)
- 読む側は「`作業用\` → 動画の隣」の順に探す(1か所の関数に集める)。書く側は `作業用\` に書く

## 2. 入口が二つになる
- 指摘: 「bat からと他のツール欄から入ったときに入口が二つになる」
- 原因: ツールの窓の「入口」リンク(`href="/"`・target なし)でその窓自体が入口に変わり、bat で開いた入口の窓も残る。既にある入口を探す仕組みが無かった
- **決定(ユーザー): 開いている入口を前に出す**
- 実装(入口 0.10.2・ui-kit v5): 入口へ戻るリンク(`a[data-ui-portal]`)を押すと、BroadcastChannel `ytt-portal` で入口の画面に問い合わせる(0.4 秒)。
  答えがあれば移らずに `POST api/ytt/focus-portal` → 入口のサーバーが題名「動画編集ツール — 入口」の窓を探して前に出す(`appwindow.focus_window`。
  前面の窓のスレッドに入力をつないでから SetForegroundWindow。入口のサーバーは前面のプログラムではないので、そのままでは点滅するだけ)。
  前に出せなければ「入口はほかの窓(タブ)で開いています」と知らせる(ブラウザのタブで裏にあるときなど)。答えが無ければ今までどおりその場で移る
- 注意: bat をもう一度押したとき(入口が起動中)は、今までどおり入口をもう1枚開く(今回の対象外)

## 3. まとめて実行を各段階から
- 要望: 「案件一覧からしかまとめて実行できなくて不便だから、各ツールからその後の作業をまとめてできる機能が欲しい」。
  ⑦ でスタジオの配信の画面・「編集」の履歴にも足したと伝えたうえで、**決定(ユーザー): ユーザーが作業する各段階に欲しい**
- 段階と入口(どれも入口の `app/autorun.py` の同じ仕組み。名前は「まとめて実行」にそろえる):
  | 段階 | 場所 | その後の作業 |
  | --- | --- | --- |
  | 配信を選ぶ | 入口の案件の一覧(既存) | 解析から全部 / 採用後を全部 / 文字起こしまで |
  | マークを付ける | スタジオの配信の画面の「まとめて実行 ▾」(⑦) | 同上(採用したマーク全部) |
  | 1つの切り抜き | スタジオのマークの行(採用・書き出し済み)に「この後をまとめて」(新規) | 書き出し(まだなら)→ 文字起こし → パック |
  | 文字起こし・校正・カット | 「編集」の題名の行の「まとめて実行 ▾」(新規。3つのタブのどれでも) | 今の文書: 文字起こし(行が無ければ)→ パック(カットがあればカットのとおり) |
  | 文書を選ぶ | 「編集」の履歴の「選んで、まとめて実行」(⑦) | 選んだ文書を同上 |
