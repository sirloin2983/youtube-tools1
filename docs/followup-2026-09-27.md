## 2. 入口が二つになる
- 指摘: 「bat からと他のツール欄から入ったときに入口が二つになる」
- 原因: ツールの窓の「入口」リンク(`href="/"`・target なし)でその窓自体が入口に変わり、bat で開いた入口の窓も残る。既にある入口を探す仕組みが無かった
- **決定(ユーザー): 開いている入口を前に出す**
- 実装(入口 0.10.2・ui-kit v5): 入口へ戻るリンク(`a[data-ui-portal]`)を押すと、BroadcastChannel `ytt-portal` で入口の画面に問い合わせる(0.4 秒)。
  答えがあれば移らずに `POST api/ytt/focus-portal` → 入口のサーバーが題名「動画編集ツール — 入口」の窓を探して前に出す(`appwindow.focus_window`。
  前面の窓のスレッドに入力をつないでから SetForegroundWindow。入口のサーバーは前面のプログラムではないので、そのままでは点滅するだけ)。
  前に出せなければ「入口はほかの窓(タブ)で開いています」と知らせる(ブラウザのタブで裏にあるときなど)。答えが無ければ今までどおりその場で移る
- 注意: bat をもう一度押したとき(入口が起動中)は、今までどおり入口をもう1枚開く(今回の対象外)

## 3. まとめて実行を各段階から
- 要望: 「案件一覧からしかまとめて実行できなくて不便だから、各ツールからその後の作業をまとめてできる機能が欲しい」。
  ⑦ でスタジオの配信の画面・「編集」の履歴にも足したと伝えたうえで、**決定(ユーザー): ユーザーが作業する各段階に欲しい**
- 段階と入口(どれも入口の `app/autorun.py` の同じ仕組み。名前は「まとめて実行」にそろえる):
  | 段階 | 場所 | その後の作業 |
  | --- | --- | --- |
  | 配信を選ぶ | 入口の案件の一覧(既存) | 解析から全部 / 採用後を全部 / 文字起こしまで |
  | マークを付ける | スタジオの配信の画面の「まとめて実行 ▾」(⑦) | 同上(採用したマーク全部) |
  | 1つの切り抜き | スタジオのマークの行(採用・書き出し済み)に「この後をまとめて」(新規) | 書き出し(まだなら)→ 文字起こし → パック |
  | 文字起こし・校正・カット | 「編集」の題名の行の「まとめて実行 ▾」(新規。3つのタブのどれでも) | 今の文書: 文字起こし(行が無ければ)→ パック(カットがあればカットのとおり) |
  | 文書を選ぶ | 「編集」の履歴の「選んで、まとめて実行」(⑦) | 選んだ文書を同上 |
- 実装で決めたこと(2026-09-27 Claude Code。ユーザーは寝ていたので、ここは質問せずに決めた。違えば直す):
  - 「編集」の題名の行(3つのタブのどれでも出る)に「まとめて実行 ▾」: 今の文書を `start-docs`(履歴の「選んで、まとめて実行」と同じ API)で1本。
    先に文書とカットを保存する。配信者(字幕の色)・「パックがあれば作り直す」も同じ。進み具合は題名の行の札(`#pillAuto`。終わって10分より前は出さない)。
    配信者の欄は、開いたとき空なら、パックのタブでこの文書に入れた名前(`tx.streamer.v1`)を入れる。終わったら「前回のパック」を読み直す
  - スタジオのマークの行(採用・書き出し済み)に「この後を ▸」: そのマークだけ(`POST /api/autorun/start` の `marks`)を「採用後を全部」で。
    書き出し済みなら書き出しは飛ばして 文字起こし → パック。上の「まとめて実行 ▾」の配信者の色も使う。同じ配信の実行が動いている間は断る(今までと同じ)。
    「解析から全部」とは組み合わせない(選んだマークだけなら解析・採用は要らない)。1回に 50 まで(`MAX_MARKS`)
  - 案件の一覧・スタジオの配信の画面・「編集」の履歴は ⑦ のまま(入口は全部同じ `app/autorun.py`・名前は「まとめて実行」にそろえる)

## 4. 配信者の名前で字幕の色
- 要望: 「配信者の名前を入れるとそのカラーコードで字幕を作ってほしい(あくまで手動で入れたときだけでいいが、まとめて実行のときも欲しい)」
- **決定(ユーザー): 文字をメンバーカラーに**(メンバーカラーの文字 + 白いふち + 外側の黒いふち。名前を入れないときは今までどおり黒い文字)
- 色の一覧: ホロカラーの `holo-colors/members.json`(読むだけ)+ ホロカラーのマイカラー(`%LOCALAPPDATA%\youtube-tools\holo-colors\my-colors.json`。読むだけ・マイカラーが先)。
  名前の照らし合わせは `ytt_core/colors.py` の1か所(ひらがな・カタカナ・全角半角・大文字小文字・空白を区別しない。名前・ローマ字・id)
- 入れる所: 「編集」の 3 パック のタブ(文書ごとに覚える)と、まとめて実行の各入口(案件・スタジオ・「編集」)。自動では入れない(スタジオの配信者名から推測しない)
- 実装で決めたこと(2026-09-27 Claude Code):
  - 照らし合わせ `ytt_core/colors.py`: NFKC・小文字・カタカナ → ひらがな・空白と区切りを除いて、名前・ローマ字・id と完全一致 → 無ければ名前の一部
    (ローマ字・id は 3 文字から)で**1人に決まるときだけ**。同じ名前はマイカラーが先。2人以上なら候補を返して決めない(「ら」→ 候補)。
    漢字はかなと見なさない(「しらぬい」では 不知火フレア に合わない)。マイカラーは inplace(テスト)では読まない
  - 名前 → 色は**サーバーで**だけ決める(画面は名前のまま送る)。cut2resolve の `output.streamer`・まとめて実行の `streamer`・zip の `streamer`。
    まとめて実行は始める前に照らし合わせ、見つからなければ断る(途中のパックで失敗させない)。照らし合わせた名前を cut2resolve に渡す
  - Text+: `resolve_textplus.text_style(color)` が塗りの要素(ElementShape 0)の色だけを変える。見た目の名前(マーカーのメモ・手順)に名前とカラーコード。
    パックの記録に `textColor`・`streamer`。区間・字幕は同じ(契約テストの対象外の追加の値)
  - 画面: ui-kit の `UIKit.streamer`(`<input data-ui-streamer>`。候補の datalist・色の見本・合う人)。候補の API は画面の共通の `api/ytt/streamer-colors`
    (どの画面からも入口が受け持つ)。パックのタブは文書ごとに localStorage `tx.streamer.v1` に覚え、字幕の見本(パック・カット)の色も変える(CSS の `--tt-cap-color`)
  - 不具合と直し: 名前を入れた直後に隣の「実行」を押すと、欄から離れたとき(change)にもう一度照らし合わせを始めて説明の文が縮み、
    ボタンが押している途中でずれてクリックが成立しなかった。同じ名前ではもう一度照らし合わせない・途中の「探しています…」を出さない、にした
