## 変更点
1. **辞書の自動学習**
   - learn_events: 差分を、同じ種類の文字(カタカナ〔ー・含む〕・漢字・英数字)が続く分だけ語の全体に広げる(トーイ→トワ、反省魂→配信魂)。ひらがなは広げない。12文字を超えたら捨てる(従来どおり)
   - _spans(学習の提案・自動適用・「そのまま残した例」の数え方)は、語の途中には当てない(_bounded)。ひらがな・記号との境目は切れ目
   - 手動の置換辞書に `|語|=>正` 構文を追加(縦棒で挟むと単語の途中に当てない。縦棒なしは従来どおり全部置換)。学習候補の「登録」は、カタカナ・漢字・英数字だけの語なら自動で `|語|` の形にする。画面の一括適用(replaceOne)も同じ規則(serve.py の _cc/_bounded/wb_split と対応)。学習候補の「登録済み」判定は縦棒を外した形で比べる
   - 限界: 「トルカ」と「トルカパパ」は別の規則になる(名前+接尾語が同じカタカナの並び)。ひらがなの断片は従来どおり
2. **落ちる問題**(原因は特定できていない。serve.log などが無いため。以下は原因の見立てと対策)
   - 見立て1(最有力): `_models` が読み込んだモデルを全部保持し続けていた。large-v3 と turbo(と A/B)を交互に使うとメモリが積み上がる → 動画編集ソフトと同時だとメモリ不足で強制終了(Python の例外にならず、黒い画面ごと消える)。対策: モデルは1つだけ保持し、別のモデルを読み込む前に手放す(gc)。MemoryError は「メモリ不足」と表示
   - 見立て2: ネイティブ(CTranslate2 等)の異常終了は Python の例外にならず痕跡が残らない。対策: faulthandler を serve.crash.log に有効化、serve.log(起動・終了・ジョブの開始と終了・使っているメモリ・例外・スレッドの例外)、`.running.json`(起動中の印。正常終了で消える)。次の起動で残っていれば「前回は正常に終了しませんでした。そのとき実行中だったジョブ…」を表示
   - 見立て3: ワーカースレッドの想定外の例外でジョブが止まったまま詰まる。対策: work_one で例外を捕まえてジョブを失敗にする
   - 対策: start.bat(CRLF)/ start.command は異常終了(終了コード≠0)で3秒後に最大3回まで自動再起動(2回目以降は --no-open)。実行中だったジョブは消える(待機列は保存していない)
   - 未検証: Windows のメモリ取得(ctypes / psapi)、start.bat の再起動ループ(実機)、黒い画面の×での終了は捕まらない(印が残るだけ)
3. **動画全体が1つのセリフ(長い行)**: 原因の見立ては、Whisper の行の終わりの時刻が声のない所(BGM・間)まで伸びる/続けて話すと長い1行になる。対策: word_timestamps=True(設定 `wordSplit`、既定オン)で単語の時刻を取り、split_segment で ①行の始まり・終わりを最初・最後の単語にそろえる ②単語の間が1秒以上あいた所で分ける ③8秒・40文字を超える行は、間の大きさ・句読点・真ん中への近さで区切りのよい所へ分ける。単語の並びと文章が合わないとき・単語が無いときは何もしない。再認識・A/B には使わない。認識は少し遅くなる(未測定)。params.wordSplit に記録。既存の文字起こしは変わらない
   - 未検証: 実際の faster-whisper での単語の時刻(日本語)の質、速度への影響、分割の閾値(1秒・8秒・40文字)は仮の値
   - 「動画全体が1つのセリフ」が別の状況(ユーザーの見た実際の症状)だった場合は再調査が必要
