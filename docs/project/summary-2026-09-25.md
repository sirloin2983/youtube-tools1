# 作業の要点(2026-09-25・cut2resolve v0.4.0 / Text+)

## ゴール(ユーザーの前提)
① 最終は 30fps で友人が編集 ② 字幕は Text+ 必須 ③ 縦でも画面外を後で使える。切り抜きスタジオの出力は 60fps 横。友人がスクリプトを実行する。

## 決めた方式(実機で成功)
- 動画は再圧縮せず元の 60fps 横のまま渡す。30fps・縦はプロジェクト側で作る(画質劣化は書き出しの1回だけ)
- プロジェクトは画面から手で作る: 30fps・1080x1920・入力スケーリング「最短辺をマッチ: 他をクロップ」→ 位置 X で画面外を使える
- スクリプト(Lua)はプロジェクトを作らない・設定を変えない。開いているプロジェクトに CUT_TextPlus(V1 映像・A1 音声・V2 Text+)と SOURCE_WITH_HANDLES を足すだけ。fps・解像度が違えば止まる
- 字幕の位置: 区間ごとの相対コマ × (タイムライン fps / 動画 fps)。60fps→30fps で位置一致を実機確認
- 結果表示: print がコンソールに出ない環境のため、マーカー(緑=完了/黄=一部失敗、メモに件数・字体)と「C2R_エラー_理由」タイムライン
- 字幕の見た目: 黄色い文字 + 黒いふち。フォントは Fusion の GetFontList() から Windows 標準の日本語フォントを選ぶ(名前の決め打ちは Font Not Found)
- 友人向け手順書をパックの「友人へ.txt」に(EDL の手順は「予備_EDLで開く手順.txt」)

## 音割れ(未解決の原因・回避済み)
- 編集ページのタイムラインだけで割れた。ファイル・素材の形式・fps・Resolve の音量処理が原因ではない
- 割れたのは API の CreateProject で作ったプロジェクト(設定の既定値が画面から作ったものと違う)。画面から作ったプロジェクトでは一度も割れていない。原因の断定はしていない(ユーザー: 「B と断定は危険」)
- 決まり: スクリプトにプロジェクトを作らせない

## 分かった注意点
- Cowork→PC への同名ファイルの再書き込みで古い内容になることがあった → 書き込み後に読み直して照合する
- cut2resolve の画面はコード更新後に起動し直さないと古いコードでパックを作る(入口から起動なら入口で停止→起動)
- GetSetting("timelineInputResMismatchBehavior") は画面の設定と一致しないことがある(参考表示のみ)
- Resolve 無料版: スクリプトの print がコンソールに出ない、io.open での書き出し不可。設定確認はプロジェクト DB(Project.db の SM_Config、zstd + protobuf)を読む
- 実行直後はインスペクタの数値変更が反映されないことがある → 10〜20 秒待つ
