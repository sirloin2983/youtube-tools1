# 文字起こしツール v0.7.1(長時間の校正作業向け)— v0.7.0 仕様書への追補

`claude/transcribe-tool-spec.md`(v0.7.0)の続き。SERVER_VERSION と APP_VERSION は 0.7.1 に揃えてある。納品は全体zip(transcribe-tool-v0.7.1-full.zip。ユーザーの transcripts/・settings.json・models の中身は含めない。上書き展開しても、それらは消えない)。

## 目的
「校正済み」を付ける作業が数時間続く前提で、(1)画面を広く使える (2)キーボードだけで「聞く→確認→次」が回る (3)途中で失敗・競合しても作業が失われない (4)数千行でも重くならない、を実現。

## サーバー側(serve.py)
- **履歴(自動スナップショット)**: 保存(PUT)時、前回の履歴から10分(HIST_INTERVAL=600秒)以上たっていれば、保存前の状態を transcripts/.hist/<tid>/<ミリ秒>.json に残す。最新30世代(HIST_KEEP)。再認識・話者判別の直前は force で必ず残す(従来の .bak 1世代も維持)。GET /api/history?id= → [{ts, segments, proofed, chars}]。POST /api/restore {id, ts} → 戻す前の状態も force で履歴に残してから復元。ts は履歴にある値だけ受ける(パス指定不可)。履歴のパスは TX_DIR から都度組み立てる(試験で TX_DIR を差し替えても本物のフォルダを汚さないため)
- **保存の競合検出**: PUT に baseUpdatedAt が付いていて、保存済みの updatedAt と違えば 409(error=conflict)。force:true で上書き可。別タブ・再認識・話者判別で先に更新された内容を、古い画面が上書きする事故を防ぐ。baseUpdatedAt を送らない従来クライアントは今までどおり(後方互換)。保存全体は _save_lock で直列化(検査→履歴→書き込みが1つの区間)
- 履歴が書けなくても保存は止めない

## 画面側(index.html)
- **集中モード**(右上ボタン / Alt+Z): 左のパネルを隠し編集を広く。**保存しない**(開くたび解除。一覧が見えず迷うのを避ける)。処理中の件数は右上のバッジに出る(押すと解除して処理状況へ)
- **表示**メニュー(localStorage `tx.view.v1`。try/catch): 文字の大きさ(13/15/17/20px)・行の間隔を詰める・動画の大きさ(大/中/小/音声だけ=54px)・画面の色(自動/明るい/暗い。`data-theme`)・休憩のお知らせ(なし/30/45/60分)。追従・1行ずつ止める・自動再生・再生速度も保存
- **キー操作**: Alt+Enter(校正済み→次へ)、Alt+↑/↓(前後の行。絞り込み中は表示行のみ)、Alt+N(次の未校正。Shift で前)、Alt+G(次の要確認。Shift で前)、Ctrl+Enter / Alt+R(この行を聞き直す)、Alt+, / Alt+.(±3秒)、Alt+[ / ](再生速度)、Alt+Z、Esc(入力欄から抜ける→Space で再生停止)。**Alt+←/→(ブラウザの戻る)、Alt+F/D/E 等は避けた**。e.code で判定(Mac の Option 特殊文字対策)。一覧は「操作キー」ダイアログ
- **移動したら自動で再生**(既定オフ): 行移動のたびにその行だけを再生(終わりで止まる)。Alt+Enter だけで聞く→確認→次を聞く
- **進み具合の帯**: canvas に全行を時間軸で描く(緑=校正済み・黄=要確認・灰=未校正)、再生位置のマーカー、クリックでその行へ。隣に「未校正 N行(音声 約X分)・今回 +N行・作業M分」(操作があった時間だけ30秒刻みで加算。放置は数えない。休憩のお知らせもこの時間)
- **用語ボタン**: 用語集(先頭16語)をワンクリックで行のカーソル位置に挿入(選択があれば置換)。mousedown で preventDefault して入力欄のフォーカスを外さない
- **続きから**: 行ID・時刻を localStorage(`tx.pos.<tid>`)に記録し、開き直すとその行へ(動画位置も)
- **履歴UI**: 「話者・置換・書き出し」内。開くと一覧、「この時点に戻す」は2度押し。復元前に未保存分を保存
- **競合UI**: 409 で自動保存を止め、上部に案内(読み込み直す / この画面の内容で上書き=2度押し)。保存失敗は5秒後に自動再試行。タブを離れる(visibilitychange)ときは待たずに保存。保存時刻を表示
- ツールバーの整理: 2段(検索・絞り込み・未校正へ・元に戻す・一括操作▼・話者…▼ / 速さ・±3秒・追従・1行ずつ・自動再生・進捗)。一括操作(選択行・全行の校正済み、確度高の提案を全部採用)は「一括操作▼」ポップオーバーへ。認識の設定の説明文(docInfo)は固定領域の外へ。固定領域の高さを ResizeObserver で測り、scroll-margin-top に反映(固定領域の下に行が隠れないように)

## 性能(4000行の文書、疑似モード・ヘッドレス Chromium)
- 課題: 全行の textarea を1つずつ「高さ auto→scrollHeight 読み」していて、入力ごとに全体レイアウトが走り、1文字入力の反応(90%点)が約129ms
- 対策: ①行に content-visibility:auto(画面外の描画・レイアウトを省く)②行の高さは CSS `field-sizing:content` が使えるブラウザではそれにまかせる(JS 計測なし)③使えない場合は IntersectionObserver(上下800px)で画面の近くの行だけを「まとめて縮める→まとめて測る→まとめて設定」で計測 ④行の参照を querySelectorAll でなく children で ⑤要確認の解除は全体描画し直しをやめ、その行だけ更新
- 結果: 開く 約0.9秒 / 入力の反応(90%点) 約20ms(field-sizing) 〜37ms(IO の代替経路)/ Alt+Enter→次の行 約0.15秒 / 未校正への絞り込み 0.06秒。旧経路(content-visibility だけを足して全行を測る)は開くのに約15秒かかり不採用(画面外の測定が強制レイアウトを起こす)
- 代替経路は URL に `?nofs=1` で強制できる(試験用)

## 話者識別の学習について(質問への回答・未着手)
質問: 話者識別も学習できるか(声の特徴に合わせる=過学習させる)。
- **A. 声紋登録(モデルは学習しない・推奨)**: 校正済みで話者ラベルのある行の音声から、話者ごとに埋め込み(声の特徴ベクトル。sherpa-onnx の既存モデルで取れる)を計算し、平均を登録声紋として保存。話者分離のあと、各クラスタを登録声紋とコサイン類似度で照合し、しきい値以上なら名前を付け、届かなければ「不明」。CPU で数分、1人あたり数分〜十数分の音声で足りる。過学習しにくく、新しいゲストも「不明」として残せる。リスク: BGM・ゲーム音・エコーなど収録条件が変わると類似度が落ちる(条件別に複数登録)/ 声の似た人と誤認する(しきい値+1位と2位の差で「不明」に倒す)/ **声紋は生体情報**なのでローカル保存のみ・配布 zip に含めない・他人の声を登録する場合は同意
- **B. 埋め込み・分割モデルのファインチューニング(非推奨)**: 大量の話者ラベル付き音声が必要。学習した人には強いが、新しい話者に弱くなる(過学習)。効くのは主に「重なって話す区間」の分割精度
- 進め方の案: A を実装。声紋を保存する場所は models 系ではなく別フォルダ(voiceprints/)にし、書き出し・配布から除外。評価は、話者ラベルを付けた校正済みの行で「登録声紋による照合」と「従来の自動判別」の一致率を比べる。**ユーザーの了承待ち(現在の作業=UI と全体zipのあとに着手する予定)**
