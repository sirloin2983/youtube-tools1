# cut2resolve v0.1.3 仕様メモ(案2: 元動画 + EDL + SRT)

切り抜きスタジオの動画などに「カット」と「字幕」を入れ、友人が DaVinci Resolve で続きを編集できる形で渡すためのツール。srt2resolve(FCPXML 方式)が Resolve で通らなかったため、動画の場所を書かない EDL 方式に切り替えた。**EDL(カット) + SRT(字幕トラック)の方式は、Resolve 実機(サンプル動画・実動画の両方)で取り込み成功を確認済み(2026-09-21)。** 残る論点は「字幕を Text+ で渡すか」(下の「次の判断待ち」)。

## ユーザーに確認できた前提(2026-09-21)
- 主なカットの決め方: **無音の自動カット**(`--silence`)。時刻リストの手書きも使える
- 字幕(SRT)の時刻は **カット前の元動画基準**。ツールがカット後の時刻に直す
- 友人に送る元動画は **切り抜きスタジオで書き出した短い動画**(大きさは問題にならない。`--copy-video` で1フォルダにまとめて送れる)
- 字幕は **後から変更できれば方式は問わない**(当初は Resolve の Text+ を希望)。友人が細かく編集するので、修正しやすい形で渡す
- Resolve は無料版(Resolve を外部から直接操作する自動化は不可)。実機の Windows PC は Claude から画面操作できる可能性があるが、ユーザーは不要と回答

## 置いた仮定(未確認のまま)
- 友人は Resolve を使う。フォントなどの見た目は運ばない(SRT にも EDL にも入らない)。友人が設定するか、別途メモで伝える

## 実機での経過
- v0.1.0 で EDL を取り込み → 「failed to link because the timecode extents do not match any clip in the Media Pool」。クリップ名の照合までは通っていた
- **原因(確定)**: 対象の動画は **Start TC = 01:00:00:00**(縦 1080x1920 / 30fps)。v0.1.0 の EDL は元動画側を常に 00:00:00:00 始まりで書いていたため、範囲が合わなかった
- 根拠: ユーザーが Resolve から書き出した EDL(Timeline 2.edl)と FCPXML(asset の `start="3600/1s"`)で開始TCと 30fps を確認。同じ2区間のカットを本ツールで作った EDL は Resolve 自身の出力と時刻が全行一致(違いは `AA/V` と `V` の表記、`SOURCE FILE` 行、CRLF のみ)
- v0.1.1: 動画に埋め込まれた開始タイムコードを ffprobe で読み、EDL の元動画側に足す。v0.1.2: シンプル版にも `--src-start-tc` を追加。v0.1.3: 友人へ.txt にタイムライン解像度・字幕の見た目の変え方・フォントの注意を追加
- **確認結果**: サンプル動画でテスト1(EDL)・テスト2(手動カットの SRT)成功、テスト3(無音カットの EDL)のカット成功(その字幕は未確認)。**実動画でも成功**。`AA/V` は問題なく読まれた
- Resolve の限界: **Text+(Fusion Title)を含むタイムラインは FCPXML で書き出せない**(「Unable to export timeline video clip because it is not associated with valid or supported source media: Fusion Title」)
- **ユーザーの Resolve では、字幕トラックの右クリックに「Text+ へ変換」の項目がない**(Resolve のバージョンは未確認)
- 縦動画なのにユーザーのプロジェクトのタイムライン解像度は 1920x1080(横)だった。Shorts なら 1080x1920 に設定が必要(取り込み成否には無関係)

## 現在の方針(字幕)
- カットは EDL、字幕は `_cut.srt` を Resolve の「読み込み → 字幕」で字幕トラックとして取り込む(**現時点で確定・渡せる状態**)。友人は文字を一覧から直接直せ、フォント・大きさ・色・位置をインスペクタでまとめて変えられる
- フォントはファイルに入らない。友人の PC に同じフォントがないと置き換わるので、フォント名を伝える

## 次の判断待ち: 字幕を Text+ で渡すか(ユーザーが友人と相談中)
- **FCPXML は友人に渡すと動画の場所(絶対パス)が合わず、動画がオフラインになり、友人が再リンクする必要がある**。ユーザーは以前、再リンクの操作が見つからなかったので詰まるリスクがある。EDL は名前で結び付くので、この問題がない
- 案A: 現状の EDL + SRT(字幕トラック)。確認済み。友人の手間が最小
- 案B: ユーザー側の Resolve で字幕を Text+ に変換してから、プロジェクト(.drp)やタイムライン(.drt)を渡す。友人は動画の再リンクだけ。変換ツールと再リンクが未確認
- 案C: 友人側で変換ツールを使う。友人に Resolve 19 以降・Python 3.10 以降・スクリプトの導入が必要
- 案D: 動画を含めない「字幕だけの FCPXML」を作る(動画パス問題が起きない)。Resolve が `<title>` を Text+ として読み込むかは未確認(試す必要がある)。FCPXML の asset の start / sequence の tcStart に 3600s(01:00:00:00)を反映する修正も必要(srt2resolve の失敗原因も同じ開始タイムコードのずれだった可能性が高い)
- 変換ツール候補: **Resolve-OpenCaptions**(https://github.com/david-ca6/Resolve-OpenCaptions、MIT)。SRT から Text+ の字幕トラックを作る Fusion スクリプト。Resolve 無料版でも可、**Resolve 19 以降・Python 3.10 以降**が必要。`ワークスペース → スクリプト → Comp` から実行。README によると Resolve の API のバグを利用しているため、Resolve の更新で動かなくなる可能性がある。第三者のスクリプトなので、実行前にコードの確認が必要。**Claude は実際には動かして試していない**
- 手元で確認が必要なこと: ユーザーと友人の Resolve のバージョン(`ヘルプ → DaVinci Resolve について`)、友人の Python の有無、友人がどこまで手間をかけられるか
- 次にやること(相談の結果しだい): 19 以降なら、サンプル動画で案B(OpenCaptions での変換 → 再リンクで渡せるか)を試す手順を作る。または案Dの「字幕だけの FCPXML」を生成して、Text+ になるか試す

## 構成(フォルダ1つ。Python 3.9+ 標準ライブラリ + ffmpeg/ffprobe)
- `cut2resolve_simple.py` シンプル版: 動画 + カットリスト(.txt) + 字幕(.srt、省略可)を順不同で指定 → `<動画名>_edl/` に EDL・カット後の字幕・友人へ.txt。`--src-start-tc` で開始TCを手動指定可
- `cut2resolve.py` フル版: 上に加えて `--keep/--drop`(残す/削る区間)、`--drop-lines 3,5-7`(字幕の行の時間帯を削る)、`--silence`(無音の自動カット。`--noise -35 --silence-min 0.6 --silence-pad 0.15`)、`--min-len`(短い残り区間の除去、既定0.3秒)、`--join-gap`(近い区間をつなぐ)、`--render`(粗編集の H.264 mp4)、`--copy-video`、`--dry-run`、`--reel/--rec-start/--src-start-tc/--name/--fps/--frames`。出力は `<動画名>_pack/`
- `cut2resolve_core.py` 共通部、`srt2resolve.py`(動画情報の読み取り・字幕パース。srt2resolve v0.1.2 と同じもの)、bat 2つ(ドラッグ&ドロップ。フル版 bat は `--silence --render` 付き)、`test_cut2resolve.py`(35件)。配布物は `cut2resolve-v0.1.3.zip`
- 切り分け用サンプル(配布済み): 縦 1080x1920 / 30fps / H.264 / 20秒 / Start TC 01:00:00:00 の test_sample.mov(秒数・フレーム・TC を焼き込み、音は 0-3/5-9/11-20 秒のみ)+ cuts.txt + subs.srt + 生成済み pack + テスト手順.txt

## 決めたこと・理由
- EDL は CMX3600、ノンドロップ、記録側は 01:00:00:00 開始(Resolve の既定の開始タイムコード)。トラックは音声ありなら `AA/V`、なしなら `V`。イベント1つ = 残す区間1つ。ファイル名は `* FROM CLIP NAME:` と `* SOURCE FILE:` の両方に入れ、リール名は `AX`(既定)。友人の PC のどこに動画を置いても、名前で結び付く(パス依存を避ける)
- 元動画側タイムコード = 動画の埋め込み開始タイムコード(無ければ 00:00:00:00)+ 区間のフレーム位置。記録側は埋め込み値に影響されない
- 29.97/59.94 も呼び名どおり 30/60 のノンドロップで数える(Resolve の既定と同じ。ドロップフレームは未対応で、埋め込み値が `;` 区切りなら `:` に読み替えて警告)
- 時刻は元動画のフレーム番号(半開区間)で統一。フレーム数は srt2resolve と同じ実測値
- 字幕の時刻直し: カットにまたがる字幕は区間ごとに分割。切られて 6 フレーム未満になった断片は捨てるが、切られていない短い字幕は残す。消えた件数を表示
- 粗編集の書き出しは ffmpeg の trim/atrim + concat をフィルタファイルで渡す(Windows のコマンド長制限と、新旧 ffmpeg の `-filter_complex_script` / `-/filter_complex` の違いに対応)。EDL が通らない場合の代替(案1 = カット済み動画 + SRT)として同梱できる
- 無音検出は ffmpeg silencedetect。話の前後に 0.15 秒残し、断片(0.3秒未満)は捨てる
- 動画のファイル名に日本語が含まれると警告(実機では日本語+スペース入りの名前でも問題なく通った)
- 友人へ.txt を自動生成(Resolve での手順、うまくいかないときの代替、Clip Attributes の確認手順、残す区間のタイムコード表)

## 未検証・注意
- テスト3(無音カット)の字幕の位置は未確認。実動画の字幕の位置も、ユーザーからは成功としか聞いていない
- 無音の自動カットは、BGM やゲーム音が常に鳴っている配信では無音にならず、ほとんど切れない可能性がある(`--noise` を上げて調整。`--dry-run` で確認)。実際の切り抜き動画での効果は未確認
- VFR の動画は EDL の時刻がずれることがある(警告が出る)。AV1/H.265/10bit は無料版 Resolve で再生できないことがある(警告が出る)
- 無音検出は動画全体の音声を読むため、長時間の配信アーカイブでは時間がかかる
- 友人の環境(Resolve のバージョン、動画のコピーの置き場所)での取り込みは未確認

## テスト
35件(時刻/カットリストのパース、区間演算、EDL の書式と算術、字幕の時刻直し、開始タイムコードの読み取りと EDL への反映、ffmpeg での無音検出・粗編集の長さ・通し実行・29.97fps)。全件通過。EDL は独立した簡易パーサで検証。加えて Resolve 出力の EDL との突き合わせで時刻が全行一致し、Resolve 実機でも取り込み成功
