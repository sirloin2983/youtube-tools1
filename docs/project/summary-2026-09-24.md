# 全ツール見直しのまとめ(2026-09-24)

## 変更点と理由
| 変更 | 理由 |
|---|---|
| 3ツールの見た目を共通部品(ui-kit)で刷新、ダーク/ライト切り替え | 「スタイリッシュに」の要望。正本1つを各ツールに写す方式にして、将来アプリを統合しても見た目がそろったままにする |
| 受け渡しの形式を統一(.clip.json / .transcript.json / cut-plan)、ツール間リンク | 「将来1つのパイプラインで流す」前提。形式だけ決めて各ツールは独立のまま(1つを直しても他が壊れにくい) |
| cut2resolve に専用画面(試算・タイムライン・パック作成) | コマンドと bat だけでは使いにくい(ユーザーの選択)。処理は画面とコマンドで同じ関数を使う |
| 不具合を約100件修正(書き出しの失敗、保存の競合で内容が消える、他ツールのリンクで 403、Windows のポート二重使用、XSS など) | コードの読み直しで見つかったもの。直したものにはテストを付け、コードを壊してテストが落ちることも確認 |
| 細かい機能(キー一覧、元の配信の表示、動画の隣に保存、マークの行から他ツールへ渡す、設定の節ごとの保存 など) | 手作業の往復を減らすため |
| 版: スタジオ 0.2.0 / 文字起こし 0.10.0 / cut2resolve 0.2.0 | 大きな変更のため |
| 納品は `_new` フォルダ+入れ替え用の bat(読んだ後に変わったファイルがあれば止まる) | 09-23 の上書き事故を繰り返さないため |

## これからの改善点
1. **実機での確認**: Windows での見た目・リンク・ポート、実際の yt-dlp / faster-whisper / Resolve での取り込み
2. **判断待ち**: 強調色(ピンク→紫)、設定の引き出し化、data.json 破損時の自動復元、文字起こし由来の残す区間の「すき間」、`?clip=` のタイトル自動入力、削除した文字起こしの履歴を残すか
3. **作成予定の新ツール**: 新着配信の監視と自動キュー投入、音量の均一化(ラウドネス)
4. **パイプラインの一括実行**: 個別ツールの完成後(受け渡しの形式はもう決まっているので、順に呼ぶ薄いスクリプトで作れる)
5. **小さな残り**: 修正データの書き出しをジョブ化(今は数分待つことがある)、Resolve パッケージの一時フォルダが C: を圧迫しうる、ui-kit への部品の移行(引き出し・ポップオーバー)

詳細: リポジトリの `docs/review/README.md` と各ツールの報告書、`docs/pipeline.md`
