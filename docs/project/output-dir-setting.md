# 出力先フォルダの変更機能(自動切り抜き v0.1.2 / 切り抜きマーカー v1.1.0)

ユーザー要望: auto-clip と clip-marker のファイル出力先を変えたい。両ツールに同じ仕組みを入れた。

## 仕様
- 標準: 自動切り抜き=serve.py と同じフォルダの clips/、切り抜きマーカー=同 exports/。変更はフルパス指定(例 D:\clips, /Users/you/Movies/clips)
- 画面: 自動切り抜き=「詳しい設定」内の「出力先フォルダ」、切り抜きマーカー=書き出しパネル下の「出力先フォルダ」。「変更」→入力→保存 / 「標準に戻す」(空で保存)
- 保存先: settings.json({"outDir": …})。APIキーの config.json とは別ファイル(キーの保存・削除で出力先が消えない)。起動時に読み込み、消えた・書き込めないときは標準に戻す
- API: PUT /api/outdir {path}。/api/state(自動切り抜き)・/api/tools(切り抜きマーカー)に outDir / defaultOutDir を追加
- 検査: 絶対パスのみ、NUL・400字超・「%」を含むパスは拒否(yt-dlp の -o テンプレートで % が特別扱いされるため)、ドライブ/ルート直下は拒否、作成・書き込みテスト(一時ファイル)に失敗したら拒否。ジョブ実行中は変更不可(409。拒否時にフォルダを作らない)。Host/Origin/Sec-Fetch-Site 検査は既存のまま
- 自動切り抜き: /clip(プレビュー)は、この起動中に使った保存先すべてを探す(変更前の結果も画面で再生可)。realpath検査は各ルートごとに維持
- 移動はしない: 既存ファイルは元の場所に残る(新しい書き出しから新しい場所)
- 切り抜きマーカーの export-log.txt も新しい保存先に出る

## 検証
- ac/test_outdir.py, cm/test_outdir.py(拒否ケース、作成、書き出し先の切り替え、settings 永続化、起動時の復元、実行中409、cross-site/Host 403、APIキー削除で出力先が消えない)、Playwright(e2e_out.js: 両画面で変更→リロードで維持→標準に戻す)。既存の test_ac / test_chat / e2e_ac も通過
- 未検証: Windows のパス(ドライブ・UNC・日本語フォルダ)での実機動作、ネットワークドライブ・同期フォルダ(OneDrive等)への書き出し(ffmpeg の書き込み中に同期が触る可能性)
