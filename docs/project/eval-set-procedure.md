# 評価用データの運用手順(文字起こしツール v0.9.3〜)

## 目的
精度が「本当に上がったか」を、学習・辞書に使っていない動画で測る。学習・辞書に使った動画で測ると、答えを見てから解いたことになり、改善して見えるだけになる(特に LoRA)。

## 守る仕組み(v0.9.3、文字起こしごとの evalSet)
- 学習から除外: 修正から学習(候補・提案・用語の自動追加)の元にしない(_doc_info が None)
- 書き出し: 修正データの書き出し(全体)から除外。個別指定は拒否
- 再認識: 拒否(機械の出力=比べる基準が変わるため)
- 一括置換・提案の採用: 画面で停止(正解が機械で書き換わるため)
- 保管データ: 各行に split=eval/train。「保管の量」に入らない(evalSec に別集計)
- 進行度: 学習用と評価用を分けて数える。評価用は準備状況(本数・校正済みの長さ・全行校正の本数)を表示
- 測定: scope=all/eval/train。「基準を記録」(eval-baselines.json。CER・字数・置換/脱落/挿入・辞書語数・メモ)
- 使える: A/B(設定の比較)・精度の測定・ボーカル分離などの前処理比較
- 限界: 評価用にする前に登録した辞書・書き出し済みデータからは外れない。追加学習の処理は未実装なので、実装時は split=eval を必ず除く

## 手順
1. **選ぶ(校正の前)**: 2〜3本・合計20〜30分。学習に入れる予定のない配信者を1人は入れる。1人/多人数、BGM 薄/濃を混ぜる。「良くなりそうな動画」を選ばない。決めたら入れ替えない。
2. **印を付ける**: 文字起こしを開き「評価用にする」にチェック。文字起こしは、辞書適用や用語集の追加を切った設定(用語集なし・large-v3)で行う。
3. **全行を校正する**: 「聞き取れない」「声が重なる」「BGM」タグを付ける。校正基準(表記・相づち・数字)は先に決める。語頭の脱落は足す。進行度カードが「準備できました」になるまで。
4. **基準を記録**: 精度測定カードの対象=評価用のみ → メモ「基準(large-v3・用語集なし・辞書なし)」で「基準を記録」。
5. **学習用を校正**: 評価用と別の動画で校正を進める。進行度は学習用のみ。
6. **施策ごとに測り直す**: 辞書・名簿・VAD・ボーカル分離・モデル・LoRA を入れたら、評価用に対して A/B または再測定→「基準を記録」(メモに施策名)。1つ前との差 pt を見る。
7. **採用判断**: 評価用で下がったときだけ採用。差が小さいとき(正解1000字未満、差2pt前後)は誤差の可能性。母数を増やすか、動画ごとの CER を見る。
8. **やってはいけないこと**: 評価用の修正から辞書を作る/評価用を再認識する/評価用の文書で一括置換する/途中で評価用を入れ替える/評価用を外して学習に使ったあとで、同じ動画を評価に戻す(汚染済み)。

## 特殊な話者(活舌・話し方が特殊)の扱い
- 別枠で評価する: 通常の評価用とは別に、その人だけの評価用(10分〜)を持つと、全体 CER に埋もれず改善が見える(動画のタイトルに [特殊] を付け、文書別 CER を見る)。
- 学習データは別バケット扱い: 最初(〜3時間)は学習の主データにしない。混ぜると全体モデルがその人の癖に引っ張られる恐れ。ただし校正はしておく(後で個人向けに使える)。
- 個人向けモデル: 十分量(目安1〜2時間、要検証)たまったらその人専用の LoRA を別モデルとして作り、その人の動画だけで使い分ける案。効果は評価用で確認。
- 校正基準: 聞こえた音ではなく「言おうとした語」を正解にする、と先に決める。人が聞いても判別できない行は「聞き取れない」にして除外(推測で埋めない)。
- 当面の実用策: 再認識で large-v3(重いモデル)を使う、系統的な崩れ(同じ言い間違い)は置換辞書、声が特徴的なので声紋登録は有利。
- 進行度: 校正に時間がかかるので、ペースの見込みを別に見る。
