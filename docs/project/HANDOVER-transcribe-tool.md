  旧「集中モード」はこれに統合(`.app.focus aside{display:none}` が映像の列の aside まで隠していたバグも解消。対象を `.app>aside` に限定)。
  文字起こしを開いていないのにメニューが閉じているときは、空の画面に「☰ メニューを開く」ボタン。編集欄が900px未満のときは、文字起こしを開いた時点でメニューを自動で閉じる
- **行の追加**: 選んだ行の下の「＋前に行」「＋後に行」、Nキー(選んだ行の後ろ)、映像の下の「＋再生位置に行を追加」、空の文書の「＋行を追加」。
  前後のすき間(最大8秒)に置く。すき間が無いときは仮の1.5秒(次の行の終わりを超えない)で置き、前後と重なる行は時刻の欄を赤く(`.times.ovl`)。
  足した行はすぐ入力できる状態になる。original(機械の出力)には足さないので、サーバーの精度測定では「脱落」として数えられ、置換の学習には使われない(既存の仕組みのまま)
- **時刻を再生位置に合わせる**ボタン(開始/終了の「再生位置」)を、選んだ行の操作の段に追加
- **一覧の行を文字中心に**: 常に見えるのは「□ ▶ 時刻 話者 文字 校正済み」だけ。時刻の微調整・行の追加・分割・結合・削除・音の状態のメモは、選んだ行(`.seg.nav`)の下にだけ出す。
  一覧が狭いとき(620px未満)は、1段目に「□ ▶ 時刻 話者 校正済み」、2段目に文字
- **映像の下の道具を3段に整理**: 再生(速さ・±3秒・⚙設定)/編集(＋再生位置に行を追加・元に戻す・まとめて校正・話者・置換・書き出し)/探す(検索・絞り込み・次の未校正)。
  一度決めたら触らない設定(再生に追従・太枠も再生に合わせる・移動したら自動で再生・時刻の微調整の幅)は「⚙ 設定」のポップアップへ。「1行ずつ止める」は前回削除済み
- **映像の列を固定+列の中だけスクロール**(2列のとき)。以前は映像の欄だけが固定で、その下の「話者・置換・書き出し」が映像の裏に潜って見えなかった
- **独立レビュー(Opusのサブエージェント)で見つかった問題を修正**:
  ①下の行のボタンを押すと、押した瞬間(mousedown)にフォーカスが移って今の行が変わり、前の行の操作ボタンの段が消えて一覧がずれ、押し損じる → 行のボタン・チェックは mousedown でフォーカスを移さず、今の行は click で切り替える
  ②ボタンにフォーカスが残り、そのあとの1文字キーやSpaceが誤爆 → ①で解消。さらにZ(削除)は2回押しに
  ③開始時刻が同じ行があると、足した行が意図と違う位置に並ぶ(sortSegsが終了時刻で並べ替えていた) → 決めた位置に挿入し、sortSegsは開始時刻だけの安定ソートに
  ④「話者・置換・書き出し」が映像の裏に隠れる → 上記の列固定で解消
  ⑤行の操作の段が、チェックを付けただけの行にも出ていた → 今の行(.nav)だけに出す
  ⑥ラベルの不統一(「未校正へ ▼」→「次の未校正(D)」、「一括操作」→「まとめて校正」、行の▶の説明「この行だけ再生(R)」など)
- 1列表示のとき(狭い画面)は `.tx-stage{display:contents}` にして、映像の欄が一覧の上に固定され続けるようにした(sticky は親の箱の中でしか効かないため)
- 使ったモデルの振り分け: 実装と設計判断はメイン(Opus)、独立レビューはOpusのサブエージェント、e2eテストの作成とProject資料の写しはSonnetのサブエージェント

## ハマりどころ・注意
- **編集スクリプトの罠**: 複数の `rep()` 置換を1つのPythonスクリプトにまとめ、途中の置換でassertionが失敗すると、ファイルへの書き込み(`open(p,'w')`)が実行されず**すべての変更が失われる**のに、直前の置換は成功していたと錯覚しやすい。**対策**: 大きな一括パッチのあとは必ず `grep -n "^def 新関数名"` 等で実際にファイルに存在するか確認してから次に進む
- serve.pyのSERVER_VERSIONとindex.htmlのAPP_VERSIONは必ず両方揃える(不一致だと赤い帯。e2e_ui_v07.pyの「版の不一致」テストで検出できる)
- 評価用(evalSet)は、印を付ける前に登録した辞書や書き出し済みデータからは外れない(校正を始める前に決める運用でカバー)
- テストの実行はffmpeg必須、Playwright(chromium)込み。1本あたり数十秒〜数分。e2e_ui_v08の「+3秒」(seekFwdのシーク確認)は
  以前タイミング依存で稀に失敗することがあった(再実行すれば通る既知のflaky。今回のv0.9.7実行では発生せず)
- **キーボードショートカットはキー単体(Shift不要)。例外はShift+Spaceのみ**(Space単体は既存の再生・停止と衝突するため)。
  今後ショートカットを追加・変更するときは、この「Space以外は単体キー」の原則と、テキスト入力中(`isTextEntry`)は
  すべて無効という既存の設計を踏襲すること
- **受け渡しの方法(2026-09-24 変更。ユーザーは git の手作業を面倒に感じている)**: クラウドからの GitHub への push は 403 で拒否される(Cowork の既知の制限)。
  zip やパッチは使わず、**ユーザーの PC のフォルダ(C:\Users\you11\Desktop\youtube-test。セッションに接続済み)へ直接ファイルを書き込む**(device_commit_files)。
  GitHub への保存は、ユーザーがフォルダ直下の **push.bat をダブルクリック**するだけ(add → 変更一覧を見せて y/N 確認 → commit → pull --rebase → push)。
  **PC のフォルダが正**。PC 側にはクラウドの複製に無いファイルがある(transcribe-tool/resolve_export.py・test_resolve_export.py・test_document_save.cjs・TRANSCRIPTION_V2_DESIGN.md。
  別のツールで作業した可能性)。編集の前に必ず PC から対象ファイルを取り込み(device_stage_files)、そのファイルを元に直して書き戻す(mtime のガードを付ける)
