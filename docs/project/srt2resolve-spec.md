# srt2resolve v0.1.1 仕様メモ

動画 + 字幕(SRT/VTT)から、DaVinci Resolve に読み込むだけで字幕を編集できるデータ(FCPXML)を作る CLI。字幕入れだけ(カットは未対応)。独立ツールで、clip-studio・文字起こしツールとは疎結合(ファイルで受け渡し)。

## 使い方
- `python srt2resolve.py 動画 字幕.srt`(2ファイルは順不同。拡張子で判別)。Windows は `srt2resolve.bat` に2つ同時にドラッグ
- 出力: 動画と同じ場所の `<動画名>_resolve/` に `.fcpxml` と `.srt`(フレーム境界に丸めた予備)
- オプション: `-o` 出力先 / `--offset` 秒 / `--font` / `--size` / `--fps` / `--frames`(フレーム数の手動指定) / `--no-titles`
- 依存: Python 3.9+(標準のみ)、ffprobe

## 決めたこと・理由
- 出力形式は FCPXML 1.8。字幕は1行ずつ「タイトル」クリップ(lane付き)として配置。Resolve 18.6 のマニュアルは FCPXML が字幕トラックを運ぶとは書いていないため、字幕トラックではなくタイトルで取り込む方針。フォント名・サイズもタイトルに入る(フォントファイル自体は入らない。相手のPCに同じフォントが必要)
- 予備として SRT も出す。Resolve の「Import Subtitle」で字幕トラックにでき、全字幕の見た目を一括で変えやすい(タイトル方式は1行ずつ独立)
- 時刻は全てフレーム境界の分数(秒)で書く(境界外だとずれる)。fps は標準値(23.976/24/25/29.97/30/48/50/59.94/60)に丸め、テストで全属性のフレーム境界を検証
- **フレーム数は映像ストリームの実測値を使う(v0.1.1)**: mp4/mov は nb_frames、mkv/webm は ffprobe -count_packets。v0.1.0 は動画全体の長さ×fps で数えており、音声のほうが長い動画(yt-dlp 結合など)だと映像より長いクリップとして書き、Resolve が既存クリップとの照合で「タイムコードの範囲が一致しない」と失敗しうる。可変フレームレート(VFR)は長さから計算(数より長さのほうが Resolve の解釈に近いと判断)。`--frames` で手動指定可
- タイムラインの解像度・fps は動画から自動決定(縦動画は 1080x1920)。スマホ縦撮り(回転メタデータ)は幅高さを入れ替え
- 時間が重なる字幕は別レーン(別トラック)へ。同じトラックで重なると取り込めないため
- 字幕テキストから XML で使えない制御文字と HTML/ASS タグを除去。文字コードは UTF-8 / Shift_JIS / UTF-16 に対応
- 動画の長さの範囲外の字幕は除外(SRT にも出さない)。出力が入力字幕を上書きする場合は中止

## Resolve 取り込みで起きたこと(ユーザー環境・報告ベース)
- 「クリップが見つかりませんでした」: 取り込み時に動画をResolveが見つけられなかった/読めなかった。AV1 動画を渡していた
- 「The clip "…" failed to link because the timecode extents do not match any clip in the Media Pool」: FCPXML の名前は一致したが、メディアプール側のクリップと長さ(タイムコード範囲)が一致しなかった。想定原因: FCPXML を作った動画と Resolve に入れた動画が別ファイル(変換前後で同名 stem)、または v0.1.0 の長さ計算。対処: Resolve に動画を先に入れず、FCPXML を作った動画そのものを指定して「ソースクリップを自動的にメディアプールに読み込む」を有効にして取り込む
- 上の失敗では赤いクリップ(オフライン)が出ず、Relink Selected Clips が使えなかった。再リンクは「メディアプールにある赤いクリップ」が前提
- **Resolve での正常な取り込みは、まだ確認できていない**

## 既知の注意
- **Resolve での実機取り込みは未検証**(開発環境に Resolve が無い)。タイトルの見た目(フォント・縁取り・位置)は Resolve 側で調整する前提。タイトルが崩れる場合は SRT 予備を使う
- 可変フレームレート(VFR)、VP9/AV1 コーデック、埋め込み開始タイムコードは警告を出す(無料版 Resolve で再生できない/位置がずれることがある)
- タイムライン開始が 01:00:00:00 の既存プロジェクトに SRT を入れると字幕が1時間ずれる(FCPXML 側は 0 開始で作る)
- 字幕は動画トラックとは独立。Resolve 上でカットを詰める場合、全トラックのロックを外してリップル削除する
- FCPXML は動画そのものを含まない(動画の場所を書いたメモ)。友人に渡すときは動画の再リンクが必要、または相手の PC でこのツールを実行する

## テスト
`test_srt2resolve.py`(24件): パース(SRT/VTT/文字コード/タグ)、時刻変換、レーン割当、ffmpeg で作った動画での通し(縦30fps/横29.97/回転/--no-titles/異常系/音声が映像より長い/mkv のフレーム実測/--frames/埋め込みタイムコード警告)。全件通過(ffmpeg 6.1)。
