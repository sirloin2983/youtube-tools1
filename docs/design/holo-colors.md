# ホロカラー(holo-colors)の設計と決めたこと

2026-09-27 Claude Code。ユーザーの依頼(2026-09-26):既存のツールとは別に、キーボードショートカットで呼び出し、
ホロライブのメンバーカラーをクリックでクリップボードへコピーするツール。自分で色を足せる。コピーしたら閉じる(閉じない設定もできる)。

使い方は `holo-colors/README.txt`(友人に渡す zip にもそのまま入る)。

## ユーザーと決めたこと(2026-09-26)
| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 形 | ブラウザではなく Windows のアプリ | ユーザーの指定 |
| 使う人 | **主に友人**(Resolve で仕上げをする人) | ユーザーの指定。友人の PC に Python があるかは確かめられていない(`docs/project/cut2resolve-spec.md` の 38 行目) |
| 作り方 | **C# の WinForms。Windows に入っている .NET Framework 4 の csc で .exe を作る** | 最初は Python + tkinter に決めたが、友人が使うと分かって変えた。友人は zip を展開して exe をダブルクリックするだけで、Python もインストールも要らない |
| 入れるメンバー | JP・DEV_IS・EN・ID・卒業したメンバー、それに新しくデビューした「アソビ★まわり隊！」 | ユーザーの指定(「遊び周りたい」と書かれていたのは、このユニットと判断した) |
| 自動起動 | 設定で選べる(既定は外す) | 呼び出しのキーを使うには裏で動いている必要があるため。勝手に登録はしない |

## 形(なぜそうしたか)
- **常駐する 1 つのプロセス**。通知領域(タスクバー右下)にアイコンを出し、一覧の窓は隠しておく。キーを押したら窓を出すだけなので一瞬で開く
  (押すたびに exe を起動する形だと、.NET の起動で 0.5 秒ほど待つ)
- 呼び出しのキーは `RegisterHotKey`。受けるのは専用の見えない窓(`MessageWindow`)。フォームの窓はプロパティを変えると作り直されることがあり、
  そのとき登録が消えるので分けた。WinForms は UI のスレッドが 1 本で、キー・通知領域・一覧がすべて同じスレッドで動く(スレッドの取り合いが無い)
- **コピーして閉じたら、呼び出す前に前面だった窓へ戻す**(キーを押した瞬間の `GetForegroundWindow` を覚えておく)。すぐ Ctrl+V で Resolve に貼れるように。
  コピーの知らせ(マウスの横の小さな帯)は `WS_EX_NOACTIVATE`・`WS_EX_TRANSPARENT` で、前面の窓を奪わず、クリックも下へ通す
- 2 つ目の起動は、動いているほうへ「一覧を出して」と伝えて終わる(名前付きの Mutex + `RegisterWindowMessage` を `HWND_BROADCAST`)。
  `--quit` で動いているほうを終わらせる(build.bat が exe を作り直す前に使う)。Mutex とメッセージの名前には作業データの場所のハッシュを入れる
  (テストは別の作業データで動かすので、普段使っているものとぶつからない)
- **× ・ Alt+F4 はアプリの終了、Esc とコピー後に閉じるのは最小化**(v1.2.1。ユーザーの指摘: × で終了しない)。
  窓を閉じるときは必ずアプリごと終わる(窓だけ破棄すると、残ったアプリがキーを押すたびにエラーになる)
- **一覧はタスクバーに出るふつうの窓。閉じる(Esc / コピー後)= 最小化**(v1.2.0。ユーザーの運用: タスクバーにピン止めして、起動中の印を見たい)。
  タスクバーのボタンがあるので、ピン止めしたアイコン(同じ exe)に起動中の印が付き、アイコンを押せば Windows が元に戻す。`--hidden`(自動起動)も最小化で始まる。
  最小化から開くときは `SetWindowPlacement` で戻る位置(マウスの近く)を先に決めてから戻す(戻してから動かすと、前の位置に一瞬出てから飛ぶ)。
  戻る先は `ForegroundTracker`(`SetWinEventHook` の EVENT_SYSTEM_FOREGROUND)が覚える最後の「ほかのアプリの窓」。タスクバー・スタートメニュー・Alt+Tab などは数えない
  (タスクバーのボタンから開いたとき、キーを押した瞬間の前面の窓だけでは戻る先がタスクバーになるため)。通知領域のアイコンは終了・設定の入口として残す
- **一覧の窓は「常に手前」にしない**(v1.1.0。ユーザーの指摘: 閉じない設定のとき、ほかのアプリの上に残り続けてうざい)。キーで呼んだときは前に出すだけ。
  設定の「一覧をいつも一番手前に表示する」で戻せる(既定は外す)
- 戻る先(`previous`)は、キーを押したときの前面の窓。一覧を開いたまま別のアプリへ移ったら、そのアプリに更新する(一覧の Deactivate。自分で隠している最中は変えない)
- 呼び出しのキーは Ctrl・Alt・Win のどれかが必須。Alt+F4・Alt+Tab・Ctrl+Esc・Ctrl+C/V/X/Z/S などは断る(`Hotkey.Problem`)。どのアプリより先に取るので、奪うと困るため。
  設定の欄にいる間はキーを外し、欄を離れる・画面が後ろへ回る・閉じる のどれでも付け直す(何度呼んでもよい作り)
- 作業データが開けなかった(ほかのソフトがつかんでいた・権限)ときは、少し待って読み直し、それでもだめならそのファイルへの保存を止める(初めの状態で上書きして消さない)。
  追加・編集・削除・並べ替えは、保存に失敗したら元に戻す
- 大きさは `Ui.Px`(システムの DPI)で合わせる。`Control.DeviceDpi` は .NET 4.7 からなので使わない。フォント・アイコンは `Ui` の1つを使い回す
- 一覧の窓は、ほかのプログラムから閉じられても隠すだけ(Windows の終了・タスク マネージャーならアプリごと終わる)
- 検索はひらがな・カタカナ・全角/半角・大文字/小文字・空白・中黒をそろえてから部分一致(空白で区切ると AND)。名前・ローマ字・グループ・メモ・カラーコードが対象
- 一覧の描画は、スクロールの分の座標を自分でずらす(`Graphics.TranslateTransform` を使わない)。TextRenderer(文字)は Transform を無視するので、
  使うと文字だけ元の位置に残る(v1.0.0 の不具合。テスト「スクロールしても札と文字が一緒に動く」が、スクロールした絵 = ずらした絵 を画素で比べる)
- 札の文字の色(黒/白)は YIQ の明るさ(150 以上なら黒)。WCAG のコントラスト比だと、鮮やかな青(#266AFF など)で黒が選ばれて読みにくかった

- JSON は `System.Web.Script.Serialization.JavaScriptSerializer`(.NET Framework に入っている)。読むときは Dictionary から1つずつ型を確かめて取る(壊れた値で落ちないように)
- 版は `Core.cs` の `AppInfo.Version` と `README.txt` の見出しの2か所を同時に上げる

## 作業データ
- `%LOCALAPPDATA%\youtube-tools\holo-colors\`(このリポジトリの約束 = `ytt_core/datadir.py` と同じ。`YTT_DATA_DIR` も同じ意味。`inplace` なら exe の横の `data`)
  - `settings.json` … 呼び出しのキー・コピーしたら閉じる・# を付ける・窓の大きさ・絞り込み
  - `my-colors.json` … マイカラー(id・名前・カラーコード)
  - `member-colors.json` … 直したメンバーの色(v1.3.0。`{"version":1,"members":{"<メンバー id>":{"colors":[{"hex","label"}]}}}`。先頭が主な色)。
    キーはメンバーの id だけ(卒業でグループが変わっても残る)。members.json に無い id は使わないが消さない。members.json と同じ色にしたら項目を消す(= 元に戻す)。
    `ytt_core/colors.py` も読み、「編集」の字幕の色 = 直した主な色(ファイルの更新日時で読み直すので入口を起動し直さなくてよい)
  - `holo-colors.log` … 起動・終了・エラー(256KB で .old に回す)
- 書き込みは一時ファイル → 置き換え。読めない JSON は `.corrupt-日時` に名前を変えて残し、初めの状態で始める(下に知らせる)
- サインイン時の起動は `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の `YouTubeTools.HoloColors`。自分のユーザーだけ・管理者の権限は要らない。
  設定のチェックを付けたときだけ書き、外すと消す。フォルダを動かしたときは「別の場所を指しています」と出す(勝手に書き換えない:
  テストのように別の場所から起動したものが、普段の登録を上書きしないため)

## メンバーの色(members.json)
### 形(version 2。2026-09-30 段7 の 7-1)
```json
{"id": "tsunomaki-watame", "name": "角巻わため", "en": "Tsunomaki Watame", "hex": "#F9AFB2",
 "colors": [{"hex": "#F9AFB2", "label": "ホロジュール", "src": ["s1", "s2"], "confidence": "high"},
            {"hex": "#DBDA89", "label": "公式サイトの画像", "src": ["s4"], "confidence": "medium"}],
 "src": ["s1", "s2", "s3", "s4"], "alt": ["#FFF29E 公式サイト画像・縁の色 (s4)"], "checked": "2026-09-30", "note": "..."}
```
- `hex` = **主な色**。字幕の色(`ytt_core/colors.py`)と 1.2.1 までの exe はこれだけを読む。**`colors[0].hex` と同じ値にする**(C# の BundledMembers と `ytt_core/tests/test_ytt_core.py` が検査)
- `colors` = その人の色の一覧(1色以上。先頭が主な色)。`label` は画面に出す短い名前(12 文字まで)、`src` はその色の出典、`confidence` は high / medium / low(基準は `docs/design/holo-colors-research.md`)
- 人の `src` = 調べた出典すべて(卒業のお知らせなど色以外も)。`alt` = 照らし合わせたが採らなかった候補(色を直すときの材料)。`checked` = 調べ直した日。`note` = 札のツールチップに出すメモ
- 最上位: `version` 2・`updated`(調べ終えた日)・`sources`(各項目に `retrieved` = 取得日、あれば `archive` = Wayback の URL)
- 案の比較: `hex` を残して `colors` を足した(採用)… 1.2.1 の exe と今の colors.py が新しい members.json をそのまま読める(友人が members.json だけ差し替えても落ちない)。
  `hex` を消して `colors` だけにすると、古い exe が全員読めなくなる(`hex` が読めないと FormatException で全体を読まない)。値が2か所に出る代わりにテストで一致を守る
- メンバーの `id` は**全体で一意**(直した色 `member-colors.json` のキーに使うため。グループが変わっても同じ id)
- 1.2.1 の exe(build 済み)で version 2 の members.json が 86 人とも読めることを確かめた(2026-09-30)

- **主な出典はホロジュール**(https://schedule.hololive.tv/ 。カバーが運営する配信予定のサイト)。配信の枠のアイコンの縁の色がタレントごとに決まっている。
  公式サイト(hololive.hololivepro.com)の HTML/CSS には色が無い(確認済み)
  - ホロジュールには最近配信した人しか出ないので、Wayback Machine の保存版 約 150 件(2019-12〜2026-09)で補った。どの人も 2020-03 以降、色は変わっていない
  - 2026-09-27 に Claude Code が今のページを取り直し、1 人だけで配信している枠の色が members.json と一致することを確かめた(ときのそら・兎田ぺこら・さくらみこ・大神ミオ・宙科そぴあ・鈴鳴つづり など)
- ホロジュールに個人の色が無い人は、公式サイトの画像から抽出した色(`confidence` が medium / low。札のメモに出どころを書いた):
  holoAN の 3 人、FUWAMOCO の 2 人(ホロジュールは 2 人共用の #F9F1E4 = ほぼ白)、春先のどか、友人A、魔乃アロエ(2020 年のホロジュールの保存版から)
- 人見クリスは色の資料が見つからないので入れていない
- 卒業・活動終了・契約解除・退職は 1 つのグループ(「卒業・活動終了」)。日付と区分は公式サイトの卒業生の一覧とカバーのお知らせ(2026-09-27 に卒業生の一覧を取り直して、天音かなた・火威青を確かめた)
- 各人の `alt` は照らし合わせたほかの候補(公式サイトの画像・wiki)。アプリは使わない。色を直したいときの材料
- **2026-09-29 ユーザー決定**: 多くのメンバーは公式の色が2色以上あるので、全員を調べ直して複数の色を持てる形にし、あとからユーザーが自分で直せるようにする(計画は `docs/plan/phase7-holo-colors.md`。**v1.3.0 で実装**(2026-09-30)。
  形は上の「形(version 2)」、調べ方と記録は `docs/design/holo-colors-research.md`)。
- 画面(v1.3.0): 2色以上の札の右下に小さな四角(最大3つ + 「+n」。札の左半分にはかぶせない)。四角を押すとその色(押した所と離した所が同じときだけ)。
  札の本体・矢印と Enter は主な色のまま(覚え直しを増やさない)。右クリックに色ごとの「コピー」と「色を直す…」。直した札は右上の角に小さな三角の印。
  案の比較: 色ごとに札を分けると押しやすいが、一覧が倍近くに伸びて検索の結果にも同じ人が並ぶので採らなかった
- **早見表と照らし合わせ(2026-09-30 ユーザー決定: 迷った候補は全部入れる・主な色は変えない)**: ホロライブ非公式 wiki の「早見表」の「公式カラー」
  (https://seesaawiki.jp/hololivetv/d/%C1%E1%B8%AB%C9%BD#content_1_7 。ホロジュール(s3)・公式サイトの画像(s4)・ブライト衣装(s14)の3つの表)と、別掲の「ペンライト」のページ(s13)にある色で、
  `colors` に無いものを2つ目以降に全部足した(339 色。公式サイトの画像 = medium、ペンライト・ブライト衣装・wiki のホロジュールの欄 = low)。
  ペンライトは色の名前なので近い色コードを当てた(`label` は「ペンライト: 水色」・以前のライブだけの色は「ペンライト旧: …」)。足し方の決まり・全員の確認の表は `docs/design/holo-colors-research.md` の「早見表と照らし合わせ」
- **早見表の3色を全員そろえて先頭へ(2026-09-30 ユーザー指示: 「全員三色ある。ホロジュールと公式サイト欄のすべてを追加」)**: 「公式カラー」の「ホロジュール」(1色)と
  「公式サイト」(三角内の濃い部分・縁のやや薄い部分の2色)を全員分(アロエは表に無い)入れ、色の一覧の並びを「主な色 → 残りのホロジュール → 公式サイト画像・濃 → 公式サイト画像・縁 → そのほか」にした
  (札の小さな四角は2つ目から3つなので、早見表の3色が札に見える)。足したのは縁の色の3人(星街すいせい・AZKi・癒月ちょこ)。同じ値の色は1つ。主な色(hex)は変えない
- **ペンライトの色は入れない(2026-09-30 ユーザー判断: 要らない)**: 上で足した「ペンライト: …」「ペンライト旧: …」の 123 色と出典 s13 を members.json から外した。色の名前に近い色コードを当てただけで、字幕の色の候補として役に立たないため
- **ブライト衣装の色も入れない・四角を大きく(2026-09-30 ユーザー: 衣装の色もいらない・もうちょっと各色大きく)**: 「ブライト衣装・…」の 86 色と出典 s14 を外した(同じ値で公式サイトの縁の色だった6人は、その色を残して出典から s14 だけ外した)。札 46 → 56px・最小の幅 148 → 172px・四角 14 → 22px(右半分に3つまで。v1.3.1)
- **出典どうしで色合いが大きく違う人**(ホロジュールを採った。上の調べ直しで扱う): アキ・ローゼンタール(ホロジュール #4E7FFC 青 / 公式サイトの画像 #DC0485 ピンク)、
  角巻わため(#F9AFB2 ピンク / #DBDA89 黄)、アイラニ・イオフィフティーン(#FF45D5 ピンク / #7BDF0E 緑)、九十九佐命(#DEB232 金 / #D583AB ピンク)
- 直し方: `members.json` を直して build.bat(テストが形を確かめる: カラーコード・id の重なり(メンバーの id は全体で一意)・名前・ローマ字・5 つの区分・`colors` の先頭 = `hex`・ラベル 12 文字まで・確かさ)。
  自分の PC だけ直すなら、アプリの右クリック →「色を直す…」(作業データの member-colors.json)
- 字幕に使うときの注意: 白に近い色(音乃瀬奏 #FFE7B5)ととても暗い色(ラプラス・ダークネス #351E3B、火威青 #1D3467、こぼ・かなえる #393464、オーロ・クロニー #20318B)は、縁取りが無いと背景によって読めない

## テスト
- `holo-colors/build.bat` … コンパイル → `build\HoloColorsTests.exe`(21 件。色・検索・キー・JSON・作業データ(直した色を含む)・members.json(複数の色・version 2 の形)・自動起動(テスト用のレジストリのキーで)・一覧の配置とキー操作・スクロールした絵・札の小さな四角)→ dist と zip
- `python holo-colors/tests/e2e_holo_colors.py` … 別の作業データ・別のキー(Ctrl+Alt+Shift+F11)で exe を起動し、本物のキー入力とクリックで確かめる:
  キーで開く・検索して Enter / 札のクリックでコピー・閉じて元の窓へ戻る・そのまま Ctrl+V・キーをもう一度 / Esc で閉じる(文字があるときはまず消す)・開いたまま別の窓へ移ってから札を押すとその窓へ戻る・2 つ目の起動・閉じない設定・# なし・
  札の中の小さな四角を押すとその色(先頭の人を2色にした members.json で)・いつも一番手前ではない・--quit(21 件)。
  キーを送る前に毎回、前面の窓がテストの窓か確かめ、違えば止める(他のアプリに文字や Enter を送らないため)。流す間はマウスとキーボードに触らない
- 見た目の確認: `HoloColors.exe --data-dir <使い捨て> --screenshot <フォルダ>` で主な画面を PNG に保存する

## リスクと注意
- **SmartScreen**: 署名の無い exe をインターネット経由で受け取ると、初回に「Windows によって PC が保護されました」が出る(README に手順)。
  コード署名の証明書は有料なので使っていない。ウイルス対策ソフトがキーの登録とクリップボードを使う未署名の exe を疑うことがまれにある
- 呼び出しのキーはどのアプリより先に取るので、既定の Ctrl+Alt+H を Resolve などが使っていれば、そちらでは効かなくなる(設定で変えられる)
- インターネットにはつながらない。書き込むのは作業データのフォルダと、設定で選んだときの HKCU の Run だけ
- 友人の Windows が .NET Framework 4.x の無い古いもの(Windows 7 の初期状態など)だと動かない。Windows 10(1903 以降)・11 には 4.8 が入っている
