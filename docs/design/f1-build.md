### 1-2 アプリと ② の口(F3a が C# で書く相手。F0 で ② に足す。**第 1 波の前にこの表で固定**)
- 起こし方: `<app>\python\python.exe <app>\src\app\server.py --headless --port 0 --parent-pid <アプリの pid>`。環境変数 `YTT_DATA_DIR`(既定 `%LOCALAPPDATA%\youtube-tools`)・`YTT_MACHINE_FILE`(= `<data>\machine.json`。既定のまま)・`YTT_FFMPEG`・`YTT_FFPROBE`・`YTT_YTDLP`・`YTT_DENO`・`YTT_STREAMLINK`・`PATH` に `<app>\tools\*`・`PYTHONIOENCODING=utf-8`。標準出力の最初の 1 行 `{"event":"ready","port","token","pid"}`(今と同じ)。標準エラーは `<data>\app\logs\headless-stderr.log` へ。終了コード 3 = もう動いている(アプリは `.flow.lock` のポートへ接続して使う)
- 止め方: `POST /api/shutdown`(待ちは `autorun-active.json` に残る = 次の起動で続きから)。応答が無ければ標準入力を閉じる → 5 秒後に kill
- 口(合言葉 `X-YTT-Token`。全部 JSON): `POST /api/flow/submit {envelope, spec}` → `{run}`(知らない項目・版の違い = 400 `{error:"spec_version"|"bad_spec", message}` → アプリは「更新してください」)/ `GET /api/flow/status` → 2.9 の形 + `blocked: null | {reason:"disk", freeGB, minGB}` + `machine: {engine, device, llmModel, gpu:{name, vramGB|null}}` / `GET /api/flow/machine`・`PUT /api/flow/machine {device?, llmModel?, caseRoot?, diskMinGB?, learningDir?}` → 保存した値(`machine.save`。合わない値は 400 の理由)/ `POST /api/flow/cancel {id}`(既存)/ `GET /api/flow/outbox` → 送り返す zip の一覧・`POST /api/flow/outbox/done {id}`(F2)
- 束の既定: アプリは `friend-defaults.json`(ユーザーが配る。束の `SECTIONS` の部分集合 + `request: {top, deliverBatch, cut, weights, videoTracks}`)に依頼の欄を重ねて束を組む(`spec.merge` と同じ「辞書は鍵ごと・それ以外は置き換え」)。`post.learning.version` には手元の学習の束の版。URL が複数なら封筒 + 束を 1 本ずつ submit(1 本ごとの本数・区間はその束に)。`memo` → 封筒 `note`・`deliverBatch` → `deliver.batch`・`streamer` → `legacy.streamer`(今の形。RV で正式な欄に)
- ② は `machine.overlay` で engine・device・llmModel を重ねる(今の形)。アプリは束にエンジンを書かない
