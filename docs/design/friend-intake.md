## 1. 目的
友人から「切り抜いてほしい配信」「友人が切り抜いた動画」を受け取り、PC で**自動で文字起こしまで**流す。
校正・カット・パックはこれまでどおりユーザーが「編集」で行う。

## 2. 決めたこと(2026-09-30 ユーザー)
| 項目 | 決定 |
|---|---|
| 依頼の種類 | ① 配信の URL(YouTube)② 友人が切り抜いた動画ファイル |
| 受け取りの経路 | ユーザーの Dropbox(有料 2TB)。友人はお金もアカウントも要らない |
| 友人の操作 | 友人の PC に小さなプログラム(C#。何も入れずに動く)を渡し、「送る」を押すだけにする |
| 送り方 | **A. Dropbox の API で直接アップロード**(アプリ専用のフォルダだけに書ける鍵)。ファイルリクエストのリンクは予備として使える |
| URL の依頼の処理 | 解析 → 自動マークの上位 N 個を採用 → 書き出し → 文字起こし(パックはしない)。N は依頼ごと(1〜10・既定 3) |
| 動画の依頼の処理 | 作業データへコピー → 文字起こし |
| 実行 | 届いたらすぐ自動で流す(ホームでの承認は要らない) |
| 友人への知らせ | しない。友人のプログラムに出すのは「送りました ✓」まで |
| 配信者(字幕の色) | 動画: 友人のプログラムで選ぶ(任意)/ URL: チャンネル名から自動(今の「まとめて実行」と同じ) |
| メモ | 書ける。自動の処理には使わず、ホームで読むだけ |
| PC が止まっていた間の依頼 | 次にホームを起動したときに流す |

## 2-2. 友人が選ぶ形(2026-10-01 ユーザー決定・ホーム 0.16.0・送るアプリ 1.1.0)
友人は送るたびに、PC でどこまで進めるかを選ぶ(アプリの既定は ①。前回の選択は覚えない)。JSON の `flow`。

| 表示名 | flow | 配信の URL | 友人の動画 |
|---|---|---|---|
| ① 全自動(パックまで作って届ける) | auto | 解析 → 上位 N 個 → 書き出し → 文字起こし → パック → 出力\ へ | 文字起こし → パック → 出力\ へ |
| ② 軽く確認(文字起こしまで) | check | 解析 → 上位 N 個 → 書き出し → 文字起こし | 文字起こし |
| ③ 全部人が行う(解析まで) | manual | 解析だけ(切り抜く所はスタジオで人が決める) | スタジオに入れて解析だけ |

- `flow` の無い依頼(1.0.0 のアプリ・手で置いたファイル)と知らない値は ②
- ① のパックは字幕の校正の前のもの。パックのフォルダを zip にして、見張るフォルダの `出力\<依頼 id>__<名前>.zip` に置く
  (zip は Dropbox の外 = パックの隣で作ってから移す。書きかけを同期させない)。止まったら `出力\<依頼 id>__<題名>.失敗.txt` に理由
- 友人のアプリの「受け取る」が `/出力/` を一覧にしてダウンロードする。そのため鍵に読みの権限(files.content.read・files.metadata.read)を足した。
  読めるのはアプリ専用のフォルダの中だけ。1.0.0 の鍵は作り直して zip を渡し直す
- (2-3 で変更)Dropbox から消すのは友人のアプリだけ(受け取って確かめたあと)。PC は消さない

### 2-3. 追加の決定(2026-10-01 ユーザー。ホーム 0.17.0・編集 0.26.1・送るアプリ 1.2.0)
- 全部のパックの既定: カットを決めていない文書は「カットしない」(ホームの設定 autorun.cut の既定 none)・音量は % で 30(packLoudness 0・packVolume 30)。保存した値が優先
- ① 全自動のパックは1本できるごとに 出力\ へ届ける。友人のアプリは受け取って中身を確かめたら Dropbox から消す(一覧は まだのものだけ)。失敗の知らせは読んで「消す」
- 画面を開いていなくても受け付ける: `start-background.bat` / `home/start_hidden.vbs`(画面も黒い画面も出さずに起動)。
  ユーザーの PC のスタートアップ(shell:startup)に「youtube-tools (裏で起動)」のショートカットを置いた(ログインで自動起動)

### 2-4. 話す人(2026-10-01 ユーザー。ホーム 0.18.0・編集 0.28.0・送るアプリ 1.3.0)
- 友人が人数(1〜10)と名前を入れると、JSON の `speakers` {"count", "names"}。PC はこの実行で文字起こしした文書だけ、文字起こしのあとに段「話者分離」
  (編集の /api/diarize に numSpeakers と names)。1人なら判別せず全部の行をその人に。2人以上は覚えている声と名前の一覧だけで照らし合わせ、1人ずつ残れば消去法
- 名前の分からない人は「話者1」などのまま。失敗しても依頼は止めない(一部失敗)。① 全自動ではパックの前なので、字幕の色は付いた名前で決まる
- 「編集」の話者判別の人数にも「1人」を足した

## 3. 全体の流れ
```
友人の PC                          ユーザーの Dropbox(2TB)                  ユーザーの PC
依頼ボックス.exe ─API でアップロード→ /アプリ/切り抜き依頼/ ─同期→ Dropbox\アプリ\切り抜き依頼\
 (動画をドラッグ / URL を貼る)                                               │ ホーム(home/intake.py)が 30 秒ごとに見る
                                                                              ▼
                                                             検査 → まとめて実行(home/autorun.py)→ 文字起こし
                                                             元のファイルは 受付済み\日付\ へ(消さない)・断ったら 失敗\ へ + 理由
```
- PC から取りに行く形(ホームのポートを外に開けない)。1つの画面の XSS で全ツールの API が使える構造なので、外からの接続は受けない(AGENTS.md の【高】)
- 予備: ブラウザの Dropbox ファイルリクエスト(保存先を同じフォルダに)。友人のプログラムが動かないときに使う。容量は受け取る側(ユーザー)だけに数えられる

## 4. 友人のプログラム(依頼ボックス)
- C# 5・WinForms。Windows に入っている .NET Framework 4 の csc で作る(ホロカラーと同じ `build.bat` の形)。置き場所は `request-sender/`(仮)
- 画面: 動画のドラッグの欄 / 配信の URL(複数可)と切り抜く数(1〜10)/ 配信者(任意。メンバーの一覧 `holo-colors/members.json` から選ぶ)/ メモ / 「送る」/ 進み具合と「送りました ✓」
- 右クリックの「送る」メニューにも出す(`shell:sendto` にショートカットを置く。最初の起動で聞く)
- 送る前に確かめる(便利のため。本当の検査は PC 側): URL が YouTube か・動画の拡張子・数の範囲
- 送るもの: 動画があれば先に動画、**最後に依頼の JSON**(下の 5)。JSON が届いた = そろった、の合図にする(同期の途中のファイルを読まないため)
- Dropbox の API:
  - アプリは「App folder」の権限だけ(`/アプリ/切り抜き依頼/` の外は読めない・書けない)。スコープは `files.content.write` だけ(読みは要らない)
  - 鍵: PKCE で一度だけ承認して得た refresh token + app key(secret は使わない)。exe には焼き込まず、隣の `config.json` に置く
  - 150MB 以下は `files/upload`、それより大きい動画は `upload_session/start → append_v2 → finish`(8MB ずつ・失敗した塊だけやり直す)
  - 名前がぶつかったら `autorename`。`Dropbox-API-Arg` のヘッダーの JSON は ASCII 以外を `\uXXXX` にする(日本語のファイル名で必要)
  - .NET Framework では TLS 1.2 を明示する(`ServicePointManager.SecurityProtocol`)
- 鍵を作る手順はユーザーの PC の補助スクリプト(`dev/` に Python。仮)で行い、できた `config.json` を exe と一緒に友人へ渡す
- **鍵をリポジトリに入れない**(Public)。`config.json` は `.gitignore`、`dev/push_helper.py` の検査に Dropbox の鍵の形を足す

## 5. 依頼の形
### 5-1. 依頼の JSON(友人のプログラムが作る。`<日時>-<乱数>.request.json`)
```json
{"v": 1, "kind": "video", "files": ["<日時>-<乱数>__にぇの叫び.mp4"], "streamer": "さくらみこ", "memo": "", "sentAt": "2026-10-01T12:00:00+09:00"}
{"v": 1, "kind": "url", "items": [{"url": "https://www.youtube.com/watch?v=xxxxxxxxxxx", "top": 5}], "memo": "", "sentAt": "…"}
```
- 動画のファイル名に依頼の id を前に付け、JSON と組にする(Dropbox の autorename で名前が変わっても `files` を見て探す。見つからなければ待つ・一定時間で失敗)

### 5-2. 手で送るとき(ファイルリクエストの予備)
- 動画: そのまま。ファイル名の頭の `【名前】` を配信者として読む(2人以上は先頭の人)。合わなければ色なしで進める
- テキスト(`.txt`): 1行に1本 `URL [数]`。空の行・`#` の行は無視。UTF-8 と Shift_JIS の両方を読む。`.url` も受け付ける(数は既定)
- 正しい行だけ受け付け、おかしい行は飛ばして理由を残す

## 6. PC 側(ホーム)
- `home/intake.py`(新規): 見張りの処理。ホームの起動と一緒に動き、「すべて終了」で止まる
  - 設定はホームの設定(`home/prefs.py`)に節 `intake` を足す: 見張るフォルダ・オン/オフ・既定の N・上限
  - 同期の途中を避ける: JSON が無い手送りのファイルは、大きさと更新時刻が 2 回続けて同じになってから
  - 受け付けたら元を `受付済み\YYYY-MM-DD\` へ、断ったら `失敗\` へ + `<名前>.理由.txt`。消さない
  - 重複: 動画はハッシュ(大きさ + 先頭と末尾の数 MB)、URL は配信 ID で、受け付けた記録(作業データの `app/intake-state.json`)と照らす
  - 動画は作業データの `app/intake/YYYY-MM-DD/` へコピーしてから処理する(Dropbox の「オンラインのみ」や同期で元が消えても、文書の元のパスが切れない)
- `home/autorun.py`: 形を2つ足す(ホームの画面の「まとめて実行」の選択肢には出さない)
  - `request` = 解析 → 採用 → 書き出し → 文字起こし(`start_new` と同じ入り方で、パックの段が無い)
  - `file` = 文字起こしだけ(編集の `POST /api/transcribe` に `sourcePath`)。記録の `kind` に `file` を足す(`_parse_rec`)
  - 重い処理は今までどおり `ytt_core.jobs.SLOTS` を通る
- ホームの画面: 受付の状態(見張り中 / 止まっている理由・最後に見た時刻・今日の件数)と、届いた依頼の一覧(メモ・配信者・断った理由)。
  進み具合と結果は、今の「まとめて実行」と「まとめて実行の記録」にそのまま出る

## 7. 安全
- 鍵(または予備のリンク)を知る人は誰でも依頼を入れられ、自動で流れる。対策:
  - 鍵はアプリ専用のフォルダだけ。漏れたら Dropbox の設定でアプリの接続を切れば無効(新しい鍵を渡し直す)
  - 上限で PC を長く占有させない(仮の値: 1日 5 件・配信 8 時間まで・動画 1 本 20GB まで。設定で変えられる)
  - 送り主の名前・依頼の中身は本人の証明にならない。受け付けの判断には使わない
- 受け付ける URL は youtube.com / youtu.be の配信・動画だけ(11 文字の ID を取り出して、それだけを渡す。任意の URL を yt-dlp に渡さない)
- 他人が作った動画を ffmpeg で読むこと自体が攻撃の入口になり得る: 拡張子と ffprobe で形を確かめてから先へ。ffmpeg は新しく保つ
- JSON・テキストは大きさの上限(例 64KB)を付けて読み、知らないキーは捨てる。パスは見張るフォルダの中だけ(`..`・絶対パス・ネットワークのパスを断る。`fsio.is_network_path`)
- 見張るフォルダにネットワークドライブは選べない(段2 の「動画を選び直す」と同じ規則)
