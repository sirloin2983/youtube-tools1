# 評価用のフォルダ(編集 0.32.0)

状態: 済み(2026-10-01 実装。編集 0.32.0、仮置きは 0.33.0。Claude Code)

## 何のためか
精度を測るためだけの動画(評価用)を、PC の決まったフォルダ(ユーザーの例: `E:\Video\切り抜き動画素材\評価用データ\<地域>\<NN_グループ>\評価用データNN_<メンバー>\`)に置いて管理する。
今までは文書ごとに「評価用にする」のチェックを手で付けていたので、付け忘れると正解を見たまま辞書・学習に使ってしまい、評価に使えなくなっていた。

## ユーザーが決めたこと(2026-10-01)
- フォルダの中の動画は**自動で評価用**にする(始める画面で既定オンにするだけ、ではない)
- フォルダの中の動画の文書は、評価用の印を**外せない**
- 動画の名前は「**動画のフォルダ名_番号_状態**」(例 `評価用データ01_ときのそら_03_未.mp4`)。状態は 済 / 未 / 未文字起こし
- 「済」= 文字のある行が**すべて校正済み**(話者は見ない)
- 整理は**入口の起動時に1回 + 画面のボタン**(Windows のタスクでの定期実行はしない。入口が止まっていると付け替えができず、名前だけ変わって文書が動画を見失うため)

## 仮置き(編集 0.33.0。ユーザー決定 2026-10-01)
- 評価用のフォルダの直下の「評価用_仮置き」(`EVAL_STAGING`)に動画を置いて作業する。仮置きの中は**名前を変えない**(評価用の印は付く)
- 移す条件(`_eval_ready`): 文字のある行がすべて**校正済み**で、すべて**話者付き**(仮の名前 話者1 などでもよい)
- 移す先: 話した秒(行の長さの合計)が**最も長い**話者のうち、名前がメンバーのフォルダ(`_eval_members`。名前が「…数字_名前」= `評価用データ01_ときのそら`、NFKC・空白・大小を寄せて比べる)と同じ人のフォルダ。
  いなければ仮置きに残し、理由を整理の結果の `staged` に出す
- 名前: 移す先で空いている番号の「フォルダ名_NN_済」(`_eval_next_name`)。途中のファイルは移す先の `作業用\` へ(`_rename_sidecars` が別のフォルダにも対応)。付け替えの記録は `why: evalSettle`
- いつ: 整理の最初の段(`_eval_staging_pass`。移したあとで数え直してから名前をそろえる)と、画面がほかの文書へ移ったとき(app.js の `openDoc` → 1.5 秒後に `POST /api/eval-folders/settle {id}`。
  再生を切り替えてから。移せなければ何もしない = 次の整理で移す)。保存のたびには移さない(開いて再生している動画を動かさないため)

## 仮置きのコピーの付け替え(2026-10-02 ユーザー決定「使う」)
- 文字起こしした動画を**コピーして**仮置きに入れると、文書は元の動画を指したままなので、仮置きの動画は「文書が無い」扱いになり移らなかった(2026-10-01 の実例: 宙科そぴあの2本)
- 整理の仮置きの段で、文書の無い仮置きの動画に、**同じファイル名で同じ大きさの動画を指す文書がちょうど1つ**あれば、その文書を仮置きの動画へ付け替える(`_eval_adopt_copy`・候補の表 `_eval_copy_index`。記録の理由は `evalStagingCopy`)。
  そのあとは今までどおり、条件(全行が校正済み・全行に話者)を満たせばメンバーのフォルダへ移る。元の動画は消さない(二重になる。片付けはユーザーが)
- 付け替えないもの: 元の動画が無い文書(大きさを比べられない)・すでに評価用のフォルダの中を指す文書(ほかの評価用を横取りしない)・行の無い文書・候補が2つ以上(理由を `staged` に残す)・処理中の文書
- 「ほかの文書へ移ったとき」の確認(`eval_settle`)は、その文書の動画だけを見るので付け替えはしない(整理のとき = 起動時・「今すぐ整理」だけ)

## 仕組み(editor/serve.py の「評価用のフォルダ」の節)
- 設定 `evalDirs`(作業データの settings.json。パスは個人の情報なのでリポジトリに入れない)。`api/settings/patch` だけで直す(`SETTINGS_PATCH_KEYS`。丸ごとの保存では消えない)。
  使うのは、あって・ネットワーク上でなく・作業データの中でも外側でもないフォルダだけ(`eval_dirs`)
- 印を付ける所(`in_eval_dir` でパスを比べる。ジャンクションは `_inside` が解く):
  - 文字起こしの開始 `validate_job`(1本・フォルダ一括・まとめて実行・依頼の受付がすべて通る)→ 用語集・文脈・置換辞書・学習した置換も使わない
  - 保存 `sanitize_transcript`・以前の版に戻す `restore_history`・付け替え `_relink_write`(画面からの付け替えと整理の両方)
  - `GET /api/transcript` の `evalLocked` で画面のチェックを固定(`syncEval`)
- 整理 `eval_organize`(`POST /api/eval-folders/organize`・起動時は `prepare` の 5 秒後に `_evalorg_startup`。一度に1つ = `_evalorg_lock`):
  - 動画 = 評価用のフォルダの下 4 段までの動画・音声(`作業用` と `.` で始まるフォルダ、`_edit` で終わる名前は除く)。番号は動画のフォルダごと:
    すでに「フォルダ名_NN_状態」の形なら番号はそのまま(同じ番号が2つなら2つ目は振り直す)、それ以外は更新日時の古い順に空いている番号
  - 状態は、その動画を sourcePath に持つ文書(行のあるもの)から `_eval_state`。文書が無ければ「未文字起こし」
  - 飛ばす: 同じ名前のファイルがある・その動画のジョブが動いている(`_path_busy`)・文書が処理中(`_doc_busy`)・名前を変えられない(開いている)
  - 名前を変える → 途中のファイル(`作業用\` と動画の隣の `.clip.json`・`.edit.json`・`.transcript.json`・`.cut-plan.json`・`.srt`・`_edit.mp4`)も同じ名前へ → 文書を `_relink_write`
    (控え `.bak/<id>.pre-relink.json`・履歴・`relinks` に `why: evalOrganize`)。途中で失敗したら文書・途中のファイル・動画の名前を元に戻す
  - 印の無い文書には印を付ける(`_eval_mark_docs`)
  - `.clip.json` の中身(`media.path`・`media.name`)は書き換えない(ほかのツールのデータ)。読む側は「.clip.json と同じ名前 + 動画の拡張子」で見つける(`pipeline_io.resolve_clip_media` の ③)
- 結果は `GET /api/eval-folders` の `last`(メモリだけ。起動し直すと消える)と serve.log

## 限界・注意
- 学習用だった文書の動画をあとからこのフォルダへ移すと、それ以降は評価用になる。ただし、それまでに辞書・学習に使った分は取り消せない
- 整理で名前を変えた動画は、スタジオの書き出しの記録(スタジオの data.json)からは古い名前のまま(読むだけの約束なので直さない)
- 開いている文書の動画の名前を変えると、画面は整理のあとで文書を読み直す(ボタンのとき)。起動時の整理は画面を開く前に終わる想定
