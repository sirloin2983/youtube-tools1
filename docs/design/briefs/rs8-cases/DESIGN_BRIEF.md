# RS8 の画面: 案件を中心にした画面 + 確かめる(DESIGN BRIEF)

関連: 進め方 `plan/rs8-cases-ui.md`・問答 `grill.md`・下調べ `inventory.md`・友人の PC `plan/f1-friend-pc.md`・画面の決まり `docs/spec/ui-guidelines.md`・10 の原則 `docs/spec/usability-heuristics.md`・画面の基準 `docs/spec/ui-review-criteria.md`

## 1. 何のための画面か
- **使う人はユーザー 1 人**(友人は送るアプリだけ = F1)。Web/バックエンドのエンジニアで動画編集は初心者。PC の大きな画面で使う(スマホは対象外)
- **ねらい**: 配信 1 本から Resolve のパックまでを、ツールをまたがず 1 つの窓で進める(今はツールをまたぐのが 3 回・画面の状態 5 つ・2 本目以降の切り抜きは 1 本ずつ探す)。あわせて、精度のための確認作業(今は画面ごとにばらばら)を 1 か所に集める
- **律速は人の時間**: 校正(動画 1 分に約 12.6〜16 分。重いのは つなぐ・分ける と文字の直し)と採用の判断。画面はこの 2 つの手間と、その間の「探す・行き来する」時間を減らす

## 2. 画面の形(決めたこと。詳しくは `grill.md`)
### 2-1 入口(ホーム)— 仮決定(使ってみて直す)
```
[LIVE の帯](録画中だけ)
┌ やること ───────────────┐ ┌ 確かめる ─────────────────────┐
│ 採用待ち 2 案件 ▶          │ │ 今いちばん効く確認 1 つ                 │
│ 校正待ち 5 本   ▶          │ │ 「あと何本で何が決まるか」  [始める]     │
│ パック待ち 1 本 ▶          │ └────────────────────────────────┘
│ 失敗 1 件       ▶          │
└──────────────────────────┘
案件 [+ 新しい案件(URL・探す)] [検索]  … 状態とメモつきの一覧
▸ 運用(依頼の受付・バックアップ・まとめて実行の記録・調子)   畳む
```
- やること: 種類ごとの件数。押すといちばん古い 1 件のその作業の所へ。案件の画面の「次へ」で同じ種類の次の 1 件へ続ける
- 新しい案件: 今のスタジオ ①(URL を入れる・配信を探す・解析の待ち)をここへ

### 2-2 案件の画面(配信 1 本 = 案件 1 つ・同じ窓で完結)
```
案件: 【配信の題名】                              確かめると効く物 n 件
┌ 一覧 ─────────────┐ ┌ [候補] / [校正] [カット・パック] ───────────┐
│ 候補(配信全体)      │ │                                              │
│ 01 02:38:38 ✓校正   │ │  選んだ物の作業                               │
│ 02 02:51:10 校正中   │ │                                              │
│ 03 03:05:44 未      │ │                                              │
│ [+ 切り抜きを足す]   │ │                                              │
└────────────────────┘ └──────────────────────────────────────────────┘
```
- 左の一覧: 一番上が「候補(配信全体)」、その下に切り抜きが 1 本 1 行(状態 = 未・校正中・校正済み・パック済み)
- 右のタブ: 候補 → [候補](プレーヤー + タイムライン + マークの一覧・採用 / 不採用・書き出し = 今のスタジオ ②)/ 切り抜き → [校正](今の編集 1)・[カット・パック](今の編集 2)
- **校正のタブの中に配信のプレーヤーを小さく出せる**(今の「隣の窓で配信を見ながら校正」の代わり)
- 1 本済んだら次の未校正の切り抜きへ(ボタンとキー)

### 2-3 確かめる
- 案件をまたいだ確認の待ち行列。[始める] で 1 枚ずつカードが出て、答えるとすぐ次へ
- **順 = 目標まであと少しの物 → 軽い物**(期限は見ない = ユーザー)
- 軽い確認はその場のカード: 自動の切り抜きの採用 / 要らない(= 70 点以上か。今の「続けて確認」A5 をここへ)・候補の採否・「別」の採否・後処理の札(残す / 戻す)・話者
- 重い確認は案件の画面の該当の所へ飛び、終わったら戻る: G2 の定点の校正・カットのたたき台
- 部品は案件の画面と共用(行の編集・候補の再生・カット)

## 3. AI が決めたこと(ユーザー「その他は任せる」。仮。違えば直す)
1. **カードの流れ**: どのカードにも [飛ばす](その日は後ろへ回す)。上の帯に「今日 n 件・この確認で決まる物: 〇〇まであと m」を出し、答えるたびに数が減るのが見える。カードの答えは今と同じ記録に書く(測る道具 `eval_*` はそのまま読める)
2. **定点の目標を 30 分にそろえる**(ドリルの帯の 15 分 `drill.py:37` は G1 の名残。今の目標は G2 の 30 分 `accuracy.py:61`)。後処理の札(`eval_fill`。FEW_ROWS 30)も「あと何本」の表に足す
3. **案件に属さない文書は仮の案件にまとめる**(ユーザー「B でいい」。はじめの案「文書だけの画面」から変えた): 「評価用」(評価用の文書 = 定点の校正 G2 の材料。案件へ移さない = option_b)と「案件の分からない文書」(案件の仕組みより前の物・元の動画を辿れない物)の 2 つの仮の案件を、案件の一覧の末尾に並べる。開くとふつうの案件と同じ画面(左に文書の一覧・右に [校正] [カット・パック])。データは今の場所のまま、画面でまとめて見せるだけ。画面は 1 種類(原則 4)・評価ドリルは「評価用」の案件を上から直す作業になり左の一覧の状態で残りが見える
4. **動画ファイルの案件**(友人の依頼・手で入れた動画)= その動画のあるフォルダ(option_b)。丸ごと 1 本なので [候補] は無く、切り抜き 1 本の [校正] [カット・パック] だけ
5. **LIVE**: 録画中の案件は [候補] のタブがライブの見た目(今のスタジオの LIVE の帯と配信中の候補)。ホームの LIVE の帯からその案件を開く
6. **今の URL**(`/studio/?video=`・`/transcribe/?doc=`・`?media=`・`#tx`・`#cut`)は案件の画面の該当の所へ転送する(古いブックマークや知らせのリンクを生かす)。`/api/*` の URL と識別子は変えない(AGENTS の互換の決まり)
7. **見た目は今の ui-kit(v25)と `ui-guidelines.md` のまま**。新しい部品(切り抜きの一覧・カード・待ち行列の行)は ui-kit に足して `dev/sync_ui_kit.py` で写す。言葉は用語集どおり
8. **キー操作は今のものを引き継ぐ**(Alt+1/2 のタブ・Shift+↓ 次の未校正・M / Shift+M / Y・Shift+D など)。足すのは「次の切り抜き」と、確かめるのカードの答え(A 採用 / X 要らない / N 飛ばす = 今の続けて確認と同じ)
9. **設定**は `/settings` のまま。各画面の ⚙ は今の規則(決定 (gl) = その画面でしか意味を持たない物だけ)
10. **作る順**(`plan/rs8-cases-ui.md` 決めたこと 4): データ(B-2 → B-3 → O2)の間は今の画面を互換で動かし、データが落ち着いてから新しい画面に替えて古い画面を消す。V1(確かめる)は案件の画面のすぐあと

## 4. 10 の原則の当てはめ(段 2。`docs/spec/usability-heuristics.md`)
この画面でいちばん効くのは 6・1・4・8・3 の 5 つ。
| # | 原則 | この設計での当て方 |
| --- | --- | --- |
| 6 | 覚えさせず見て分かる | 入口の「やること」と案件の左の一覧の状態で、次の一歩が画面に出る。2 本目以降の切り抜きを「探す」が無くなる(一覧の行を押すだけ)。確かめるは「今いちばん効く物」を AI が選んで出す(どこで何をすればいいかを覚えなくてよい) |
| 1 | 状態を見せる | 切り抜きごとの状態(未・校正中・校正済み・パック済み)・作業の件数・確かめるの「あと m」が答えるたびに減る。重い処理(解析・書き出し・文字起こし・パック)の進み具合は今の帯のまま |
| 4 | 一貫性 | ツールごとに違ったヘッダー・タブ・キーを案件の画面 1 つにそろえる。候補の再生・行の編集は案件の画面と確かめるで同じ部品 = 同じ見た目・同じキー |
| 8 | 必要な物だけ | 入口の運用(受付・バックアップ・記録・調子)は畳む。案件の画面は選んだ 1 本の作業だけを右に出す。配信のプレーヤーは校正のときだけ小さく |
| 3 | 取り消せる | 採否・要らない・後処理の札は今のとおり戻せる。O2 で人の直しが機械の作り直しで消えない・機械が変わった行は選び直せる |
| 7 | 柔軟さと効率 | やることの「次へ」で同じ種類を続けて片付ける近道・今のキー操作を引き継ぐ |
| 5・9・2・10 | — | 今の決まり(押せない理由を出す・エラーは何が / なぜ / 次にどうする・用語集・画面の中の短い説明)をそのまま当てる |
