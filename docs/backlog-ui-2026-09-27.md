## A. ユーザーの要望(2026-09-27。会話で出たもの)

### A-1. 「…」の選択肢が画面の外に出る(編集 1 文字起こし の一覧の上の「…」)
- 原因: 「…」は一覧の上の段の右端にあるのに、選択肢の箱を「ボタンの左端から右へ広げる」指定(`transcribe-tool/index.html` の `#jumpMenu .ui-pop-body[data-align=left]`)にしているため、右の画面の外へはみ出す
- ユーザー: 入口を文字のボタンに戻さなくてよい(「…」のままでよい)
- 案A: 右端にそろえる(`data-align` を外す。1行)。案B(おすすめ): ui-kit の `.ui-pop` で、開くときに位置を測って、はみ出す側だけ反対へ広げる(スタジオ・ホームの「…」も同じ問題を防げる)

### A-2. 話者判別の話者名から字幕の色を決める
- 今: 字幕の色は、パックを作るときの**配信者の名前1つ**から決めた1色(`ytt_core/colors.py`・`cut2resolve/pack.py` の `textplus_color`)。話者判別の名前(「話者1」など。`transcribe-tool/serve.py` の `apply_diarization`)は色に使っていない
- 案: 文書の `speakers[].name` を `ytt_core/colors.py` で照らし合わせて話者ごとの色を決め、パックでは行ごとにその行の話者の色(Text+ は1つずつ作るので行ごとに色を変えられる)。
  名前が一致しない話者・話者なしの行は、今の配信者の色
- 気をつけること: 判別の誤りがそのまま色の誤りになる(パックの字幕の見本で話者ごとの色を先に見せる)。名前の一部で2人以上に当たるときは今と同じく決めない。
  パックの作り方が変わるので `tools/test_resolve_pack_contract.py` も直す

### A-3. 話者を覚える(声の記憶)
- 今: 話者判別はその文書の中で声を比べて分けるだけで、前の文書を覚えていない
- 案: sherpa-onnx の声の特徴(埋め込み)で、校正済みで話者名が付いた行の音声から人ごとの声を登録 → 判別のあと各グループを登録と比べ、十分似ていれば名前を自動で付ける(A-2 と組めば色まで自動)
- 気をつけること:
  - 判別モデル(VoxCeleb・CAM++・ERes2Net)ごとに声の特徴が比べられないので、登録はモデルごと
  - マイク・BGM・声色で似ている度合いが下がる。似ていなければ名前を付けない(しきい値は実際の配信で調整)
  - 声の特徴は個人を見分けられる情報: 作業データ(`%LOCALAPPDATA%\youtube-tools\`)にだけ置き、リポジトリに入れない(Public)。人に渡すときも抜く
  - 登録の量の目安は 1人あたり数分〜十数分(精度の画面の「話者ごとの正解の量」で見られる)
- 進める順番のおすすめ: A-1 → A-2 → A-3(A-2 は A-3 が無くても、名前を手で付ければ使える)

## B. UI レビューの結果(2026-09-27。ユーザーから渡されたもの)

対象: ホーム・スタジオ・編集。確かめ方: 見本のデータで実際の画面を操作・コードを読む(アプリ・実データは変えていない)。

### 優先度: 高
**B-1. ホームで選んだ文字起こしとは別の文書が開く**
- 同じ動画から複数の文字起こしを作っているときに起きる。「昔の配信アーカイブ」を押して「テスト用の音声」が開くことを再現
- 原因: 文書 ID ではなく動画のパスでリンクし(`app/portal.js` の `/transcribe/?media=…`)、その動画のいちばん新しい文書を開くため
- 直す方向: 保存済みの文書へのリンクは文書 ID を使う

**B-2. 書き出しの欄の後ろでキーが効く(スタジオ)**
- 「書き出し」を開いたまま → を押すと、後ろの再生位置が動くことを再現
- 採用・不採用などのキーも同じ守りに頼っているので、影響の範囲を確かめる(採用・不採用の誤った変更そのものは未再現)
- 直す方向: 欄を開いている間は後ろのキーを止める(編集の `document.querySelector('.ui-drawer:not([hidden])')` と同じ扱い。docked で並べているときの扱いは要検討)

**B-3. 右クリックのメニューの対象と、選んでいる行が食い違う(編集)**
- 右クリックのメニューを開いて ↓ を押すと、メニューの項目ではなく後ろの行が移動する。メニューの対象は右クリックした元の行のまま(不一致は再現。誤った編集の確定はしていない)
- 直す方向: メニューを開いている間は後ろの行の移動を止め、矢印キーはメニューの中の移動に使う(`transcribe-tool/app.js` の `ctxMenuEl`。W/S など左手のキーも止める)

### 優先度: 中
**B-4. 「見送り」の案件が「次にやること」に出る(ホーム)**
- 直す方向: 案件の状態(`app/portal.js` の `STATUS`: 見送り・投稿済み)を見て、通常の候補から外す

**B-5. 「次にやること」に配信者・日時がない(ホーム)**
- 同じ題名が並ぶとどの配信か分からない。直す方向: 題名に加えて配信者・日時、必要なら切り抜きの名前

**B-6. 編集からスタジオへ戻ると、元の配信の確認画面ではなく解析の追加画面になる**
- 再解析を求められているように見える。直す方向: 元の配信が保存済みなら、その配信の確認画面を開く

**B-7. 履歴を開くと編集の欄が狭くなる(編集)**
- 1440px でも字幕の本文と操作のボタンが段を分けて並び、一度に見える行が減る
- 直す方向: 履歴は残したまま、幅に応じて重ねて出す・開閉・列の幅の調整を考える(**履歴の削除や「最近5件だけ」への再変更はしない**)

**B-8. 字幕の行の操作ボタンが薄く小さい(編集)**
- 「校正済み」などが使えない状態に見えやすい。文字のコントラスト 約 4.03:1・高さ 26px(基準の 4.5:1・28px を下回る)
- 直す方向: 使える操作と補助の情報の見た目を分け、文字の色と押せる範囲を直す

**B-9. 「設定」が何か所にも分かれ、案内と実際の場所が合わない(編集)**
- 時刻の微調整の幅は映像の下の設定にある(`#adjStep`)が、説明はツールの設定(右上の ⚙)を案内している。右上の設定を探しても無い
- 直す方向: 設定の名前・説明・置き場所をそろえる

**B-10. カットの区間・端をキーボードだけで選べない(編集 2 カット)**
- 微調整のキーはあるが、区間や端を選ぶのはマウスだけ(DOM とイベントの処理から確認)
- 直す方向: 前後の区間への移動、始まりの端・終わりの端の選択をキーでできるようにする(`transcribe-tool/cut.js`。今のキー S・Del・I/O・X・, . と重ならないように)

### 見た目・一覧の見やすさ
**B-11. スタジオのマークの一覧で操作の部品が目立ちすぎる**
- 各マークに始まり・終わりの微調整ボタンが計 12 個ずつ並び、候補を比べにくい
- 直す方向: 選んでいるマークだけ詳しく開くなど、一覧では時刻・長さ・ラベル・判定を中心に見せる
