# 画面の共通のルール(2026-09-26 の全面見直しで決めたもの。2026-09-27 の2回目の見直しで改訂。2026-10-07 気が利く画面へ(段 9)で部品の決まりを追記)

ホームと2つのツール(切り抜きスタジオ・編集)の画面を直すときは、このルールに合わせる。
2回目の見直し(2026-09-27)の設計: `docs/design/briefs/ui-overhaul/DESIGN_BRIEF.md`(ユーザー承認)・実装で決めた細部: `docs/design/briefs/ui-overhaul/IMPLEMENTATION.md`。
部品と色は `ui-kit/`(正本。`python dev/sync_ui_kit.py` で各ツールへ写す)。見本は `ui-kit/styleguide.html`。
**合格の基準と測り方は `docs/spec/ui-review-criteria.md`**(2026-10-07。機械で測る A は `py -3.10 dev/ui_audit.py all --demo`、人が見る B は見直し役)。画面を直したら A を 0 件にする。
使う人は Web の開発者だが動画編集は初心者。**「次に何をすればいいか」が画面だけで分かる**ことを一番に考える。
考え方の物差しは Nielsen の 10 の原則(`docs/spec/usability-heuristics.md`。2026-09-27 ユーザー指示)。

## 1. 言葉(用語集)
画面の文言はこの言葉にそろえる。新しい言葉を足すときはここに書く。

| 使う言葉 | 意味 | 使わない言葉 |
| --- | --- | --- |
| 配信 | YouTube の配信(アーカイブ)1本。スタジオで解析・マークする元 | 動画(配信のことを指すとき)・ストリーム |
| 動画ファイル | 手元の動画ファイル(YouTube でないもの) | ― |
| 切り抜き | スタジオが書き出した mp4 1本 | クリップ(画面の文言では使わない)・ショート |
| マーク | 配信の中の区間の印(候補・採用・不採用・書き出し済み) | ― |
| 文字起こし | 切り抜き(か動画ファイル)1本ぶんの字幕のデータ | トランスクリプト |
| 行 | 文字起こしの1行(字幕1つ) | セグメント |
| 校正 / 校正済み | 聞いて文字を直すこと / 直し終えた行 | ― |
| 編集 | 文字起こし・カット・パックを1つの画面の3つのタブ(1 文字起こし / 2 カット / 3 パック)でする道具(transcribe-tool。2026-09-26〜)。ホームの切り替え(appnav)の名前 | 文字起こしツール(ツール全体を指すとき)・cut2resolve(画面を指すとき) |
| カット | 動画のどこを残すかの決まり(残す区間の並び)。2 カット のタブで決め、`<id>.edit.json` に保存 | カットリスト・編集点 |
| 残す区間 / 削る区間 | カットで Resolve に残す時間 / 外す時間(タイムラインの区間) | クリップ(画面の文言では使わない)・削除区間 |
| たたき台 | カットを決める出発点(行から・無音・時刻リスト・スタジオ)。そのあと手で直す | 自動カット・プリセット |
| 残す / カット済 | 行を Resolve の仮編集に残すか、外すか(カットから決まる。行の右の札と「まとめて」のメニューで変えるとカットも変わる)。2 カット の右の字幕の一覧の行の札も同じ「残す / カット済」(段7 E-25 では今の状態を出す 1 つの札だったが、「残す」を押すとカット済になり逆に読めたので、1 文字起こし と同じ [残す][カット] の 2 択に = UI の見直し (bc)) | 削除(行そのものを消す操作と混ざる)・削る / 戻す(行の札では使わない。タイムラインの区間の「削る区間」は別) |
| パック | Resolve へ渡すためのフォルダ(動画・カット・Text+ 字幕・手順書)。cut2resolve の pack.py だけが作る。「編集」の 3 パック のタブで、カットのとおりに作る | パッケージ・Resolveパッケージ |
| 作り直し | パックを作ったあとでカット・字幕を直したので、パックが古いこと(3 パック のタブと題名の行に出す) | 再生成・更新 |
| ホーム | 最初の画面(次にやること・案件の一覧・起動の管理)。2026-09-27 に入口と案件の画面を1つにした | 入口・ポータル |
| 案件 | 配信1本ぶんの作業のまとまり(ホームの一覧) | ― |
| まとめて実行 | 案件の残りの作業を順に自動で進めること | 一括実行 |
| キー操作 | キーボードの近道の一覧(ヘッダーのボタン名もこれ) | 操作キー・キー・ショートカット |

専門用語(EDL・Text+・FCPXML・タイムコード・LUFS・CER など)は、画面に出す最初の場所で `<abbr class="ui-term" title="説明">EDL</abbr>` にする
(点線の下線で「説明がある」と分かる。説明は1文で)。

## 2. ヘッダー(全画面で同じ形)
左から: 切り替え `ui-appnav`(ホーム / スタジオ / 編集。`<nav class="ui-appnav" data-ui-appnav="portal|studio|transcribe">`)→ 版(`#ver`。小さく)→ 段のタブ(あれば)→
右寄せで [ツールの操作(アイコン+文字、多くて3つ)] → [キー操作] → [⚙ 設定(`data-ui-settings`)](右端。テーマは設定の中。v14 でヘッダーの明暗のボタンをやめた)。録画中の札(ui-kit v16)が出るときは操作の先頭。
- ブランドの印と名前・「他のツール」のメニュー・「入口」のリンクは置かない(2026-09-27 でなくした)
- ホームの項目は start.bat で起動したとき(1つのポートに取り込まれているとき)だけ出る。ホームがほかの窓で開いていれば、移らずにその窓を前に出す(`UIKit.portal`)
- 開いている動画を引き継ぐときは `UIKit.appnav.setLink('transcribe', '?media=…')`(同じタブの中で移る)
- キーボードの近道の一覧のボタンは「キー操作」(アイコンつき)
- 保存の状態はヘッダーの1か所。実行中の札は点滅させない(回転の輪と数字だけ)

## 2-2. 設定と右の欄
- 設定はヘッダーの ⚙ の1か所(`UIKit.settings`)。中は「このツール」の節と「全体」の節(テーマ・文字の大きさ・キーの帯)。全体はどのツールで変えても全部に効く
- 設定・書き出し・パックの詳しい設定のように、主な作業と並べて使う道具は右の欄(`ui-drawer`)に入れる。
  幅 1280px 以上で作業と並べたいもの(スタジオの書き出し)は docked(裏も操作できる)、設定は modal(裏を止める)
- 確認は `UIKit.dialog.confirm`(ブラウザの confirm・画面ごとの確認のダイアログを作らない)。取り消せない操作は danger(最初のフォーカスは「キャンセル」)
- **確認の方式は 2 つだけ**(2026-09-29 気が利く画面へ 段1。ブリーフ `docs/design/briefs/ux-consistency/DESIGN_BRIEF.md`):
  - 取り消せない操作(消す・上書き・止める)= `UIKit.dialog.confirm({title, body, ok, cancel, danger})`(→ Promise<boolean>。Esc は false)
  - 3 択以上(例: パックの上書き = やめる / 別の場所を選ぶ / 上書きして作り直す)= `UIKit.dialog.choose({title, body, buttons: [{label, value, kind}], cancel})`(→ Promise<value>。ui-kit v23。画面ごとに dialog を作らない = UI の見直し (be))
  - 一覧の行の中の小さな取り消せない操作(マーク・グループ・文書の削除・録画の停止)= 二度押し `UIKit.confirmTwice(btn, run, text)`(1 回目でボタンの文字を text(「もう一度押すと削除」など)に変えて `.armed`、3 秒以内のもう 1 回で run。画面ごとに二度押しを作らない)
  - **取り消せる操作は確認しない**: すぐ実行して、知らせの [元に戻す](`UIKit.toast` の `action`)で戻せるようにする(行のカット済・全行を校正済み など)
- ポップオーバー・「…」は `details.ui-pop`(外のクリック・Esc で閉じる。開く印は文字の ▾ ▸ ではなく `.ui-caret` = ui-kit v23。開いたら画面に収まる位置へ ui-kit が置き直す。中身をあとから読み込むときも同じ = ui-kit v22。中身を自分の class で作るときは `data-ui-fit` を付ける = ui-kit v23)
- アイコンは SVG の `UIKit.icon` だけ。文字記号(☰ ⚙ ✂ ✓ ▶ ▾ ▸ ⋮ ×)をアイコンに使わない(文の中で設定を指すときは「設定」と書く)。矢印 ← → ↑ ↓ は kbd と「A → B」の文で使ってよい
- 知らせは `UIKit.toast(message, {kind, ms, action, detail})`(成功は短く、失敗は何が起きたか+どうすればいいか):
  - **次の一手のボタンを 1 つ**付けられる: `action: {label, fn}`(例: 書き出し完了 [編集で開く]・パック完了 [フォルダを開く]・失敗 [もう一度])。ボタンのある知らせは 8 秒(完了系)か `ms: 0`(消えない。× か ボタンで閉じる)。本文を押しても閉じない
  - **重ねるのは 2 つまで**(ui-kit v21。積み上がると画面の下の操作を隠すため)。あふれたら 失敗でない時間で消える知らせ → 失敗でないボタン・消えない知らせ → 古いもの の順に閉じ、**失敗の知らせ(`kind: 'err'`)は最後まで残す**(ui-kit v22・v23)。押し流されて困る案内は知らせでなく欄に出す(例: 編集の 3 パック の「前回のパック」の案内)

## 2-2b. まとめて実行の部品(2026-09-29〜10-07 気が利く画面へ 段4)
- 「まとめて実行」の入口(ホームの案件の行・紐づかない文書・編集の題名の行と履歴・スタジオ ① ③)は、**すべて `UIKit.autorun` を使う**(入口ごとに小さなフォームを作らない)
  - `UIKit.autorun.panel(el, {kind: 'video'|'docs'|'new', modes})` = 要約 1 行 + 「設定を変える」(`details.ui-pop` の中に全部の欄。値を変えたらすぐ保存し、どの入口でも次からの既定になる)
  - `UIKit.autorun.start(path, body, estBody)` = 見積もり → やることが 0 なら始めない(「やることがありません: 理由」)→ 始める → 終わったら完了・失敗の知らせ([やり直す] など)
  - 状態の言葉は `UIKit.autorun.stepLabel` / `runLabel`(待ち・実行中・済み・飛ばした・一部失敗・失敗・中止・やることがありませんでした)。画面ごとに言葉を作らない
- 値の置き場所は 1 か所: 形・採用数・カットの方法・上書き・失敗したとき = ホームの設定 `autorun`(`UIKit.prefs`)/ パックの fps・縦横・話者の色・予備・音量 = 編集の設定(3 パック のタブと同じ値)
- 使えないとき(ホームから開いていない・ライブの録画・スタジオから消えた配信)も隠さず、押せなくして理由を出す(下の 3 の「押せないメニュー」か、disabled + 理由の文)

## 2-3. キー
- **1つのキーは全体で1つの意味**。同じキーが画面やタブで別の意味にならないようにする
- **例外(2026-09-30 ユーザー決定。現状維持)**: 校正(1 文字起こし)の S=次の行・W=前の行・Q=3秒戻る は、2 カットでは S=分割・Q/W=端の選択(入り・出し)になる。校正の左手キーは 0.18.2 でユーザー決定により残したもので、タブが違えば画面の見た目も違い混同しにくいため変えない
  - 今後キーを足すときは、校正とカットの両方にあるキーは同じ意味にする。別の意味になってよいのは既存のこの 3 つ(S・W・Q)だけ
- 共通の再生キー(全ツール・全タブ。`UIKit.keys.playback`): Space 再生・停止 / J 1秒戻る / K 止める / L 再生(もう一度で速く)/ ← → 1秒(Shift で5秒)/ , . 1コマ / I O IN・OUT(始まり・終わりの印)
- 単体キー(Shift なし)が基本。入力欄・select・contenteditable にフォーカスがあるときは効かない
- よく使うボタンにはキーを書く(`<kbd class="ui-kbd">`)。画面の下の細い帯(`UIKit.keybar`)にいまの場面の主なキーを5〜7個出す(設定で消せる)
- **キーの一覧 = キー配置の設定**(2026-09-29 段6・ui-kit v8/v14): ヘッダーの「キー操作」(と `?`)で開く一覧の、各キーのボタンを押すとその場で次のキーを待って割り当てを変える
  (Esc = 取り消しだけ・Delete = 外す・重なったら一覧の中に「「X」から外しました [戻す]」)。部品は `UIKit.keymap`(編集・スタジオで同じ)。⚙ の「キー配置を変える(?)」は同じ一覧を開く(変える場所を 2 つ作らない)。
  共通の再生キーはホームの設定 `keymap.playback` に 1 つ。帯・ボタンの横のキー・ツールチップ・知らせの文は今の割り当てから作る(固定の文字で書かない)

## 3. ボタンと状態の札
- ボタンは3種類だけ: `primary`(その欄の主な操作。1つの欄に1つ)/ 普通・`ghost`(補助)/ `danger`(消す・止めるなど戻せない操作。必ず確認つき)
- 状態の札(`.pill`)は押せない表示だけ。ボタンに見える札を作らない。押せるものは必ず `.btn`
- 色の意味: ok = 済み・動作中 / wait = まだ・待ち / run = 実行中 / warn = 注意 / err = 失敗 / info = 情報。言葉は「済み」「まだ」「実行中」「注意」「失敗」を基本に
- 1つの状態を変える入口は1か所にする(同じ操作のボタンを別の場所に2つ置かない)
- **一覧の行の中の「次の一手」のボタン**は `.ui-next-btn`(ui-kit v21): `<a class="btn small ui-next-btn" href="…">校正 12 行</a>` / `<button class="btn small ui-next-btn">パックを作る</button>`。
  札とほぼ同じ高さ(行の高さをそろえる)・アクセントの文字・右に →・押せる範囲は 28px。行き先が無いときは `.btn` を付けない(押せない案内の文字だけ)。
  使っている所: ホームの案件の行の次にやること・編集の履歴の「パックを作る」「作り直す」。押せない札(`.pill`)を次の一手に使わない
- **押せないメニュー**(ui-kit v21): `details.ui-menu` / `details.ui-pop` の入口が今は使えないときは、隠さずに `UIKit.menuOff(details か summary, 理由, 使えるときの title)` を呼ぶ
  (`summary[aria-disabled=true]` になり、押しても・Enter・Space でも開かずに理由を知らせる。理由を空で呼ぶと戻る)。画面ごとに summary の click を止めない。
  使っている所: 編集の題名の行・スタジオ ① ③ の「まとめて実行」(ホームから開いていない・ライブの録画)。ボタンの押せない理由は `disabled` + `title`(と必要なら `aria-describedby` の文)

## 3-2. 時刻を入れる欄(2026-10-02)
- 時刻(1:23:45)を手で入れる欄を新しく作るときは、ui-kit の `UIKit.timebox`(`<span data-ui-time>`。`ui-kit/README.md` の v11)を使う。「:」を打たせない・
  時 → 分 → 秒 の順に数字だけ・← → で場所を選ぶ・↑ ↓ で動かす(ユーザーが送るアプリ 2.0.0 で決めた形。`docs/spec/friend-intake.md` の 2-10)
- YouTube の URL(…?t=)の貼り付けは、配信の位置を入れる欄だけ(`data-ui-time-youtube`)。ほかの欄では付けない(ユーザー「必要な時だけでいい」)
- 誤り(終了が開始より前など)は、その場で欄を `aria-invalid="true"` にして、欄の下に「何が・どう直す」を出す(送る・保存するまで待たない)
- 形の使い分け(ユーザー決定 2026-10-02): 配信の中の位置(長い)= 時:分:秒(0.1 秒まで要るなら `data-ui-time-tenths`)/ 切り抜きの字幕の行(短い)= 分:秒.0.1秒(`data-ui-time-short`)
- 使っている所: 編集の行の開始・終了(0.40.0)・スタジオのマークの開始・終了とコラボの合わせる時刻(0.15.0)。スタジオの「現在位置」は今までの入力欄のまま(秒の数字でジャンプできるため)
- 値を保存する・描き直すのは、確定(`ui-time-commit` = Enter か欄を離れたとき)で。描き直したあとにフォーカスを欄へ奪い返さない(`detail.to` へ戻す)

## 4. 一覧(件数が多いもの)
- 上に道具の行(`.ui-listbar`): 検索(残りの幅いっぱい)・絞り込み・並び替え・件数(`.ui-count`)
- 1件は1行(高さをそろえる)。詳しい中身は開いたときだけ(`details` か、選んだときに右側に出す)
- 一覧は**1枚の紙**(`.ui-sheet`: 外枠1つ・行の間は細い線。1件ごとの角丸・枠・影にしない)。ホーム・編集の履歴・スタジオのマークの一覧(段5 5-4。2026-10-01)で同じ。選んだ行は `outline`、開いた行は `--panel-2` の背景
- 同じ題名が並んでも見分けられるように、**だれの・いつの**(配信者・日時。日時は `UIKit.fmt.ago()`)を必ず出す
- まとまり(配信者ごと・状態ごと)は `details.ui-group`。既定は今使っているまとまりだけ開く
- 「次にやること」があれば1つだけ(`.ui-next`。例: 「校正 12 行」「パックを作る」)
- フルパスは常に出さない(開いたときか、`title` で)。長い名前は末尾(ファイル名)が見えるようにする
- 200件を超えても重くならない作り(絞り込んだ分だけ描く・「もっと見る」)

## 5. 段階的に見せる
- 最初に要るものだけを見せる。まだ使えない欄(入力前の書き出しなど)は、閉じるか「〜すると使えます」と出す
- 詳しい設定は `details.ui-disclosure`(「詳しい設定」)に入れる。既定値で困らないものは全部そこへ
- 空の表示は2文: 「まだ〇〇はありません」+「〇〇すると、ここに出ます」
- エラーは「何が起きたか」+「どうすればいいか」。技術的な原文は後ろに小さく(`<details>` か `title`)

## 6. 狭い画面・キーボード・見た目
- 幅 390px で横にはみ出さない・文字が1文字ずつ縦に割れない(短いラベル + select の組は `.lag.keep`。ホームの画面は portal.css で `.lag` を折り返さない)。見る幅は 390・960・1440(主な作業の場面は 1920 も)
- 横に並べた欄は、狭い画面では縦に積む。主作業(一覧・プレーヤー)に早く届く順に並べ、設定は閉じておく
- 押せる部品(ボタン・入力欄・select・summary・`.btn` のリンク)は高さ 28px 以上(アイコンだけのものは幅も)。文中のリンクと、label に包まれた 16px の checkbox は除く。当たり判定は見た目より広げてよい(`.ui-next-btn` の `::before`・タイムラインの区間の端)
- フォーカスの輪(`--ring`)を消さない。キーボードだけで全部の操作ができる
- 既定は明るいテーマ。明るい(アイスライト)/暗い(ネオンシアン)の両方で確かめる(鋼の白・ターミナルグリーンはできれば)。映像の周りは両テーマで暗い灰色(`--stage-bg`)。文字の濃さは 4.5:1 以上(状態の札は `--ok-ink` などを使う)。
  `--ink-4` は明るいテーマで面に対して 3.2〜3.6:1 しかないので、placeholder・空の欄(--)・押せない物・飾りにだけ使い、情報の文字(時刻・件数・説明)には `--ink-3` 以上。文字の青は `--accent-ink2`(`--accent` は薄い面の上で足りない)。ボタンを薄く見せるのに opacity を使わない(押せないときだけ)
- **赤い面(`background: var(--danger)`)の上の文字は `var(--danger-on)`**(ui-kit v22。明るいテーマは白、暗いテーマは濃い色。暗いテーマの `--danger` は明るい赤なので、白い文字は 2.9:1 で読めない)。
  `#fff` を直に書かない。使っている所: 赤い帯 `.errbar`・`.badge`・`.btn.danger.solid`・録画の停止の二度押し(`.ui-live-acts .btn.armed`)・編集の行の札「カット済」・スタジオの LIVE の札
