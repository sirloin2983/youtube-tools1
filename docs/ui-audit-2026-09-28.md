- 修正方針: モーダル中はタブ切替を止めるか、切替前に正式な close 処理を通す。共通設定も含め、マウス・キー双方で確認する。
- 証跡: `gpt2-pack-hidden-modal.png`。

### 02. 「評価用・学習に使わない」でも「声を覚える」を実行できる条件になっている

### 10. zip は「同じ中身」と案内するが、一部の設定が渡らない

- **P2 / コード確認。** 通常パックは粗編集動画・詳細タイムコード・リール名を渡すが、zip のリクエストは渡さない。
- 根拠: `pack-tab.js:179` の同一内容の説明、`:241` の通常作成、`:312` のzip。`resolve_export.py:237` の `create_package` にも該当引数がない。
- 影響: 同じ条件を選んだつもりで、人へ渡すzipと手元のパックが異なる。
- 修正方針: 対応設定をそろえるか、zipで使えない設定を明示する。通常作成とzipの契約テストに、同梱物と詳細設定の差分も追加する。

### 11. 設定の保存失敗を画面に出さない

- **P2 / コード確認。障害注入は未実施。** 編集とスタジオ確認画面の設定保存は失敗を空のcatchで捨てる。
- 根拠: `transcribe-tool/app.js:241`、`clip-studio/review.js:726`。
- 影響: サーバー停止・ディスク書込みエラー等でも画面上では設定が変わり、次回起動時に元へ戻る。キー配置などで特に混乱する。
- 修正方針: 設定の未保存状態・失敗理由・再試行を用意する。文書の保存表示と混同しない。別窓からの同時変更も確認する。

### 12. 話者ごとの色が、字幕の見本には反映されない

- **P2 / コード確認。話者名変更による実画面の色不一致は未確定。** 話者→色の対応表はあるが、字幕見本は文字列だけから作り、全体の配信者色を使う。
- 根拠: `pack-tab.js:82` の `renderSpk` と `:155`〜`:157` の見本生成、`index.html:893` の `--tt-cap-color`。実際のパックには話者別色を別途渡す。
- 修正方針: 字幕見本に話者情報も渡して実出力と合わせる。難しければ「配信者の基本色の見本。話者別色は未反映」と明示する。カット画面の字幕も対象。

### 13. 保存済みカットの読み込み失敗を、新規のたたき台と区別しない

- **P2 / コード確認。通信障害は未注入。** `/api/edit` が失敗しても `ed = null` にし、draftが取れればたたき台の区間を表示する。
- 根拠: `cut.js:123`〜`:154`。壊れたファイルを示す `ed.broken` には通知があるが、GETの失敗にはない。
- 影響: 既存カットが無いように見え、違う区間を編集・確認し始める。rev競合の保護はあるため「即上書きで消失」とは断定しない。
- 修正方針: 未作成・破損・通信失敗を分離。保存済み状態が読めない間は理由と再試行を出し、勝手に新規扱いにしない。

### 14. ホームのメモを保存中に追記すると、新しい下書きを消す競合がある

- **P2 / コード確認。低速通信での実再現は未実施。** Aを保存→応答前にBへ追記→Aの保存応答で下書き全体を削除する。
- 根拠: `app/portal.js:483`〜`:486`。送信値と現在の入力の一致を確かめず `delete d.memo` する。
- 影響: 入力欄にBが残っていても「保存しました」と出る。その後の再描画ではAに戻り得る。
- 修正方針: 送信時の値/編集世代を覚え、保存した版だけを保存済みにする。保存中の追記は保持し、二重送信の応答順にも対応する。

### 15. 文字起こしの「1コマ」が、素材のfpsによらず1/30秒

- **P2 / コード確認。60fps素材による実再生確認は未実施。** `app.js:1894` は共通再生キーへ `fps: 30` を固定で渡す。一方カットは素材のfpsを渡す(`cut.js:847`)。
- 影響: 60fps素材では1回で約2コマ分、24fpsでは1コマ未満の移動量となり、タブ間でも感触が違う。
- 修正方針: 取得済みの素材fpsを共用。可変fps等で正確なフレーム移動を保証できない場合は、「1コマ」と断定しない表記も検討する。

### 16. キーを変えても、ツールチップ・通知・カットのキー帯が標準配置のまま

- **P3 / コード確認。** 音の状態のX/C/V、削除の「もう一度Z」、カットのSpace・I/O・コマ送り等が固定文字列。
- 根拠: `app.js:1456` / `:1813`、`cut.js:389`、カットのHTML内のキー説明。
- 修正方針: キー一覧だけでなく、帯・title・通知を同じ割当表から出す。割当解除時も嘘のキーを表示しない。

## 設計判断を伴う改善・既知の未対応

### 17. 「声を覚える」の対象に、未確認・手動の重なりタグの行も入り得る

- **P2相当の改善候補 / コード確認。現在のAGENTSは「名前を付けた1秒以上の行」を仕様としているため、単純な仕様違反とは扱わない。**
- `serve.py:2875` の `voice_groups` は長さ・MIXED_FLAGを確認するが、校正済み・手動タグの `overlap` / `bgm` / `unclear` を確認しない。
- リスク: 間違った話者割当や複数人の声を混ぜた登録が、以後の名前付けに影響する。登録ボタンからは実際に使う行・除外理由が分からない。
- 改善案: 登録前に対象者・行数・秒数・未確認の割合を見せる。「校正済みだけ」等の対象条件はユーザーと決める。判別用途の `voice_groups` まで一律に校正済み限定にせず、登録と推定を分ける。

### 18. 「本人」「ゲスト」などの一般名でも、文書をまたいで同じ人物として声を混ぜる

- **P2相当の改善候補 / コード確認。** `app.js:813` と `serve.py:3026` は「話者+数字」以外を名前として受け付け、`serve.py:3066` 以降では同名の既存ベクトルに混ぜる。
- リスク: 別配信の別人を「本人」として登録すると、同じ記憶に混ざる。登録ごとの取消しはなく「忘れる」は名前単位。
- 改善案: 一般名には固有名への変更を案内。既存名へ足すときは対象と登録量を示し、同一人物であることを確認できるようにする。声の特徴は今後も作業データ内だけに置く。

### 19. 動画の移動・改名で参照が切れると、画面だけでは復旧できない

- **P2 / WORKLOGにもある既知の未対応。新発見とは数えない。** コードでは一般的な再生エラーを出すだけで、ファイルを選び直して既存文書へ付け替える導線がない(`app.js:2127`)。
- 影響: 新たな文字起こしを作り直すか、外から参照を修理する必要があるように見える。
- 改善案: 元の字幕・校正・カットを保持した再リンク。長さなどの照合、別動画への誤リンクの警告、バックアップを設計する。コーデック非対応とファイル不存在も分ける。自動推測で無確認に付け替えない。

### 20. YouTubeプレーヤー本体の準備待ちに、時間切れと再試行がない

- **P2相当の条件付き候補 / 見本環境で長時間の準備表示を観察、コード確認。実配信では未検証。** 架空IDと接続環境の影響があるため「実配信が常に失敗する」という指摘ではない。
- `review.js:573` のIFrame APIスクリプトには12秒のタイムアウトがあるが、`:671` の `new YT.Player` 後、onReady/onErrorのいずれも来ない場合の準備完了待ちにはない。
- 改善案: プレーヤー本体にも時間切れ・再試行・YouTubeで開く・時刻入力で続ける案内を出す。回線遮断/埋込み制限で追加検証する。
- 証跡: `gpt2-studio-light-1280.png` 等。読み込み状態の見た目の証拠であり、外部サービス側の原因は未確定。
