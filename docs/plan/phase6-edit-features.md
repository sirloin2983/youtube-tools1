# 段6: 編集の機能を足す
> 状態(2026-10-01): **済み**(編集 0.30.0・cut2resolve 0.16.0。6-1〜6-6 すべて。実装で決めた細部は `docs/design/edit-tool-design.md` の 11「段6」)。以前の状態(2026-09-29): 未着手。行の後の余白を設定で変えられるようにし(B-1)、2 カット の字幕の段で行の時刻をドラッグで直す・行を分けられるようにする(B-2)

## 目的
- B-1: 語尾が切れるときに、行の後ろの余白(今は決まった 0.2 秒)を自分で延ばせるようにする。本物の文字起こしでは行の終わりの 82% がこの決まった余白で決まる(`docs/design/edit-tool-design.md` の 12 ⑥「測った結果」)ので、ここを変えられれば「語尾が切れる」の多くを画面だけで直せる(⑥ の聞き比べの代わり)
- B-2: 2 カット の字幕の段で、波形を見ながら行の始まり・終わりをドラッグで直し、長い行をその場で分ける。1 文字起こし のタブへ戻らずに済むようにする。文書(`transcripts/<id>.json`)と編集の内容(`<id>.edit.json`)の両方を書くので、保存の競合(409)を両方で扱う

## 各作業の細かい計画

### 6-1 B-1a pack.py に「行の後の余白」(`padAfter`)
- 今の動き: `RowEdge.pad_after = 0.2`・`pad_before = 0.1` は決まった値(`cut2resolve/pack.py:38-50`)。`row_edge_from` は `on`・`after`・`before` だけ読む(`:196-211`。`widen_row_edges` は `:214-`)。決まった余白は上限の中(`min(after, pad_after)`。`:223`)。
  設定は文字起こしの `/api/settings` の `rowEdge` をそのまま保存(`editor/serve.py:6017-6021`)し、下書き(`:952`)・zip(`:5963`)・まとめて実行(`home/autorun.py:527-550` → cut2resolve の `spec.rowEdge` → `cut2resolve/serve.py:499-503`)が同じ `row_edge_from` で読む
- 変えること: `row_edge_from` に `padAfter`(秒。0〜`ROW_EDGE_MAX`)を足す → `dataclasses.replace(..., pad_after=…)`。
  **`padAfter` が `after`(終わりを広げる上限)より大きいときは `after` も `padAfter` まで上げる**(「余白も上限の中」の規則のままだと、上限 0.5 秒より長い余白が効かないため)。
  `pad_before` は変えない(決めたのは「行の後」だけ)。既定(`padAfter` 無し)は今と同じ 0.2 秒 → 既存のパック・契約テストの結果は変わらない
  - 案: 無音が見つかった端にも「最低でも padAfter 秒」を足す(無音の中へ延ばす)形もあるが、`widen_row_edges` の規則(「端がもう無音の中なら動かさない」)と契約テストを変えることになる。今回は**決まった余白の値だけ変える**(規則は変えない)
- 変えるファイル: `cut2resolve/pack.py`(`row_edge_from`・docstring)・`docs/design/edit-tool-design.md` の 12 ⑥(設定の形 `{on, after, before, padAfter}`)
- テスト: `cut2resolve/tests/test_pack.py` の `TestRowEdgeRule.test_row_edge_from`(`:1105-1115`)に `padAfter`(0.4 → `pad_after 0.4`・`after` が上がる・範囲外 `3` / 文字 / bool は ToolError)、`test_fixed_pad_without_silence` に余白 0.4 の1件。
  `test_serve.py`(`:457-463` の `spec.rowEdge`)に `padAfter` を通す1件。契約テスト `dev/tests/test_resolve_pack_contract.py` の `RowEdgeContract`(`:490-`)に「`padAfter` 0.4 で、端の上限は後 0.5 秒のまま・広げる前の区間を含む・カット済の行に入らない」の乱数の1件を足す(既定の件は変えない)。
  流す: `python -m unittest cut2resolve/tests/test_cut2resolve.py cut2resolve/tests/test_pack.py cut2resolve/tests/test_serve.py`、★`python -m unittest dev/tests/test_resolve_pack_contract.py`(**単独で**)、`python -m unittest editor/tests/test_metrics.py editor/tests/test_resolve_export.py -q`、★`python -m unittest home/tests/test_autorun.py`
- リスク・エッジケース: 古い設定(`padAfter` 無し)はそのまま既定。`padAfter` だけ入って `on:false` なら広げない(今と同じ)。cut2resolve の CLI(`--no-row-edge`)には足さない(画面の設定だけ)
- 終わりの条件: `row_edge_from({"padAfter": 0.4})` で後ろの決まった余白が 0.4 秒になり、既定のパックは変わらない。テストが通る

### 6-3 B-2a 字幕の段で行を選ぶ・端をドラッグで動かす
- 今の動き: 字幕の段 `#tlSubs` は見えている行を `.tt-s` で描くだけ(`editor/cut.js:350-357`)。押すとその行の頭へ移るだけ(`:778`)。ドラッグできるのは区間の端 `.tt-h` だけ(`:723-756`)。
  行の時刻は 1 文字起こし のタブで数字を直す(0.01 秒に丸める。`serve.py:514`)
- 変えること:
  - 行を押すと選ぶ(`M.sel = {kind:'row', i}`。今の「頭へ移る」も続ける)。選んだ行にだけ左右のつまみ(区間の `.tt-h` と同じ見た目で小さく。当たり判定は外 6px まで)を出す
  - つまみのドラッグで行の始まり/終わりを動かす。吸い付く先は今の `snapTargets`(無音の境目・再生位置・区間の端・ほかの行の端)。**前後の行を越えない**(重ならない)・長さは1フレーム以上。ドラッグ中は `#tlTip` に「行の終わり 0:12.34(+0.20秒)」
  - 放したら `S.doc.segments[i]` の `start`/`end` を 0.01 秒に丸めて書き、`h.markDirty()`(`app.js:1346`。文書の保存と `CUT.docChanged` が今の仕組みで走る)。フレームの境目は 0.01 秒に丸めると少しずれる → 丸めた後の値で描き直す
  - `h` に `markDirty`・`pushUndo`・`lockJob`・`renderDocSoon`(1 文字起こし のタブを次に見せるときに描き直す)を足して渡す(`app.js:2739-2740`)
  - キー: 行を選んでいるときの `,` `.` は選んだ端を1コマ(区間の端と同じ意味。`cut.js:852`)。新しいキーは作らない
- 変えるファイル: `editor/cut.js`・`editor/app.js`・`editor/index.html`(`.tt-s` のつまみ・選んだ行の CSS、キー操作の一覧)
- テスト: `editor/tests/e2e_edit_cut.py` に「行を選ぶとつまみが出る・終わりを右へドラッグすると文書の `end` が変わって保存される・隣の行を越えない・1 文字起こし のタブの時刻も変わっている」。流す: `editor/tests/e2e_edit_cut.py`・`editor/tests/e2e_edit_tabs.py`・★`node --test editor/tests/test_document_save.cjs`
- リスク・エッジケース: 区間の本体・削る区間の押し分け(`:769-786`)と字幕の段の当たり判定がぶつからないように、つまみの `pointerdown` を先に見る。文字の無い行は描いていない(`:354`)ので動かせない(今のまま)。評価用の文書でも時刻は直せる(1 文字起こし のタブと同じ)。速さ: 数千行でも見えている行だけ描く今の作りを保つ
- 終わりの条件: 字幕の段で行の端をドラッグして直せ、文書に保存される

### 6-4 B-2b 行を広げたら残す区間も広げる・元に戻す
- 今の動き: 行の「カット済」は編集の内容(区間)から決まる(`serve.py:879-923` の `edit_cut_flags`・`apply_edit_cuts`、画面は `cut.js:71-84`)。行の時刻だけ変えると、残す行の広げた分が削る区間に入ったままになる(パックでは字幕がそこで切れる)。
  カットが「行から」のまま手で直していなければ、行が変わると「行から」を作り直す(`cut.js:278-296`)。元に戻すは区間(`cut.js:94-112`、`M.undo`)と文書(`app.js:1557-1565`、`S.undo`)で別々
- 変えること:
  - 残す行(カット済でない行)の端を**外へ**動かし、新しい所が削る区間に入るときは、その分だけ区間も足す(`addRange`。`cut.js:44`)。内へ縮めたときは区間を削らない(カットを勝手に減らさない。削りたければ区間の端を動かす)。
    カット済の行は区間を変えない。カットが「行から」のまま(pristine)なら区間は触らず、今の作り直しに任せる
  - 1回のドラッグ = 1つの操作として、文書の元に戻す(`pushUndo`)と区間の元に戻す(`M.undo`)に同じ印(時刻)を付けて積む。2 カット のタブの Ctrl+Z は、いちばん上が同じ印なら両方を戻す。
    監査05(1 文字起こし のタブの元に戻すを「新しい方から」にする)をこの段より先に入れていれば、その2つの積み方(時刻の比べ方)をそのまま使う
- 変えるファイル: `editor/cut.js`・`editor/app.js`
- テスト: `editor/tests/e2e_edit_cut.py` に「手で直したカットで、残す行の終わりを削る区間の中へ広げる → 区間も広がり、編集の内容(`/api/edit`)に保存される」「縮めても区間は変わらない」「Ctrl+Z で行の時刻と区間が一緒に戻る」
- リスク・エッジケース: 広げた先が別のカット済の行にかかる → そこで止める(`rowsCut` の考え方と同じ。カット済の行を生き返らせない)。区間を足すと隣の区間とつながる(`addRange` がまとめる)
- 終わりの条件: 残す行を広げると残す区間も広がり、1回の元に戻すで両方戻る

### 6-5 B-2c 字幕の段で行を分ける
- 今の動き: 行を分けるのは 1 文字起こし のタブの行の操作だけ(`app.js:2087-2100` の `doSplit`。文字の欄のカーソル位置と再生位置で分ける)。2 カット のタブの S は区間の分割(`cut.js:645-649`)
- 変えること: 選んだ行の上に小さな道具(「再生位置でこの行を分ける」)を出す。押すと小さな確認の欄(文字の入力欄に行の文字・カーソルは時刻の比で決めた位置)で文字の分け目を選んで Enter。
  時刻は再生位置(行の端から 0.3 秒より内側のときだけ。それ以外は押せない)。分けた2行は `doSplit` と同じ形(右の行は新しい id・`flag` は空)で、`pushUndo` → `markDirty`。区間は変えない(カット済の印は区間から付け直される)
  - キーは足さない(S は「区間の分割」のまま。1つのキーは1つの意味)。行の右クリックのメニューは作らない(B-9 の Shift+右クリックは 1 文字起こし のタブの文字の欄の話)
  - 案: 単語の時刻(`transcripts/<id>.words.json`。`serve.py:2322-2356`)から分け目を自動で決める方法もあるが、読む API が無く足すことになる。今回は `doSplit` と同じ比の推定 + 人が直す
- 変えるファイル: `editor/cut.js`・`editor/app.js`(`doSplit` の中身を「行の番号・文字の位置・時刻」で呼べる関数に分けて共用)・`editor/index.html`
- テスト: `editor/tests/e2e_edit_cut.py` に「行を選び再生位置を中ほどに → 分ける → 2行になり文字と時刻が分かれ、保存される・元に戻すで1行に戻る」。1 文字起こし のタブの分割のテスト(`editor/tests/e2e_row_editing.py` などで `doSplit` を使う所)も通す
- リスク・エッジケース: 文字が1文字の行は分けられない(今と同じ)。話者・校正済み・音の状態のメモは両方の行へそのまま写す(`doSplit` と同じ)。校正済みの行を分けたら校正済みのまま(今の `doSplit` と同じ動き)
- 終わりの条件: 2 カット のタブで行を分けられ、1 文字起こし のタブにも同じ結果が出る

### 6-6 B-2d 保存の順番と 409・処理中の鍵
- 今の動き: 文書は `PUT /api/transcript`(`baseUpdatedAt` で 409。`serve.py:751-765`)→ 画面は `#conflictBar`(`app.js:1355-1393`)。編集の内容は `PUT /api/edit`(`baseRev` で 409 `{rev}`。`serve.py:1046-1080` の `save_edit`)→ 画面は `M.conflict` の案内(`cut.js:169-195`)。
  どちらの書き込みも `apply_edit_cuts` を通すので、行のカット済の印は後から書いた方で合う。認識・話者判別の間は文書を鍵で止める(`app.js:798-803` の `lockJob`・`applyLock`)
- 変えること:
  - 1回の操作で両方を書くとき(6-4)は、**編集の内容を先・文書を後**に保存する(文書の保存で `apply_edit_cuts` が新しい区間から印を付けるので、途中で止まっても次の保存で合う)。サーバーに両方を1回で書く API は作らない(下の案)
  - どちらかが 409 になったら、その側の今の案内を出し、もう片方の保存は続ける(片方だけ進んでも、次の読み直しで印は合う)。2 カット のタブで文書の 409 が出たときも、1 文字起こし のタブの `#conflictBar` と同じ内容をカットのタブの上にも出す(今は 1 文字起こし のタブにしか出ない)
  - 文書の保存が競合中(`S.conflict`)・処理中の鍵(`lockJob()`)のときは、字幕の段のつまみと「分ける」を出さない(押せない理由を title に)
  - 案: `POST /api/edit/rows`(`baseUpdatedAt` と `baseRev` を一緒に受けて両方を1つのロックで書く)にすれば半端な状態が無くなるが、画面の文書の保存(0.7 秒まとめて全体を送る)と別の道になり、画面の未保存の文字の直しと食い違う・自分の保存で自分が 409 になる。**今の2つの保存を順に使う**方にする(サーバーは変えない)
- 変えるファイル: `editor/cut.js`・`editor/app.js`・`editor/index.html`
- テスト: `editor/tests/e2e_edit_cut.py` に「別のタブで文書を先に保存 → 字幕の段でドラッグ → 文書の 409 の案内がカットのタブにも出る・区間の保存は進む」「別のタブで区間を先に保存 → 行を広げる → カットの 409 の案内」「認識中は字幕の段を動かせない」。
  サーバーは変えないが、流す: `python -m unittest editor/tests/test_metrics.py editor/tests/test_resolve_export.py -q`・`editor/tests/e2e_ui_mounted.py`・`editor/tests/e2e_edit_tabs.py`・`editor/tests/e2e_edit_pack.py`(行の時刻を直した後の「作り直し」の札)
- リスク・エッジケース: ドラッグ中はカットの保存を送らない(`scheduleSave` の `M.drag`。`cut.js:165`)のと同じく、行のドラッグ中も文書の保存を止める(放してから)。文書を切り替えた・タブを離れたとき(`h.onLeave`。`cut.js:828`)は両方を保存。
  パックの「作り直し」の判定(文書の `updatedAt` と `packRev`。`serve.py:1036-1044` の `get_edit`)は、行の時刻を直すと作り直しになる(意図どおり)
- 終わりの条件: どちらの 409 も今と同じ案内で選べ、保存の失敗で行の時刻や区間を黙って失わない

- 入口・スタジオ・ui-kit は変えない(`home/autorun.py` は `rowEdge` をそのまま渡すだけで変わらない)

## 実機で確かめること
- start.bat で起動し直してから: 語尾が切れていた切り抜きで、パックの詳しい設定の「行の後の余白」を 0.3〜0.4 秒にして、行からのカットのパックを Resolve で聞き比べる
- 手で直したカットでは余白を変えても区間が変わらず、案内が出る
- 2 カット の字幕の段で、ずれている行の終わりを波形に合わせてドラッグ → 1 文字起こし のタブの時刻も変わる・Resolve の Text+ の字幕の出る時刻が変わる
- 長い行を再生位置で分けて、パックの字幕が2つになる
- 2つの窓で同じ文書を開いて、片方で保存してからもう片方で行を動かす(409 の案内)

## 決まったこと(2026-09-29 ユーザー。計画を書いたあとに聞いた分)
- 「行の後の余白」は**無音が見つからないときの決まった余白だけ**を変える(規則と契約テストの既定の場合は変わらない)
- 設定は**後ろだけ**(前の余白 0.1 秒は今のまま)
- 残す行を外へ広げたときは、**残す区間も自動で広げる**(広げたことは知らせる。縮めるときは区間を変えない)
