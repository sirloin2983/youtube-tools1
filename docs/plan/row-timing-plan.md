## 2. 調べたこと(本物の作業データ 122 本を入口の API で読むだけ。確かめ済み 15 本・校正済み 203 行で人の時刻と比べた)
### 2-1 whisper.cpp(large-v3・Vulkan)の時刻が 1 秒単位に丸まる文書がまだ多い(主因)
- 行の境目が整数秒の行は **2,344 行のうち 27%**。半分以上の行が整数秒の文書が **17 本 / 122**(263 行)。`-nfa` を入れたあとの 10-05 23 時のまとめての作り直し(70 本)でも 33%
- 丸まった文書の例 47e38cb99dbe(風真いろは): 機械 `6.00–8.00 / 12.00–14.00 / 14.00–16.00 / 22.00–24.00 …`(14 行すべて)→ 人は `5.40–8.00 / 12.00–13.40 / 13.40–14.50 / 21.50–23.10`。**ずれは最大 1 秒**
- **原因は音声の中身で、フラグやドライバではない**(10-06 に whisper-cli を直接流して確かめた):
  - 同じ文書の音声でも、評価用の flac(仮置きの mp4 から)では丸まらず、済 の mp4 からの wav では全行が丸まる。2 つの wav は同じ(相関のずれ 0・残差 0.1%)= **わずかな違いで丸まるモードに入る**(大きく不安定)
  - `-bs 1`・`-mc 0` の有無・`-nth` の有無・`-tp 0 -nf`・`-sow -ml`・音量 −3/−6 dB は効かない(別の 2 本では全部そのまま丸まる)。先頭に 0.5 秒の無音を足すと**格子が 0.5 秒ずれるだけ**(X.50 に丸まる)= 中身で決まる 1 秒の量子化
  - `--dtw large.v3` のトークンの時刻は丸まらないが人から遠い(始まりの中央 |差| 0.22 秒 vs 予測の時刻 0.10 秒。10-04 の結論と同じ)
  - Silero(faster-whisper の VAD)の声の区間へ寄せると**悪くなる**(始まり |差|>0.3 秒 27% → 39%)。BGM・ゲーム音で声を取りこぼす(「ねー」5.40–8.00 を 5.76–6.18 としか見ない)
  - **faster-whisper(CTranslate2・CPU・large-v3 int8)は丸まらない**(同じ 3 本で整数の境目 1/24・3/50・0/46)。単語の時刻は人の境目に近い(47e38 の 19 の境目のうち 14 は ±0.25 秒。外れたのは faster-whisper が行を落とした所)。40 秒の音声に 23〜29 秒(CPU)。`small` は 4.7 秒で、単語の時刻は ±0.2 秒が多いが 0.4〜0.8 秒の外れが数か所
### 2-2 丸まっていない文書の残りのずれ(校正済み 182 行)
- 始まり: 機械が 0.3 秒以上**早い** 28 行(15%。うち無音のあと 6 行 = 先頭 0.00 から始まる行が声の 3〜4.6 秒前から出る)・遅い 19 行・±0.3 秒以内 135 行
- 終わり: 機械が 0.3 秒以上**早い 39 行(21%)**・遅い 5 行・±0.3 秒以内 138 行。**人は字幕の終わりを機械より後ろに直している**(平均 +0.15 秒)。10-05 の「行末を 0.1 秒早く」は「この行だけ再生」で聞くための目安で、字幕として直すときは逆の向きになっている
- すき間: 人は続いている行を**くっつける**(人の行の 31% がすき間 0・22% が 0.01〜0.15 秒)。機械は `trim_ends` で必ず 0.1 秒あける(51% が 0.01〜0.15 秒)= 字幕が一瞬消えてまた出る

## 4. A の作り(実装するときの形。確認のあと)
1. `ed_jobs.expand_segments` のあと(whisper.cpp のときだけ)に、窓ごとの「整数の境目の割合」を数える(`start`・`end`・`end + END_TRIM` が ±0.011 秒で整数)。4 割以上の窓を「丸まった窓」とする
2. 丸まった窓の音声を、ワーカーの中で faster-whisper(`device=cpu`・`large-v3`・`word_timestamps=True`・`condition_on_previous_text=False`・`vad_filter=False`)に流し、単語(start・end・文字)を取る。CPU の重い処理なので `ytt_core/jobs.py` の SLOTS を通す。モデルが無ければ取得(入口の API 経由で本物の作業データへ)
3. 行ごとに `ed_retime` の当て方(行の文字 ↔ 単語の文字の fitting alignment。`alt_fold` で寄せる)で始まり・終わりを決める。当たらない行(文字の 6 割未満)は今の時刻のまま。前後の行と重ならない所まで詰める
4. words.json はその窓だけ faster-whisper の単語に置き換える(あとの「分け直す」「時刻を単語に合わせる」が良い単語を使えるように)
5. `recognition.runs[].post` に `retimed: {windows, rows}` を残す。測る道具(`eval_asr.py`・`ed_alt.run_alt`)も同じ後処理を通す(0.52.1 の決まり)
6. テスト: `test_whispercpp`(丸まりの判定・当て方)・`dev/tests/test_eval_asr`・e2e_drill(1 本ずつ作り直し)。測り直し: 確かめ済み 15 本で 2-2 の表(前 → 後)

## 7. 原則(2026-10-07。`../spec/row-timing-policy.md`)に沿った直し方の計画(**まだ実装しない**)
ユーザーの原則: ① 発言が区間に収まる > ② 前後の発言を入れない > ③ 喋っていない時間を除く。
確かめ済み 22 本(校正済みで文字が合う 255 行。保存してある機械の出力)で、直し方ごとに原則の数字を試算した(人の行を正解に。原則の文書の「測り方」):

| 直し方 | ①頭が切れる | ①末が切れる | ②前が入る | ②次が入る | ③はみ出し(平均) |
| --- | --- | --- | --- | --- | --- |
| 今(END_TRIM 0.1 あり) | 20% | **34%** | 13% | 6% | 0.46 秒 |
| 7-1 END_TRIM をやめる | 20% | 27% | 13% | 7% | — |
| 7-2 前の行の終わりを次の行の始まりへ(すき間 0.3 秒以下) | 20% | 21% | 13% | 10% | 0.51 秒 |
| 7-2 同(すき間 0.5 秒以下)**← 採る案** | 20% | **20%** | 13% | 10% | 0.51 秒 |
| 参考: 次の行の始まりを前の行の終わりへ(逆向き) | 15% | 34% | **23%** | 6% | 0.54 秒 |
| 参考: 境目を真ん中に | 16% | 30% | 20% | 7% | 0.52 秒 |

読み方: 7-2 は ① を 13 pt 良くして ② を 4 pt 悪くする = 原則の順位どおり。逆向き(始まりを前へ)は ①頭 を 5 pt 良くする代わりに ②前 を 10 pt 悪くするので採らない。
①頭 20% の内訳は、すき間のあとの行 5 / 48・続いている行 45 / 207 = 続いている行の境目で機械が人より遅く始まる。7-2 では直らない(境目をどちらへ動かしても ① か ② が崩れる)。
単語の時刻が正しい所では `split_segment`・配り直しが境目を言葉に合わせるので、ここは 1 秒丸めと認識の揺れの問題(6)。

### 7-1 `END_TRIM` を 0 に(既定でやめる)
- `editor/ed_jobs.py` の `END_TRIM` の既定 0.1 → 0(環境変数 `TRANSCRIBE_END_TRIM` は残す = 戻せる)。`quant_is_int` は END_TRIM を足した値も見ているので 0 でも動く
- テスト `tests/test_whispercpp.py` の `test_trim_ends`(既定 0.9 → 1.0)・`test_expand_segments_whole_flow`(1.88 → 7-2 のあとは 2.0)。README の v0.53.1 の説明に「0.57.1 でやめた」を足す

### 7-2 続いている行の終わりを次の行の始まりへ延ばす(`join_rows`。全エンジン)
- `expand_segments` の最後(trim/pull のあと)に `join_rows(rows, JOIN_GAP=0.5)`: 0 ≤ 次の始まり − 前の終わり ≤ 0.5 秒 なら 前の終わり = 次の始まり。縮めない・重なりは触らない・最後の行はそのまま・単語は変えない
- 配り直し `quant_retime` の中でも、窓の行(idx)に同じ `join_rows` をかける(配り直しで新しくすき間ができるため)
- 範囲・全体の再認識は `finish_range_lines` → `expand_segments` なので自動で通る。疑わしい所の認識し直し・2 つ目のエンジンの候補は時刻を使わないので通さない
- 画面: 「この行だけ再生」は次の行の頭を少し含むようになる(1 を優先した結果。校正で気になれば `TRANSCRIBE_JOIN_GAP=0` でやめられるようにする)
- テスト: `JoinRowsTest`(0.5 以下はつなぐ・0.5 超はそのまま・重なりはそのまま・最後の行・単語の不変・faster-whisper でも効く)

### 7-3 配り直しの重なりの詰め方の見直し(原則 1 の観点)
- 今: 「あとの行の始まりを信じて前の行の終わりを詰める」= 前の行で ① を崩すことがある(6 の さくらみこ 783157af3200 で終わりが悪くなった例)
- 案: 候補の端(始まり・終わり)が隣の行の候補と重なるときは、**その端だけ採らない**(今の時刻のまま)にして、7-2 の join に任せる。言葉の端を聞き直した単語で「切る」方向(①)には動かさない
- 数字で決めるのは 1 秒丸めの文書が校正でたまってから(今は n=10)。7-1・7-2 と一緒に実装してよい(変更は小さい)
