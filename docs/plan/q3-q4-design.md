# Q3 自動の測定・Q4 評価ドリルと定点 の実装の決めごと(2026-10-04 Claude Code + Fable)

> **状態(2026-10-04): 実装中**。上の計画は `docs/plan/master-plan-2026-10.md` の Q3・Q4。ここは実装の細部の決めごと(Fable と相談して決めた)。

## (a) 自動の測定(Q3)
- 置き場所: 入口の新しい見張り `home/accuracy.py`(`home/backup.py` と同じ形: 設定の節 `accuracy` {enabled, nightFrom: 1, nightTo: 6}・`_loop` / `tick` / `snapshot`・記録 `app/accuracy-state.json`)。
- 測る道具(dev/eval_*.py)は**子プロセス**で呼ぶ(`sys.executable`・優先度は通常より下・黒い画面なし・時間切れあり)。
  理由: `eval_asr.load_serve` は serve.py を別名で読み、環境変数(作業データの場所)を書き換えるので、入口の中で import できない。ほかの道具も形をそろえる。編集のサーバーには置かない(盛り上がり・カットはスタジオ・cut2resolve のデータ)。
- 結果: 各道具は今どおり `<ツール>/evals/<領域>/` に保存。入口は最新 2 件の要約だけを state に写す(文字起こし: CER・95% の範囲・文書数・文字数 / 盛り上がり: 上位 10 の採用率・見逃し率 / 話者・カット: 道具の要約の鍵を足すだけ)。
  「調子」の画面に「精度」の行を領域ごとに「直近 x(前回 y)・日時・文書数」。文書数 2 未満は「まだ少ない」。
- 手が空いた判定: 入口の SLOTS に動いている・待っているものが無い・編集の `/api/jobs` に動いているジョブが無い・文字起こしの文書の最後の更新が 30 分以上前・夜の窓(1〜6 時)か「今すぐ」ボタン。軽い測定は 1 日 1 回。
- **重い測定(認識し直しての比較)は今回入れない**(分岐と `heavyEnabled: false` の箱だけ)。定点が 0 分・GPU のモデルが未取得で、エンジンの決定(I-1a)は手で `eval_asr run` を回す方が先。
  入れるときは: 入口が SLOTS を 1 つ持って子プロセス、条件 = 前回から評価用の校正済みの秒が +5 分 かつ whisper.cpp が使える。

## (b) 夜のまとめての文字起こし(Q4)
- 編集側の見張り `editor/ed_evalbatch.py`(`ed_evalaudio` と同じ形: 裏のスレッド・忙しいときは待つ・ファイルのロック)。既存のフォルダ一括(一度に全部を入れてユーザーのジョブが後ろに並ぶ)は使わない。
  評価用_仮置き と「未文字起こし」の動画から、文字起こし済み・動いているものを除いた分を**待ちが 2 件までになるよう少しずつ**入れる(ユーザーの操作が割り込める)。
- 評価用の印・ヒントなしは、`validate_job` が評価用のフォルダの中の動画に付ける既存の規則で保証(evalSet も明示)。GPU は編集の設定(処理方式)のまま。
- 始め方は**ボタン**(⚙ の評価用のフォルダの隣「仮置きをまとめて文字起こし(手が空いたとき少しずつ)」→ `POST api/eval-batch/start|stop`・`GET api/eval-batch`。処理状況に 1 行)。
  360 本は CPU で数時間。PC を点けておくかはユーザーの判断。止めるまで続く(起動し直しても `eval-batch.json` の enabled で続く)。夜間の自動開始はしない。

## (c) 評価ドリル(Q4)
- 別ページ `editor/drill.html` + `drill.js` + サーバーの部品 `ed_drill.py`(簡易版 lite.html と同じ配り方・CSP)。編集の画面は 1 文書をまるごと保存する作りで、20 文書 × 1 行と相性が悪いため。ホームと編集の「精度」からリンク。
- 選び方: 評価用(evalSet)の文書だけ(目的が定点)・文字あり・未校正・聞き取れない印なし・直近 10 分に更新した文書は除く(開いている可能性)。乱数で 20 行・同じ文書から最大 2 行。
  `GET api/drill/pick` が行・文書の updatedAt・話者の一覧・候補の名前を返す。再生は既存の `/media`(開始・終了)。
- 保存は行ごと `POST api/drill/row {id, rowId, baseUpdatedAt, text, speaker | speakerName, tags, proofed: true}`: 保存のロックの中で読み、updatedAt が違えば 409(ドリルは「別の所で変わった」と飛ばす)、行だけ差し替え・proofedAt = 今・校正の手間・履歴を残す・**updatedAt を上げる**(開いている編集の画面の次の保存を既存の 409 の案内に乗せる。上げないと古い保存で消える)。新しい名前は話者の一覧に足す。
- 定点の「あと何分」`GET api/drill/status`: 評価用の校正済みの秒 → 900 秒(15 分)の残り。条件(全行校正済みの文書で): 話者 = 一般の名前でない名前の種類(4 以上)・配信 = 配信の ID か動画のフォルダ(メンバー)の種類(3 以上)・重なり / BGM = 印の秒(各 30 以上)・呼び名 = 名簿に当たる行(10 以上)。ドリルの上と進み具合のカードに出す。
- 「全行をこの人に」: 既存の `single_speaker`(diar.json も書く)をそのまま使う。話者のカードに候補の選択とボタン(評価用で話者の無い行があるとき)。候補 = 覚えた声 → メンバーのフォルダの名前 → 配信の文脈。
