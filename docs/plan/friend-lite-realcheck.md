# 友人用 文字起こし簡易版: 実機で確かめてもらうこと(Resolve)

> 状態(2026-10-02): **確認待ち**(ユーザーの PC の DaVinci Resolve で)。計画は `docs/plan/friend-lite-plan.md`。
> 結果は WORKLOG に「実機の確認」として書き、ずれがあれば Claude Code に伝えてください(直すのは `cut2resolve/resolve_textplus.py`)。

## 何を確かめるか
1. **60fps の横動画を 30fps の Resolve プロジェクトで使ったとき、字幕が声とずれないか**(ブリーフのエッジケース)
2. 簡易版の字幕の見た目(型 `lite`): MS ゴシック・大きさ 0.08(仮)・位置・話者ごとの文字の色とふちの色が入るか
3. 記号([?]・[笑])が字幕に出ないこと・記号だけの行が字幕にならないこと

## なぜずれる可能性があるか(仕組み)
- 字幕の時刻は文書では秒で持ち、パックを作るときに**動画のコマ**(60fps なら 1 秒 = 60 コマ)に直して Lua に埋め込む
- Resolve のタイムラインは 30fps(1 秒 = 30 コマ)。Lua は「置いたクリップの位置からの相対」で字幕を置き、動画のコマ → タイムラインのコマを比(30/60)で直す(`resolve_textplus.caption_segments` と Lua の `ratio`)
- 比の丸めで 1 コマ(30fps で約 0.033 秒)ずれるのは想定内。それより大きい・時間とともに広がるずれは不具合

## 手順(15 分くらい)
1. 見本の動画を作る(コマンドプロンプトで。声の代わりに 1 秒ごとの「ピッ」と画面の時計が入る 3 分の動画):
   ```
   ffmpeg -f lavfi -i "testsrc2=size=1920x1080:rate=60:duration=180" -f lavfi -i "sine=f=1000:d=180,volume='if(lt(mod(t,1),0.1),1,0)':eval=frame" -vf "drawtext=text='%{pts\:hms}':fontsize=96:fontcolor=white:x=40:y=40:box=1:boxcolor=black" -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest %USERPROFILE%\Videos\lite-60fps-check.mp4
   ```
   (drawtext で止まるときは `-vf "..."` を外す。testsrc2 にもコマの番号が出ます)
2. `lite\start.bat` で簡易版を開き(まだ無ければ入口の http://localhost:8700/transcribe/lite.html)、その動画を選ぶ。配信者は誰でもよい
3. 文字起こしのあと、校正の画面で次の3行を直して確認済みにする(ほかの行はそのままでよい):
   - 0:10.000〜0:12.000 の行に「十秒」(行の時刻を「今の位置を開始/終了にする」で合わせる)
   - 1:30.000〜1:32.000 の行に「九十秒 [笑]」(行が無ければ足す)
   - 2:50.000〜2:52.000 の行に「[?]」だけ
   - 話者を2人にし、2人目の色を「水色 + 紺ふち」にして 1:30 の行に付ける
4. 書き出す → 開いたフォルダの隣の `Resolve用ファイル` を見る
5. Resolve で **新しいプロジェクトを 30fps・1920x1080** で作る(プロジェクト設定 → マスター設定 → タイムラインのフレームレート 30)
6. `Resolve用ファイル\ResolveにText+スクリプトを登録.bat` を実行 → Resolve のメニュー「ワークスペース → スクリプト」から登録したスクリプトを実行(`Resolveでの手順.txt` のとおり)
7. できたタイムライン `CUT_TextPlus` で確かめる:
   | 見る所 | よい状態 |
   | --- | --- |
   | 0:10 の字幕「十秒」の出始め | 画面の時計 00:00:10.0x と同じコマ(±1 コマ) |
   | 1:30 の字幕「九十秒」(記号なし) | 時計 00:01:30.0x と ±1 コマ。**10 秒の所と比べてずれが広がっていない** |
   | 2:50 の [?] だけの行 | 字幕が無い |
   | 1:30 の字幕の色 | 水色の文字・紺のふち |
   | ほかの字幕 | 黄色の文字・黒いふち・MS ゴシック・画面の下の方に収まる大きさ |
   | タイムラインのマーカー | 緑(黄色ならメモに理由。フォントが無い・値が入らなかったなど) |
8. 結果を書く: 各行の「よい / ずれた(何コマ)」と、字幕の大きさ・位置の感想(0.08 が大きい・小さい)。写真があると助かります

## ずれたときに Claude Code が見る所
- `cut2resolve/resolve_textplus.py` の `caption_segments`(動画のコマ)と Lua の `ratio`(タイムラインのコマへの換算)
- 大きさ・位置: `TEXT_STYLE_LITE` の `Size`(0.08 は仮)・`VerticalTopCenterBottom`
- ふちの色が入らない: Lua の `cap.outline` の `outlineN`(要素 2)と、マーカーのメモの「読み替え」
