### 直さなかったもの(理由)
- ③ の「操作の設定」の保存は `GET /api/settings` → `PUT`(全体)なので、別のタブで同時に変えると片方が消えうる(低)。サーバーに部分更新の API が無いため、画面だけでは直せない → サーバー担当への提案。
- 起動直後、設定の読み込み(1秒未満)が終わる前に変えた ③ の設定は、読み込んだ値で上書きされる(低)。実害が小さく、直すと保存の順番の管理が複雑になるため見送り。
- マークの行の「書き出し先」は出力先フォルダからの相対パスで、出力先を変えたあとは元の絶対パスが分からないため、**マークの行には受け渡しのリンクを出していない**(書き出しの一覧にだけ出す)。サーバーがマークに絶対パスを持てば出せる → 提案。
- 既存の `e2e_review.py`(手で見る用のサーバー)は変えていない。新しい `e2e_ui.py --serve` が上位互換(自動マーク・グラフ・コラボ・事務所の登録つき)。

## 3. 追加した機能と使い方
- **書き出した切り抜きを他のツールへ**(③ の書き出しの一覧、完了した行): 「文字起こしで開く」= `UIKit.tools.url('transcribe', ports, '/?media=' + encodeURIComponent(mp4 のパス))`、
  「Resolve 用に渡す」= cut2resolve の `/?video=`、「パスをコピー」。`.clip.json` のパス(`manifest`)があれば「.clip.json あり」の印。
  mp4 の絶対パスは、サーバーが各ファイルに `path`(または `mediaPath`)を入れていればそれを、無ければジョブの `outDir`(書き出し開始時の出力先)+ `file`(相対)から組み立てる。
  どちらも無い(絶対パスが分からない)ときはリンクを出さない。Windows のパスなら区切りを `\` にそろえる(単体テストあり)。**URL だけでは相手のツールは処理を始めない**(docs/pipeline.md 3.)。
- **`?url=` の受け取り**: `http://localhost:8800/?url=<YouTube URL>` で開くと ② 解析の URL 欄に入れ、お知らせを出して「解析に追加」にフォーカスする。自動では始めない(e2e で確認)。
  受け取ったあとアドレスから `?url=` を消す(再読み込みで二重に入れないため)。
- **キー操作の一覧**: ヘッダーの「キー」か `?` キー。③ のいまの割り当て(カスタムも反映・今をマークの長さつき)を表示。`Esc` で閉じる。③ で `?` を別の操作に割り当てた場合はそちらが優先。
- **設定の引き出し**: ヘッダーの「設定」(歯車)。右から出るので、③ の作業中でも画面を移らずに出力先などを変えられる。API キーが無いときは歯車に印。`Esc`・背景のクリックで閉じる。
- **他のツール**: `GET /api/siblings`(`{"tools": {...}}`)の実際のポートでリンク。404・失敗なら既定のポート。メニューを開くたびに確かめ直し、応答に載っていない(起動していない)ツールは灰色+「起動していないようです」。
- そのほか: 書き出し全体の進み具合のバーと、行ごとの進み具合、折りたたんだ書き出し欄の見出しに「書き出し中 2/5件」、プレーヤーの「準備しています…」、
  各画面の読み込み中(スケルトン)・空の状態の案内、通知の色分け(成功=緑・失敗=赤、クリックで閉じる)、② の URL 欄で Ctrl+Enter / パス欄で Enter で追加、
  ① のワード欄で Enter で検索、④ のアンカーの欄で Enter で保存・開いたら最初の欄にフォーカス、保存の状態の表示(何もしていないときは「自動保存」)。

## 4. 見た目の刷新(配置の判断と理由)
- **ヘッダー**: ui-kit の `ui-header`。狭い画面(〜1100px)ではヘッダーの右のボタンをアイコンだけに、720px 以下ではタブを2段目に・③ のタブ名を「確認」に短縮。
  ヘッダーの高さを実測して CSS 変数 `--cs-head` に入れ、sticky の位置(① の選択バー・② のキュー・③ の右列)を合わせている(タブが2段になっても重ならない)。
- **設定を「引き出し」にした理由**: 以前はページ上部の折りたたみ。モーダルの `<dialog>` にすると最上位のレイヤーに乗るため、事務所の登録中に出る通知(トースト)が背景の下に隠れる。
  そこで固定配置の引き出し+背景に `inert`(裏の画面を操作できない・通知は見える)にした。ui-kit に引き出しの部品が無いので app.css に `cs-drawer` として実装(ui-kit への要望)。
- **① 探す**: 条件を「期間・ワード」「一致・探す場所・表示本数・最低再生数」「切り替え」「事務所(チップ)」の段に整理。結果は事務所ごとのカードに表。
- **② 解析**: 「入れる+設定」と「キュー」を左右2列(1000px 未満は縦)。キューは画面の高さに収めて中だけスクロール。状態は左の丸(実行中は脈打つ)と色分けの印。
  解析の設定は「見出し+入力+補足」の格子に(以前は長い説明が括弧で1行に入っていた)。
- **③ 確認・書き出し**(情報密度を優先): 左=動画・タイムライン(+グラフ・再生操作を1枚にまとめた)・今をマーク・IN/OUT/追加/遅れ補正を1段・操作の設定(折りたたみ)。
  右=書き出し(折りたたみ可)+マーク一覧。**右の列を画面の高さに収めて sticky にし、一覧だけがスクロール**する(以前は左の列を sticky にしていたが、左が画面より高いと下が見えなくなるため)。
  タイムラインの色: 候補=`--warn`、自動の候補=`--c-4`、採用=`--ok`、不採用=薄い灰、書き出し済み=灰。グラフの線は ui-kit の `--c-audio / --c-chat / --c-com`(e2e で一致を確認)。
  シアター表示では「今をマーク」を右の列に移し、狭いので長さの − ＋ を隠す(長さは「操作の設定」のキー配置でも変えられる)。
- **④ コラボ**: 左=動画の選択(カード型のチェック)、右=グループ。アンカーの入力は「点1 / この動画 / 基準」の格子。
- 新しいクラスには接頭辞(`cs-`、④ は `cl-`、③ は既存の `rv-`)。JS・テストが使う id・既存のクラスは変えていない(③ の絞り込みボタンは `btn small` → `ui-seg` の子に変えたが、JS は `data-filter` で参照)。

## 6. 未確認のこと・リスク
- **Windows 実機(Chrome / Edge、Segoe UI・Yu Gothic UI)での見た目**は未確認(サンドボックスは Linux の chromium と別のフォント)。文字幅の違いで折り返しが変わる可能性がある。
- Playwright の chromium は H.264 を再生できないため、e2e の動画は webm にした(実際の Chrome / Edge は mp4 を再生できる)。**実際の YouTube 埋め込み**は未確認(オフライン)。
- 「パスをコピー」は `navigator.clipboard`(localhost は安全な場所として扱われる)→ だめなら `execCommand('copy')`。Windows の Edge で未確認。
- `/api/siblings` と書き出しの `path` / `manifest` はサーバー担当が実装中。現時点のサーバーでは siblings は 404(既定のポートで動く)、パスは `outDir` + `file` から組み立てて動く。
- `inert` 属性(設定の引き出し)は Chrome/Edge 102 以降。古いブラウザでは裏の画面も押せるだけで、壊れはしない。

## 7. ユーザーに判断してほしいこと(安全な既定で進めた)
1. **③ の前/次のマークを「一覧の並びどおり」にした**(点数順で表示しているときの動きが変わる。時刻順では従来どおり)。コードのコメントの意図に合わせたが、時刻順のままがよければ戻せる。
2. **設定を右の引き出しに**した(以前はページ上部の折りたたみ)。
3. 強調色は ui-kit 共通の紫にした(以前のスタジオはピンク)。スタジオらしさはブランドのアイコン(ピンク→紫)で出している。ピンクにしたい場合は app.css で `--accent` を上書きできるが、3ツールでそろえる方針なので既定は共通色。
4. ④ の「グループから外す」を2回押しに、空欄で API キーの「保存」を押したときは何もしないようにした。
5. `?url=` を受け取ったら、アドレスから `?url=` を消す(ブックマークや再読み込みで二重に入れないため)。

## 8. ui-kit への要望
- `.badge` がダークで「明るい赤に白字」(コントラスト 2.7)。ダークでは暗い字(例 `color: var(--bg-2)`)に。スタジオは app.css で上書き中。
- `.empty` は汎用的な名前なので、ツール側の状態クラス(`is-empty` の代わりに `empty` を使っていた)とぶつかった。`ui-empty` のような接頭辞付きの名前にするか、README に注意を書く。
- **引き出し(ドロワー / シート)**の部品。モーダルの `<dialog>` だとトーストが隠れるので、固定配置+`inert` の形がよさそう(スタジオの `cs-drawer` / `cs-scrim` を正本に持っていける)。
- トーストの種類(ok / err / info の印)。スタジオは `.toast.ok` などを app.css に実装。トーストは両テーマで常に暗い面なので、印の色は固定色にしている。
- `ui-menu`(他のツール)の「外側をクリック / Esc で閉じる」動作を ui-kit.js に。スタジオは core.js に実装。
- `UIKit.tools.render` に「起動していないツール」の表示オプション(ports に無いツールを灰色に)。スタジオは描画後に手で足している。
- 入力欄の「見出し+部品+補足」の縦の単位(スタジオの `cs-opt`)と、ヘッダーの高さを CSS 変数で配る仕組み(sticky 用。スタジオは JS で `--cs-head` を実測)。

## 9. 他の担当に伝えること
- **サーバー担当(clip-studio backend)**: 画面は書き出しジョブの各ファイルの **mp4 の絶対パスを `path`(次に `mediaPath`)**、`.clip.json` のパスを **`manifest`(文字列)** で読む。
  無ければ `outDir` + `file` から組み立てる(`outDir` が絶対パスのときだけ)。フィールド名が違う場合は review.js の `clipPathOf` / `handoffHTML` を合わせる。
  `/api/siblings` は `{"tools": {"studio": 8800, ...}}`(載っていないツールは起動していないと表示)。提案: マークにも書き出したファイルの絶対パスを持たせる(マーク行から受け渡せる)、`/api/settings` の部分更新(`review` だけ等)。
- **文字起こし担当**: スタジオからは `/?media=<encodeURIComponent(mp4 の絶対パス)>` で開く。Windows のパスは `\` 区切り(例 `C:\Users\...\exports\動画\01_....mp4`)。
- **cut2resolve 担当**: スタジオからは `/?video=<mp4 の絶対パス>` で開く。
- 画面の API 呼び出しは `Studio.api` に集約し(③ の保存も含めた)、メディアの URL も `Studio.url` を通す。統合時は core.js の `Studio.base` を変えれば移せる。
