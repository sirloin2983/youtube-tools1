# 改善提案の実施状況(2026-09-20 時点)

提案8項目のうち、ユーザーが「簡単にできるものだけ実装」と指定した 1・3・4・5・7 の扱い。

## 実装済み
- **1. 再解析の高速化(auto-clip v0.2.0)**: 音量の解析結果(長さ・全帯域・2kHz以上の1秒ごとのdB)を cache/signals/<動画ID>.json に保存(最新30本)。同じ動画で感度・長さ・山の位置・重みを変えて再解析するとき、ダウンロードと ffmpeg をやり直さない(チャットは v0.1.1 から別キャッシュ)。保存時に0.1dBへ丸め、初回の解析にも同じ丸めを適用して「キャッシュの有無で結果が変わらない」ことをテストで確認。キャッシュの検査(形式・長さの整合・値の範囲)に外れたら無視して再解析。配信中・配信直後の動画は長さが変わるため、「キャッシュを使わない」チェックを用意
- **3. 判定の記録(一部)**: 候補ごとの「○ よかった / × ちがう」(再度押すと取り消し)を feedback.jsonl に追記(動画ID・区間・ピーク・点数の内訳・材料の使用状況・設定のみ。パス等は含めない。5MB超で .old に退避)。POST /api/feedback
- **5. stream-rank → auto-clip(stream-rank v0.1.2)**: 各行に「この配信を切り抜く」リンク(http://localhost:8795/?url=…)。auto-clip は ?url= を受けて URL 欄に入れる(自動開始はしない。URL自体はサーバー側で従来どおり検証)。ポートが標準でないときは手でアドレスを直す
