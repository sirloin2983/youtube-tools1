# 文字起こしの精度向上計画(2026-09-24 改訂・文字起こしツール v0.9.8 時点)

条件: PC は変えない(GPU は AMD Radeon RX 7800 XT。CUDA は使えない)。運用費はできるだけ抑える。最初の評価・学習の段階だけは多少の費用を許容する。
方針(ユーザー案を採用): **クラウドは「毎回使う認識エンジン」ではなく「初期の比較と、たまの点検に使う測定器」**。最終的な外部課金は 0 円、残るのは電気代だけにする。
共通ルール: どの施策も評価用(学習・辞書に使っていない動画)で測り、勝ったときだけ採用する(`eval-set-procedure.md`)。

## 段階0: 完全無料で基準を作る(API 0 円・最初の1〜2回)
今ある校正済みデータで次を測る。目的は「どの種類の音声にお金(と手間)を使う価値があるか」を決めること。
- 現在の文字誤り率(CER)→ 既存の「認識精度の測定」で出る
- 人物名・固有名詞の誤り → 既存の「用語が正しく出た率」(用語集・辞書の語)。名前ごとの内訳は未実装
- 小声・重なり・BGM 区間の誤り → 「声が重なる」「BGM・音が大きい」のメモ(X/C/V)ごとに CER を分けて集計する(未実装)。
  **小声は印が無い** → 保管済みの行の音声(dataset/)から音量を計算して、音量の低い行を自動で分類する
- 信頼度と実際の誤りの関係 → **注意: 今の保存形式には信頼度(avg_logprob など)が残っていない**(「要確認: 自信が低い」の印の有無だけ)。
  今すぐ測れるのは「印あり/なし」での CER の差まで。連続値で測るには、(1) 今後の文字起こしで original に avg_logprob・no_speech_prob・compression_ratio・単語の確率を保存する、
  (2) 既存分は「設定の比較(A/B)」の再認識時に信頼度も記録する、のどちらか(両方やる)
- large-v3 と turbo の差 → 既存の「設定の比較(A/B)」で出る。anime-whisper(感情のこもった声・笑い・叫びに強い。用語集のプロンプトは入れない)も候補に足す
- 統計の注意: 数千〜1万字程度だと、CER の差が 1 ポイント未満なら誤差の範囲のことが多い。同じ行どうしで比べる

## 段階1: 初期比較だけクラウドを使う(一回限り 約100〜500 円・3〜5回)
難所を合計 30〜60 分切り出して(通常会話・小声・叫び声・笑い声・重なり声・BGM が大きい場面・固有名詞が多い場面)、
ローカル large-v3 / ローカル turbo / クラウド ASR 1種類 / 人の正解 を比べる。
- クラウド ASR の料金(2026-09 時点、OpenAI): gpt-4o-transcribe $0.006/分($0.36/時 ≈ 57 円/時)、gpt-transcribe $0.0045/分(≈ 43 円/時)、
  gpt-4o-mini-transcribe $0.003/分(≈ 29 円/時)。1ドル=158円前後で計算。30〜60分 × 3〜5回でも数百円に収まる
- OpenAI API に送った音声は、既定では学習に使われない。/v1/audio/transcriptions は乱用監視のための保存も「なし」(Zero Data Retention の対象)
- 注意点:
  - クラウドの文字起こしは、「えっと」などのつなぎ言葉を消したり、言い回しを整えたりしがち。人の正解(字幕の書き方)と揃わない分が「誤り」に数えられるので、
    比べる前に「つなぎ言葉・数字の書き方(漢数字/算用数字)を正解にどう書くか」を決め、比較のときは両方を同じ規則で正規化する
  - gpt-4o-transcribe は単語ごとの時刻を返さない(行単位で送るので問題は小さい)。1回 25MB まで。`prompt` に用語を渡せる
  - クラウドの結果は、人が確認するまで正解データ(学習用)に入れない(別のモデルの推測にすぎない)
- ここで決めること: ローカルだけで十分な条件 / クラウドへ送る信頼度の境界 / 誤認識しやすい人物名 / 再認識で直る音声と直らない音声 / 音源分離を使うべき条件

## 段階2: クラウドを難所だけに制限(移行期間・約5〜20 円/入力音声1時間)
turbo で一次認識 → 信頼度が低い区間だけ large-v3 → それでも不一致ならクラウド。送る量は全体の 5〜10%(1時間の動画で 3〜6 分)。
送信の制限: 1区間 最大30秒 / 1動画 最大5分 / 1日 最大50円 / 月の上限 300〜500円 / 上限に達したら完全ローカル / 同じ音声は二度送らない / 手動承認式も選べる
- 実装の注意:
  - 料金は「送る前に」音声の長さ × 単価で見積もって台帳(ローカルの JSON。月ごと)に記録し、上限を超えるなら送らない(送ったあとに数えると、同時に送ったときに上限を超える)
  - API キーはローカルの設定ファイル(git 管理外。config.json は .gitignore 済み)か環境変数に置く。ログ・画面・書き出しに出さない
  - 「同じ音声」の判定は、16kHz にそろえた音声のハッシュ(sha256)+モデル名+設定で行う。結果をキャッシュして、用語集や表示を変えただけでは認識をやり直さない

## 段階3: 通常運用を完全ローカル化(API 0 円・電気代 約5〜30 円/入力音声1時間)
初期の修正結果を、ローカルの資産として蓄積する: 人物別の名前・愛称 / ゲーム別用語集 / よくある誤認識と正解の組み合わせ / 話者ごとの口癖 /
チャンネル固有の言葉 / 前回までの字幕 / タイトル・概要欄・チャット・画面の文字(OCR)。
例: 誤認識「ふぶき」→ 候補「フブキ」「吹雪」→ 登場人物に白上フブキ → 採用「フブキ」。これをクラウド LLM ではなく、ローカルの規則と候補のスコアで反映する。
- すでにある土台: 置換辞書(「|語|」で語の途中に当てない指定あり)、修正から学習した候補(回数・却下の記録つき)、用語集の自動追加、ホロライブの名簿
- 足りないもの: 動画ごとに効かせる用語集(認識に渡るのは先頭約150字/ホットワード約300字までなので、その配信に出る人だけに絞る)、ゲーム別・人物別の束、
  タイトル・概要欄・チャットからの語の取り込み(yt-dlp でタイトル・概要欄・チャットのリプレイは取れる。切り抜き系のツールで使用実績あり)
- 定常運用: 通常区間 turbo / 低信頼区間 large-v3 / 重なり声はその区間だけ音源分離 / 固有名詞はローカル用語集 / 文章の整形はルール / クラウドは標準で無効
- 電気代の目安: PC 全体で 300〜400W 前後、家庭用の電気代の目安単価 31 円/kWh として、処理に 0.5〜2 時間かかる量で 5〜25 円程度(処理時間しだい)

## 段階4: コラボの複数視点は必要な区間だけ処理
メイン視点だけ全体を認識 → 聞き取れない時間を検出 → その時間だけ別視点の音声を切り出す → 別視点で再認識。4時間・3視点でも、別視点を全体の10%だけ使えば追加は48分程度。
- 補足(今後のため):
  - **別視点は「タダの音源分離」になる**: 重なり声の場面でも、各配信者の配信ではその人のマイクの声が一番大きく、きれいに入っている。
    重なり声は音源分離より、発言者本人の視点で聞き直す方が有効なことが多い(話者判別の結果と組み合わせて「誰の視点を使うか」を決める)
  - **時刻合わせが必要**: 視点ごとに配信の開始時刻・遅延が違い、途中でずれることもある(配信の遅延・コマ落ち)。共通して聞こえる声で、該当区間の前後数十秒を相互相関して毎回合わせる
  - ダウンロードは必要な区間だけ(yt-dlp の区間指定)にして、時間とディスクを節約する
  - 切り抜きスタジオのコラボ用の仕組み(`collab-mark-spec.md`)と情報(どの配信がどのコラボの別視点か)を共有する

## 段階5: クラウドは保守点検専用(月 0〜100 円程度)
使うのは、新しいゲームを始めた / 新しい出演者が増えた / マイク・録音の設定が変わった / ローカルのモデルを更新した / 誤り率が悪化した / 月1回の代表サンプルの比較、のときだけ。

## 費用のまとめ(ユーザー案)
| 段階 | API 費用 | 電気代 | 合計 |
|---|---|---|---|
| 初期評価 | 一回 100〜500 円 | 数十円 | 100〜600 円 |
| 移行期間 | 5〜20 円/時 | 5〜30 円/時 | 10〜50 円/時 |
| 安定運用 | 0 円 | 5〜30 円/時 | 5〜30 円/時 |
| 保守点検 | 月 0〜100 円 | 数十円 | 月 0〜150 円程度 |

電気代も削る処理の順番: VAD で無音を除く → turbo で一次認識 → 確信度が高い区間は終了 → 不確実な区間だけ large-v3 → 重なり声だけ音源分離 → 別視点も該当時間だけ。
「全区間を large-v3 で2〜3回」「全視点を毎回認識」を避ける。中間結果は音声ハッシュ単位で保存する。

## 推奨する着地点
- RX 7800 XT で Whisper をローカル実行 / turbo → large-v3 の段階認識 / クラウドは初期3〜5回だけ・以後は標準で無効(明示的なボタン操作に限定、月の上限は 0 円か 100 円)
- 人物・ゲーム別の用語集を修正履歴から自動生成 / 複数視点と音源分離は難所だけ
- **補足: 今のツールは faster-whisper なので GPU は NVIDIA しか使えず、AMD では CPU で動いている。RX 7800 XT を使うには、whisper.cpp の Vulkan 版を組み込む必要がある**
  (RX 9070 XT で large 系が実時間の7.5〜8倍という報告あり)。faster-whisper のホットワードは使えなくなる(プロンプトのみ)ので、用語集の効き方は A/B で確認する。
  CPU のままでも「低信頼区間だけ large-v3」なら処理量は1〜2割で済むので、GPU 対応は段階2以降でよい
