# 自動カット設計 v1

## 目的

文字起こしツールで人が採用した区間を元動画上のフレーム範囲に変換し、各区間の前後に編集余白を残した、非破壊のResolve受け渡しパッケージを作る。カット判断はUIと分離し、Resolve用の書き出しは既存の `cut2resolve` に寄せる。

## 現在の実装

`cut2resolve/auto_cut.py` は独立CLI兼ライブラリ。動画 + 採用区間JSON + 任意の元時刻SRTを受け、`--handles` (既定10秒) を各採用区間の両側へ追加し、動画境界で切り詰める。重なった保持区間は統合する。すべてフレーム番号の半開区間 `[start, end)` で扱う。

```json
{
  "schema": "youtube-tools-cut-plan/v1",
  "segments": [
    {"id": "seg-12", "start": 12.4, "end": 28.1, "status": "adopted", "label": "見どころ"}
  ]
}
```

`start` / `end` は元動画先頭を0秒とする秒。`status` 省略時は採用扱い、`rejected` 等は無視する。文字起こしUIは後でこの契約を直接出すか、保存形式から変換してライブラリ `build_plan()` を呼ぶ。未確定・未採用の行を誤ってカット根拠にしないよう、status が明示されて採用済みの区間だけを入力する。

## 出力

- EDL: Resolveでカット点を調整できるタイムライン。参照元はファイル名ベース
- FCPXML: トリム済みソースクリップと編集可能なタイトル要素を含む補助タイムライン
- SRT: カット後の字幕時刻へ変換した字幕トラック用データ
- `cut-plan.json`: 元動画の基本情報、選択区間、保持区間、削除区間、フレームレート、編集ハンドルを保存。復元・差分比較・将来のUI再編集用
- `友人へ.txt`: 各ファイルの用途とResolveでの受け渡し注意
- `--copy-video`: 必要なら元動画を同梱。容量を避けるため既定ではコピーしない

出力ファイルが既にある場合、通常CLIは停止し、`--force` で明示したときだけ上書きする。入力とのパス衝突は強制指定でも拒否する。

## 後で文字起こし画面へ統合する境界

画面側は「残す/カット済み」等の状態を管理し、採用区間を秒またはミリ秒で渡す。エクスポータ側で動画情報を一度だけ取得し、fps分数と実測総フレーム数を基準に全時刻を丸める。字幕はその同じ保持区間で再マッピングする。保存元JSONと自動生成プランを分離し、エクスポートで元の文字起こしを変更しない。

統合時に必要な作業: 既存の `cutState` / Transcript JSON と契約の対応、採用状態UI、ハンドル表示、削除区間復元UI、出力先と上書き確認UI、タイムライン上の編集を再読込するためのJSON round-tripテスト。

## 制約・未確認

- FCPXMLはタイトル要素を作るが、DaVinci Resolve 21.1 FreeでText+ (Fusionタイトル)として読み込まれる保証はない。実機操作テストを飛ばす指示に従い、今回はファイル構造と自動テストまで。Text+確定が必要なら、後日新規テストプロジェクトで確認し、必要に応じResolve内スクリプト方式を追加する。
- FCPXML内の素材参照はパスを含む。`--copy-video` で同梱してもフォルダ移動後に再リンクが必要になる可能性がある。EDLはファイル名ベースで別経路として同梱する。
- `start/end` のJSON契約は初期版。clip-studio の内部DBを直接読む結合は避け、文字起こし側がこの公開契約へ変換する。データ形式を共有する時は schema version を上げる。
- 既存の無音検出は補助機能として維持する。自動カットの主入力は採用区間であり、音量だけで発話内容の価値を判断しない。
