# 新ツールの作成予定(2026-09-24 決定)

既存ツール(配信ランキング → 切り抜きスタジオ → 文字起こし → cut2resolve → 友人が Resolve で編集)に追加するツールの提案6件に対する、ユーザーの判断。

## 作成予定
### A. 新着配信の監視と自動キュー投入
- よく切り抜く配信者のチャンネルを監視し、新しいアーカイブをスタジオのキューに自動投入して、夜間に解析まで済ませる
- 案: チャンネル RSS(`https://www.youtube.com/feeds/videos.xml?channel_id=...`、APIキー不要・軽量)で新着検出 → スタジオの既存キューAPI(127.0.0.1)を叩く。常駐させず Windows タスクスケジューラで定期実行
- 注意: 配信中・直後のアーカイブは長さが変わるので、公開から一定時間(例: 3時間)経過後に投入。投入済みIDを記録して二重投入を防ぐ

### B. 音量の均一化(ラウドネス調整)
- 書き出した切り抜きを ffmpeg `loudnorm` の 2-pass で YouTube 基準(約 -14 LUFS)に揃える
- 2-pass を選ぶ理由: 1-pass より時間は倍だが正確。対象は短いクリップなので時間は問題にならない
- 組み込み先の候補: 独立ツールではなく、cut2resolve の `--render` やスタジオの書き出しのオプションにする方が保守しやすい(実装時に決める)

## 絶対に作る・ただし後で
### C. 受け渡しの一括実行(パイプライン)
- スタジオの採用区間 → cut2resolve のカットリスト → 文字起こし → 友人用パック(EDL + SRT)を一括で
- **着手条件: 個別のツールが完成してから**(ユーザー指示)
- 設計方針(案): 各ツールはファイル受け渡しのまま、順に呼ぶ薄いスクリプトにする(1ツールの更新で他が壊れにくい)
- 前提の未確認事項: 文字起こしツールが実物のスタジオ data.json を読めるか

## 今回は予定に入れなかったもの(提案のみ)
- 投稿後の成績トラッカー(YouTube Analytics API で再生数・維持率を取得し feedback と紐づけ)

- BGM・著作権リスクの警告(歌枠などで市販曲区間を警告)

## 編集時間短縮の案(2026-09-24 提案・未判断)

## 不採用
- **文字起こしツール: 「聞き取ったそのままの文章」と「字幕に表示する文章」の分離(2026-09-24、ユーザー判断で実装しない)**。検討した内容: 利点=学習・CER の正解データが字幕用の編集で汚れない、テンポ詰めに使える、字幕を作り直せる。欠点=二重編集の手間、片方だけ直したときのずれ、行の結合・分割の対応、保存・書き出し・学習・dataset・UI の全体に影響、過去データは分離できない
