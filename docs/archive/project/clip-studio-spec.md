# 切り抜きスタジオ (clip-studio) 仕様メモ(現行 v0.1.7)

> **2026-09-24 追記(v0.2.0)**: 画面を共通の ui-kit で刷新(設定は右から出る引き出し、? でキー一覧)。書き出した mp4 の隣に `youtube-tools-clip/v1`(`.clip.json`)、書き出し済みのマークに mp4 の絶対パス(`path`)、`/api/siblings`、画面の設定の節ごとの保存(`PUT /api/settings {section, value}`)。「文字起こし連携は作らない」はマークの検出に使わないという意味で、書き出した切り抜きを文字起こしツールで開くリンクは付けた。詳細は `docs/review/clip-studio-*.md`。

配信ランキング(sr v0.1.2)+自動切り抜き(ac v0.2.0)+クリップマーカー(cm v1.1.0)を1つに統合した新規ツール。旧ツールは残置(データも別)。文字起こしツールは対象外。**縦動画(9:16)・字幕焼き込み・文字起こし連携は作らない(編集ツールは別で考える)**。

## 使い方の前提(ユーザーの運用)
- 自動候補は「長さの調整」に使うことが多く、切り抜きの多くは自分で見つけた区間を手動マークして書き出す。手動マークは自動候補とは無関係に探した区間なので、重なりが0でも問題ではない
- 精度改善は、自動候補の採否だけでなく、手動マークの位置に何が起きていたか(音量・チャット・コメント・みんなの再生)の記録から進める

## 画面(4ステップ)
1. 探す: 4事務所(ホロライブ/にじさんじ/ぶいすぽっ!/ネオポルテ)の人気配信を検索→チェック(最大10本)
2. 解析: バッチキュー(1ワーカー、最大10本、失敗はスキップして続行、中止/やり直し/チャット待ちスキップ)。完了した配信から「確認する」
3. 確認: cm 由来のレビューUI。解析結果は「候補」の自動マーク(点数・理由タグ付き)として入る
4. **コラボ(v0.1.6〜)**: 複数人のコラボ配信をグループにまとめ、動画間の時刻のズレ(アンカー点)を指定する画面。詳細は `claude/collab-mark-spec.md`
入口4つ(② 解析): ランキング→バッチ / URL直接 / ローカルファイル / 解析せず確認画面だけ開く

## 検出ロジック(analyze.py)
- 材料3つ: 音声(全帯域 0.6 + 2kHz以上 0.4 の音量の跳ね上がり)/ チャット(件数の log を9秒平滑、「草」等は重み付き、スパチャは+4)/ コメント欄の時刻。それぞれ「ふだん(前後150秒の中央値)からの偏差 ÷ MAD」= 無単位の点(上限6)。重みは 音声1.0・チャット1.0・コメント0.7(UIの既定。実運用では 0.8/1.1/0.8 で使われている)
- 合計を5秒平滑 → しきい値(高1.2/標準2.0/低3.2)以上の山を高い順に選び、山を「ピークより前 X%」に置く区間にする(静かな位置へ±4秒スナップ)
- v0.1.4〜 チャットの遅れの自動推定: 音声の点とチャットの点(ずらす前)の相関を 0〜30秒で計算し、最も一致する遅れを使う(前後1秒で平滑、一致度 0.08 未満 or 最良と最悪の差 0.04 未満なら不採用)。不採用のときは設定の「遅れ補正」秒(既定8)。設定 `lagAuto`(既定オン)
- v0.1.4〜 冒頭の減点: 合計に (t/headSec)² を掛ける(0秒で0倍 → headSec 秒で1倍、既定180秒、0で無効)。設定 `headSec`。終盤の減点はしない(実データで終盤の採用が多かったため)
- v0.1.4〜 コメント欄: 1つのコメントに時刻が3つ以上ある(チャプター一覧)場合、各時刻の重みを 1/個数 にする。stamps は (秒, いいね数, 重み)
- v0.1.4〜 チャットの「盛り上がり」判定: 「！」「!」単独では数えない(「！！」以上は数える)
- **v0.1.5〜 配信タイプ別の重み(試験的・既定オフ)**: 設定 `typePreset`(オン)/ `typeOverride`(自動・ゲーム・雑談・歌枠・その他)。タイプはタイトル・タグ・カテゴリから推定(歌枠 > 雑談 > ゲーム(Gaming)> その他)。倍率(仮の初期値): 歌枠 音声×0.6 / 雑談 音声×0.8・チャット×1.1 / ゲーム・その他 なし。オフでも推定タイプは記録する

## 記録するデータ(v0.1.5〜。後から実データで精度を見直すため。解析の結果には影響しない)
- **archive/<動画ID>.json.gz**(cache とは別・最大2000本・2時間の配信で約40KB): 1秒ごとの音量(全帯域・高音域、0.1dB)/ チャット(重み付き活気・「草」等の件数・発言した人数・スパチャ件数)/ コメント欄の時刻(秒・いいね・重み・文面の先頭60文字)/ 動画の付加情報 / 推定した配信タイプ / 解析ごとの設定・使った遅れ・候補(直近5回分)。再解析で材料は上書き、runs は履歴として増える
- **cache/meta/<動画ID>.json**(24時間で再取得・最大300本): yt-dlp -J から、みんなが最も再生した場面(heatmap: [開始,終了,値0〜1])・チャプター・カテゴリ・タグ・再生数・いいね・コメント数・登録者数・公開日・配信状態。取れなくても解析は続く(注意書きが出る)。配信の解析と並行して取得
- **feedback.jsonl**: 従来の採否に加えて、event(adopt/reject/delete/export)、src(auto/manual)、動画の長さ、配信タイプ、自動マークは auto0(最初の区間)と手で直した量(dStart/dEnd)。**手動マークの採用・不採用・書き出し初回も「よかった/ちがう」で記録**(手動の削除・候補のままの作成は記録しない)
- 材料の集計(点数)は archive から再計算できる。手動マークの位置での各材料の点も、archive の系列と data.json のマークの結合で後から出せる
- 「みんなの再生(heatmap)」は現状は記録のみ。点数には使っていない(粗い・冒頭が高く出やすい・再生数が少ない動画では無い。効果を確認してから重みを付ける)

## マークの判定(v0.1.3〜)
- src: manual(手動) / auto(自動候補) / **collab(v0.1.6〜。コラボグループの採用マークから転写された候補。`collabFrom: {videoId, markId}` で由来を持つ。自動採用はしない、必ず候補として入る。**v0.1.7〜 転写先に既に重なるマークがあれば新規候補は作らずそちらへ統合する(開始・終了を両方の区間を覆うよう広げ、理由欄に由来だけ追記。判定・src は変えない)**。詳細は `claude/collab-mark-spec.md`)**。いずれもサーバーだけが決める(クライアントは書き換え不可)
- status: ""(候補) / adopted(採用) / rejected(不採用) / exported(書き出し済み)。exported はサーバーだけが付ける。クライアントの指定は無視
- クライアントが設定できるのは 候補/採用/不採用。書き出し済みに 採用/不採用/候補 を送ると、file を外してその状態に戻る。書き出し済みの時刻を動かすと「採用」に戻る(v0.1.7〜: コラボ統合で範囲が実際に広がった場合も同じ扱い)
- 手を入れた自動マーク(status が空でない/ラベル有/時刻変更)は再解析後も手動マークとして残る → 不採用にした区間は再解析でも復活しない
- フィードバック: 自動マークの 採用=good / 不採用=bad / 書き出し初回=good / 候補のまま削除=bad(判定済みの削除は記録しない)。手動マークは上記のとおり
- 書き出し対象: 採用のみ(既定)/ 採用+候補 / 不採用以外すべて。「全動画の採用を書き出す」(クライアントで動画ごとに順番に実行。画面を開いたまま)
- 確認画面の効率化: 前/次のマーク(] [)、採用 y / 不採用 u(押すと次の候補へ)、移動時に区間を自動再生、絞り込み(全部/候補/採用/不採用/書き出し済み)、時刻順/点数順、行の折りたたみ(すべて折りたたむ/開く)、候補をすべて採用
- レイアウト: 余白を削減(確認画面は全幅・上下左右 ~8px)

## 設計判断
- サーバー主権のストア(data.json)。動画に rev、PUT /api/video の baseRev 不一致は 409 → クライアントがマージ(サーバー由来の項目はサーバー優先、手元の未保存編集(時刻/ラベル/判定)は再適用)
- 解析結果の series(グラフ)は cache/series/<動画ID>.json にも保存(最新60本、v0.1.3〜)。マークは data.json。signals/chat はディスクキャッシュ
- チャット先読み(v0.1.2〜): バッチで今の配信の解析中に、次の配信のチャットを裏で先に取得(同時1本、cache/chat へ)
- 書き出しは cm 方式(ffmpeg/yt-dlp、精度優先/速度優先、動画ごとのフォルダ、同時1件)
- **書き出しの音量調整(v0.1.7〜)**: 書き出し設定に「音量」(1〜200%、既定75%)を追加。元の音量(100%)だと大きすぎるとの声から、既定を下げた。実装は `exporter.py` の `apply_volume`: 書き出し(ffmpeg/yt-dlp どちらの方式でも)完了後に、映像は無劣化のまま(`-c:v copy`)音声だけ `-af volume=` で再エンコードする一手間を追加する方式。100%指定時はこの一手間自体を省く。設定は precision/maxHeight と同じく画面の「設定」に保持し、/api/export に `volume` として渡す
- 設定(APIキー・出力先・事務所登録)は上部の折りたたみ「設定」
- data.json は壊れたら data.json.corrupt-<ts> に退避して空で起動
- 診断(v0.1.1〜): studio.log(終了・例外・シグナル)/ studio.crash.log。start.bat/command は終了後も画面を残す。Windows では子プロセスを別プロセスグループで起動
- テスト: test_studio.py(store)/ test_api.py(HTTP層・疑似モード)/ test_analyze.py(判定ロジック・付加情報・archive)/ test_exporter.py(v0.1.7〜。書き出しの音量調整。実際に短い合成動画をffmpegで作って確認)/ e2e_analyze.py(疑似モードの解析通し、ffmpeg 必要)

cm: コメント欄候補抽出、CSV/TSV。 ac: 自動書き出し、○×ボタン(採用/不採用に置換)
