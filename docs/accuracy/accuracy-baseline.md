# 文字起こしの精度の基準(段階0・2026-09-24 測定)

今ある校正済みデータ(PC の transcribe-tool)を読むだけで測った、現在の精度の出発点です。ツールは変えていません。クラウドも使っていません。
再計算: `python tools/baseline_analysis.py transcribe-tool docs/accuracy`(数値は `docs/accuracy/accuracy-baseline.json`)。

**CER(文字誤り率)** = 機械の出力を、人が直した正解に合わせるのに必要な「置き換え・抜け・余分」の文字数 ÷ 正解の文字数。低いほど良い。
句読点・空白・記号・全角半角の違いは数えない(ツールの「認識精度の測定」と同じ計算)。

## 1. データの量(棚卸し)
| 項目 | 値 |
|---|---|
| 文字起こし | 24本(校正済みの行があるのは 20本) |
| 校正済みの音声 | **約 8.5 分**(学習用 5.9 分・評価用 2.6 分)、259 行、正解 2,652 文字 |
| 評価用 | 10本に印。ただし**校正済みの行があるのは 6本**(さくらみこの評価用 4本は未校正) |
| 配信者 | 夏色まつり・さくらみこ・白上フブキ・大空スバル・鷹嶺ルイ・ロボ子さん(評価用はまつり・みこの2人だけ) |
| モデル | large-v3 19本、large-v3-turbo 5本(設定はどれも「声の検出: 標準」) |
| 音の状態のメモ | 重なり 15行・BGM 10行・聞き取れない 10行 |
| 用語集・置換辞書 | **どちらも空**(自動の辞書適用・用語の自動追加もオフ) |

正式な評価セットの目安(合計 15〜30 分以上、元の配信 3〜5 本以上、話者 4 人以上、通常/BGM/重なり/小声/叫び/笑い/固有名詞/無音を含む)には、
**評価用が 2.6 分・2 人しかなく、まだ足りません**。今回の数字は「おおよその出発点」として扱ってください。

## 2. 全体の精度
| 対象 | CER | 95% の範囲(文書単位のブートストラップ) | 内訳(置換 / 抜け / 余分) |
|---|---|---|---|
| 全体 | **8.4%** | 6.1〜11.1% | 101 / 78 / 43 |
| 評価用 | 8.7% | 3.7〜14.6% | 17 / 47 / 11 |
| 学習用 | 8.2% | 5.7〜11.6% | 84 / 31 / 32 |

- 誤りの 45% が「別の字に置き換え」、35% が「抜け(聞き逃し)」、19% が「余分(幻覚など)」
- 文書ごとの差が大きい(0.7%〜36.8%)。悪いのは白上フブキの短い回(turbo・36.8%)、さくらみこ評価用01(28.2%)、フブキ2(18.5%)、みこ 09-13(16.3%)

## 3. 条件ごとの精度
| 条件 | CER | 量 | 読み取れること |
|---|---|---|---|
| 「声が重なる」の行 | **24.3%** | 14 まとまり・111 字 | 通常の約3倍。多くが「余分」(17字)=重なった別の人の声を拾っている |
| 「BGM・音が大きい」の行 | 3.3% | 9 まとまり・123 字 | 今のデータでは BGM は大きな問題ではない(量が少ないので断定はできない) |
| 印なし | 7.9% | 225 まとまり | — |
| 「要確認」の印あり | **18.0%** | 39 まとまり | 印なし(7.1%)の約2.5倍。**印は怪しい行をよく当てている**(人の確認を集中させる価値がある) |
| 音量 下位1/4(-38〜-32dB) | 9.4% | 61 | 抜けが多い(32字) |
| 音量 2番目 | 9.7% | 61 | — |
| 音量 3番目 | 5.6% | 61 | — |
| 音量 上位1/4(-25〜-11dB) | 7.9% | 62 | 抜けが多い(36字。叫び・早口の可能性) |

- 小声(音量が小さい行)でも、はっきり悪くはならない。音量による差は、量が少なく誤差の範囲
- 要確認の印の内訳: 話者が不確か 18・音声でない可能性(BGMなど)18・自信が低い 3
- **信頼度(avg_logprob など)は保存されていない**ので、連続値の「信頼度と誤りの関係」はまだ測れない。今後の文字起こしで保存する必要がある

## 4. モデルの差
| モデル | CER | 95% の範囲 |
|---|---|---|
| large-v3 | 7.4% | 5.0〜10.2% |
| large-v3-turbo | 13.3% | 7.7〜21.5% |

- ただし **別々の動画での比較**(turbo は古い回・フブキの短い回が多い)なので、モデルの差なのか動画の差なのかは分けられない。
  同じ音声で比べるには、ツールの「設定の比較(A/B)」で、評価用の校正済みの行を両方のモデルで認識し直す(無料・ローカル)

## 5. 人名・固有名詞
- 名簿(`hololive-roster.json`)の**正式な名前(白上フブキ など)は、話し言葉にはほとんど出てこない**(出たのは 2 語だけ。どちらも正しく認識)
- 実際の修正で多いのは**呼び名・愛称**: トーイ/トーア→**トワ**(3回)、マチョ→**まちゅ**(2)、すぅー/すばる→**スバル**(2)、トルカ→**ポルカ**(2)、みく→**みこ**、ヘヨ→**ミオ**
- 用語集・置換辞書が空なので、**呼び名を用語集と置換辞書に入れるだけで、この種類の誤りはかなり減らせる見込み**(費用ゼロ・すぐできる)。
  ただし「みく→みこ」のように普通の言葉と重なるものは、置換辞書で一律に置き換えると別の所を壊すので、用語集(認識のヒント)に入れるか、「|語|」の語単位の指定にする

## 6. 結論(どこに手間とお金を使うか)
1. **呼び名・愛称の用語集と置換辞書**(効果: 大・費用: 0)。いちばん確実。呼び名の一覧はユーザーの入力が必要(`docs/accuracy/USER_INPUT.md`)
2. **重なり声**(効果: 中・該当する行だけ)。CER 24% で最も悪い。別視点の音声(コラボの各配信者の配信)で聞き直すのが本命、次に音源分離。まずは件数を増やして測る
3. **抜け(聞き逃し)**が全体の 35%。「声の検出」を「弱め」にした場合を A/B で比べる(無料)
4. **large-v3 と turbo** は同じ音声で A/B してから判断する(今の差は動画の違いの可能性)
5. BGM・小声は、今のデータでは優先度が低い(ただしデータが少ない)
6. クラウド比較(段階1)に進む前に、**評価用を 15 分以上・4 人以上に増やす**のが先。今の量だと、どの施策でも差が誤差に埋もれる

## 7. 測定の限界
- 校正済みは 8.5 分・2,652 字と少なく、条件別(重なり・BGM など)は数十〜百字程度。1〜2 ポイントの差は誤差の範囲
- 評価用はまつり・みこの2人だけ。汎化の確認用(学習に入れない人)のデータはまだ無い
- 未校正の評価用 4本(さくらみこ)は数に入っていない
- 「聞き取れない」の行は数えていない(ツールの測定と同じ)
