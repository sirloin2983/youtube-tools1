==========================================================
  ホーム(ランチャー)  はじめに読んでください(版は全体で 1 つ = ytt/version.py)
==========================================================

ツール(切り抜きスタジオ・編集・cut2resolve)を、1回の操作でまとめて起動・終了するためのホームです。
文字起こしツールは「編集」(文字起こし・カット・パック)で、cut2resolve の画面は「編集」に統合されています
(cut2resolve はパックを作る部品として裏で動き、ホームのカードは出しません)。
統合計画(notes:docs/design/integration-plan.md)に沿って、ツールをホームの中に取り込みます。
3つとも取り込みます: 切り抜きスタジオ(http://localhost:8700/studio/)・文字起こし(/transcribe/)・cut2resolve(/cut2resolve/)。
文字起こしの認識(faster-whisper)だけは、落ちてもホームごと止まらないよう、別のプログラム(src\pipeline\transcribe\worker.py)で動きます。
起動は start.bat だけです(各ツールの単独起動はありません)。使い方の全体はリポジトリ直下の README.txt。

■ 使い方
  1. youtube-tools フォルダ(リポジトリ直下)の start.bat をダブルクリック(Mac は start.command)
  2. 黒い画面が1つ開き、ツールが裏で起動します。ブラウザでホームの画面(http://localhost:8700/)が開きます
  3. ホームの上には「処理の状況」(動いている処理・待っている処理・失敗)が出ます。下には案件(配信ごと)の一覧があり、
     行を押すと案件の画面(/cases)で候補・校正・カット・パックの作業ができます。新しい配信は「新しい案件」から。
     ヘッダー左の「ホーム / 案件 / 確かめる / 設定」で行き来します(同じタブ・窓の中。新しい窓で開きたいときは Ctrl を押しながら)。
     ホームの「確かめる」の [始める] で、人が答えると精度が上がる軽い確認を 1 枚ずつ答えられます(/check。下の「確かめる」)。
  4. 終わるときは、下の「詳しく」を開いて「すべて終了」(誤操作を防ぐため2回押し)を押すか、黒い画面を閉じる / Ctrl+C

  ※ 黒い画面は1つだけです。3つのツールの出力は黒い画面ではなくログ(下の「詳しく」の「ログ」)に出ます
  ※ 画面を閉じても、サーバーは動いたままです。案件の一覧やヘッダーの切り替えでいつでも開き直せます

■ 確かめる
  - 確かめるの画面(/check)があります。ホームの「確かめる」の [始める]・案件の画面の上の「確かめると効く物 n 件」から開きます。
    カードは 4 種類: 切り抜く価値があるか([送る]・[要らない] / [採用]・[不採用])・どちらの読みが正しいか(1 / 2 / 打ち直す)・
    これは誰の声?(名前 / その他 / 声が混ざっている)・行の時刻が合っているか(波形の印を ← → で動かす)。答えるとすぐ次へ・Z で 1 つ前に戻す・N で今日は後ろへ。
    自動でできた切り抜きの [送る](友人へ届ける)・[要らない](ごみ箱へ)は戻せないので、次のカードに答えたとき(か画面を離れたとき)に確定します。
  - 自動でできた切り抜きの確認(採用・要らない)は、確かめるの「切り抜く価値があるか」で行います。
  - 答えの記録は %LOCALAPPDATA%\youtube-tools\app\check\answers.jsonl(1 枚 1 行)。精度の自動測定の「目標まであと何件」にも数えます。

■ 案件の画面
  - スタジオの画面(/studio/)と編集の画面(/transcribe/)のページはなく、案件の画面(/cases)とホームにまとめています。
    今の画面は新しい URL だけを作ります(動画のパスで開くときは /cases?v=<動画のパス>#proof)。
  - ヘッダーの切り替えは「ホーム / 案件 / 設定」。「案件」は前に開いていた案件を開きます(このブラウザの覚え)。
  - YouTube Data API キー・事務所の登録・コラボは、ホームの「新しい案件」の末尾の「探す設定」にあります(/#new?set=key|reg|collab で開く)。

■ 裏で動かす
  画面も黒い画面も出さずにホームを起動します。友人からの依頼の受付・まとめて実行は、画面を開いていなくても進みます。
  - start-background.bat(リポジトリ直下)をダブルクリック。画面を見たいときは、いつもどおり start.bat(裏で動いているホームにつながります)
  - Windows にログインしたときに自動で裏で起動するには、スタートアップのフォルダ(エクスプローラーのアドレス欄に shell:startup)に
    src\app\start_hidden.vbs へのショートカットを置きます。やめるときはそのショートカットを消します
  - 止めるときは、画面の「詳しく」→「すべて終了」
  - PC がスリープしている間は進みません(Windows の電源の設定でスリープまでの時間を長くするか、使わないときだけスリープに)
  - 記録は %LOCALAPPDATA%\youtube-tools\app\logs\launcher.log

■ 友人からの依頼の受付(設計は notes:docs/spec/friend.md)
  友人のアプリが Dropbox に送った依頼(配信の URL・友人が切り抜いた動画・ライブ配信)を、ホームが見張って ① 全自動(パックまで)で流します。
  1. 友人に送ってもらう仕組みを用意する: 友人のアプリ(src\friendapp\README.txt)
  2. ホームの「依頼の受付」を開き、見張るフォルダ(Dropbox\アプリ\切り抜き依頼 など)を入れてオンにする。
     Dropbox のアプリでそのフォルダを「オフラインで利用可能」にしておく(「オンラインのみ」だと PC にファイルが来ません)
  3. 届いたら 30 秒ごとの確認で受け付けます(「今すぐ確認」ですぐ)。進み具合は「まとめて実行」と同じ所に出ます
     依頼はいつも ① 全自動です(依頼の JSON の flow が ② check・③ manual の古いアプリの依頼も ① として扱います):
       配信: 解析 → 点数の高い N 個 → 書き出し → 文字起こし → パック / 動画: 文字起こし → パック。
       パックはできるたびに 1 本ずつ zip にして見張るフォルダの 出力\ に置き、確認用の動画(480p)と .meta.json を zip の隣に置きます。
       友人のアプリの「受け取る」に届きます(字幕は校正前)。止まったときは 出力\ に「<依頼>__<題名>.失敗.txt」
     - N は依頼ごと(1 以上・上限なし。書かなければ設定の既定。候補が足りなければある分だけ)
     - 動画は作業データ(%LOCALAPPDATA%\youtube-tools\app\intake\日付\)へコピーしてから処理します。配信者を指定されていれば、パックの字幕の色に使います
       (コピーが 30fps の H.264 + AAC でなければ、コピーを 30fps に作り直します。元の動画は触りません。作り直せなくてもコピーのまま進め、理由を「理由.txt」に残します)
     - 受け付けた元のファイルは 受付済み\日付\ へ、断ったものは 失敗\ へ移し、理由を「<名前>.理由.txt」に書きます(消しません)
     - アプリを通さずに置いたファイル(手で置いた動画・URL の .txt など)は受け付けません: 失敗\ へ移し、理由「友人のアプリから送ってください」
       (② 軽く確認 = 文字起こしまでの道は 2026-10-19 に無くしました)
  安全のため: URL は YouTube だけ・動画は ffprobe で確かめてから・同じ配信 / 同じ動画は2回流さない・
  配信の長さ / 動画の大きさの上限(設定で変えられます。1 日の件数の上限はありません)。配信中・配信前の URL は断ります。
  ホームが起動していない間に届いた依頼は、次に起動したときに流します。覚えている内容は …\app\intake-state.json

■ ホームの画面でできること
  - 「処理の状況」: まとめて実行の実行中(今の段・全体の進み)・待ち(順番)・失敗(段と理由)と、自動の切り抜きの失敗。
    押すと案件の行・案件の画面へ。採用・校正・パックの残りはここに出さない(案件の一覧の行の結果で読む)
  - 案件(配信ごと)の一覧: 配信1本ごとに、依頼(誰の・何を)と結果(書き出した切り抜き・校正の済み具合・パックの有無・失敗)。
    行を開くと切り抜きの一覧・「まとめて実行」・状態・メモ。
    どの配信にも紐づかない文字起こし(手元の動画ファイルなど)は「単体の文字起こし」の1行(件数と「編集の履歴で見る」= 「編集」の履歴を
    「種類: それ以外」で開く)に出ます。一覧は「編集」の履歴が主です。その下の「選んで、まとめて実行」で、検索して選んだ文書を
    まとめて文字起こし・パックへ進められます(「編集」の履歴の「選んで、まとめて実行」と同じ)
  - 自動でできた切り抜き(リアルタイム切り抜きの自動の採用・配信後の全自動): 切り抜きに「自動」の札。一覧の上の「自動の切り抜き: 未確認 n 件」で絞り、
    [採用(友人へ届ける)] か [要らない](ごみ箱フォルダへ・スタジオのマークを不採用に・誤検出として記録)を選びます。
    友人の依頼・自動で届ける録画の切り抜き(届けるのが決まりの物)は「未確認」に数えません。まとめて実行が届けた切り抜きには「届けた」が付きます
  - まとめて実行の結果はファイルに残ります(%LOCALAPPDATA%\youtube-tools\app\logs\autorun-runs.jsonl。1MB を超えたら .1 に回します)。
    ホームを起動し直しても、案件・単体の文字起こしの行に「前回 …: 失敗 ・ 止まった理由(3日前)」が出て、
    案件の下の「まとめて実行の記録」(既定で閉じています)を開くと、終わった実行を新しい順に見られます。
    書くのは実行が終わったとき(完了・失敗・中止)だけです。順番待ち・実行中の実行は …\app\logs\autorun-active.json にも残り、
    ホームを起動し直すと(「すべて終了」・黒い画面を閉じた・強制終了のどれでも)同じ実行が続きから進みます(済んだ段は飛ばし、途中の段は頭からやり直す)。
    版の赤い帯の「起動し直す」も、まとめて実行の待ち・実行中では断りません(書き出しの最中・人が始めた仕事があるときは断ります)
  - 「詳しく」(既定で閉じています): 各ツールの状態(起動中・動作中・別の画面で起動済み・停止・異常終了)・開く/起動/停止/再起動・
    ログ・窓で開く(10-24 から固定。切り替えの欄は無い)・すべて終了
  - 一覧の非表示: 案件・次にやること・単体の文字起こし・届いた依頼・まとめて実行の記録は、行の「非表示にする」で一覧から隠せます
    (データは消しません)。一覧の上の「非表示 n件を表示」で薄く出して「表示に戻す」で戻せます。スタジオ ③ の配信の一覧・「編集」の履歴も同じです
  - ⚙ の設定(右上): テーマ(明るい/暗い/OSに合わせる)・文字の大きさ・キーの帯を出すか(全体の設定。どのツールで変えても全部に効きます)

■ ホームに取り込んだツール
  ホームのプログラムの中で動くので、カードに「ホームに取り込み」と出て、「停止」「再起動」は押せません(「すべて終了」で一緒に終わります)。
  アクセスの記録は …\app\logs\studio.log・cut2resolve.log に、ツール自身の記録は %LOCALAPPDATA%\youtube-tools\studio\studio.log・…\cut2resolve\work\serve.log に出ます。
  「すべて終了」のとき cut2resolve の書き出しが動いていれば、取り消してから終わります。
  取り込みで問題が出たときは、start.bat の代わりに黒い画面で「python src\app\server.py --no-mount」と打つと、別のプログラムとして起動します。
  安全のため、ホームと取り込んだツールの画面には、外から入れられたスクリプトを動かさない仕組み(CSP)と、書き込みの操作の合言葉(起動ごとに変わる)を付けています。
  画面を開いたままホームを起動し直したときに「合言葉が違います」と出たら、画面を再読み込みしてください。

■ すでに別の黒い画面でツールを起動している場合
  そのツールは「別の画面で起動済み」と表示され、ホームからは起動も停止もしません(同じデータを2つのサーバーで取り合わないため)。
  ホームでまとめて管理したいときは、その黒い画面を閉じてから、「詳しく」の「起動」を押してください。
  古い版が動いているときは、カードにその旨が出ます。

■ 異常終了したとき
  カードに「異常終了」と出て、黒い画面にもログの最後の数行が出ます。「ログ」を開いて最後のメッセージを確認し、「起動」で起動し直せます。
  自動では起動し直しません(同じ原因で何度も落ち続けるのを避けるため)。

■ コマンド(上級者向け)
  python src\app\server.py [--no-open] [--port 8700] [--only studio,transcribe]
    --no-open   ブラウザを開かない
    --port      ホームのポート(使用中なら次の番号。8700〜8719)
    --only      起動するツールを絞る(studio / transcribe / cut2resolve をカンマ区切り)
    --no-mount  ツールをホームに取り込まず、別のプログラムとして起動する(問題が出たときの回避)

  各ツールは、それぞれのフォルダで「serve.py <既定のポート> --no-open」として起動します(ホームと同じ Python)。
  Mac / Linux の文字起こしツールは、src/editor/.venv があればその Python を使います。

  その他のコマンド(リポジトリ直下から。この PC では python を py -3.12 と読み替える):
    py -3.12 src\manage\keep\backup.py --restore <写す先>   バックアップから作業データへ写し戻す(ホームを止めてから。手順は notes:docs/spec/data.md の「写し戻しの手順」)

■ 安全のための決まり
  - ホームのサーバーは 127.0.0.1(この PC)だけで待ち受けます。他の PC からは開けません
  - 起動・停止などの操作は、ホームの画面からだけ受け付けます(他のサイトからの操作・埋め込みを拒否)
  - ログには動画の題名やファイルの場所が入ることがあります。この PC の画面にだけ表示し、外には送りません

■ 設定の画面とパネル(notes:docs/spec/data.md の 6)
  - ホームの ⚙ には設定の画面へのリンクがあります(「窓で開く」の欄は 10-24 に消した = いつも窓)。まとめて実行の既定と「試験中の機能」(リアルタイム切り抜きのスイッチ・書き出したあとの自動の流れ・配信中の候補)は
    設定の画面(⚙ の「設定の画面を開く」。http://localhost:8700/settings)で変えます。
  - 「依頼の受付」「バックアップ」のパネルにあるのは、状態・「今すぐ確認」「今すぐ写す」・オン/オフのスイッチ・今のフォルダの表示・「設定を変える」(設定の画面の節へ)です。
    見張るフォルダ・数・写す先・間隔は設定の画面で変えます。フォルダが空のままオンにすると、入口が断って理由を出します。
    案件の行の「設定を変える」(まとめて実行の採用する数・カット・上書き)も使えます。

■ ライブの切り抜きの届け方と片付け(decisions 3-20 = ユーザー決定)

■ 守りと記録(配信ごとの結果の記録・自動の安全弁・配信の終わりと GPU の取り合い。ユーザー決定)

■ 自動の採用の余白・設定の読み込み

  - 配信中の検出の「候補を最初に見た時刻」の記憶は、見かけなくなった候補の分を 1 時間で消します(長く動かしても増え続けない)。

  - そのために、届けた zip の中身(パックのフォルダ・切り抜きの動画・マークの id)を logs\deliveries.jsonl に 1 行ずつ残します(1 本ずつの zip でも)。

  - まとめ動画は等速で、各クリップの「i/N 題」の札をずっと出します。480p・crf 28 は同じ(5 本 × 90 秒で約 7.5 分・30〜50MB の見込み)。

  - zip の中に まとめ.mp4 を入れません(受け取ったあとは要らない)。zip の隣の <zip の名前>.preview.mp4 は置きます(友人のアプリの「まとめ動画を見る」が使う)

■ ファイルの保存期間(ユーザー決定)
  - ごみ箱フォルダ(自動の片付けで移した物・自動の切り抜きの「要らない」)は **3 日**で起動時に消えます(src\manage\keep\cleanup.py の TRASH_DAYS)
  - 自動の片付け(10-24 から。手で選ぶ画面は無い): 友人へ届けた切り抜きの動画とパック・依頼の動画は、届けてから **3 日**でごみ箱フォルダへ。
    受付済み・送り返しの受付済み・失敗の物も **3 日**(KEEP_DAYS)。文書・作業用の記録・字幕と、届けていない物は残します
  - リアルタイム切り抜きの退避した速報版は、入れ替えから **3 日**で消えます(src\home\live_cleanup.py の KEEP_SEC)
  - 起動し直しで戻すまとめて実行は、**3 日**より前のものは戻しません(src\home\autorun.py)
  - 方針(ユーザー決定): 精度の改善になるデータ(校正済みの文字起こし・評価用・採用や誤検出の記録)は残し、ただの控えは早めに消す。変えていないもの: マークの無い録画 24 時間・文字起こし・案件・パック・Dropbox の 出力\(友人が受け取る/要らないまで)・バックアップ・編集の履歴と字幕のキャッシュ

■ 依頼の受付に「1 日の上限(件)」はない(ユーザー決定)

■ 自動でできた切り抜きの確認と「採用」で友人へ届ける・自動の切り抜きのカット・候補の長さを人の記録から・配信中の候補のワーカー
  [確認の一覧と届ける(M9・M12)]
  - 案件の一覧で、自動でできた切り抜き(.clip.json の出どころが「配信中の候補」= 自動の採用(M11)か「配信後の解析」= 配信後の全自動(M7))に
    「自動」の札と左の線・出どころ・点数(あれば)・「控え」(1 時間の枠から外れた候補。あれば)・未見/見た・届けた・失敗の文(「調子」と同じ文)を出します。

  - 一覧の上の「自動の切り抜き: 未確認 n 件」を押すと、まだ見ていない・届けていない自動の切り抜きがある配信だけに絞って行を開きます(もう一度押すと戻す)。
    「編集で開く」で開くと「見た」になります
  - [採用(友人へ届ける)]: パックを zip にして Dropbox の 出力 に置きます(「編集」の 3 パック の「友人へ届ける」と同じ作り方)。パックがまだのとき・
    依頼の受付の Dropbox のフォルダが決まっていないときは押せず、理由を出します。
    届けたら案件に記録し(二度は届けない)、live\live_feedback.jsonl に人の「良い」(event deliver)を 1 行
  - [要らない]: パック・切り抜きの動画・.clip.json などの途中のファイルを ごみ箱フォルダ(片付けと同じ場所。ごみ箱\<日付>\discard\。3 日で起動時に消える)
    へ移し、スタジオのマークを不採用にして、live\live_feedback.jsonl に誤検出(event reject・人の「悪い」)を 1 行。その文字起こしは一覧で非表示に
    (データは消しません)。スタジオにつながらない・ファイルを移せないときは、移した分を元に戻して何も変えません。どちらも二度押しで確かめます
  - API: POST /api/cases/auto {op: seen|deliver|discard, id, markId}(src\home\cases.py の auto_review)。案件ファイル(…\app\cases.json)に
    確認の記録(auto)を持ちます。GET /api/cases の切り抜きに auto・review、案件に autoClips、全体に auto
  - 点数は 採用の経路(live_detect → live.adopt → 書き出し → .clip.json の source.live.score)に通してあり、一覧に出ます
  [配信中の候補のワーカー(M8・M10・直し)]
  - 候補が早く出る(仮の候補): チャットを待たずに音だけで先に計算し、盛り上がりの上り始めで「仮の候補」を出します(山からおよそ 40〜50 秒。
    本番の候補はチャットの遅れ・未来を 30 秒見る・山の確定を待つので 90〜110 秒)。チャットの分がそろって確定すると、同じ行のまま本番の候補に
    置き換わります(区間・点数が直ることがあります)。仮の候補は「区間の終わり待ち」と同じ扱いで、採用できず・1 時間の枠にも数えません。
    本番の候補にならなかった仮の候補は「見送り」(控えも見るで出る)にします。本番の候補の区間・点数は仮の候補が無いときと同じです
  - 同時に測るのは 2 本まで: 録画中の配信が 3 本以上のときは古い 2 本を測り、ほかは「順番待ち」(スタジオの帯と「調子」に文が出ます)。
    前の録画の検出が終わると、そのときのライブ端から測り始めます(それより前は候補を出しません。順番待ちのうちに配信が終わった録画は、あとで音だけで測ります)
  - 雰囲気の変わり目(ゲーム → 雑談 → 歌など。音の 5 分の中央値が前の 5 分より 6dB 以上動いた)のあと 60 秒は、候補にするしきい値を 1.3 倍にします(変わり目は出すぎやすいため)
  - 候補の長さを人の記録から(M10): 夜の自動測定(src\eval\tools\eval_marks.py)の「人が選んだ区間の長さ」の見本が 20 個・配信 5 本以上あれば、新しく測り始める録画の
    候補の長さをその中央値(10〜120 秒)に、山の前の割合もその値にします。足りなければ今までどおりスタジオの解析の設定(45 秒)。
    YTT_LIVE_LENGTH=off で使いません(ホームが config.json の lengthHint に目安を書き、ワーカーが読みます)
  - 自動の採用の切り抜きのカット(M8): 配信中の自動の採用・配信後の全自動で書き出した切り抜きは、カットを選んでいなければ区間の全体でパックにします
    (ホームの「まとめて実行」のカットの設定が「行から」でも。区間は検出が静かな所に合わせて絞ってあるため)。「書き出したあと」のカット(無音で削る など)を選べばそれ

■ 配信中の盛り上がりの候補と自動の採用(試験中。線 D の L2・M11)
  - 配信中の候補: 「詳しく」の ⚙ 設定 → 試験中の機能 →「配信中の候補(盛り上がりの検出)」をオンにすると、録画中の配信の音(全体と高い音)と
    チャット(yt-dlp の live_chat)から、スタジオのアーカイブの解析と同じ式(src\ytt_core\excite.py)で盛り上がりを見つけて「候補」にします。
    感度(高い・ふつう・低い)と 1 時間の本数(1〜30。既定 6)を選べます。1 時間の枠を超えたら点数の低い候補を「控え」にします(人が採用・見送りしたものは数えません)。
    候補はスタジオの LIVE の帯に出ます(帯の表示はスタジオの側)。候補が出るまでは 1〜2 分ほど遅れます(未来を 30 秒見る + チャットの書き出しの遅れ約 20 秒 + 山の確定)
  - 計算は別のプログラム(src\home\live_excite_worker.py。ホームが起動・見張る子プロセス。優先度は通常より下)。
    状態を 1 分ごとに保存するので、ホームを起動し直しても続きから。心拍が 2 分止まる・落ちたら起動し直します(数は「調子」に)。メモリが 512MB を超えたら保存して起動し直します。
    ライブ端から 2 分以上遅れたら 60 秒ずつまとめて測り、10 分以上遅れたら古い所を飛ばして追いつきます(配信が終わったら飛ばした区間の音を測り直して残します)。
    チャットが止まったら間隔をあけて起動し直し(30 秒 → 最大 10 分)、1 時間に 6 回を超えたら音だけで続けます。チャットのファイルは 64MB で新しくし、配信が終わったら消します
  - 候補の自動の採用(M11。いつもオン): ホームが候補を最初に見てから決めた分(設定の「確定から待つ分」。既定 5 分)待って、まだ枠に残っている候補(終わり待ちの候補は除く)を
    サーバー側の採用(M1。origin auto)に渡し、書き出し → 文字起こし → パックまで進めます(届けるのは人が確かめてから)。自動で採用した候補は枠に数えたまま入れ替えません。
    スタジオにつながらないときは次の見回りでやり直し、5 回で諦めて「調子」の失敗に出します
  - API: GET /live/api/peaks?recorder=&recording=&since=(候補・変わった候補・遅れ・チャットの状態・600 点のグラフ)・
    POST /live/api/peaks {op: adopt|dismiss|restore, …}(採用・見送り・戻す)。中身と形は src\home\live_detect.py の先頭(計画 plan\line-d-detect.md の 3)
  - 「調子」: 「盛り上がりの検出」の行(動いているか・遅れ・チャット・起動し直しの数・自動の採用)と、失敗の一覧に kind detect(ワーカーの不具合・起動し直しが多い・自動の採用を諦めた)
  - 作業データ: %LOCALAPPDATA%\youtube-tools\app\live\excite\<録画元>\<録画>\(state.json・series.jsonl・peaks.json・decisions.json)。記録は logs\excite.log

■ 次にやること・案件の行のボタン
  - 「次にやること」に、文字起こし待ち・書き出し待ち・確認前の候補を出します(配信ごと。押すとスタジオの ③ 確認でその配信を開きます)。
    確認前の候補は、解析したがまだ 1 本も採用・書き出ししていない配信の、採用・見送りを決めていないマークの数です(案件の一覧の todo。S-6)。
    並びは 進行中 → 校正 → パック → 文字起こし → 書き出し → 候補の確認(仕上げに近い作業から)
  - 案件の行の「→ 書き出し 2本」などの札を、押せるボタンです(候補の確認・書き出し・文字起こし = スタジオの ③、校正・パック = 編集のその文書。
    見送り・投稿済みの案件には出しません。S-18)
  - 配信が 1 本も無いときの表示に「スタジオで配信を探す」「依頼の受付を設定する」のボタンがあります(S-13)
  - スタジオから消えた配信の「まとめて実行」を、隠さずに押せなくして、理由と戻し方(スタジオに同じ配信を入れ直す)を出します(S-25)
  - ツールの画面へのリンク(編集で開く・スタジオで開く・編集の履歴で見る・まとめて実行の記録の文書)は、新しいタブ・窓ではなく同じ窓で移ります
    (新しい窓は Ctrl を押しながら。「詳しく」のツールのカードの「開く」だけは今までどおり新しい窓。S-15)
  - 次にやることの紐づかない文書の行に、元のファイル名と更新日時を添えます(同じ題名を見分ける。S-26)
  - まとめて実行でツールが動いていないときの文を、何が起きたか・どこで何を押すかの文にします(「詳しく(サーバーの管理)」で起動 → もう一度実行。S-19)
  - 「実行」を押したらフォーカスを「中止」へ移し、終わったら「実行」へ戻します。配信者(と採用する数)の欄の Enter で実行します(変換の確定の Enter では動きません。S-24)

■ 「起動し直す」はまとめて実行が動いていても断らない・配信後の全自動の進み具合
  - 版の赤い帯の「起動し直す」(api/ytt/restart-self): まとめて実行の待ち・実行中があっても断らずに起動し直します(
    起動し直したあとに同じ実行が続きから進むため)。応答の notice と launcher.log に「まとめて実行の待ち・実行中の N 件は、
    起動し直したあとに続きから進めます」。
    実行中の段がツールで動かしている仕事(文字起こし・話者分離・解析・パック)も数えません(起動し直したあと、その段を頭からやり直します)。
    次のときは理由を出して断ります: 同じツールに人が始めた仕事がある(「編集」のほかのジョブ・スタジオのほかの解析)・
    書き出しの最中(まとめて実行の書き出しの段も)・そのほかの重い処理(波形・30fps にそろえる・リアルタイム切り抜きの書き出しなど)。
    録画は、起動し直しても止めずに続きます
  - まとめて実行: ① 全自動で Dropbox へ届けたら、すぐ待ちの記録(autorun-active.json)に残します
    (段の途中で起動し直しても、同じパックを二度置かないため)
  - リアルタイム切り抜き(試験中)の配信後の全自動(M7): GET /live/api/exports?recorder=&recording= の archiveInfo.afterStream に、
    採用したジョブの進み具合 progress {total・exported・archived・handed・finished・failed} と、帯に出す 1 行 text を持ちます。

■ 起動し直しで まとめて実行を戻す・空き容量の見張り・録画中の書き出しの枠・配信後の全自動(線 D の M4〜M7)
  - まとめて実行の待ち・実行中を、ホームを起動し直しても戻します(M5): 順番待ち・実行中の実行を作業データの app\logs\autorun-active.json に残し
    (入れたとき・段を始めたとき・段が済んだとき・終わったとき)、起動したときに同じ実行(同じ id)として「待ち」に戻します。済んだ段は飛ばし、
    途中だった段(文字起こしなど)は頭からやり直します(どの段も「まだ無いものだけ」作るので、続きから進みます)。
    「すべて終了」で順番待ちを「中止」にしません(記録の autorun-runs.jsonl にも書きません)。起動し直してすぐは、ツールの準備ができるまで待ちます(2 分まで)。
    7 日より前に入れた実行は戻さず、記録に「中止」と書きます。
  - 空き容量の見張り(M4。リアルタイム切り抜きがオンのとき): 書き出し先(パックも切り抜きの隣に作る)と作業用の live\work の空きを 1 分ごとに調べ、
    20 GB 未満で「調子」に注意、5 GB 未満で**新しい書き出しと文字起こしを「空き待ち」**にします(止めずに待ち、空けば続けます。
    書き出しの途中で失敗して書きかけが壊れるより戻しやすいため)。録画待ちの書き出しは録画元に問い合わせずに待ち、書き出しが済んだものは
    まとめて実行へ渡すのを待ちます。知らせは「調子」の「リアルタイム切り抜きの空き」・スタジオの LIVE の帯(書き出しの行の文)・記録(launcher.log。変わったときだけ)。
    アーカイブで本番版に作り直すのも、空くまで待ちます。録画の部品の見張り(録画先を 1 GB で止める・20 GB で注意)はそのまま別にあります
  - 録画中の書き出しの枠(M6): 重い処理の同時実行の上限(既定 2)とは別に、**録画中のライブの書き出しだけが使える枠を 1 つ**あります
    (src\ytt_core\jobs.py の RESERVED。仮の値。本物の 3 時間の配信で決め直します)。文字起こし 2 本で上限が埋まっていても、配信中の書き出しは待たされません。
    録画が終わったあとの書き出しは、順番を待ちます
  - 配信後の全自動(M7。既定オフ): 「詳しく」→「試験中の機能」→「書き出したあとの自動の流れ」の「配信が終わったら、アーカイブの解析で自動で切り抜く(パックまで)」と
    「1 時間あたり」(1〜30。既定 6)。オンのとき、録画が終わって 30 分たち、アーカイブを使えるようになったら(本番版と同じ確かめ方)、人が触らずに:
      1. 録画の真ん中あたりの音(60 秒)を録画元から取り、アーカイブの音と照合して、録画とアーカイブの時刻のずれを求める(照合済みのマークがあればそのずれ)
      2. アーカイブ(YouTube の動画)をスタジオの今の解析にかける(設定はスタジオで保存した解析の設定。候補の数は N の 2 倍まで増やす)。スタジオで解析済みならそれを使う
      3. 候補を点数の高い順に、録画の範囲に入る・人のマークと重ならない上位 N 本(N = 録画の長さ(時間)× 1 時間あたり。1〜30)を、
         画面なしの採用(origin archive = 自動の採用は「良い」に数えない)でスタジオの録画にマークし、書き出す
      4. 書き出したら本番版に作り直し(「自動で本番版に作り直す」がオフでも)、入れ替えてから まとめて実行で文字起こし → パック
         (本番版にできなければ、速報版のまま進めて理由を出します)。届けるのは人が確かめてから(全自動では届けません)
    進み具合は GET /live/api/exports?recorder=&recording= の archiveInfo.afterStream、止まった理由は「調子」の「リアルタイム切り抜きの失敗」(配信後の自動)。
    オンの間は、自動の切り抜きが済むまで(録画が終わって 2 日まで)その録画を自動で消しません。2 日より前に終わった録画は自動では切り抜きません

■ 画面なしの「マーク + 書き出し」・書き出したあとの設定・失敗を 1 か所に(線 D の M1〜M3)
  - サーバー側の「マーク + 書き出し」(M1): 入口の中の採用(recorder, recording, start, end, label, origin)の 1 つで、スタジオの配信(録画)に採用のマークを足し、
    書き出しまで進めます。スタジオの画面を閉じていても動きます。書き出しが済んだら、ホームがスタジオのマークを「書き出し済み」にします(画面の書き出しも同じ)。
    start・end は録画の頭からの秒(スタジオのマークと同じ)か、絶対時刻(UTC)。同じ区間(±0.5 秒)のマークがあれば使い回し、書き出しの途中・済みなら新しく作りません。
    これから作る自動の採用(配信後のアーカイブの解析 M7・配信中の検出 M11)もここを通ります
  - 採用の出どころ origin: manual(人)・auto(配信中の検出)・archive(アーカイブの解析)。書き出しのジョブ・.clip.json(source.live.origin。自動は mark.src も auto)・
    作業データの app\live\live_feedback.jsonl(採用の記録。盛り上がりの学習の記録 feedback.jsonl とは別)に残します。自動の採用は「良い」に数えません
  - 書き出したあとの自動の流れ(M2。設定 live.auto): 「詳しく」→「試験中の機能」(オンのとき)の「書き出したあとの自動の流れ」で、
    書き出したあと(API が指定しないときの既定)・パックのカット・文字起こしのエンジン・モデル・自動の採用の前後の余白(秒。既定 2)を選べます。空 = 今までどおり(ホームの設定・「編集」の設定のまま)。
    (エンジンは「空(編集の設定のまま)」と whisper.cpp、モデルは「空」と large-v3 から選びます。保存してあった範囲外の値は「空」と読みます)
    新しく頼んだ書き出しから効きます(頼んだときの値を覚えて、まとめて実行へ渡します)
  - 失敗を 1 か所に(M3): 書き出し・まとめて実行へ渡す・文字起こし・パックの失敗を、src\home\live_failures.py の 1 つの関数で 1 つの文にして、
    「調子」の「リアルタイム切り抜きの失敗(7 日)」とスタジオの LIVE の帯(書き出しの行。書き出しの失敗は失敗の文・それ以外は注意の行)に同じ文で出します。
    読むのは作業データの app\live\exports.json と app\logs\autorun-runs.jsonl だけです(書き換えません)

■ 「すべて終了」で録画の部品も止める
  - リアルタイム切り抜き(試験中)がオンのとき、「すべて終了」・黒い画面を閉じる・Ctrl+C でホームを終えると、録画の部品(src\pipeline\ingest\recorder.py)も止めます
    録画の部品に「終わって」と伝え(POST /live/quit)、応答が無い・終わらないときは、
    ホームが起動したものだけ強制的に止めます(スタジオの ffmpeg と同じ止め方)
  - **録画中なら止めません**(録画は続きます)。そのことは記録(launcher.log)と「すべて終了しました」の画面に出ます。
    部品も終わらせたいときは、スタジオで録画を止めてから、もう一度ホームを起動して「すべて終了」
  - リアルタイム切り抜きがオフで、人が別に起動した録画の部品は触りません

■ 精度の自動測定の「入口の条件(あと何本・何分)」
  - 「詳しく」→「調子」の精度の行の下に「入口の条件(あと何本・何分)」: 次の工程を始めてよい量(plan\README.md の 7)を、今 / 目標 / あと で 1 行ずつ出します。
    G1 定点 15 分・G2 定点 30 分・G2 普段の校正 30 分・学習用の校正 3 時間・確かめ済みの話者の行 200・採用の記録 配信 10 本・たたき台つきのパック 20 本・
    「別」の候補の判定 100 件。値は直近の精度の測定のもの(夜に 1 日 1 回か「精度を今すぐ測る」)。測る道具が無い・まだ測っていないものは「未測定」
  - 値の出どころ: 定点 = src\eval\tools\eval_asr.py の確かめ済みの秒・話者の行 = eval_speakers.py・採用の記録 = eval_marks.py の判定のある配信・パック = eval_cut.py の
    最終がパックの文書・「別」の候補 = eval_alt.py の判定できた候補。
    普段・学習用は、測るときにホームが文字起こしの文書を読んで数えます(評価用でない文書の校正済みの行の長さ = 「編集」の進行度と同じ数え方。
    普段と学習用を分ける印が無いので、同じ数を 30 分と 3 時間の目標に比べます)
  - 目標の値は src\home\accuracy.py の GOALS の 1 か所(各道具の「まだ少ない」の値と同じ。食い違うとテストが落ちます)。API は GET /api/accuracy の goals

■ アーカイブで本番版に作り直す・録画を自動で消す(試験中)
  - 本番版に作り直す(src\home\live_archive.py・live_align_worker.py): 書き出した切り抜き(速報版)を、配信のあとアーカイブから作り直して同じ名前で入れ替えます。
    yt-dlp でアーカイブの用意と開始時刻を確かめ、配信の音を 1 回だけ取り、速報版の音と照らし合わせて(別のプロセス。numpy)アーカイブの秒を求め、
    スタジオの書き出し(区間の書き出しの部品)で作って、速報版との音のずれが 1 コマ以内なら入れ替えます。使い方はスタジオの README の「アーカイブから本番版」
    API: POST /live/api/archive・/live/api/archive/cancel、GET /live/api/exports の archive・archiveInfo。設定 live.autoArchive(既定オン)
  - 録画を自動で消す(src\home\live_cleanup.py。設定 live.autoDelete 既定オン): 全部入れ替わった録画はすぐ・マークの無い録画は 24 時間・退避した速報版は 3 日。
    録画の部品の POST /live/<録画>/delete を使います(画面からは呼べません)
  - 書き出しのあとの流れ(POST /live/api/export の after: none / auto。古い画面・保存値の check = 文字起こしまでは auto として読みます)と配信者の名前(streamer)を、まとめて実行に渡します。
    POST /live/api/begin は配信のチャンネル名も返します

■ リアルタイム切り抜き(試験中)はスタジオの中で
  - 録画の画面(http://localhost:8700/live/)はありません。配信中の録画・再生・マーク・書き出しは、スタジオの中で行います
    (スタジオの README の「リアルタイム切り抜き」。オンのとき /live/ を開くとスタジオへ移ります)。
  - スタジオの画面が使う API があります(オンのときだけ): POST /live/api/begin {url}(配信の状態を yt-dlp で調べ、配信中・配信前なら録画を始める)・
    POST /live/api/export の studio の形(スタジオのマーク = 録画の頭からの秒 を受けて、絶対時刻にして書き出す)
  - どのツールのヘッダーにも「録画中」の札(ui-kit の UIKit.liveBadge)。入口の共通の API POST api/ytt/live {op: status | stop}。オフの間は何も出ません
  - 設定 live.quality(録画の画質。best / 1080p / 720p。既定 1080p。スタジオの設定の「ライブの録画」で変える)
  - 録画の部品は、名前を入れずに始めた録画に配信の題を自動で付けます

■ 友人の区間の長さを依頼の自動の候補に使う
  - まとめて実行を中止すると、その実行が入れたスタジオの解析も取り消します(スタジオで自分で入れた解析は止めません)。
  - 友人の区間の長さを使う: 友人の依頼で、足りない分を自動の候補で埋めるために解析するときだけ、友人が指定してきた区間の長さの中央値(10〜120 秒に収める)を候補の長さに使います。
    条件: 測る道具の結果(スタジオの作業データの evals\marks の 30 日以内のいちばん新しいもの)で、友人の区間が 20 個以上・配信 5 本以上。足りない間は今までどおりスタジオの設定の長さ。
    ユーザー自身のまとめて実行・スタジオの画面での解析には効きません。解析済みの配信を長さの違いで解析し直すこともしません。
    止めるときはホームの設定 autorun.friendLength = false か、環境変数 YTT_FRIEND_LENGTH=off

■ 依頼の「配信者」: 人ごとの字幕の色・URL の依頼にも配信者
  - 友人のアプリの依頼を受ける: 「配信者」の人ごとに字幕の色(6 桁のカラーコード)を指定できる。

  - 配信の URL の依頼にも配信者(1 人目の名前)が付く: メンバーと合えば、チャンネル名からの自動より優先して字幕の色に使う。合わない・無いときは今までどおり
  - 受付の一覧には「配信者: n人(…)・色の指定 n人」、字幕の色の元の人は「字幕の色: 名前」と出します
  - 2.0.0 までのアプリの依頼も受け付けます

■ リアルタイム切り抜きの書き出しの音量・開始の補正・画質(音量と反応の遅れはスタジオに合わせる)

■ リアルタイム切り抜き(試験中・既定はオフ)のマークと書き出し
  - リアルタイム切り抜き(試験中・既定はオフ)のマークと書き出し(線 D の P2。src\home\live_export.py): 録画の画面で再生しながら

    文字起こしへ(「まとめて実行」の文字起こしだけの形で順番に入れる。切れる)。状態(録画待ち・取得中・作り直し中・済み・失敗と理由)と取り消しは画面に。

■ 精度の自動測定
  - 精度の自動測定(src\home\accuracy.py): 「詳しく」→「調子」に「精度」の行(文字起こし・盛り上がり・話者・カットの領域ごとに
    直近の数字・前回・測った日時・文書数)と「精度を今すぐ測る」。夜(既定 1〜6 時。設定 accuracy の nightFrom・nightTo)に手が空いていれば 1 日 1 回、

    手が空いたとは、重い処理・「編集」のジョブ・まとめて実行が動いておらず、文字起こしの文書の更新から 30 分たっていること。
    設定の enabled は既定でオン(軽く、作業データは読むだけ)。認識し直す重い測定は入れていません。記録: app\accuracy-state.json。API: GET api/accuracy・POST api/accuracy/run
    自動の測定が作った結果ファイルだけ、領域ごとに新しい 30 件を残して古いものを消す(手で流した結果は消さない)

■ 異常終了の見張り

  (予期しない電源断 Kernel-Power 41・EventLog 6008・ハードのエラー WHEA)とアプリの落ち(Application Error 1000。python・ffmpeg・msedge・chrome・whisper-cli・llama-server など exe の名前ごと)を数え、

  読めないときは「読めませんでした」。数えるのは作業データの大きさと同じ別のスレッド(10 分持つ。「数え直す」で即)。src/home/health.py の crash_counts

  - zip の作り方は src/home/deliver.py の1か所(① 全自動の届け方 autorun._deliver_one も同じものを使う)。zip は Dropbox の外で作ってから移す
  - 送れるのは cut2resolve が作ったパックのフォルダだけ(ytt_core.txindex.is_pack_dir)。数 GB の zip は裏で作り、画面は状態を聞き直す。同時に作るのは1本

■ 一覧の項目を任意に非表示に
  - 増えていく一覧の項目を、行の「非表示にする」で隠せます: 案件(配信ごと)・次にやること(校正待ち・パック待ちの1行ずつ。実行中は隠せない)・
    単体の文字起こし・届いた依頼・まとめて実行の記録。スタジオ ③ の配信の一覧・「編集」の履歴も同じ部品
  - 隠しても、データ(案件の状態・メモ・文字起こし・記録)は消さない。一覧の上の「非表示 n件を表示」で薄く出し、「表示に戻す」で戻す。
    「非表示 n件を表示」はその画面の間だけ(開き直すと、また隠れている)。隠した直後の知らせの「元に戻す」でも戻せる
  - 案件を隠すと、その案件の校正待ち・パック待ちは「次にやること」にも出ない。文字起こしを(ここか「編集」の履歴で)隠すと、その文書も出ない。
    まとめて実行中の案件は、隠していても一覧に出す
  - 覚える場所はホームの設定(prefs.json)の節 hidden(一覧ごとに 2000 件まで。超えたら古いものからまた見えるようになる)。どの窓・ツールで隠しても同じで、
    別の窓で隠した分は、その窓に戻ったときに読み直す。ホームから開いていない(合言葉のない)画面では、非表示の操作は出ない
  - API: api/ytt/prefs の op "hide"({list, ids, hidden})。部品は ui-kit の UIKit.hide

■ 作業データのバックアップ
  - ホームに「作業データのバックアップ」があります。写す先のフォルダ(作業データとは別のドライブ)を決めてオンにすると、入口が動いている間、
    決めた間隔(既定 1 時間)で作業データを <写す先>\youtube-tools-data\ へ写す。オンにしたとき・先を変えたときは、すぐ1回写す。「今すぐ写す」もある
  - 写すもの: 文字起こしと校正・カット・スタジオの data.json とマーク・採用の記録・設定・声の登録・パックの記録・案件。
    写さないもの: キャッシュ(cache)・一時ファイル(work)・ログ・モデル(models)・実行ファイル(bin)・ブラウザのプロファイル・書き出した動画(exports)
  - 変わったファイルだけを写す。写した先のファイルは消さない。上書きするときは、その日の最初の1回だけ 1つ前を「.prev」の名前で残す
  - API キーの設定(studio\config.json)も写るので、写す先は自分の PC のドライブにする(共有・クラウドのフォルダは避ける)
  - 戻すとき: 入口を「すべて終了」してから、<写す先>\youtube-tools-data\ の中身を %LOCALAPPDATA%\youtube-tools\ へ写す
  - 設定はホームの設定(prefs.json)の節 backup。部品は src/home/backup.py。API は GET /api/backup・POST /api/backup/run

■ 依頼の時間指定・カット・解析の重み
  - 友人が配信の URL に「区間(開始〜終了)」を付けて送れる(依頼の JSON の items[].ranges)。区間の前後に 2 秒の余白を足して切り抜く。
    区間が「切り抜く数」に足りない分だけ、自動の見どころ(点数の高い順・区間と重ならないもの)で埋める。区間が足りていれば解析はしない
    (その区間だけを取りに行くので速い)。③ 全部人が行う の依頼では区間は使わない(解析だけ)
  - 友人が ① 全自動のパックのカットを選べる(cut: none = カットしない / silence = 無音を削る)。指定の無い依頼はホームの設定(既定はカットしない)
  - 友人が解析の重み(音声・チャット・コメント。0〜3)を指定できる(weights)。解析済みの配信でも、重みが違えば解析し直す(取り込み済みのデータは使い回す)
  - 同じ配信の URL を前に受け付けていても断らない。解析・書き出した切り抜き・文字起こしは使い回し、① はパックを今回の設定で作り直して届ける
  - 依頼の一覧に「区間: 1:23:45〜1:25:10」「カット: 無音を削る」「重み: …」を出す
  - スタジオ 0.14.0 の API(POST /api/video/request-marks)を使う

■ 依頼の映像トラックの数

■ 運用の安定化(調子・片付け・起動し直す)
  - 依頼の受付: 見る間隔(秒)を設定の欄で変えられます(既定 30 秒)。友人のアプリからの依頼を受け付けなかったとき(形が正しくない・上限を超えた・動画が届かない など)、

  - 「詳しく(サーバーの管理)」の先頭に「調子」: 版・認識ワーカー・ffmpeg / yt-dlp・空き容量・作業データの大きさ・エラーの件数

  - ツールの画面の「入口」(ヘッダー・「他のツール」の先頭・案件の画面の「← 入口へ」)は、入口がほかの窓・タブで開いていれば、
    新しく開かずにその窓を前に出す。
    入口の画面が BroadcastChannel で答え(ui-kit v5 の UIKit.portal)、POST api/ytt/focus-portal で入口のサーバーが題名「動画編集ツール — 入口」の窓を探して前に出す
    (Windows。前面の窓のスレッドに入力をつないでから SetForegroundWindow。appwindow.focus_window)。前に出せないとき(ブラウザのタブで裏にあるなど)は
    「入口はほかの窓(タブ)で開いています」と知らせる。入口が開いていなければ、今までどおりその場で入口へ移る
  - まとめて実行に「配信者(字幕の色)」: 案件の画面(とスタジオ・「編集」の履歴)で名前を入れると、パックの字幕の文字をその人のメンバーカラーにする。
    POST /api/autorun/start・start-docs の streamer(始める前に照らし合わせ、見つからなければ 400)。候補は POST api/ytt/streamer-colors {q, all?}
    (画面の共通の API。ui-kit の UIKit.streamer が使う)。名前 → 色の規則は src/ytt_core/colors.py(ホロカラーの一覧とマイカラーを読むだけ)
  - マークの行の「この後を ▸」: そのマークだけを 書き出しから全部(② の口に mode full + 束の run.from export + marks。50 まで)。「編集」の題名の行の「まとめて実行 ▾」は start-docs を1本で使う
  - スタジオの ① 探す からのまとめて実行: POST /api/autorun/start-new {items: [{id, title, channel}], top?, streamer?}。
    まだスタジオに無い YouTube の配信を「解析から全部」で(配信ごとに1つの実行・10 本まで・すでに順番待ちの配信は skipped)。
    解析のキューに入れるまでは受け取った題名で進め、題名・配信者は解析のキューにも渡す

■ まとめて実行のパックと始められる場所(notes:docs/design/edit-tool-design.md の 12)
  - まとめて実行のパック: カットの無い文書は「編集」の「行から」の設定(行の端を声の止まる所まで広げるか)で作る。パックは最小限(cut2resolve の既定)。
    Text+ 字幕の改行は「編集」の字幕の文字数の設定(縦の改行の文字数)
  - まとめて実行を、案件の画面のほかに、スタジオの配信の画面(同じ API)と「編集」の履歴(選んだ文書を 文字起こし → パック。
    POST /api/autorun/start-docs。文書ごとの実行・同じ文書の二重の登録は断る・パックがあれば既定で飛ばす(作り直すで上書き)・カットがあればカットのとおり)から始められる
  - 「パック済み」(案件の一覧・まとめて実行が作り直さない判定)は、cut2resolve の「パックを作った記録」か、cut-plan.json でも見る(src/ytt_core/txindex)

■ 「編集」: 文字起こし + cut2resolve の統合(notes:docs/design/edit-tool-design.md)
  - 入口のカード: 文字起こしツールは「編集」、cut2resolve はカードを出さない(部品。止まっているときだけ、起動のためにカードを出す)。流れは ① スタジオ → ② 編集
  - /cut2resolve/ の画面を開くと /transcribe/(「編集」)へ転送する(?video= は ?media= にして渡す。src/home/mount.py の page_to)。API(/cut2resolve/api/…)はそのまま
  - 案件の一覧の切り抜きの行は「編集で開く」の1つに
  - まとめて実行のパック: 「編集」でカットを決めてある文書はそのとおり(cut2resolve の spec.keeps)に作り、作った記録を「編集」に残す(作り直しの知らせ)。
    カットの無い文書は文字起こしの行だけを残す規則

■ 案件の一覧(1 件 1 行)・入口の使いやすさ
  - 案件(配信ごと)の一覧を、配信1本 = 1行にしています。
    行には配信の題名・配信者・いつの配信か・状態・切り抜きの数・
    文字起こしの校正の進み具合・パックの有無・「次にやること」(書き出し/文字起こし/校正/パックを作る、のうち
    いちばん先に残っている作業)を出す。行を開くと、切り抜きの一覧・まとめて実行・メモが今までどおり出る
  - 一覧の上に道具の行: 検索(題名・配信者)・状態の絞り込み・並び替え(新しい順・次にやることが多い順・配信者順・
    題名)・件数。絞り込んだ分だけ描き、「もっと見る」で 30 件ずつ増やす
    (配信が多くても重くならない)。まとめて実行が動いている行は、進み具合を見失わないよう閉じない。
    選んだ絞り込み・並び替えはブラウザに覚えさせる(まとめ方は 10-24 に消した)
  - 切り抜き1件の行は、状態の札とボタンを見分けやすく整理し、動画のフルパスは常には出さず、ファイル名だけ見せて
    フルパスはマウスを乗せたときだけに
  - 入口の「すべて終了」の確認(2回押し)に、あと何秒で確認が消えるかを表示するようにした
  - 狭い画面(390px)で「まとめて実行」などのラベルの文字が1文字ずつ縦に割れる不具合を、入口・案件の画面の CSS で防いだ
  - 案件の一覧が使う項目(配信の日時の目安・文字起こしの校正の進み具合の合計・パックの有無の合計・「次にやること」)を
    入口の /api/cases に含まれます(各ツールのデータは読むだけ)

■ 窓で開く・画面のエラーの記録
  - 窓で開く(src/home/appwindow.py): 入口の画面の「窓で開く」がオンのとき(既定)、Microsoft Edge のアプリモード
    (--app=<URL> --user-data-dir=<専用のプロファイル>)の窓で開く。オフにするといつものブラウザで開く。設定は %LOCALAPPDATA%\youtube-tools\app\settings.json の "window"。
    Edge が見つからない・起動できないときは、いつものブラウザで開く。環境変数 YTT_APP_BROWSER で使うプログラムを変えられる(Chrome など Chromium 系)
    - 窓の中の「新しいタブで開く」リンクは、画面(ui-kit の UIKit.win)が入口に頼んで開く: このパソコンの画面 → 同じ形の窓、外のサイト → いつものブラウザ
    - 窓で開けるのは入口と、動いているツールのポートの画面だけ。外のサイトは http / https だけ。10 秒に 8 回まで(画面の不具合・XSS で窓を大量に開かせない)
    - リモートデバッグのポートは開かない。窓を閉じても入口は終わらない(終わるのは「すべて終了」)
  - 画面のエラーの記録(src/home/clientlog.py): 入口と3ツールの画面で捕まえられなかったエラー(error・unhandledrejection)を
    %LOCALAPPDATA%\youtube-tools\app\logs\client-errors.jsonl に1行1件の JSON で残す(1分に30件まで・512KB で .1 に回す)。
    /api/log?tool=client で末尾を読める
  - 画面の共通の API(api/ytt/client-log・open-window・open-external): 入口の画面は /api/ytt/…、取り込んだツールの画面は /studio/api/ytt/… などの
    相対パスで呼び、どちらも入口が受け持つ(src/home/mount.py がツールに渡さず入口へ回す)。検査は入口の API と同じ(POST・Host・Origin・Sec-Fetch-Site・合言葉・16KB まで)
  - POST /api/window {mode: browser|app}(合言葉つき)、/api/status に window {mode, available, browser, profile}
  - まとめて実行の「解析から全部」は、スタジオの ② で保存した解析の設定(スタジオの /api/settings の analyze)で解析する

■ まとめて実行・コミット前の検査
  - 案件の画面の各配信に「まとめて実行」(src/app/autorun.py)。押すと、残りの作業を順に自動で進める。形は解析から全部だけ(2026-10-19):
      未解析なら解析 → 人の採用 + 自動マークの点数の高いものを指定の数まで採用 → … → パック(人が採用した配信にも自動の候補の上位を採用する数まで足す。人が選んだ 1 本だけ進めるときは、案件の画面の候補のマークの行の「この後を」)
    各ツールの画面と同じ API を順に呼ぶ(同じ検査・同じジョブ管理・重い処理の順番待ち)。まだ無いものだけを作るので、止めてももう一度押せば続きから。
    書き出しはスタジオの ③ の設定、文字起こしは文字起こしツールの設定を使う。
    パックは文字起こしの行だけを残す規則と Text+(字幕は校正前。校正したら cut2resolve で作り直す)。同じ名前のパックがあれば作らない。
    自動で採用したマークは、学習の記録(スタジオの feedback)に入れない。1本ずつ順に処理し、入口を終えると順番待ちの分は消える
    API: GET /api/autorun・POST /api/autorun/start {id, mode, top?}・POST /api/autorun/cancel {runId}(合言葉つき)
  - push.bat: コミットの前に dev\removals.txt のファイルを git rm し、送るファイルに個人データ・秘密情報らしいものがあれば止める(dev\push_helper.py)
  - 各ツールの start.bat・start.command はありません。使い方はリポジトリ直下の README.txt に一本化しています

■ 案件の画面・重い処理の同時実行の上限
  - 「案件(配信ごと)の一覧」の画面(http://localhost:8700/cases)。
    切り抜きスタジオの配信1本ごとに、書き出した切り抜き・文字起こし(校正の進み具合)・Resolve 用のパックの有無を並べる。
    紐づけは開くたびに各ツールのデータから組み立て直す(各ツールのデータは読むだけ)。
    人が付ける「状態」(作業中・投稿済み・見送り)と「メモ」だけを %LOCALAPPDATA%\youtube-tools\app\cases.json に保存する。
    状態かメモを付けた案件は、スタジオから配信を消しても最後に見えた内容で残る
  - 重い処理(スタジオの解析・書き出し、文字起こし、cut2resolve のパック作り)は、入口の中で合わせて同時に 2 つまで(src/ytt_core/jobs.py)。
    3つ目からは順番待ち(各ツールの画面に「他のツールの処理が終わるのを待っています」)。上限は環境変数 YTT_MAX_HEAVY_JOBS(1〜8)。
    (serve.py を直接起動したときは、そのツールの中だけで数える)
  - 入口の /api/status に heavy(上限・実行中・順番待ち)を返す

■ 作業データの置き場所
  - 3つのツールの作業データ・設定・記録の置き場所を %LOCALAPPDATA%\youtube-tools です(notes:docs/spec/data.md)。
    最初の起動で、各ツールのフォルダにある以前のデータをコピーする(元は消さない)。入口の画面には出さない(置き場所とパスのコピーの欄は 10-24 に無くした)
  - 入口とツールの出力の記録は %LOCALAPPDATA%\youtube-tools\app\logs

■ 文字起こしの取り込みと認識ワーカー
  - 文字起こしも入口の中に取り込む(/transcribe/)。認識は別のプログラム(tx_worker.py)で動き、落ちてもその文字起こしが失敗になるだけで、
    入口・スタジオ・cut2resolve は止まらない(次の文字起こしで自動的に起動し直す)。認識の記録は transcribe-tool\worker.log
  - 「すべて終了」では、文字起こしの待っている・動いているジョブを取り消し、認識のプログラムも終わらせる

■ cut2resolve の取り込み
  - cut2resolve も入口の中に取り込む(/cut2resolve/)。CSP は cut2resolve 自身のもの(script-src 'self')をそのまま使う
  - 取り込むツールの CSP がインラインのスクリプトを許していれば、取り込まずに別のプログラムとして起動する

■ 切り抜きスタジオの取り込みと安全の仕組み
  - 切り抜きスタジオを入口の中に取り込む(/studio/)。取り込めないときは自動で別のプログラムとして起動。--no-mount で別のプログラムとして起動
  - 書き込みの操作に合言葉(CSRF トークン)、取り込んだ画面に CSP
  - 1つのポートで入口と取り込んだツールの両方を受け持つ(要求の最初の行を覗いて振り分ける)
