cut2resolve v0.22.3(「編集」の部品・コマンド)
==================================================

切り抜いた動画に「カット」と「字幕」を入れて、DaVinci Resolve(以下 Resolve)で続きを編集できる形(パック)にして渡すツールです。
動画そのものは作り直さず、「どこを残すか」の指示(EDL)と、カット後の時刻に直した字幕(SRT)を作ります。
  EDL … 編集ソフトどうしでカットの位置を受け渡すための、昔からある文字のファイル。Resolve の「読み込み → タイムライン」で読めます。
すべてこのパソコンの中で処理し、動画や字幕を外部に送りません。


■ 準備
  - Python 3(https://www.python.org/downloads/ 。インストール時に「Add python.exe to PATH」にチェック)
  - ffmpeg / ffprobe(文字起こしツール・切り抜きスタジオと同じもの)
  - serve.py(API)はリポジトリのフォルダのまま使う(隣の ytt_core フォルダの共通部品を使う。コマンドの cut2resolve.py は単体でも動く)


■ 画面は「編集」に統合しました(v0.11.0・2026-09-26)
  cut2resolve の画面(index.html・app.js・app.css)は消しました。同じことは「編集」(入口のカードの「編集」、http://localhost:8700/transcribe/)でできます。
  入口の中で http://localhost:8700/cut2resolve/ を開くと「編集」へ移ります(?video= で渡した動画は「編集」で開きます)。
    前の画面                              「編集」では
    ① 無音で自動                          2 カット のタブの「たたき台: 無音 ▾」(音量・長さ・前後に残す秒数)
    ② 残す区間(文字起こし・スタジオ)     2 カット のタブの「行から」「スタジオ」(スタジオの残す区間があるときだけ出る)
    ③ 時刻リスト                          2 カット のタブの「たたき台: 時刻リスト ▾」
    試算・カット後の見え方                 2 カット のタブのプレビュー(削った所を飛ばして再生)と、3 パック のタブの「これから作るパック」
    書き出し(Text+ パック・粗編集の動画)   3 パック のタブ(置き先の fps・大きさ・粗編集の動画・タイムコード・リール名・出力先・上書きの確認・中止)
  たたき台は区間を決める出発点で、そのあとタイムラインで手で直せます。文字起こしをしていない動画も「文字起こしせずに開く」で開けます。
  補助の FCPXML(Resolve では未確認)は画面から外しました。要るときはコマンド(--fcpxml)で作れます。
  このフォルダは、パックを作る部品(pack.py。パックを作るのはここだけ)・API(serve.py。「編集」とまとめて実行が使う)・コマンドとして残ります。


■ API(serve.py。入口の中の /cut2resolve/api/...)
  - あるのは GET api/ping・api/siblings・api/job?id=(ジョブの状態)と、POST api/plan(試算。ジョブ)・api/build(パックを作る。ジョブ)・
    api/job/cancel・api/open-folder(パックのフォルダだけ)。書き込み系は合言葉(X-YTT-Token)が要る。呼ぶのは「編集」(2 カット・3 パック)と入口の「まとめて実行」
  - v0.22.0 で消した API(消した画面のためのもので、使う側が無かった): api/state・api/inspect・api/upload・media/<合言葉>(動画の配信)と、
    plan・build の結果の mediaUrl・roughcutUrl。消した API は 404 を返す
  - spec.keeps(v0.11.0): 残す区間を秒の組 [[開始, 終了], …] でそのまま渡す(「編集」のカット)。余白・最短・つなぎ・無音検出はしない(pack.EDIT_KEEPS)。
    preset と一緒には使えない。0.5 秒より短い区間は注意を出す。上限 5000 区間
  - 文字起こしの行から作るとき(preset "transcript-rows"・mode keep の keepSource "transcript"・コマンドの --keep-rows)は、
    区間の端を声の止まる所まで広げる(pack.ROW_EDGE。語頭・語尾が切れないように。終わりは 0.5 秒先・始まりは 0.3 秒前までの無音
    (-35dB・0.15 秒以上)まで。無音が無ければ 前 0.1 秒・後 0.2 秒。カット済の行は越えない)。spec.rowEdge = false で広げない・
    {"after": 秒, "before": 秒} で上限を変える(0〜2 秒)・{"padAfter": 秒}(v0.16.0)で無音が無いときの「後の余白」を変える(0〜2 秒。前の余白 0.1 秒は変えない。
    padAfter が after より大きいときは after も padAfter まで上げる)。{"on": false} でも広げない(padAfter は無視)。コマンドは --no-row-edge で広げない。keeps・時刻リスト・スタジオの区間には使わない
  - 重なる字幕(v0.21.0): Text+ のパックは、カットで詰めたあとの時刻で 0.3 秒以上重なる字幕を別の段に分ける(最大 3 段。計算は resolve_textplus.stack_captions の 1 か所)。
    段 1 = 今までの字幕のトラック、段 2・3 = その上のトラック(映像トラックが N 本なら V(N+1)〜V(N+3))で、縦の位置を上へ 0.2 ずつずらす(LANE_STEP_Y。仮の値 = 実機で見て決める)。
    0.3 秒未満の重なりは、前の字幕の終わりを次の始まりで切る。一度置いた字幕は動かさず、空いているいちばん下の段へ入れる。重なりの無いパックは今までと同じ中身。
    見積もり(summary)に captionLanes・captionsStacked・captionsTrimmed。SRT・EDL は重なったまま。字幕ごとの話者は、字幕を作った行から直接たどる(重なる行でも正しい人の色)
  - 字幕に出さない行(v0.21.0): 文字起こしの行の noSub: true は、時間は残す区間に数え、字幕は作らない(pack.row_has_caption)。段分けは noSub を外したあとで数える。見積もりに noSubRows
  - output.speakerStyles(v0.21.0): {"話者の名前": {"color": "#RRGGBB" か "RRGGBB"}} = 話者ごとの字幕の見た目(今は色だけ。検査は serve.SPEAKER_STYLE_KEYS の許可の一覧。知らない鍵は捨てる)。
    色の決まり方: 指定の色 → メンバーカラー(speakerColors が真のとき)→ 配信者の色 → 黒。指定は speakerColors が false でも効く。名前は ytt_core.colors.normalize でそろえて同じときだけ
  - / と /index.html は「画面は「編集」に統合しました」の案内だけを返す(スクリプトなし)
  - パックは最小限(v0.12.0・v0.13.0): Text+ パックは動画(フォルダの直下)・create_resolve_textplus_project.lua・textplus-template.drb・登録用の .ps1 と .bat だけ。
    手順書(友人へ.txt)は API では書かず、結果の readme(画面の「Resolve での手順を見る」)で返す。コマンドは今までどおり 友人へ.txt も書く。
    output.backup = true のときだけ予備(EDL・予備_EDLで開く手順.txt・カット後の SRT)も。Text+ の計画の .json(textplus-import.json)は出さない(Lua に埋め込み済み)。
    cut-plan.json はフォルダに置かず、作業データの packs\<ハッシュ>.json(パックを作った記録。%LOCALAPPDATA%\youtube-tools\cut2resolve\packs)に残す。
    「パック済み」「フォルダを開く」はこの記録か、以前のパックの cut-plan.json で決める(ytt_core/txindex.py)
  - コマンド(cut2resolve.py)は今までどおり、EDL・SRT・友人へ.txt・cut-plan.json をフォルダに書く(Text+ の .json だけは出さない)


■ Resolve での読み込み(友人へ.txt にも同じ手順が入ります)
  1. 元動画をメディアプールに入れる
  2. ファイル → 読み込み → タイムライン → EDL を選ぶ(クリップ名で動画と結び付きます)
  3. 字幕: ファイル → 読み込み → 字幕 で SRT を入れ、タイムラインにドラッグ
  ※ 縦動画(Shorts)はタイムラインの解像度を 1080x1920 にしてください。
  Text+ 用パックを選んだ場合は、出力内の「Text+の使い方.txt」に沿って登録し、fps・解像度が合うテストプロジェクトで実行してください。


■ 単独のコマンド(手で使う道具。ytt_core を読まないので、このフォルダだけでも動く)
  - cut2resolve.py(パックを作る。中身は API と同じ pack.py): python cut2resolve.py 動画.mp4 カットリスト.txt [字幕.srt]
    (出力は <動画名>_pack/。以前のシンプル版 cut2resolve_simple.bat は 2026-09-26 に廃止)。cut2resolve.bat に動画・字幕などをドロップ(フル版。無音カット+粗編集つき)
  - auto_cut.py(採用区間 JSON = youtube-tools-cut-plan/v1 から、前後の余白つきの EDL・FCPXML・SRT・cut-plan.json): python auto_cut.py 動画.mp4 採用区間.json [字幕.srt]
  - srt2resolve.py(カットせず、動画 + 字幕から FCPXML(字幕をタイトルとして並べる)と、フレームに丸めた SRT): python srt2resolve.py 動画.mp4 字幕.srt
  - 補助の FCPXML(カット済みのタイムライン + 字幕のタイトル。Resolve の実機では未確認): python cut2resolve.py … --fcpxml
  python cut2resolve.py --help / python auto_cut.py --help / python srt2resolve.py --help で全オプション
  Text+ パックは python cut2resolve.py 動画.mp4 字幕.srt --textplus で作成できます(--textplus-fps 60 / --textplus-size 1920x1080 で置き先を変更)。
  スタジオの余白つき素材を使わないときは --no-edit-media。
  出力先にファイルがあるときは止まります。上書きは --force。
  上書きのとき、前に写した動画が元の動画と同じ大きさ・更新日時なら、動画のコピーは飛ばします(v0.22.1。音量をそろえるときは作り直す。
  音量をかけた写しを飛ばすのは「編集」・まとめて実行(API)のときだけ。v0.22.2)。


■ 受け渡しの形式
  docs/spec/pipeline.md(リポジトリ直下)を参照。youtube-tools-transcript/v1・youtube-tools-cut-plan/v1 を読みます。


■ 注意
  - 可変フレームレート(VFR)の動画は EDL の時刻がずれることがあります(警告が出ます)。
  - AV1 / H.265 / 10bit の動画は無料版の Resolve で再生できないことがあります。
  - API のサーバーは 127.0.0.1(このパソコン)からだけ使えます。動画は配信しません(v0.22.0 で動画の配信 media/ を消しました)。
  - ログ: %LOCALAPPDATA%\youtube-tools\cut2resolve\work\serve.log(2026-09-26 まではこのフォルダの work\ の中)


■ v0.22.3 の変更点(2026-10-09・内部の整理。動きは同じ。直した不具合 2 つ)
  - 直した不具合 1: API の試算(api/plan)が、無音の検出(動画の音声を全部読む重い処理)が要るときも、他のツールの重い処理の順番(ytt_core.jobs の SLOTS)を
    待たずに走っていた(パックの作成 api/build と「編集」の行の端の検出は待っていた)。今は、無音で削る(mode silence・無音を重ねる)試算と、行の端を声の止まる所まで
    広げる試算のうち、検出結果がまだ覚えてないものだけ順番を待つ(待っている間は「他のツールの処理が終わるのを待っています」。「取り消す」で止められる)。
    検出が要らない試算(時刻リスト・残す区間・検出結果が覚えてある試算)は今までどおり待たない
  - 直した不具合 2: 一時ファイルの付け替えのやり直し(srt2resolve の _replace_retry)が、読み取り専用のフォルダなど待っても直らない拒否(PermissionError)まで
    6 回待っていた。ytt_core の fsio と同じ規則(Windows の一時的なロック winerror 5・32・33 だけ 0.1 → 0.2 → 0.4 秒で 4 回まで)にそろえた
    (単独のコマンドは ytt_core を読まないので、規則だけ写してある)
  - 内部の整理: 指定を省いたときの値(無音 -35 dB・0.6 秒・0.15 秒、画質 crf 18、開始タイムコード 01:00:00:00、リール AX)の正を cut2resolve_core の DEFAULT_* と
    pack.Request の 1 か所に(API の serve.py とコマンドの cut2resolve.py は読むだけ。コマンドの --help の「既定」はここから出る)・
    一時ファイルに書いて付け替える処理を srt2resolve.staged に 1 つ・Text+ の手順書は Text+ の計画から 1 回だけ作る(新しいパックの「手順を見る」と
    前のパックの「手順を見る」が必ず同じになる)・応答の見出し、本文の読み方、ログの回し、待ち受けの独占は ytt_core の部品に(見出しの中身・状態コード・エラーの文は同じ)
  - 小さな変化(動きは同じ): 残す区間(spec.keeps)に無限大の時刻を送ると、エラーの文が「時刻は数で指定してください」になる(どちらも 400 bad_keeps)

■ v0.22.2 の変更点(2026-10-07・音量をかけた写しも飛ばす。E-15 の続き)
  - 「編集」の既定(音量 30%)のように音量をかけて動画を写すとき(音量 %・音量をそろえる。cut2resolve_core.copy_video_gain)も、前と同じ条件なら
    作り直さない。条件 = 元の動画(名前・大きさ・更新日時の秒)・実際にかける量(dB。ffmpeg に渡す小数 2 桁)・書き出しの設定(音声の形式・ビットレート・
    開始タイムコードなど ffmpeg の出力のオプション)。加えて、置き場所の動画が前に写したときのまま(名前・大きさ・更新日時の秒)であること。
    1 つでも違えば今までどおり作り直す。飛ばしたときは結果の注意に「動画 ○○ は前に同じ音量(-10.5 dB)をかけて写したものと同じ…コピーを飛ばしました。」(info)
  - 記録の置き場所: 作業データの「パックを作った記録」(packs/<フォルダのハッシュ>.json)に鍵 videoCopy を足した(形はそのまま。ytt_core.txindex は
    この鍵を読まない)。パックのフォルダには何も足さない(友人に渡すフォルダを最小限にする・隠しファイルを置かない 2026-09-26/27 の決まりのため)。
    そのため飛ばすのは記録を書く API(「編集」の 3 パック・入口のまとめて実行)のときだけで、コマンド(cut2resolve.py)では今までどおり毎回作り直す
    (コマンドは音量の指定が無いので、音量をかけた写しを作らない)。パックのフォルダを動かした・消したときは記録と合わないので作り直す
  - 音量をそろえる(LUFS)ときは、残す区間の音量の測定は毎回する(カットが変わるとかける量が変わるため)。測った量が前と同じ(小数 2 桁)なら写しを飛ばす
  - 判定は cut2resolve_core.same_gain_copy の 1 か所(条件は gain_copy_key・記録は gain_copy_record)。パックの中身(EDL・SRT・Lua・cut-plan)は変えていない

■ v0.22.1 の変更点(2026-10-07・同じ動画はコピーを飛ばす。「気が利く画面へ」段 7 の E-15)
  - パックに動画を入れるとき(Text+ パック・--copy-video・auto_cut.py --copy-video)、置き場所に同じ名前の動画があり、大きさと更新日時(秒単位)が
    元の動画と同じなら、コピーを飛ばして前に写したものをそのまま使う。結果の注意(warnings)に「動画 ○○ は前に写したものと同じ…コピーを飛ばしました。」を
    1 行出す(API の warningLevels は info)。違えば今までどおり上書きでコピーする(写した動画の更新日時は元に合わせる。前からそう)
  - 理由: 同じ場所にパックを作り直すたびに数 GB の動画を写し直していた。比べ方は rsync の既定と同じで中身は読まない(読み比べると写し直すのと同じくらいかかる)。
    写した動画は更新日時を元に合わせてあるので、元の動画を作り直した(スタジオで書き出し直した)ときは更新日時が変わり、コピーし直す
  - 音量をそろえる・音量 % のとき(音声を作り直す。cut2resolve_core.copy_video_gain)は対象外で、毎回作り直す(→ v0.22.2 で前と同じ条件なら飛ばす)
  - 動画が同じなら置き換えないので、Resolve などが前のパックの動画を開いたままでも、動画の置き換えで止まらない
    (Windows では開かれているファイルを置き換えられないことがある。Resolve の実機では未確認)
  - 判定は cut2resolve_core.same_copy の 1 か所。パックの中身(EDL・SRT・Lua・cut-plan)は変えていない
