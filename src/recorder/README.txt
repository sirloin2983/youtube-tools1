録画の部品(recorder) v0.3.2 — リアルタイム切り抜き(試験中)の録画
==========================================================================

配信中の YouTube を録画し、録画しながら見返せるようにする部品です(線 D の P1。計画: plan/line-d-live-clipping.md の 0)。
再生・マーク・書き出しの画面はスタジオの中です(P3。2026-10-05。以前の別の「録画の画面」は消しました)。書き出しはホームが行います。

■ 使い方
  1. ホームの「詳しく(サーバーの管理)」→「試験中の機能」で「リアルタイム切り抜き(試験中)」をオンにする(既定はオフ)
     → ホームが数秒〜30 秒のうちに、この部品を裏で起動します(黒い画面は出ません)
  2. スタジオの ② 解析の URL の欄に、配信中・配信前の YouTube の URL を入れる → 録画が始まり、③ 確認・書き出しでその録画が開きます
     配信の前でも始められます(始まると自動で録画します)。名前は配信の題が自動で付きます
  3. ③ のプレイヤーで、録画済みの所を再生・シークできます。「ライブ端へ」で最新へ
  4. 配信が終わると自動で「終了」になります。手で止めるときは、③ の LIVE の帯の「録画を止める」か、ヘッダーの「録画中」の札の「停止」
  5. マークと書き出し: いつものスタジオの操作でマーク → 「マークしたらすぐ書き出す」がオンなら自動で書き出し。
     終わりの時刻まで録画が届くのを待ってから、ホームが区間のセグメントだけをこの部品から取り、30fps に作り直して、
     スタジオの書き出し先(配信の名前のフォルダ)に置きます。
     区間に録画の欠け(繋ぎ直しの間)があるときは書き出さずに「要差し替え」と出ます(配信のあと、アーカイブから作り直せます)
  6. 配信のあと: アーカイブが用意できたら、書き出した切り抜きを本番の画質で作り直して、同じ名前で入れ替えます(自動。スタジオの帯の「アーカイブで作り直す」でも)。
     全部入れ替わった録画は消します(下の「録画の置き場所」)

  オフの間は、画面にも出ず、この部品も起動しません(入口の動きは今までと同じです)。

■ 録画の置き場所
  既定は E:\Video\live-rec\ です。スタジオの設定(⚙)の「ライブの録画」で変えられます(録画中は変えられません)。
  ドライブが無いときは、作業データの中へ勝手に逃がさず、画面に案内を出して録画を始められないようにします。
  1時間あたり約 3〜4GB 使います。空きが 1GB を切ると録画を止めます。
  録画は自動で消します(2026-10-05 から。スタジオの設定の「ライブの録画」の「本番版に入れ替えたら録画を消す」でオフにできます):
    ・書き出したマークが全部、アーカイブから作り直した本番版に入れ替わった録画 … すぐ
    ・マークが 1 つも無い録画(試しに始めて止めた・見ただけ)… 終わって 24 時間
  1 本でも作り直せなかったマーク・採用のまま書き出していないマークがある録画は消しません。録画中・配信待ちの録画も消しません。
  空き容量はスタジオの設定の「ライブの録画」と、ホームの「調子」(オンのときだけ「録画元」の行)に出ます。

  <置き場所>\<録画の id>\recording.json          録画の記録
  <置き場所>\<録画の id>\session_001\index.m3u8   セグメントの一覧(HLS)
  <置き場所>\<録画の id>\session_001\seg_000000.ts 4 秒ごとのセグメント(配信をそのまま写したもの。作り直さない)
  切れて繋ぎ直すたびに session_002・003… が増えます。

■ 切れたとき・落ちたとき
  - 配信が切れたら 5 → 10 → 30 秒(以後 30 秒ごと)の間を空けて繋ぎ直します。10 分繋がらなければ「終了」にします
  - この部品が落ちた・PC を起動し直した: 次に起動したとき、書きかけのファイルを片付け、録画中だった物は新しいセッションで続けます
    (ホームがオンの間は 30 秒ごとに見回って、止まっていれば起こし直します)
  - ホームの「すべて終了」・黒い画面を閉じる・「起動し直す」では、録画は止まりません

■ ログインしたら自動で
  ホームを裏で起動するショートカット(src\home\start_hidden.vbs を shell:startup に置く。src\home\README.txt の「裏で動かす」)を使えば、
  ホームがこの部品も起こします(リアルタイム切り抜きがオンのときだけ)。

■ 入れる物
  streamlink(配信の取得)。setup\install.bat で入ります(setup\requirements.txt に版を固定)。ffmpeg は今までどおり。

■ 作業データ(リポジトリの外)
  %LOCALAPPDATA%\youtube-tools\recorder\  token.txt(合言葉)・settings.json(置き場所)・logs\recorder.log
  ホームから起動したときの黒い画面の出力: %LOCALAPPDATA%\youtube-tools\app\logs\recorder.log

■ 変更の記録
  v0.3.2(2026-10-07) 録画の記録(recording.json)の sessions が null・リストでない(手で書き換えた)ときも、起動時の復旧で落ちず、
                       空(dict でない物は除く)として読む。ほかは内部の整理(子を閉じるジョブ・窓を出さない指定は共通部品 ytt_core の物に)
  v0.3.1(2026-10-07) 内部の整理。動きは同じ(API・録画のファイル・既定の値・streamlink と ffmpeg の呼び方は変えていない。
                       録画中に書き換わる再生リストを読み直すとき、前に確かめたセグメントのファイルを調べ直さない)
  v0.3.0(2026-10-05) 録画を消す API(POST /live/<録画>/delete。録画中は消さない・置き場所の直下の録画のフォルダだけ)。
                       ホームが、本番版に入れ替え終わった録画・マークの無い録画を自動で消すのに使う
  v0.2.2(2026-10-05) 名前を入れずに始めた録画に、配信の題を自動で付ける(YouTube の oEmbed。取れなければ題なしのまま録画は続く)。
                       画面はスタジオの中へ(P3。別の「録画の画面」は消した)
  v0.2.1(2026-10-04) 録画の画質の既定を 1080p に(ユーザー決定。4K の配信で容量が膨らむのを避ける。720p・いちばん良い(best)も選べる)
  v0.2.0(2026-10-04) P2: 区間の取得 GET /live/<録画>/segments?start=&end=(区間にかかるセグメントと欠け・録画済みの最後の時刻。
                       ホームの書き出しの「録画待ち」と「取得」が使う)
  v0.1.0(2026-10-04) 最初の版(P1): streamlink + ffmpeg の HLS 録画・繋ぎ直し・起動時の復旧・HTTP の API(合言葉)・
                       ホームの中継と録画の画面(hls.js)・「調子」の行
