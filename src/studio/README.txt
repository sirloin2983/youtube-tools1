【スタジオの画面はありません】
  スタジオの画面(/studio/)は、案件の画面とホームにまとめました。使い方の全体はリポジトリ直下の README.txt。
    ① 探す・URL から入れる・解析の順番待ち … ホームの「新しい案件」(引き出し。中身は rank.js・queue.js のまま)
    ② 確認・書き出し                       … 案件の画面(/cases?c=<配信の id>#cand)の「候補」(中身は review.js のまま)
    ⚙ の API キー・事務所の登録・コラボ     … ホームの「新しい案件」の末尾の「探す設定」(コラボは collab.js のまま)
    ⚙ の出力先・ライブの録画の表示          … 設定の画面(/settings)
  配信は /cases?c=<配信の id>#cand で開きます。API は /studio/api/…、作業データと識別子は clip-studio です。
  画面の部品 rank.js・queue.js・review.js・collab.js は src/app/ui/studio/ にあります(URL の /studio/rank.js などは serve.py の STATIC が UI_DIR から配ります)。
  以下の説明の「① ② のタブ」「ヘッダーの設定(⚙)」は、案件の画面・ホームの対応する場所に読み替えてください。

【これは何?】
  「配信ランキング」「自動切り抜き」「切り抜きマーカー」の3つを1つにまとめたツールです。
    ① 探す      ホロライブ・にじさんじ・ぶいすぽっ!・ネオポルテの人気配信を一覧にし、解析したい配信にチェック。
                先頭の「URL から入れる」で配信の URL を直接入れることもできます。選んだ配信は順番に自動解析
                (音量・チャット・コメント欄)し、順番待ちはその右に出ます。解析の設定(本数・長さ・感度など)は設定の画面(ホームの ⚙ → 設定の画面を開く)
    ② 確認      自動で付いたマークをプレイヤーで見ながら直し、必要なものだけ mp4 に書き出します
  コラボ(複数人の配信をグループにまとめ、一人が採用したマークを他の人の配信にも候補として転写)は
  ヘッダーの設定(⚙)の「コラボ」節から使えます(ほぼ使わない機能のため)
  ※ 合成動画・チャット・疑似のYouTube応答でテストしています。Windowsではローカル動画の書き出し・音量調整、
    ブラウザ上での保存失敗と復旧も確認しています。実際のYouTube(取得・埋め込み・ライブ配信)は未検証です。

【コードの場所】
  このフォルダに残るのは serve.py(API の配線)・handoff.py(実行中のポートの共有)・startup.py です。
  案件の画面が読む部品(rank.js・queue.js・review.js・collab.js)は src/app/ui/studio/ にあります。
  解析 analyze と盛り上がりの式 excite → src/pipeline/analyze/・まとめて解析 batch → src/flow/batch.py・書き出し exporter と .clip.json の組み立て manifest → src/pipeline/export/・
  マークの保存 store と判定の記録 feedback → src/human/review/・探す rank と seed.json → src/human/find/・文字起こしとの紐づけ txlink → src/manage/cases/txlink.py。
  共通の道具(子プロセス・ffprobe・API キーなど)は src/ytt/ にあります(URL の関数は src/ytt/yturl.py)。
  テスト: src/human/review/tests/test_studio.py・src/pipeline/analyze/tests/test_analyze.py・src/pipeline/export/tests/test_exporter.py(画面と API のテストはこのフォルダの tests/)

【ライブの録画の音量】
  - ライブの録画の LIVE の帯に、音量のつまみと「消音」のボタンがあります(「ライブ端へ」の横)。ライブの録画のプレーヤーは標準のコントロールを出さない
    (その時間は映像をつないだ秒で、スタジオの時間と食い違うため)ので、配信中に音量を変える口は、このつまみと ↑↓・M のキーです。
    つまみとキーは同じ値(② の設定 volume・muted)を動かします。「編集」を別の窓で再生している間は下げる・消す(編集で再生中は …)が優先されます(帯に案内が出ます)。

【設定(⚙)と設定の画面】
  - 解析(材料・本数・長さ・感度・詳しい設定)・書き出しのあと自動で文字起こし・音量・ミュート・確認の進め方・反応の遅れ補正・ライブ判定・ライブの録画の置き場所・画質・自動の作り直し・録画を消す・
    配信中の候補・自動採用・候補の文字起こし・友人へ届ける・出力先フォルダの変更は、設定の画面(ホームの ⚙ → 設定の画面を開く。http://localhost:8700/settings)で変えます(notes:docs/spec/data.md の 6)。
  - ⚙ にあるもの: YouTube Data API キー・出力先フォルダ(今の値)・② の操作(キー配置を変える・ライブのマークをまとめてずらす)・ライブの録画(今の置き場所と空き)・コラボ・事務所の登録。
  - 「前回の音量の解析を使わない(やり直す)」は、① の「URL から入れる」の「動画ファイル・コラボ・やり直し」の中にあります(その場だけの指定)。
  - 音量・ミュートは再生の欄と ↑↓・M のキーで変えます。設定の画面で変えた値は、⚙ を開いたとき・画面に戻ったときにスタジオへ反映します。

【① 探す の先頭と解析の設定】
  ・タブは「1 探す」「2 確認・書き出し」の 2 つです。
  ・URL を入れて「解析に追加」する欄と、解析の順番待ちの一覧は、① 探す の先頭にあります(動画ファイルのパス・コラボは「動画ファイル・コラボ」を開くと出ます)。
    ホームや ② から URL を受け取ったときも、① の先頭の欄に入ります。
  ・「解析の設定」(材料・本数・長さ・感度・詳しい設定)は設定の画面で変えます。① の「解析の設定」ボタンで設定の画面が開きます。保存先は settings-ui.json の analyze です。

【API の入力の検査・書き出しの名前の規則】
  - 入口の「アーカイブで本番版に作り直す」(POST /api/live/section)は、数として読めない start・end に「start・end が数値ではありません」(400)を返します。
  - チャットの先読みの動画 ID は ASCII の 11 文字だけを通します。
  - API の本文は UTF-8 の JSON だけを受け付けます(NaN・Infinity を含む本文は 400)。本文の読み取り・動画の送り方(Range)・ポートの取り方・子プロセスの止め方・JSON の読み方は共通部品(ytt_core)です。
  - 書き出しの名前の規則(保存先のフォルダ・持ち主の印・<番号>_<開始>-<終わり>_<ラベル>・書きかけ .partial)は共通部品 ytt_core(names)の 1 か所にあります。入口のライブの書き出しも同じ物を読みます。
  - 書き出しでは、同じファイルの長さ・映像の有無を、ファイルの更新日時と大きさが同じあいだは前の結果で使います(ffmpeg -i を何度も呼ばない)。

【設定「自動の切り抜きを確認なしで友人へ届ける」(入口と組)】
  - 設定の「配信中の候補」に「自動の切り抜きを確認なしで友人へ届ける(1 本ずつ)」(ホームの設定 live.autoDeliver。既定オン)。配信中・配信後に自動で採用した切り抜きのパックを、
    できしだい Dropbox の 出力 へ置きます。人が採用した切り抜きは今までどおりホームの案件から。

【配信中の候補に「何と言っていたか」の文字(入口の D-11 案 b と組)】
  - ③ の LIVE の帯の候補の行に、その区間の文字起こし(入口が編集の whisper.cpp(GPU)で候補ごとに作る)を「…」の 1 行で出します(80 字まで。title に全文)。
    付くのは候補が確定してから 1〜2 分あと(音を取って認識する時間)。文字は採用の判断用で、字幕の正本は書き出したあとの文字起こしです。
  - 設定の「配信中の候補」に「候補を文字起こしする(GPU の whisper.cpp)」(ホームの設定 live.liveTx。既定オン)。whisper.cpp とモデルが無いときは帯の見出しに「文字起こしなし(理由)」。

【配信中の候補を ③ の LIVE の帯に出す(線 D の L3。入口の検出(線 D の L2)と組で使います)】
  - ライブの録画を開いているとき、入口が録画しながら見つけた盛り上がりの「候補」を、LIVE の帯の一覧に出します(設定の「ライブの録画」の
    「配信中の候補」をオンにしたときだけ。既定はオフ)。見出しの 1 行に 候補の数(この 1 時間 n/6)・遅れ・チャットの状態・自動採用の待つ分(自動の採用はいつもオン)
  - 候補の行: 時刻・点数・理由・状態の札(枠 / 控え / 採用 / 見送り)と [再生](5 秒前から区間の終わりまで)・[採用](マークにして、すぐ書き出しへ。
    書き出したあとと配信者は帯の設定のとおり)・[見送り](知らせの「元に戻す」と、行の [戻す] で戻せます)。いつもは枠と採用だけ、「控えも見る」で控えと見送りも
  - 一覧は 3 秒の見回りでも作り直しません(変わった所の文字と札だけ)。入れ替えで外れた候補は薄くしてから数秒で消します。
    いま再生している候補・マウスが乗っている候補・キーボードで選んでいる候補の行は、外れても消さずに残し、離れてから消します(押そうとしたものが入れ替わらないように)
  - タイムラインに候補の印(点線の枠。押すと 5 秒前から再生)。採用した候補はマークの印になります。解析していない録画でも、候補の盛り上がりのグラフを出します
  - キー: p = 次の候補を再生・z = いま再生している(か、直前に再生した)候補を採用(「標準」「左手だけ」とも。キー操作の一覧で変えられます)。
    候補が出ている間は、下のキーの帯に「次の候補」「候補を採用」を出します
  - 設定の「ライブの録画」に「配信中の候補(試験中)」: オン/オフ・感度(高い / ふつう / 低い)・1 時間に出す候補の数(1〜30)・
    確定から待つ分 1〜60(候補はいつも自動で採用します)。入口が対応していないとき(古い入口)は、この群を出しません
  - 入口が古くて候補の API が無いときは、最初の 1 回で聞くのをやめます(見回りのたびにエラーを出さない)

【前回の場所・書き出し完了の [編集で開く]・空の状態の次の一手・押せない理由・リンクの開き方】
  - ③ 前回の場所: 配信ごとに、再生位置と選んでいたマークを覚えて、次にその配信を開いたときに戻します(3 時間の配信を何回かに分けて確かめるとき、毎回 0:00 から探さなくてよい)。
    覚えるのはこのブラウザ(窓)の中だけです。録画中のライブの録画は、ライブ端から再生します
  - 書き出しが済んだ知らせに [編集で開く](書き出しの欄の行の「編集で開く」と同じ。何本か書き出したときは 1 本目。つないだ 1 本・ライブの録画の書き出しも)。知らせは 8 秒出します
  - 空の状態に次のボタン: ② の解析キューが空なら「① 探すで配信を選ぶ」、③ で配信を開いていないときは「① 探すで選ぶ」「② 解析へ」、
    設定の「コラボ」で配信もグループも無いときは「② 解析へ」(まとめられる配信があれば「まとめる配信を選ぶ」)
  - 押せない理由を出す: ホームから開いていないときの ③・① の「まとめて実行」と、ライブの録画での ③ の「まとめて実行」は、隠さずに押せない形にして理由を出します
    (押すと理由を知らせる)。「全部の配信の採用を書き出す」「書き出す」「失敗した分だけやり直す」も、押せないときはいつも理由をボタンの説明に出します
  - リンクの開き方: 「案件で見る」(まとめて実行の帯)・「案件の一覧」(① のまとめて実行)は、新しいタブではなく、ホームが別の窓で開いていればその窓を前に出します
    (開いていなければこの画面がホームへ移ります)。「編集で開く」は別の窓(窓で開いているとき)・新しいタブで開きます(配信を見ながら隣で字幕を直せるように)
  - 設定の「書き出しのあと自動で文字起こしを始める」を、このブラウザの保存からスタジオの設定(サーバー)へ移しました(窓とブラウザで値が変わりません)。
    前のブラウザの値は、最初に開いたときに 1 回だけ引き継ぎます

【ライブの録画の帯に「配信後の自動の切り抜き」の進み具合】
  - リアルタイム切り抜き(試験中)で「配信が終わったら、アーカイブの解析で自動で切り抜く」(ホームの設定)がオンのとき、終わった録画の帯に、
    ホームが知らせる進み具合の 1 行を出します(例: 「配信後の自動の切り抜き: 書き出し → 本番版 → パック(3 本のうち 書き出し 3・本番版 2・…)」。
    失敗があれば注意の色)。進んでいる間は 15 秒ごとに読み直します。設定がオフ・ホームが古いときは何も出しません
  - 版の赤い帯の「起動し直す」: ホームが「まとめて実行の待ち・実行中の N 件は、起動し直したあとに続きから進めます」と返したら、その文も帯に出します(ui-kit v20)

【ライブの録画: アーカイブで本番版に作り直す・録画を自動で消す・書き出したあとの流れ・配信者・① 探す の「配信中」】
  リアルタイム切り抜き(試験中)がオンのときだけ動きます。
  - 本番版に作り直す: 配信が終わってアーカイブが用意できたら、書き出した切り抜き(速報版)を、アーカイブから本番の画質で作り直して、同じ名前・同じ場所で入れ替えます。
    文字起こし・カットはそのまま使えます(速報版の音とアーカイブの音を照らし合わせて時刻を合わせます。ずれが 1 コマを超えたら入れ替えません)。
    速報版は 配信のフォルダ\作業用\速報版\ に 7 日残します。録画の欠けで書き出せなかった「要差し替え」のマークも、ここで作ります。
    自動(録画が終わって 30 分後から 1 時間ごとに用意を確かめる。7 日でやめる。設定の「ライブの録画」でオフにできます)と、終わった録画の帯の「アーカイブで作り直す」。
    マークと書き出しの行に「本番版」の札。入れ替えの前に作った Resolve パックは、中の動画が速報版のままなので作り直してください(行に出ます)
    できないもの: アーカイブが残らない・メンバー限定・非公開・配信者が切り貼りして音が合わない区間(速報版のまま。理由が出ます)
  - 録画を自動で消す(設定の「ライブの録画」の「本番版に入れ替えたら録画を消す」。既定オン): 書き出したマークが全部本番版に入れ替わった録画はすぐ消します。
    マークが 1 つも無い録画は、終わって 24 時間で消します(スタジオの一覧の行も)。作り直せなかったマーク・採用のまま書き出していないマークがある録画は消しません。
    消した録画を開くと「録画は消しました(本番版に入れ替え済み)」と出ます(マークと本番版はそのまま使えます)
  - 書き出したあと(LIVE の帯): 何もしない / 文字起こしまで(軽く確認)/ 全自動(文字起こし → パックまで。字幕は校正前です)。手動の「書き出す」にも効きます
  - 配信者(LIVE の帯): 字幕の色を決める配信者の名前を、配信のチャンネル名から自動で決めます(覚えた名前があればそれ)。帯の「配信者: 〇〇」を押すと直せます。
    決まらないときは「未設定(字幕は既定の色)」
  - ① 探す に「終わった配信 / 配信中」の切り替え: 「配信中」では、登録した事務所のいま配信中の配信と、24 時間以内に始まる予定を並べます。
    「録画する」「始まったら録画」で、そのまま録画を始められます。YouTube Data API を使います(最初の 1 回が登録チャンネルの数ほどのユニット、見ている間は 1 時間に約 250 ユニット)。
    新しく立った枠が出るまで最大 20 分かかります。メンバー限定は題の言葉から判定します(題に無いメン限は、録画の開始で失敗します)

【ライブの録画: 編集で再生している間は、配信の音を下げる・消す】
  - 配信を見ながら、書き出した切り抜きを「編集で開く」(別の窓)で文字起こしを直すと、配信の音と編集の音が二重になるので、
    編集の窓で再生している間だけ、スタジオの配信の音を自動で下げます(2 割)。編集の再生を止めると元の音に戻ります。映像・録画・マークはそのままです
  - LIVE の帯の「編集で再生中は」で切り替え: 音を下げる(既定)/ 音を消す / そのまま。設定の音量・消音そのものは変わりません
  - 窓どうしが同じ PC の中で「いま鳴っている」を知らせ合うだけで、外へは何も送りません

【ライブの録画の画面の決まり】
  - 録画のプレイヤーには、動画の標準のコントロール(下の再生バー)を出しません(つなぎ直しの欠けがあると、その時間がスタジオの時間と食い違うため)。
    再生・シーク・音量はスタジオの操作で(映像をクリックしても 再生 / 停止)
  - 録画では、マークの「ライブ」の印と「ライブ印のマーク n件」を出しません(YouTube の配信中に付けたマークをあとでずらすための印で、録画では意味が無いため)
  - ヘッダーの「録画中」の札の一覧は、「停止」で止めたら閉じます

【配信中の録画をスタジオの中で: リアルタイム切り抜き(試験中)。notes:plan/line-d-live-clipping.md の 0-8】
  ホームの「詳しく」→「試験中の機能」で「リアルタイム切り抜き(試験中)」をオンにしたときだけ動きます(既定はオフ)。
  - 始め方: ② 解析の URL の欄(か ③ の「開く」の欄)に、配信中・配信前の YouTube の URL を入れるだけ。配信の状態を調べて(数秒〜)、
    配信中・配信前なら録画を始め、自動で ③ 確認・書き出しに移ってその録画を開きます。終わった配信(アーカイブ)なら解析します
  - 見る・マークする: ③ のプレイヤーで、録画を数秒遅れで再生します(巻き戻し・「ライブ端へ」もできる)。今をマーク ①〜⑤・一瞬・IN/OUT など、
    いつもの操作がそのまま使えます。マークの時刻は「録画の頭からの秒」です(配信の頭からの秒ではありません)
  - 書き出し: LIVE の帯の「マークしたらすぐ書き出す」(既定オン)がオンなら、マークを付けた時点で採用にして書き出します
    (終わりの時刻まで録画が届くのを待つ → 30fps に作り直す → いつもの書き出し先へ。「書き出しのあと自動で文字起こし」がオンなら文字起こしへ)。
    オフなら、いつもどおり 採用 →「書き出す」。録画中でも書き出せます。区間に録画の欠け(つなぎ直しの間)があると書き出せません(要差し替え)
  - 録画の状態: LIVE の帯に 録画中 / 配信を待っています / つなぎ直し中 / 停止 / 終了 と出ます。「録画を止める」は二度押し。
    録画は、スタジオやホームを閉じても裏で続きます。どのツールのヘッダーにも「録画中」の札が出て、そこから開く・止めるができます
  - 再生は、③ を離れる・他のタブやツールへ移ると止まります
  - 設定(⚙)の「ライブの録画」: 録画の置き場所(C 以外のドライブを勧めます。1時間あたり約 3〜4GB)・空き・画質(既定 1080p)
  - ライブの録画は、解析・コラボ・つなげて1本に・全部の配信の書き出し の対象になりません。スタジオの一覧から削除しても、録画そのものは消えません

【盛り上がりの記録(feedback.jsonl)の行(notes:plan/line-bc-master-plan.md の Q2)】
  - 作業データの feedback.jsonl に、人の最終の操作を足して残します(既存の「採用・不採用・削除・書き出し」の行はそのまま)。足した行は verdict が good / bad ではない値です:
      manual_add(miss)      手で足したマーク = 自動の見逃し。その時いちばん近かった自動マークの点数と距離(秒。重なっていれば 0)を nearAuto に、自動マークの数を autoCount に残す
      manual_remove(unmiss) 手で足した候補のマークを手で消した
      unadopt(retract)      採用(書き出し済みを含む)を候補に戻した。prevStatus に前の状態
      delete_judged(retract) 採用・不採用・書き出し済みのマークを削除した。prevStatus に前の状態
    まとめて実行の自動採用・依頼の受付での採用は、書きません(人の判断ではないため)。
  - 再解析で、手を入れた自動マーク(採用・不採用・書き出し済み・ラベルあり・時刻を動かした)が手動マークに変わるとき、最初の自動区間 auto0 を auto0Orig に移して残します
    (マークの側に残す。画面からは書き換えられない)。あとの採用・書き出しの行も、auto0・手で直した量(dStart / dEnd)を持ちます(reanalyzed: true)
  - 書き出したマークがパックになった・友人に届けた、を「強い良い」として紐づけるのは Q3 の測る道具が txindex から読みます(ここには書きません)

【書き出しはいつも 30fps】
  - 書き出す切り抜き・前後10秒の編集用素材・つないだ1本は、元の動画が 60fps・29.97fps でも、いつも 30fps の固定(H.264・yuv420p・AAC)に作り直します。
    後ろの「編集」・Resolve のパックが 30fps を前提にできるようにするためです(notes:plan/line-bc-master-plan.md の Q1)。時刻(秒)はずれません。
    60fps は1コマおきに落とし、29.97fps はコマを落とさず約 33 秒に1コマを複製してそろえます。作り直しの設定は ytt_core/normalize.py の1か所(画質は今までの精密と同じ crf 18)
  - 「高速」は、速い設定(x264 の ultrafast。画質の設定 crf 18 は同じ・ファイルは少し大きい)での作り直しです。コピーでは fps を変えられないためです。
    開始がキーフレームの分だけ前にずれることはなく、位置は精密と同じくちょうどになります(.clip.json に actualStart は付きません)
  - YouTube の区間取得は 2 段です: yt-dlp で区間を前後 2 秒の余裕つきで「そのまま」取り(作り直さない)、ffmpeg で正確な区間に切って 30fps に作り直します(画質の設定 crf 18 を通すため)。
    取った区間は 作業用\ に置き、切ったら消します

【探す・盛り上がりのグラフ・キー配置の場所】
  - ① 探す: 期間の早見の先頭に「昨日0時〜今」(開始 = 昨日・終了 = 今日。昨日の0時から今の時刻まで)。

  - ③ の盛り上がりのグラフを見やすくした: 高さ 152px(狭い画面 128px)・時間の目盛りと補助線(幅に合わせて 5秒〜2時間の間隔)・
    マークの帯を状態の色に(候補・採用・不採用・書き出し済み。選んでいるマークは太い線)・山に点と縦の線・札は横の位置で段に分けて重ねない・マウスの位置の時刻
  - キー配置を変える場所は ? の一覧だけにした。③ の「操作の設定」には「キー配置を変える(?)」のボタン。「標準」「左手だけ」は一覧の上の「まとめて変える」で選ぶ。

【配信の非表示】
  - ③ 確認の配信の一覧で、配信を一覧から非表示にできます(行の右の「隠す」。入口から開いたときだけ)。配信のデータは消えません(一覧で見えなくするだけ)。

【時刻の欄】
  - ③ 確認のマークの「開始」「終了」と、コラボの「合わせる時刻」を、数字だけで入れる時刻の欄にしました(編集と同じ動き)。形は 時:分:秒.0.1秒(例 0:01:23.5)。
    欄を選んで数字だけ打つ(001235 → 0:01:23.5。「:」は打ちません)。← → で 時・分・秒・0.1秒 を選び、↑ ↓ で選んだ所を ±1(Shift で ±10)。
    BackSpace = 選んだ所を 0・Ctrl+V = 1:23:45 や 1:23.5 の形の貼り付け・Enter か欄を離れると確定(おかしな時刻は理由を出して元に戻します)。
    開始を直して Tab を押すと、そのまま次の部品へ進みます。
    「現在位置」(時刻を入れて Enter でジャンプ)の欄は別の形です(5025 のような秒の数字も使えるため)

【友人の依頼の時間指定(API)】

    解析していない配信でも、区間だけなら使えます(書き出しのときに、その区間だけを取りに行きます)

【ラウドネス調整・自動マークの採用 API】

  ・入口の「案件」の画面の「まとめて実行(解析から全部)」用に、自動マークの点数の高いものを採用にする API(POST /api/video/adopt-top)があります。

【セリフの表示・重い処理の同時実行の上限】

    (行数と校正の進み具合つき。行を押すとその行だけ再生。文字起こしで「カット」にした行は線を引いて表示)。

  ・解析と書き出しは、他のツールの重い処理(文字起こし・Resolve 用のパック作り)と合わせて同時に 2 つまでです

【作業データの置き場所】

【.clip.json・runtime・起動時の確認・ログ】
  ・書き出した動画ごとに、隣へ「<動画の名前>.clip.json」を作ります(例: 01_00h12m34s-00h13m19s.mp4 → 01_00h12m34s-00h13m19s.clip.json)。

    速度優先で書き出したときは、実際の開始がキーフレーム(映像の区切り)の分だけ前にずれるので、分かる場合はその秒も入れます(ffprobe が必要。ffmpeg に同梱)。
  ・起動中は、このフォルダの1つ上の .runtime フォルダに studio.json(使っているポート)を置き、終了時に消します。

  ・ログの控えの名前は studio.old.log / studio-errors.old.log です

    未保存の編集や一括書き出しがある間は、ページを閉じる前にブラウザが確認します。
  ・一括書き出し中の通信断を「完了」と扱わず、そのジョブの状態確認を続けます。
    残りの動画は自動開始しません。進捗を確認してから再実行してください。
  ・「全動画の採用を書き出す」は、1動画に51件以上あっても50件ずつ順に処理します。
  ・Windowsの一時的なファイル使用中エラーでは、最大0.7秒待って保存・音量調整後の置き換えを再試行します。
    解消しない場合は対象ファイルと対処を表示し、studio-errors.log に詳細を記録します。
  ・動画作成後に「書き出し済み」の記録だけが保存できなかった場合は、作成済みの動画を保持して注意を表示します。

【準備】
  1. Python 3(https://www.python.org/downloads/ 。Windows は「Add python.exe to PATH」にチェック)
  2. ffmpeg     Windows: winget install Gyan.FFmpeg   / Mac: brew install ffmpeg
  3. yt-dlp     Windows: winget install yt-dlp.yt-dlp / Mac: brew install yt-dlp
     Deno       Windows: winget install DenoLand.Deno  / Mac: brew install deno
       (今の yt-dlp は YouTube の取得に JavaScript の実行環境として Deno を使います。yt-dlp と一緒に入ることもあります)
     (入れたら黒い画面を開き直してください。旧ツールで入れたものと共通です)
  4. リポジトリ直下の start.bat をダブルクリック(ホーム。準備と起動の全体はリポジトリ直下の README.txt)
     ホームの画面のヘッダー左の「スタジオ」で http://localhost:8700/studio/ が開きます(…/studio/?step=rank で開くと ① 探す から)。※ 127.0.0.1 ではなく localhost で開いてください(YouTube埋め込みのため)
  5. 画面右上の「設定」(歯車)を開き、YouTube Data API のキーを入れる(ランキングの検索に必要。無くても②③は使えます)

【最初にやること(初回だけ)】
  ・設定 →「事務所の登録」で、4事務所のチャンネルを取り込みます。
    ホロライブ・にじさんじ・ぶいすぽっ! は「公式から取り込み」→「追加して解決」。
    ネオポルテは公式の一覧がないので、チャンネルのURL(または @ハンドル)を入れて「追加して解決」します。
  ・旧ツールの data.json や設定は引き継ぎません。

【使い方】
  ① 探す   期間・ワードを決めて検索 → 解析したい配信にチェック(最大10本)→「選んだ配信を解析に追加」
  ② 解析   順番に解析します。進み具合が見えます。失敗した配信は飛ばして続きます(「やり直し」で入れ直せます)。
           1本終わるごとに「確認する」が押せます(他の配信の解析は裏で続きます)。チャット取得が長いときは「チャットを待たずに進める」
  ③ 確認   自動マークが「候補」として入った状態で開きます。1件ずつ 採用 / 不採用 / 候補 を決めて、「採用」だけを書き出します。グラフに音量・チャットの山と、マークの点数・理由(「音量が急上昇」など)が出ます。
           ・マーク①〜⑤のボタン(長さ違いの区間)、I / O(IN・OUT)、±0.5 / 1 / 5秒の微調整、シアター、ライブ配信対応は切り抜きマーカーと同じです
           ・キー配置は右上の「キー操作」(? キー)の一覧で変えられます(標準 / 左手だけ)。音量・確認の進め方などは右上の「設定」の「③ の操作」にあります
           ・判定: 各マークの「採用」「不採用」「候補」ボタン(書き出すと「書き出し済み」)。上の 全部/候補/採用/不採用/書き出し済み で絞り込み、時刻順/点数順で並べ替えられます
           ・キー(標準): ] 次のマーク / [ 前のマーク(移動するとその区間を自動再生)/ y 採用 / u 不採用(押すと次の候補へ進みます)。自動再生や自動で次へ進む動作のオン/オフは、設定の「③ の操作」で変えられます
           ・マークの行は左の山形の印で折りたたみ(「すべて折りたたむ」「すべて開く」もあります)。「候補をすべて採用」もあります
           ・書き出す対象(「書き出しの設定」の中): 採用のみ(標準)/ 採用+候補 / 不採用以外すべて。「全部の配信の採用を書き出す」で、採用マークがある全部の配信を順番に書き出します(この画面を開いたままにしてください)
           ・書き出しは切り抜きマーカーの方式: YouTube は必要な範囲だけ取得。精密・画質の上限なしの固定です(設定ファイルに残る古い切り出し方式・最大画質の値は読みません)。
             書き出す動画はいつも 30fps(H.264・AAC)に作り直します(高速は速い設定での作り直しで、位置は精密と同じくちょうど)
           ・書き出し先: 標準では %LOCALAPPDATA%\youtube-tools\studio\exports\<動画名>\(以前このフォルダの exports を使っていた場合はそのまま)。変更は設定の「出力先フォルダ」
           ・書き出し済みマークの時刻を動かす、または「採用」を押し直すと、「書き出し済み」が外れます(採用に戻り、書き出し直せます)
  始め方は4つあります: ①ランキングから / ②URLを直接貼る / ③手元のファイル(フルパス)/ ④解析せずに確認画面だけ開く(手動でマークだけ付けたいとき)
  コラボ(設定の「コラボ」節)   複数人のコラボ配信で、一人が付けたマークを他の人の配信の「同じ瞬間」にも候補として転写します(自動採用はしません。必ず候補として入り、採用/不採用は人が決めます)。
           1. ② の「解析する配信を入れる」で、まとめて入れた配信を「コラボとしてまとめる」にチェックすると、追加した配信が1つのグループになります(あとから設定の「コラボ」節でも、題名・配信者で探して選び「まとめる」できます)。
           2. 設定の「コラボ」節で、グループの各配信(基準の配信以外)に「アンカーを指定」→ 両方の配信で同じ瞬間を見つけて時刻を入力(1点だけでもよい。2点指定すると配信中のズレの変化(ドリフト)にも対応します)。
           3. これでズレの対応ができたので、以降はどちらかの配信でマークを「採用」にするたびに、同じグループの他の配信にも、その瞬間(前後2〜3秒広げた範囲)が「候補」として自動で追加されます。採用するかどうかは、その配信を見ながら人が決めてください。
           ・グループから配信を外しても、すでに転写された候補・採用済みマークは残ります。基準の配信を外す、または残り1本になる場合はグループごと削除されます(ズレの基準が失われるため)。

【解析のしかた】(自動切り抜きと同じ)
  音声・チャット・コメント欄を、それぞれ「ふだん(前後5分の中央値)からどれだけ跳ね上がったか」で点数にして足し合わせます(重みは 音声1.0・チャット1.0・コメント0.7)。
  チャットの遅れ・冒頭・コメントの扱い:
  ・チャットの遅れを動画ごとに自動推定します(音量の山とチャットの山の一致から。詳しい設定の「チャットの遅れを自動で推定する」。はっきりしないときは従来の「遅れ補正」の秒数を使います)。推定した秒数は解析結果の注意書きに出ます。
  ・配信の冒頭は、0秒で0倍 → 「冒頭の減点」の秒数(標準180秒)で1倍へ、なだらかに点数を戻します(挨拶・BGMの誤検出対策。0で無効)。
  ・コメント欄の時刻が1つのコメントに3つ以上ある場合(チャプター一覧)は、1つあたりの重みを 1/個数 に下げます。
  ・チャットの「！」1つだけでは盛り上がりに数えません(「！！」以上・「草」・「w」などは数えます)。
  解析のあとから見直すための記録:
  ・後から精度を見直すためのデータを記録するようにしました(解析の結果や画面の動きは変わりません)。
      - archive フォルダ: 解析した配信ごとに、1秒ごとの音量・チャット(草の件数・発言した人数・スパチャ)・コメント欄の時刻と文面の先頭60文字・解析ごとの設定と候補(直近5回分)を圧縮して保存します(2時間の配信で約40KB。最大2000本)。
      - cache/meta: YouTube の動画情報(みんなが繰り返し見た場面・チャプター・カテゴリ・タグ・再生数・登録者数)。yt-dlp で取得します(取れない動画・配信直後は記録なし。取れなくても解析はそのまま進みます)。
      - feedback.jsonl: 手動で切った区間を採用・不採用にしたとき、書き出したときも記録します。自動の候補には、最初の区間(auto0)と手で直した量(dStart / dEnd)、操作(adopt / reject / delete / export)も付きます。
  ・改善のためにデータを送るときは、data.json・feedback.jsonl(feedback.jsonl.old があればそれも)・archive フォルダをお渡しください。
  区間は点数の山を65%あたりに置き、近くの静かな所に端を寄せます。感度・本数・長さ・重みは②の設定で変えられます。
  チャットの取得は配信の長さ(チャット数)に比例して時間がかかります。複数本を解析するときは、今の配信の解析中に「次の配信のチャット」を裏で先に取っておきます(同時に1本まで)。
  自分の番が来たときは待たずに使えるので、まとめて解析するほど全体が短くなります(1本だけのときは変わりません)。
  同じYouTube動画の再解析は、音量の解析結果とチャットをキャッシュ(cache/)から使うので速く終わります。配信中・直後の配信は「前回の音量の解析を使わない」をオンに。
  チャットのキャッシュは最新 30 本・合計 1GB まで(古いものから消します。合計の上限は環境変数 STUDIO_CHAT_CACHE_MB で変えられます)。

【フィードバック(自動で記録)】
  自動マークの「採用」・書き出し=「よかった」、「不採用」・候補のまま削除=「ちがった」として、feedback.jsonl に1行ずつ残ります(画面での集計はまだありません。感度・重みの見直し用)。

【旧ツールにあって無い機能】
  ・切り抜きマーカー: コメント欄からの候補抽出、CSV/TSV の出力・読み込み
  ・自動切り抜き: 見つけたらそのまま書き出す(自動書き出し)、○×ボタン(採用/不採用に置き換え)
  ・文字起こしツールは含みません(保留中)
  旧ツールのフォルダはそのまま使えます(このツールとは別のデータです)。

【データについて】(置き場所は %LOCALAPPDATA%\youtube-tools\studio\。リポジトリの外。Windows を入れ直すと消えるので、ときどき別のドライブへコピーしておいてください)
  data.json(動画・マーク。壊れたときは data.json.corrupt-日時 に退避して新しく始まります。.bak は直前の控え)/ settings-ui.json / registry.json / config.json(APIキー)/
  feedback.jsonl / cache/(チャット・音量・グラフ)/ work/(作業用・自動で消えます)/ exports/(書き出し結果。動画ごとに .clip.json も)/
  studio.log・studio-errors.log(1MB を超えると *.old.log に1世代だけ残します)
  他の人にこのデータのフォルダを渡すときは config.json を抜いてください。解析結果のグラフは cache/series/ に保存され(最新60本)、再起動後も表示されます。

【できないこと・注意】
  ・笑い声や叫び声を聞き分けているわけではありません。大きい音・高い音の急上昇を見ています。ゲームの効果音・BGM・音量の急変にも反応します
  ・チャットのリプレイは、無効・削除された動画、メンバー限定チャットでは取れません(音声だけで判定します)
  ・メンバー限定・年齢制限・非公開の配信は取得できないことがあります
  ・縦動画(9:16)への変換・字幕の焼き込みはありません(横のまま書き出します)
  ・コラボのズレは今のところ手で指定するだけです(音声どうしの自動推定はまだ)。ズレが一定でない配信(回線落ち・広告の位置が動画ごとに違うなど)には、まだ十分に対応できません
  ・グループの基準の動画を外す(または動画ごと削除する)と、グループごと削除されます。すでに転写されたマークは残りますが、グループを作り直してズレを指定し直す必要があります
  ・YouTube から取得した映像には、著作権・利用規約が関わります。自分の配信や、許諾を得たものにだけ使ってください
  ・サーバーは自分のPC(127.0.0.1)だけで待ち受けます。外に公開しないでください

【困ったとき】
  ・途中で終了して黒い画面も閉じてしまう: 終了時に画面を閉じず理由を表示し、studio.log(作業データの studio フォルダ)に終了の原因を記録します。
    起きたら、黒い画面のメッセージと studio.log(と studio.crash.log があればそれ)を教えてください
  ・画面の上に赤い帯: 古いサーバーが残っています。帯の「起動し直す」か、ホームの「すべて終了」→ start.bat で起動し直してください
  ・YouTubeのプレイヤーが出ない / 黒いまま: 必ず http://localhost:ポート/ で開いてください。広告ブロッカーが埋め込みを止めていないかも確認を
  ・「音声を取得できませんでした」: yt-dlp が古い可能性があります。yt-dlp -U で更新してください(winget で入れたときは winget upgrade yt-dlp.yt-dlp)
  ・ホームのポート8700が使用中のときは次の番号(8701…)で起動します。黒い画面に表示されたアドレスを開いてください

DaVinci Resolve用の編集余白
---------------------------
書き出し時に、通常の切り抜きとは別に前後10秒を含む編集用素材（*_edit.*）と
対応情報（*.edit.json）を同じフォルダへ作ります。通常の切り抜きの長さは変わりません。
文字起こしツールのResolveパッケージはこの素材を自動で使うため、Resolve上でカット位置を
前後へ動かしたり、削除区間をSOURCE_WITH_HANDLESタイムラインから復活できます。
