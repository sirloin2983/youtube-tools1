# 文字起こしツール v2 実装引き継ぎ設計書

更新日: 2026-09-23  
状態: 設計のみ。実装保留。評価用データの準備後、ユーザー確認を得てから着手する。  
対象: `transcribe-tool`。`clip-studio` は既存連携を壊さない範囲だけ対象とする。

## 0. 次の実装担当AIへ

最初にこの文書を最後まで読むこと。コードを変更する前に、末尾の「実装前確認」をユーザーへ提示し、変更対象・変更内容・依存追加を確認すること。

最初の実装ターンでは、精度改善パイプラインを一気に作らない。次の順序を守る。

1. 新しい評価データの内容を監査し、固定する。
2. 現行テストと評価値を保存する。
3. 認識バックエンド抽象化だけを行い、出力が変わらないことを確認する。
4. RX 7800 XT向けの `whisper.cpp` Vulkanバックエンドを追加する。
5. 同一音声で速度・CER・メモリを比較する。
6. 比較結果をユーザーへ提示し、次段階の実装許可を得る。

評価データが未完成の間は、手順3以降へ進まない。

## 1. 目的

切り抜き動画向け日本語文字起こしの精度を、追加ハードウェアと定常的なクラウド課金なしで改善する。

主要目標:

- 通常運用は完全ローカルで完結する。
- 現在のPC（Core i9-13900KF / Radeon RX 7800 XT 16GB / RAM 32GB）を使う。
- AMD GPUを文字起こしへ利用する。
- 難しい区間にだけ計算量を集中する。
- 既存の編集UI、保存データ、`clip-studio` 連携を維持する。
- 改善を感覚ではなく、固定評価セットのCER等で判定する。
- 将来のモデル交換、複数視点、音源分離を追加できる構造にする。

精度の暫定目標:

- 現在の小規模評価におけるCER 6.73%を参考値とする。
- 新しい固定評価セット完成後に正式な基準値を取り直す。
- 第一目標は、同じ固定評価セットで相対誤り20%以上削減。
- 第二目標は、相対誤り30%以上削減。
- 評価データ完成前にCERの達成値を受け入れ条件へ固定しない。

## 2. 確定している制約と方針

### ハードウェア

- CPU: Intel Core i9-13900KF
- GPU: AMD Radeon RX 7800 XT 16GB
- RAM: 32GB
- PC、GPU、メモリは変更しない。
- 複数の大型モデルを同時常駐させない。
- モデル切り替え時は前モデルを明示的に解放する。

### 費用

- 定常的なAPI利用は行わない。
- クラウドは初期評価の数回だけ許容される。
- クラウド機能を実装する場合も、既定値は無効とする。
- 自動的な外部送信は禁止する。
- API利用には、1動画・1日・1月の上限を持たせる。
- 同じ音声を二重課金しないよう、音声ハッシュと設定で結果をキャッシュする。

### 実装上の方針

- 現在の `serve.py` と `index.html` を直ちに全面書き直さない。
- `serve.py` は当面エントリーポイントとして残す。
- 新機能は小さなモジュールへ分離し、既存ルートから呼び出す。
- 保存済み `transcribe/v1` 文書を破壊的に移行しない。
- 新しい情報は後方互換な任意フィールドとして追加する。
- 保存、履歴、評価用保護、競合検出を維持する。
- すべての処理はローカルのジョブキューを通す。

### AMD GPU

- 現行実装は `faster-whisper` の `cuda` または `cpu` のみで、RX 7800 XTを利用できない。
- v2の第一GPUバックエンドは `whisper.cpp` の Vulkanとする。
- Windows版ROCm/PyTorchを第一候補にしない。
- `faster-whisper` CPUは互換・緊急用バックエンドとして残す。
- Vulkanが利用できない場合、無言でCPUへ切り替えず、UIへ理由を表示する。

### 主なファイル

8. `transcribe/v1` JSONとして保存

- 通常文字起こし
- 範囲指定、フォルダ一括、マーカー連携
- 部分再認識
- A/B比較
- 校正済み・評価用保護
- CER測定
- 話者判別
- 用語集・置換辞書・修正候補
- 履歴、自動バックアップ、保存競合検出
- 修正データのアーカイブ
- `clip-studio` のマーカー参照

## 6. ASRバックエンド境界

### バックエンドが持つ責務

- 利用可能性の検査
- バージョン、実行方式、対応モデルの報告
- モデルのロードと解放
- 音声ファイルの文字起こし
- キャンセル
- 進捗通知
- 生の信頼度情報を可能な範囲で返す

### バックエンドが持たない責務

- ffmpegによる元動画切り出し
- UI向け行分割
- 用語辞書による後処理
- 保存、履歴、評価用保護
- 複数バックエンドの候補選択

### 概念インターフェース

```python
class AsrBackend:
    id: str

    def probe(self) -> BackendInfo: ...
    def transcribe(self, audio_path, request, progress, cancelled) -> AsrResult: ...
    def unload(self) -> None: ...
```

### 共通結果

```text
AsrResult
  backend_id
  backend_version
  model_id
  model_fingerprint
  language
  duration_sec
  wall_time_sec
  segments[]

AsrSegment
  start
  end
  text
  words[]           任意
  avg_logprob       任意
  no_speech_prob    任意
  compression_ratio 任意
  backend_confidence 任意
```

信頼度項目が存在しないバックエンドでも動作すること。欠損値を0として扱わない。

## 7. 保存形式

既存の `transcribe/v1` を維持する。次の任意フィールドのみ追加可能とする。

```json
{
  "recognition": {
    "pipeline": "local-cascade-v1",
    "primaryBackend": "whisper-cpp-vulkan",
    "runs": [
      {
        "backend": "whisper-cpp-vulkan",
        "model": "large-v3-turbo-q5",
        "modelFingerprint": "...",
        "settingsHash": "...",
        "audioHash": "...",
        "wallTimeSec": 0,
        "device": "Radeon RX 7800 XT"
      }
    ]
  }
}
```

要件:

- 旧文書は変更なしで開ける。
- 新文書も旧UIが未知フィールドを無視できる。
- 人間が編集する `segments[].text` と、機械の基準出力 `original` の意味を変えない。
- A/B評価では、候補結果を文書本体へ上書きしない。

## 8. ローカル低コストパイプライン

### 定常運用の推奨フロー

```text
1. 音声抽出
2. 音声ハッシュでキャッシュ確認
3. VAD
4. turbo系モデルで全体を一次認識
5. 区間信頼度を計算
6. 低信頼区間だけlarge-v3で再認識
7. 候補を音響・文脈・用語から選択
8. 行分割・要確認フラグ
9. 保存
```

ただし、RX 7800 XT上で `large-v3-turbo` と `large-v3` の実測が取れるまでは、順序を固定しない。場合によっては最初からlarge-v3を1回実行した方が総時間・精度とも良い可能性がある。

### 低信頼区間の初期条件

閾値は固定値として完成扱いにしない。初期候補:

- 平均log probabilityが低い。
- no-speech probabilityと出力文字が矛盾する。
- compression ratioが高い。
- 同じ文の反復。
- 日本語設定なのに説明できない英字列が多い。
- 2つのデコード結果が大きく異なる。
- 極端に短い発話。
- BGM / overlap / unclearタグのある区間。
- 用語候補の音が近いが表記が一致しない。

正式な閾値はdevデータで決め、testデータでは変更しない。

### 用語補正

- 全文への無条件一括置換を精度改善の主方式にしない。
- 誤語・正語・話者・ゲーム・前後文脈・採用回数を記録する。
- 用語はASRプロンプト、候補選択、最終表示の各層を区別する。
- 評価用文書から自動学習しない。

## 9. キャッシュ

キャッシュキー:

```text
audio_sha256
+ backend_id
+ backend_version
+ model_fingerprint
+ normalized_recognition_settings
```

キャッシュ対象:

- ASRの生結果
- VAD区間
- 任意で音源分離結果
- OCR・チャット文脈

キャッシュに含めないもの:

- 人間が編集した字幕
- UI表示設定
- 書き出し形式

要件:

- 用語集変更時に、ASRを再実行すべき場合と後処理だけでよい場合を区別する。
- 破損キャッシュは自動的に無視できる。
- キャッシュ削除は対象と容量をUIで確認してから行う。
- 初期実装では自動削除を行わない。

## 10. クラウド利用ポリシー

定常運用では不要。実装する場合の必須条件:

- 既定値OFF。
- APIキー未設定でも全機能のローカル部分が動作する。
- ユーザーが対象区間と送信を明示的に確認できる。
- 元動画全体を自動送信しない。
- 送信前に秒数と概算額を表示する。
- 1区間、1動画、1日、1月の上限を持つ。
- 評価用データを外部送信する場合、別途確認する。
- 結果と請求対象音声ハッシュを保存し、再送しない。
- クラウド結果を無条件で正解扱いしない。

初期評価終了後の推奨設定:

```text
cloud.enabled = false
cloud.autoSend = false
cloud.monthlyBudgetYen = 0
```

## 11. 複数視点と音源分離

初回実装には含めない。バックエンド比較とカスケードが安定した後の拡張とする。

複数視点:

- メイン視点だけ全体認識する。
- 低信頼時間だけ他視点を切り出す。
- 各動画の時刻オフセットと時間ドリフトを推定する。
- 全視点を常に全文認識しない。

音源分離:

- 全体へ常時適用しない。
- overlap判定区間だけ適用する。
- 元音声と分離音声の両方を認識し、悪化時に元へ戻せるようにする。
- 分離処理が作った人工音を正解と誤認しないよう、評価を独立して行う。

## 12. 評価指標

必須:

- CER（全体micro）
- クリップ単位CER（macro）
- 置換、脱落、挿入
- 幻覚区間数
- 固有名詞の再現率
- wall time
- real-time factor
- 最大RAM使用量
- GPU使用、VRAM使用量（取得可能な範囲）

難易度別:

- clean
- bgm
- overlap
- whisper / shout / laughter
- proper-noun
- silence / non-speech

将来:

- 話者誤り率
- タイムスタンプ誤差
- 字幕用正規化文に対するCER
- 人間の修正時間

合否は全体CERだけで決めない。cleanが改善してもoverlapの欠落が増えた場合は退行とする。

### Phase 3: 信頼度ルーター

目的: 全体を何度も認識せず、難所だけ再認識する。

- 区間信頼度の正規化。
- 低信頼区間の結合と前後余白。

- 候補比較。
- provenance保存。

完了条件:

- testで相対CERが改善、または同等精度で処理時間が短縮。

- 既に高信頼の区間を悪化させない。
- キャッシュで同じ二次認識を繰り返さない。

### Phase 4: 文脈・用語候補

目的: 固有名詞の誤りをローカルで減らす。

- 話者、ゲーム、動画単位の用語スコープ。

- 評価用データの学習除外。

完了条件:

- 固有名詞セットの再現率向上。
- 一般語の誤置換増加が許容範囲内。
- 提案を却下でき、次回へ反映される。

### Phase 5: 任意拡張

- 複数視点の難所回収。
- overlap限定音源分離。
- OCR / チャット文脈。
- 初期評価専用クラウド比較。
- 十分な学習データが集まった場合だけ追加学習を再検討。

## 15. セキュリティとプライバシー

- サーバーは引き続き `127.0.0.1` のみにbindする。
- Host / Origin検査を維持する。
- 外部コマンド引数はリストで渡し、shellを使わない。
- モデル名から任意パスを参照させない。
- ダウンロード物はURL、サイズ、SHA-256を固定する。
- 音声、字幕、話者情報をクラウドへ送る前に明示確認する。
- ログへ字幕全文、APIキー、個人情報を出さない。
- キャッシュ、評価、モデルの削除は対象を明示する。

## 16. 失敗時の動作

- Vulkan利用不可: 理由と修復案を表示。ユーザーが選んだ場合だけCPU実行。
- モデル不足: 必要容量と取得元を表示。
- メモリ不足: モデル解放後に一度だけ再試行。無限再試行しない。
- サブプロセスクラッシュ: stderr末尾を安全に記録し、ジョブを失敗状態にする。
- キャッシュ破損: そのエントリを無視し、原本から再生成する。
- 部分結果: 正式文書へ自動確定しない。
- 評価中の失敗: 成功分だけで総合CERを出さず、評価不成立と表示する。

## 17. 実装しないもの

少なくともPhase 1〜3では次を行わない。

- PC交換やGPU交換。
- 常時クラウド文字起こし。
- 自動課金。
- LoRAやモデル微調整。
- 全音声への音源分離。
- 全視点の常時全文認識。
- LLMによる自由な文章書き換え。
- 既存文字起こしデータの一括破壊的移行。
- `serve.py` / `index.html` の全面リライト。
