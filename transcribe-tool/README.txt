==========================================================
  文字起こしツール  v0.14.1  はじめに読んでください
==========================================================

【これは何?】
  動画・音声ファイルの話し声を文字にして、字幕ファイル(SRT / VTT)やテキストとして
  書き出すツールです。文字起こしは、自分のパソコンの中だけで行います
  (動画や音声はインターネットに送られません)。
  ・認識のあとで、画面上で誤変換を直せます(再生しながら1行ずつ聞き直せます)
  ・文字を検索して、その場面へジャンプできます
  ・「切り抜きマーカー」で記録したポイントの範囲だけを文字起こしできます

  ※ v0.3.1 では「話者の自動判別」(誰が話しているかの色分け・名前付け)が入りました。
  ※ これは初期の版です。実際の音声での認識精度は、使いながら調整していきます。


----------------------------------------------------------
 ① 最初の準備(1回だけ)
----------------------------------------------------------
  1. Python 3 をインストール(無料)   https://www.python.org/downloads/
       Windows: インストーラーで「Add python.exe to PATH」に必ずチェック
  2. ffmpeg をインストール(無料。音声を取り出すのに使います)
       Windows: スタートメニューから PowerShell を開いて
                  winget install Gyan.FFmpeg
                (終わったら、開いている黒い画面は一度閉じる)
       Mac:     ターミナルで  brew install ffmpeg
  3. このフォルダの install.bat をダブルクリック(Mac は install.command)
       → 文字起こしのエンジン(faster-whisper)が入ります。数分かかります

  4. (NVIDIA の GPU がある人だけ) install-gpu.bat をダブルクリック
       → GPU を使えるようになり、処理がかなり速くなります(RTX 3060 など)
       ※ 対応するのは NVIDIA(GeForce / RTX)だけです。AMD(Radeon)・Intel の GPU と、
         Mac の GPU は使えず、CPU で処理します。
       ※ 入れたあとは、ツールを起動し直してください。画面の左上に、GPU を使えるかどうかが出ます。

  5. (話者の自動判別を使う人だけ) install-diarize.bat をダブルクリック(Mac は install-diarize.command)
       → 判別に使う部品(sherpa-onnx)が入ります。GPU は不要で、どのパソコンでも CPU で動きます。
       ※ 判別用のモデル(約46MB)は、初めて使うときに自動でダウンロードされます。
       ※ Mac で .command が使えないときは、ターミナルで  python3 -m pip install -U sherpa-onnx numpy
         (先に install.command を実行済みなら  .venv/bin/python -m pip install -U sherpa-onnx numpy)

  ※ 切り抜きマーカーで ffmpeg をすでに入れている人は、2 は不要です。
  ※ zip は「展開(解凍)」してから使ってください。


----------------------------------------------------------
 ② 起動のしかた
----------------------------------------------------------
  リポジトリ直下(youtube-test フォルダ)の start-all.bat をダブルクリック(Mac は start-all.command)。
  入口の画面(http://localhost:8700/)の「文字起こしツール」の「開く」で http://localhost:8700/transcribe/ が開きます。
  使い終わったら入口の「すべて終了」か、黒い画面を閉じてください。
  ※ このフォルダの start.bat・start.command での単独起動は 2026-09-26 にやめました。準備と起動の全体はリポジトリ直下の README.txt


----------------------------------------------------------
 ③ 基本の使い方
----------------------------------------------------------
  1. 左の「新しく文字起こしする」で、動画・音声ファイルのパスを貼る
       Windows: ファイルを Shift+右クリック →「パスのコピー」
       Mac:     Finder でファイルを option+右クリック →「"…"のパス名をコピー」
     (範囲を入れると、その部分だけ処理します。空欄なら全体です)
  2. 「文字起こしを開始」。左の「処理状況」に進み具合が出ます
       ・初めてのモデルを使うときは、ダウンロードのため最初に時間がかかります
       ・何本でも追加できます(順番に1本ずつ処理します)
  3. 終わると右側に文字起こしが開きます。再生しながら直します
  4. 「話者・一括置換・書き出し」を開いて、SRT などで書き出す

  ■ 切り抜きマーカーのポイントを文字起こしする
     「切り抜きマーカーのポイント」タブを開くと、隣の clip-marker フォルダの
     data.json を自動で読みます(なければ「data.json を選ぶ」から選ぶ)。
     動画と元ファイルのパスを確認し、対象のポイントにチェックを入れて開始します。
     ・「前後の余裕」は、ポイントの前後に足す秒数です(話の頭が欠けるのを防ぎます)
     ・パスは、切り抜きマーカーの書き出し設定に入力済みなら自動で入ります

  ■ 直すときの操作
     ・行の文字をクリックして直す(自動で保存されます)
     ・行の ▶ = その行だけ再生(行の終わりで必ず止まります。R・入力中は Ctrl+Enter でも可)。
       続けて全体を流すときは、映像そのものの再生ボタン(または Space)を使います
     ・行をクリックして選ぶと、その行の下に操作のボタンが出ます:
       開始・終了の −/＋/再生位置、＋前に行・＋後に行(行の追加)、分割、次と結合、削除
     ・分割 = 文字の途中にカーソルを置いて押すと、2行に分けます
     ・行の追加(v0.9.8) = 認識で抜けたセリフを書き足します。「＋前に行」「＋後に行」(N キー)、
       または映像の下の「＋再生位置に行を追加」。前後の行のすき間に置かれます。すき間が無いときは
       仮の長さ(1.5秒)で置かれ、時刻の欄が赤くなります(前後と重なっている印)。「再生位置」ボタンで、
       聞きながら開始・終了を合わせてください
     ・「要確認」の印は、認識が怪しい行です(押すと確認済みになります)。
       「要確認だけ」にチェックすると、その行だけ表示されます
     ・「元に戻す」ボタン(文字の入力中以外は Ctrl+Z でも可)で、分割・結合・削除・置換を戻せます
     ・話者: 自動判別は下の「■ 話者を自動で判別する」。手動なら
       「話者を追加」→ 行の左のチェックで行を選ぶ →「適用」
     ・一括置換: 「誤=>正」の辞書を作っておくと、どの文字起こしにも使えます

  ■ 話者を自動で判別する(誰が話しているかを、行ごとに色分けする)
     1. 文字起こしを開き、動画の下の「話者・置換・書き出し」ボタン(検索欄の右端)を押す。
     開いた中の「話者の自動判別」を使う
     2. 人数が分かっていれば「人数」を選ぶ(コラボなら人数を指定するのがおすすめ)
     3. 「話者を自動で判別」。処理中は編集できません(終わると自動で読み込み直します)
     4. 各話者の「▶ 聞く」で発言を聞いて、「話者1」を本人の名前に直す
     5. 間違った行は、行の話者欄で直す。
        「要確認: 声が混ざっている可能性」の行は、1つの行に2人以上の声が入っています。
        その行は「分割」して、それぞれに話者を付けてください
     ・すでに付けた話者は、判別すると置き換わります(直前の状態は transcripts/.bak に
       1つだけ残ります)。手直しは、判別の「あと」にしてください
     ・字幕に話者名を出したいときは、書き出しの「話者名を付ける」にチェック
     ・文字起こしのモデルとは無関係に使えます(どのモデルで作った文字起こしにも使えます)
     ・CPU で処理するので、長い音声は時間がかかります。まず短い範囲で、かかる時間を
       確かめてください。判別できるのは、1回3時間の範囲までです

  ■ 校正済み・認識精度の測定(v0.7.0)
     「校正済み」= 聞いて確認して、その行の文字が正しいと判断した印です。
     ・各行の「校正済み」ボタン(または Shift+Space。付けると次の行へ進みます。入力中は Alt+Enter)
     ・「選択行を校正済みに」「全行を校正済みに」(全行は、聞いて確認した文字起こしだけ)
     ・「絞り込み」で、校正済み/未校正の行だけを表示できます
     ・置換辞書・修正の提案の採用・再認識で、聞かずに書き換わった行は、校正済みが外れます
     左の「認識精度の測定」に、校正済みの行を正解とした文字誤り率(CER)が出ます。
     ・内訳は 置換(別の字に間違い)/ 脱落(聞き逃し)/ 挿入(余計な字。幻覚など)。
       機械が出した行を人が消した数、用語(用語集・辞書)が正しく出た率も出ます
     ・「印のない旧データも含める(仮)」で、v0.6 までに直した分を仮計算できます
     ・「設定の比較(A/B)」…開いている文字起こしの校正済みの行の音声を、モデル・用語集の
       有無の違う設定で認識し直して、正解との差を比べます(文字起こしは書き換えません)。
       結果は evals フォルダに残ります。重いモデルほど時間がかかります
       (v0.8.1)設定ごとに用語集を変えられます。「用語集」にチェックを入れた設定の下の欄が
       空なら、左の共通の用語集(+自動追加)を使います。書くと、その設定だけ、その語だけを
       使います(自動追加はしません)。例: なし / 共通 / その動画に出る人だけ、の3つを比べる。
       注意: 認識に渡る用語は、実際には先頭約150字(プロンプト)・300字(ホットワード)までです。
       長い用語集は後ろが切れるので、多く入れるほど良いとは限りません
     ・修正データの書き出しで「校正済みの行すべて(学習用)」を選ぶと、直していない行も
       入ります(将来の追加学習では、正しく認識できた行も必要です)
     ・日本語の文字起こしで、英字が目立つ行(英語の幻覚のことが多い)は「要確認」になります。
       用語集に入れた英字の語(Apex など)は数えません

  ■ 長時間の校正作業向けの機能(v0.7.1 / キー操作は v0.8.0 で左手だけに変更)
     ・左のメニューの開閉(v0.9.8。左上の「☰」、メニュー内の「◀ 閉じる」、または G)…
       メニューを閉じると、映像と一覧を広く使えます(開閉の状態は覚えています)。処理中の件数は、右上に出ます。
       画面が狭いときは、文字起こしを開いた時点で自動で閉じます
     ・「表示」…文字の大きさ・行の間隔・動画の大きさ(「音声だけ聞く」で映像を隠せます)・
       画面の色(明るい/暗い。右上の ☾/☀ ボタンと同じ設定)・休憩のお知らせ。この設定は、そのブラウザにだけ保存されます
     ・左手だけで校正できます(v0.8.0)。v0.9.7 からは「キー単体」で操作します(Shift 不要。一覧は右上の「操作キー」)
         Q 3秒戻る  W 前の行  E 3秒進む  R もう一度聞く
         A 前の未校正  S 次の行  D 次の未校正  F 次の要確認
         Z この行を削除(2回押し)  X 聞き取れない  C 声が重なる  V BGM・音が大きい
         T 行の文字を直す(入力欄へ)  G メニューの開閉  B 移動で自動再生  N 後ろに行を追加
         Shift+Space 校正済みにして次へ(Space だけは、単体だと再生・停止なので Shift 付き)
         1〜9 / 0 行の話者を割り当て / 話者なし
       文字を入力しているとき(入力欄にカーソルがあるとき)は、文字は普通に入力されます。
       Esc で入力欄から抜けると、操作キーが使えます。Space(Shiftなし)は再生・停止、Ctrl+Z は元に戻す。
       基本の流れ: S で行を選ぶ → R で聞く → 合っていれば Shift+Space /
       直すなら T で入力 → Esc → Shift+Space。「移動したら自動で再生」(B)をオンにすると、
       Shift+Space の連打で「聞く → 確認 → 次を聞く」が続きます
       (入力中は、Ctrl+Enter で聞き直し、Alt+Enter で校正済みにして次の行へ、Alt+1〜9 で話者も使えます)
     ・行の「音の状態のメモ」(X / C / V。行をクリックすると、行の下にボタンが出ます)…
       「聞き取れない」の行は、精度の測定・追加学習の正解には使いません(あとから学習に使うかを選べます)
     ・画面上部の「進み具合の帯」…全体を時間軸で見て、校正済み(緑)・要確認(黄)・未校正(灰)を
       確認できます。クリックでその位置へ移動します。その横に、未校正の残りと、今回の校正数・
       作業時間が出ます(操作している時間だけを数えます)
     ・用語のボタン…用語集の語を、行のカーソル位置にワンクリックで入れます
       (文字を選んでから押すと、その文字を置き換えます)
     ・文字起こしを開き直すと、前回の続きの行へ移動します(このブラウザに位置を記録します)
     ・自動バックアップ…保存内容を10分ごと(と、再認識・話者判別の直前)に自動で残します
       (1本あたり最新30世代。transcripts/.hist)。「話者・置換・書き出し」の「履歴」から、
       その時点に戻せます(戻す前の状態も残ります)
     ・保存の競合の検出…別のタブや再認識で先に保存された内容を、古い画面で上書きしそうなときは、
       自動保存を止めて選ばせます(読み込み直す/この画面の内容で上書き)。
       保存に失敗したときは、5秒後に自動で再試行します
     ・数千行の文字起こしでも軽く動くように、行の描画・高さの計算を見直しました

  ■ 保存データ(将来の学習用。v0.8.0)
     校正した成果を、元の動画に頼らない形で、このフォルダの dataset/ に自動で残します
     (左の「保存データ」カード。10分ごと・文字起こしを切り替えるとき・画面を離れるときに保管。
      「今すぐ保管」「校正済みのある全部を保管」もあります)。
     ・校正済みの行(文章・話者・音の状態のメモ・機械の出力との対応・時刻)と、行ごとの音声(16kHz・FLAC)
     ・人が消した行(幻覚などの「負例」。機械の出力と音声)
     ・その範囲の全体の音声(設定でオフにできます。3時間で約200MB。元の動画を消しても、別のモデルで認識し直せます)
     ・話者ごとの正解の量(声紋登録の見込みに使えます)
     形式は dataset/README.txt に書いてあります(index.jsonl が全体の一覧)。
     目安: 追加学習(LoRA)は、正解が2〜3時間分から。声紋登録は、話者1人あたり数分〜十数分から。
     音声を新しく保管するには元のファイルが必要です(すでに保管した音声は、元のファイルが無くても残ります)。
     ※ 話者の声・会話の内容が入ります。他人に渡す・クラウドに上げるときは、相手の同意と規約を確認してください。
       他の人にフォルダを渡すときは、dataset/ も抜いてください。

  ■ v0.12.0 の変更(2026-09-26・Resolve パッケージを cut2resolve の Text+ パックに一本化)
     ・「Resolveパッケージ(zip)をダウンロード」の中身を、cut2resolve の Text+ パックと同じものにしました
       (友人の PC の Resolve で確かめた方式。作り方が2通りあったのを1つにまとめました)。
       zip を展開してできるフォルダの「友人へ.txt」の手順で取り込みます。Resolve のプロジェクトは手で作ってからスクリプトを実行します
       (以前の zip はスクリプトが新しいプロジェクトを作っていました)。
     ・選ぶのは、Resolve で作るプロジェクトの fps(24・25・30・50・60)と画面の大きさ(縦 1080×1920 / 横 1920×1080)です。
       カットの位置は動画自身の fps で数えるので、60fps の動画で 30 を選んでも、カットの位置はずれません
       (以前は、動画と違う fps を選ぶとカットの位置がずれていました)。
     ・字幕の直し: 動画の終わりをまたぐ行の字幕も(終わりで切って)入れます。SRT の番号は時刻の順です。
       ちょうど半フレームの時刻の丸めが、1フレームずれることがあったのを直しました。
     ・切り抜きスタジオの前後10秒の余白つき素材(動画の名前.edit.json)は、これまでどおり使います(cut2resolve でも使えるようになりました)。
     ・zip から無くなったもの: timeline.fcpxml(代わりに EDL が入ります)。
     ・このツールのフォルダの隣に cut2resolve のフォルダが必要です(リポジトリのまま使っていれば、そのままで動きます)。

  ■ v0.11.0 の変更(2026-09-25・入口への取り込みと、認識の別プロセス化)
     ・文字の認識(faster-whisper)と話者判別(sherpa-onnx)を、別のプログラム(tx_worker.py)で動かすようにしました。
       メモリ不足などで認識の部品が落ちても、落ちるのはその部品だけです。そのジョブは「失敗」になり、次の文字起こしで自動的に起動し直します
       (以前はサーバーごと止まり、黒い画面を開き直す必要がありました)。認識の部品の記録は worker.log に出ます。
     ・しばらく(15分)文字起こしをしなければ、認識の部品ごと終わらせてメモリを返します(次の文字起こしでは読み込み直しに数十秒かかります)。
     ・リポジトリ直下の start-all.bat(入口)から使うときは、入口と同じアドレスの http://localhost:8700/transcribe/ で動きます

----------------------------------------------------------
  ・GPU(NVIDIA)がなくても動きますが、CPU だけだと遅くなります。
    長い動画は、動画の長さ以上の時間がかかることもあります。
    まずは短い範囲で試して、時間を確かめてください。
  ・「処理方式」は「自動」のままで大丈夫です(GPU が使えれば GPU、だめなら CPU)。
    処理中の表示に、実際に使っている方式(GPU / CPU)が出ます。
  ・small … 軽い。精度はそこそこ
  ・medium … バランス型(迷ったらこれ)
  ・large-v3 … 高精度。重いので GPU 推奨
  ・large-v3-turbo … large-v3 に近い精度で、より速い(迷ったらこれも候補)
  ・kotoba-whisper … 日本語向けの高速モデル。速い代わりに、声が重なる・BGM が大きい
    ・聞き取りにくい音声では、抜けや誤変換が増えることがあります
  ・「品質」を「速度優先」にすると速くなりますが、精度は少し下がります
  ・初回のダウンロードは数百MB〜数GB。以降はインターネットなしで使えます


----------------------------------------------------------
 ④-2 精度が低いときの試し方
----------------------------------------------------------
  まず、1〜2分の短い範囲だけで、設定を変えて比べてください
  (「範囲」を入れて何回か実行すると、結果が別々に保存されます)。
  ・全体的に間違いが多い → モデルを large-v3 か large-v3-turbo にする
  ・声が抜ける・途中がまるごとない → 「無音・BGMの扱い」を「弱め」か「使わない」に
  ・話していない文(「ご視聴ありがとうございました」など)が出る → 「標準」に
  ・声が小さい・人によって音量が違う → 「小さい声を持ち上げる」をオンに
  ・名前や用語が違う → 「用語集」に入れる。直らないものは「置換辞書」で直す
  ・品質は「精度優先」にしておく(「速度優先」は精度が下がります)
  ・複数人の声が重なる場面は、どの設定でも間違いやすい部分です。
    その場面は「要確認」の行や、聞き直しながらの修正で直してください

----------------------------------------------------------
 ⑤ 精度についての注意(必ずお読みください)
----------------------------------------------------------
  ・BGM や歌、ゲーム音が大きいところ、複数人が同時に話すところでは、誤認識や
    抜けが増えます。「無音・BGMの扱い」は、無音部分での
    でたらめな文(「ご視聴ありがとうございました」など)と、声の抜けの、
    どちらを減らすかの調整です(標準の「弱め」は、声を抜かない側です)。
  ・それでも出る誤認識は、「要確認」の印を付けます。印がない行にも
    間違いはあるので、公開する字幕は必ず聞いて確認してください。
  ・固有名詞(名前・グループ名)は誤変換されやすいです。用語集に入れるか、
    置換辞書で直してください。
  ・話者の自動判別も間違えます。特に、声が似た人、同時にしゃべる場面、笑い声や短い
    相づち、BGM の大きい場面は苦手です。人数を「自動」にすると、声が似た人を1人に
    まとめたり、1人を複数人に分けたりします。人数が分かるなら指定してください。
    重なって話している場面は、片方の人にしか割り当てられません。
  ・BGM と声を分ける処理(ボーカル分離)は入っていません。


----------------------------------------------------------
 ⑥ データについて
----------------------------------------------------------
  ・文字起こしは、このフォルダの transcripts/ に保存されます(1件1ファイル)。
    バックアップはこのフォルダをコピーしてください(transcripts/.hist に、自動の履歴も残ります)。
  ・ホロライブの名簿(v0.8.2): 設定の「用語集」の下の「ホロライブの名簿から追加」で、所属(期・ユニット
    など)にチェックして「用語集に追加」を押すと、その名前が用語集に入ります。設定の比較(A/B)の
    設定別の用語集にも、「名簿から足す」で入れられます。名簿は hololive-roster.json(公式サイトで
    確認、2026-09-22 時点)。メンバーの増減があったら、このファイルを直せます(形式は見ればわかります)。
    ★用語集のうち、認識に効くのは先頭の約150字だけです(画面に「先頭N語まで」と出ます)。
    全員を入れると後ろが切れるので、その動画に出る人・ユニットだけに絞ってください
  ・用語集・置換辞書は settings.json に保存されます。
  ・話者判別のモデルは models/ フォルダに保存されます(消しても、次回また自動でダウンロードされます)。
    ダウンロードしたファイルは、配布元と同じものか(ハッシュ)を確認してから使います。
  ・元の動画・音声ファイルは、移動や削除をしないでください
    (聞き直しの再生に使います。なくても文字の編集は可能です)。
  ・更新するときは、フォルダの中の .py ファイル(serve.py・pipeline_io.py・resolve_export.py)と
    index.html・app.js・ui-kit.js をまとめて上書きします(serve.py と app.js の片方だけだと、画面の上に赤い帯が出ます。
    pipeline_io.py・resolve_export.py が無いと「動画の隣に保存」「Resolve パッケージ」が使えません。
    「Resolve パッケージ」は隣の cut2resolve フォルダの部品で作るので、cut2resolve も一緒に更新してください。
    app.js・ui-kit.js が無いと画面が真っ白になります)。
  ・動画の隣に保存した .transcript.json / .srt / .cut-plan.json には、文字起こしの文章と元の動画のパスが入ります。
  ・他の人にフォルダを渡すときは、transcripts/ と settings.json と dataset/ を抜いてください(serve.log には動画名が入っています)。


----------------------------------------------------------
 ⑦ 困ったとき
----------------------------------------------------------
  ・「準備が必要です」と出る → 表示された内容(ffmpeg / faster-whisper)を実行
  ・NVIDIA の GPU があるのに CPU で動く → install-gpu.bat を実行して、ツールを起動し直す。
    それでも GPU にならない場合は、NVIDIA のドライバを最新にしてください
  ・「話者判別の部品(sherpa-onnx)が入っていません」と出る → install-diarize.bat を実行して、
    ツールを起動し直す。入らないときは、Python のバージョンが新しすぎる可能性があります
    (Python 3.10〜3.12 がおすすめ)
  ・話者判別のモデルをダウンロードできない → インターネット接続を確認(初回のみ必要)
  ・話者が多すぎる・少なすぎる → 「人数」を指定してやり直す
  ・「モデルを読み込めませんでした」 → インターネット接続を確認(初回のみ必要)。
    ディスクの空き容量も確認してください
  ・「音声を取り出せませんでした」 → 動画に音声がない、またはファイルが壊れて
    います。別の形式(mp4 など)に変換して試してください
  ・動画が再生されない → mkv など、ブラウザで再生できない形式です。
    文字の編集と書き出しは、再生できなくても使えます
  ・画面の上に赤い帯が出る → 古い版の黒い画面が残っています。閉じてから
    start を起動し直してください
  ・Python が見つからない → Python を入れ直し、「Add python.exe to PATH」に
    チェックを入れる
  ・ポート番号が使用中と出る → 自動で次の番号を使います。表示されたアドレスを開く
  ・「動画のフォルダに書き込めません」 → 動画が読み取り専用の場所(DVD・共有フォルダなど)にあるか、
    同じ名前のファイルを他のアプリで開いています。動画を書き込めるフォルダへ移すか、ダウンロードを使ってください
  ・「元の動画が見つかりません」(動画の隣に保存) → 文字起こしのあとで動画を移動・削除しています。元の場所に戻してください
  ・起動時に「※ …」と出る → 書いてある準備をしてから、黒い画面を閉じて起動し直してください

DaVinci Resolve連携
-------------------
- 文字起こしを開き、各行の「残す／カット済」で仮編集を指定します。
- 「話者・一括置換・書き出し」内の「Resolveパッケージ(zip)」で書き出します。
  Resolve で作るプロジェクトの fps と画面の大きさ(縦・横)を選んでから押します。
- 中身は cut2resolve の Text+ パックと同じです: 動画(media フォルダ)、Text+ 字幕を作るスクリプトと登録用の bat、
  手順書「友人へ.txt」、予備の EDL と手順書、字幕(SRT)、cut-plan.json。
- zip を展開してできるフォルダの「友人へ.txt」の手順で取り込みます(プロジェクトは手で作る → bat で登録 →
  「ワークスペース」→「スクリプト」→「cut2resolve TextPlus Import Lua」)。
- CUT_TextPlusは再編集用、SOURCE_WITH_HANDLESは削除区間の復旧用です。
- 切り抜きスタジオで新しく書き出した素材には前後10秒の編集余白があります。
