# サムネの案を数パターン出す(提案 P5 の設計)

状態: **S の試作をコマンドで作った(2026-10-09。`src/editor/thumb_ideas.py`(同じ日に dev/ から移した)・7)・画面のボタンと M(LLM のキャッチ)はまだ**(設計 2026-10-08。ユーザー「サムネはそのまま使用することはなく、イメージを数パターン示すほうがよさそう。LLM の使用も同時に検討」)

- 経緯: `plan/proposals-2026-10.md` の P5。投稿までの手作業で最大なのがサムネ(1 本 5〜15 分・ショートにも 1 本ずつ作っている・1 日 3〜6 本 = 1 日 15〜90 分)
- 関連: LLM の実行部品は `plan/llm-postfix.md`(P18)と共通。フレームの切り取りは却下した P9(縦型)の「配信者ごとのレイアウト」の小さい版

## 1. 何を作るか
- 入力: 切り抜き(mp4)・文字起こし(校正前でも可)・話者と配信者(メンバーカラー)・あなたの過去の題名(【一言】の作風の見本)
- 出力: **1 枚の「案の一覧」**(PNG。例 2 列 × 3 行 = 6 案)+ JSON(各案の元の時刻・文・レイアウト名)。1 案 = 候補のフレーム + キャッチ(3〜6 字)+ 補助の 1 行 + レイアウト(文字の位置・寄り)。**そのまま使う完成品ではなく、作るときの参照**(ユーザーの希望)
- 置き場所: パックのフォルダ `_pack/thumb-ideas.png`・`thumb-ideas.json`。編集の 3 パック に「サムネの案」ボタン(パックとは独立に押せる)。まとめて実行の最後にも任意で付けられる

## 2. 作り方(3 つの部品)
### 2-1 フレームの候補(ffmpeg だけ。新しい依存なし)
- 時刻の候補: (a) 盛り上がりの山(`.clip.json` の区間の点数・スタジオの解析の系列)(b) 声の大きい瞬間(RMS)(c) 文字起こしで笑い・叫び・伸ばし棒の多い行の頭 (d) 場面の切り替わりの直後(ffmpeg の scene 検出)。近い時刻をまとめて 8〜12 時刻
- 1 時刻につき 1 枚(前後 ±0.3 秒で 3 枚取り、ブレ・黒の少ない 1 枚 = ffmpeg の `thumbnail` / `signalstats`)
- 切り取り: 配信者ごとの「アバターの矩形」を初回に人が 1 回指定して覚える(P9 で却下したテンプレの小さい版。無ければ中央と右下の 2 案)。将来はアニメ顔の検出(ONNX。deepghs/anime_face_detection)で自動
- 出力の比率: 縦 9:16(ショート)と、チャンネルページで見える 3:2 の安全領域の枠線を描く(文字を置ける場所が分かる)

### 2-2 キャッチの候補(ローカル LLM。P18 と同じ実行部品)
- 入力: 文字起こし(区間の全部。短い)+ 話者 + 配信の題名 + あなたの過去の題名 30 本(作風の見本 = few-shot。【尊い】【暴露】【ゴツい】…)
- 出力: JSON で 6 案 `{catch: "3〜6 字", sub: "補助の 1 行(12 字以内)", at: "元になった行の時刻", why: "1 行"}`
- 制約(プロンプトと検査の両方で): 名簿に無い名前を作らない・文字起こしに無い事実を足さない・誤解を招く見出しを作らない(カバー社の「本意から離れた刺激的なサムネ」を避ける)。検査で落ちた案は捨てて規則案で埋める
- LLM が無い・止めたとき: 規則の簡易版(行の中の感情の言葉 = 笑い・叫び・驚き・伸ばし棒・名簿の呼び名 から拾う)

### 2-3 1 枚にまとめる(ffmpeg の `drawtext` + `tile`)
- フォント: けいふぉんと(Windows に入っている前提。無ければ MS ゴシック)。白い文字 + 太い黒ふち(運営者の経験則)。配信者のメンバーカラーを縁か帯に
- 6 案の並べ方: 同じキャッチ × 違うフレーム、同じフレーム × 違うキャッチ、文字の位置(上/下/左)を混ぜる = 「イメージの幅」を見せる
- 各案に番号・元の時刻・レイアウト名を小さく。`src/home/deliver.py` の drawtext(textfile で日本語を渡す)の作りを流用

## 3. 守り・リスク
- 「そのまま使わない」が前提なので、画像の品質より案の幅を優先。完成品の自動生成はしない(作ると「どちらが本物か」の混乱 = 段 14 を却下した理由と同じ)
- ガイドライン: サムネを理由に削除されることがある。LLM の案に NG の判定は付けられないので、判断は人。制約は上の 2-2
- 時間: 1 本の案を出すのに ffmpeg が数秒・LLM が 10〜30 秒(8B・Vulkan)の見込み。GPU は文字起こし(whisper.cpp)と取り合うので `SLOTS` を通す
- フォントの再配布はしない(けいふぉんと の規約。Text+ と同じ)

## 4. 大きさと順番
- S(1〜3 時間): 2-1 + 2-3 を規則のキャッチで(LLM なし)。これだけでも「どのフレームか」の参照にはなる
- M(4〜10 時間): 2-2。LLM の実行部品は P18 と共通なので、先に作ったほうに相乗り
- 効果の測り方: サムネ 1 本 5〜15 分 → 目標 2〜5 分(あなたの感覚で前後を比べる)。6 案のうち使った数(採用率)を JSON に残す

## 5. 決めた(2026-10-09。ユーザー「他はおすすめでいい」→ AI のおすすめで)
1. 案は 6(2 列 × 3 行)。比率は縦 9:16 で、3:2 の安全領域の枠線を描く
2. 配信者ごとのアバターの矩形は初回に 1 回指定して覚える(自動の顔検出はあと)
3. キャッチは LLM 案と規則案を並べて出す(どちらが使われたかを JSON に残して LLM の価値を測る)
4. 置き場所はパックのフォルダ(`_pack/thumb-ideas.png`・`.json`)
5. 先に S(LLM なし。2-1 + 2-3 + 6 の他チャンネルの参考)で試し、使えそうなら M(LLM のキャッチ)を P18 の実行部品に相乗り
6. **他のチャンネルも参考にする**(ユーザー 10-09): 下の 6

## 6. 他チャンネルの参考(2026-10-09 に見た型。設計時の見本 + 動かすときの参照の行)
### 6-1 見た型(あなたの視聴者が見ている他の切り抜きチャンネル 3 つ: ホロスクエア・ホロの伝道師・ホロまる。公開ページを内蔵ブラウザで)
- 文字: **白か黄色の太い文字 + 太い黒(紺・赤)の縁 + 影**。2 行 × 4〜8 字で画面幅の 9 割。配信者の色を縁や帯に使う
- 顔: アバターを**胸から上で大きく**(縦の 5〜6 割)。背景は配信の画面のまま(ゲーム画面)か、少しぼかす
- 型 A「上に小さい状況・下に大きいキャッチ」(ホロの伝道師。上の帯に小さい白文字で状況「キョーコのお手洗いの言い方を」、下に大きく「修正したいつづり」)
- 型 B「大きい 2 行のキャッチ + 顔の寄り」(ホロスクエア。「わしのコマ ない…!」のように感情の言葉を大きく)
- 型 C「吹き出しのセリフ」(白い角丸の箱に 「自分はどっちでもいい」。発言そのものを見せる)
- 型 D「一語ドン」(ホロまる。「は？」「誰」のような 1〜3 字を特大に)
- あなたのチャンネルとの違い(印象): 文字が細め・行数が多め(3〜4 行)・顔が小さめの回がある。他チャンネルは「文字を減らして太く・顔を大きく」で統一されている。6 案のうち 4 案は型 A〜D のどれかで作り、2 案はあなたの今の型で作って並べる
### 6-2 動かすときの「参照の行」(1 枚の下段)
- **同じ元配信を切り抜いた他チャンネルのサムネ**を最大 5 枚(yt-dlp の `ytsearch` で元配信の題名・配信者名を検索。API の割り当ては使わない。サムネの URL は公開情報)。「参照用。使わない・保存しない(一時のキャッシュ)」の札を付ける。同じ場面を既に出しているチャンネルが分かる = P16(ネタ被り)の小さい版にもなる
- **あなたの過去の伸びた 5 本のサムネ**(同じ配信者。日報(`plan/analytics-daily-report.md`)の動画の表から再生数の上位。それまでは Data API の自分の動画の一覧)。作風をそろえる参照
- 他人のサムネは参照に見せるだけで、案の画像には合成しない(著作物)。6-1 の型は「作り方」として使う

## 7. S の試作(2026-10-09。`src/editor/thumb_ideas.py`。はじめは dev/ に置いた)
- 使い方(リポジトリ直下で): `py -3.10 src/editor/thumb_ideas.py "<切り抜きの動画>"`。動画の隣に `<名前>_thumb-ideas.png`(2 列 × 3 行 = 6 案・1080×2880)と `.json`(案ごとの型・時刻・文字・切り取り)ができる。文字起こしは動画のパスが同じ文書を自動で探す(`--doc` で指定も)。雑談のようにアバターが中央の配信は `--crop center`、アバターの位置が決まっていれば `--rect x,y,幅,高さ`(元の動画の画素)でそこへ寄せる
- 中身: 時刻 = 音の大きい瞬間(0.5 秒ごとの RMS)・場面の切り替わり・感情の強い行(！？・伸ばし棒・笑い・繰り返し・感情の言葉)から 3 秒以上離して 6 つ。6 案 = 型 A(帯に小さい状況 + 黄色の大きいキャッチ)・B(大きい 2 行・縁はメンバーカラー)・C(白い吹き出し)・D(一語ドン)・今の型 2 つ(3〜4 行の細め)。切り取りは中央(縦いっぱい)と右下の寄せ(ゲーム実況のアバター)を交互。2:3 の範囲の枠線・案の番号・型・時刻の札。文字は游ゴシック Bold(けいふぉんとが入っていればそれ)
- 本物の切り抜き 2 本で見た(さくらみこのマリオ・鈴鳴つづりの雑談): ゲーム実況は右下の寄せで顔が大きく入る。雑談はアバターが中央なので右下の寄せは背景だけになる → `--crop center`。**配信者ごとにアバターの位置を覚える仕組み(5 の 2)が要る**ことを確かめた。キャッチは文字起こしの行の切り方しだいで文の途中から始まることがある(参照としては使える)。文字が顔に重なる案がある(覚えた位置を避けて置くのは組み込むとき)
- まだ: 編集の 3 パックの「サムネの案」ボタンとアバターの位置を覚える画面(並行セッションの src/editor の見直しのあと)・M(LLM のキャッチ。P18 の Qwen3-8B と llama-server に相乗り)・6-2 の参照の行(他チャンネルの同じ元配信のサムネ・自分の伸びた 5 本)
