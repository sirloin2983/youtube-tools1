# サムネの案を数パターン出す(提案 P5 の設計)

状態: **設計の案・実装はまだ**(2026-10-08。ユーザー「サムネはそのまま使用することはなく、イメージを数パターン示すほうがよさそう。LLM の使用も同時に検討」。計画 `plan/data.js` には未反映)

- 経緯: `plan/proposals-2026-10.md` の P5。投稿までの手作業で最大なのがサムネ(1 本 5〜15 分・ショートにも 1 本ずつ作っている・1 日 3〜6 本 = 1 日 15〜90 分)
- 関連: LLM の実行部品は `plan/llm-postfix.md`(P18)と共通。フレームの切り取りは却下した P9(縦型)の「配信者ごとのレイアウト」の小さい版

## 1. 何を作るか
- 入力: 切り抜き(mp4)・文字起こし(校正前でも可)・話者と配信者(メンバーカラー)・あなたの過去の題名(【一言】の作風の見本)
- 出力: **1 枚の「案の一覧」**(PNG。例 2 列 × 3 行 = 6 案)+ JSON(各案の元の時刻・文・レイアウト名)。1 案 = 候補のフレーム + キャッチ(3〜6 字)+ 補助の 1 行 + レイアウト(文字の位置・寄り)。**そのまま使う完成品ではなく、作るときの参照**(ユーザーの希望)
- 置き場所: パックのフォルダ `_pack/thumb-ideas.png`・`thumb-ideas.json`。編集の 3 パック に「サムネの案」ボタン(パックとは独立に押せる)。まとめて実行の最後にも任意で付けられる

## 2. 作り方(3 つの部品)
### 2-1 フレームの候補(ffmpeg だけ。新しい依存なし)
- 時刻の候補: (a) 盛り上がりの山(`.clip.json` の区間の点数・スタジオの解析の系列)(b) 声の大きい瞬間(RMS)(c) 文字起こしで笑い・叫び・伸ばし棒の多い行の頭 (d) 場面の切り替わりの直後(ffmpeg の scene 検出)。近い時刻をまとめて 8〜12 時刻
- 1 時刻につき 1 枚(前後 ±0.3 秒で 3 枚取り、ブレ・黒の少ない 1 枚 = ffmpeg の `thumbnail` / `signalstats`)
- 切り取り: 配信者ごとの「アバターの矩形」を初回に人が 1 回指定して覚える(P9 で却下したテンプレの小さい版。無ければ中央と右下の 2 案)。将来はアニメ顔の検出(ONNX。deepghs/anime_face_detection)で自動
- 出力の比率: 縦 9:16(ショート)と、チャンネルページで見える 3:2 の安全領域の枠線を描く(文字を置ける場所が分かる)

### 2-2 キャッチの候補(ローカル LLM。P18 と同じ実行部品)
- 入力: 文字起こし(区間の全部。短い)+ 話者 + 配信の題名 + あなたの過去の題名 30 本(作風の見本 = few-shot。【尊い】【暴露】【ゴツい】…)
- 出力: JSON で 6 案 `{catch: "3〜6 字", sub: "補助の 1 行(12 字以内)", at: "元になった行の時刻", why: "1 行"}`
- 制約(プロンプトと検査の両方で): 名簿に無い名前を作らない・文字起こしに無い事実を足さない・誤解を招く見出しを作らない(カバー社の「本意から離れた刺激的なサムネ」を避ける)。検査で落ちた案は捨てて規則案で埋める
- LLM が無い・止めたとき: 規則の簡易版(行の中の感情の言葉 = 笑い・叫び・驚き・伸ばし棒・名簿の呼び名 から拾う)

### 2-3 1 枚にまとめる(ffmpeg の `drawtext` + `tile`)
- フォント: けいふぉんと(Windows に入っている前提。無ければ MS ゴシック)。白い文字 + 太い黒ふち(運営者の経験則)。配信者のメンバーカラーを縁か帯に
- 6 案の並べ方: 同じキャッチ × 違うフレーム、同じフレーム × 違うキャッチ、文字の位置(上/下/左)を混ぜる = 「イメージの幅」を見せる
- 各案に番号・元の時刻・レイアウト名を小さく。`src/home/deliver.py` の drawtext(textfile で日本語を渡す)の作りを流用

## 3. 守り・リスク
- 「そのまま使わない」が前提なので、画像の品質より案の幅を優先。完成品の自動生成はしない(作ると「どちらが本物か」の混乱 = 段 14 を却下した理由と同じ)
- ガイドライン: サムネを理由に削除されることがある。LLM の案に NG の判定は付けられないので、判断は人。制約は上の 2-2
- 時間: 1 本の案を出すのに ffmpeg が数秒・LLM が 10〜30 秒(8B・Vulkan)の見込み。GPU は文字起こし(whisper.cpp)と取り合うので `SLOTS` を通す
- フォントの再配布はしない(けいふぉんと の規約。Text+ と同じ)

## 4. 大きさと順番
- S(1〜3 時間): 2-1 + 2-3 を規則のキャッチで(LLM なし)。これだけでも「どのフレームか」の参照にはなる
- M(4〜10 時間): 2-2。LLM の実行部品は P18 と共通なので、先に作ったほうに相乗り
- 効果の測り方: サムネ 1 本 5〜15 分 → 目標 2〜5 分(あなたの感覚で前後を比べる)。6 案のうち使った数(採用率)を JSON に残す

## 5. 決めてほしいこと
1. 案の数(6?)と比率(縦 9:16 だけ / 3:2 の枠も)
2. 配信者ごとのアバターの矩形を 1 回指定する形でよいか(自動の顔検出はあと)
3. キャッチは LLM 案と規則案を並べて出すか(LLM の良し悪しを見るため)
4. 置き場所(パックのフォルダ / 案件のフォルダ)
5. 先に S(LLM なし)で試すか、M まで一度に作るか
