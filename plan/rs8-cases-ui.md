## 決めたこと(10-10 深夜。ユーザー)
1. **画面の形 = 案件を中心に組み直す(b)+ V1「確かめる」を一緒に設計する**(ユーザー「V1 も考慮しないといけない」→ 案のとおり):
   - 入口は 2 本 = **案件**(作る。配信 1 本 → 候補の採否 → 切り抜き → 校正 → カット → パック。スタジオと編集は案件の中のタブになり、ツールごとの入口は無くなる)/ **確かめる**(精度を上げる。案件をまたいだ待ち行列。今いちばん効く確認を 1 つずつ・各項目に「あと何本で何が決まるか」)
   - 軽い確認(候補の採否・自動の切り抜きが 70 点以上か・「別」の採否・後処理の札・話者)は**その場のカード**で続けて答える / 重い確認(G2 の定点の校正・カットのたたき台)は**案件の画面の該当の所へ飛び**、終わったら戻る
   - **部品を共用する**(行の編集・候補の再生・カットを、案件の画面と確かめるのカードの両方から使える部品に)= 画面の形は (b) と V1 を一緒に決める。案件の画面にも「この案件で確かめると効く物 n 件」を出す
2. **作る範囲 = 画面の形は (b) と V1 を一緒に決め、RS8 で作るのは案件の画面まで。V1 はその直後**(おすすめのとおり。RS8 はデータの移動 B-2・B-3 も抱えて大きいため)

3. **O2 = 文書を「① の機械の結果 + 人の上書きの層」から毎回組み立てる・人の層が人の直しの正**(O1 の「文書が正・over.json は派生の控え」から変える): 人の層に**全部**持たせる = 文字・校正済み・話者・字幕を出さない・音のメモ(時刻つきの人の行)/ 時刻を動かす・分ける・つなぐ(人の行の時刻。覆われた機械の行は人の行に置き換わる)/ **消す = 「この時間帯の機械の行は要らない」の印**(作り直してもその時間帯の機械の行を出さない = O1 の穴を塞ぐ)/ 足す(人の行)/ カットは今のまま `edit.json`(区間)。**機械の結果が変わったら(案 A)** 人の直しを残して行に「機械の結果が変わりました」の印 → 開くと 前の機械 / 今の機械 / あなたの直し を並べて [自分の直しのまま] / [今の機械にする] を選べる(既定は自分の直しのまま)。印の付いた行は案件の画面にも確かめるにも出せる

4. **RS8 の中の順番 = 形は先に紙で決め、作るのはデータが先**: ① 画面の形を先に設計(見本と部品の分け方。V1 と共用する部品がデータの持ち方に響くため。問答 → 設計の要点の文書 → 見本の順)→ ② データを B-2(先にバックアップの規則)→ B-3 → O2 の順で移す(今の画面は互換の口で今のまま動かす = 段ごとに今のテストが効く・途中でも普段の作業ができる)→ ③ URL も CLI で(B-3 のあと)→ ④ 新しい画面を作り、古い画面を消す。一度に変える物を 1 つに(コードの単位とデータの単位を一度に変えない)

5. **1.0.0 にする時 = RS8・V1・コードと画面の見直し 1 周・友人の PC で ② + ① が動いた(F1)のが全部済んだら**(案 B。メインの形 = 友人の PC が実際に動いた時を区切りに・友人のアプリ版とユーザーの PC の版を 1.0.0 からそろえる)。それまでは仮の 0.x
