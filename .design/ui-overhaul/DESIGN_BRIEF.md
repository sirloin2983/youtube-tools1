# Design Brief: 画面の全面見直し(ホーム・切り抜きスタジオ・編集)

作成: 2026-09-27(Claude / Cowork。ui-dev-workflow の段階1〜2)
状態: **ユーザーの確認待ち**(確認が取れるまで実装しない)
実装: PC の Claude Code(実機で動画・GPU を使って確かめられるため)。この文書がその作業の正本

---

## Problem

ショート動画を作るたびに、次の3つの画面でいちばん時間と気力を取られている。

- **編集の校正**: ボタンの入口が多くて探す。いま再生している声が、一覧のどの行なのか追いにくい。単体キーが多くて覚えられず、押し間違える。
- **編集のカット・パック**: タイムラインは4段あって見る所が多く、ズームと移動がやりにくく、区間の端もつかみにくい。パックは毎回、手順1〜7を上から見る必要がある。
- **スタジオの確認**: 盛り上がりのグラフから、どこを見ればいいか読めない。いちばん使う「今をマーク」が、IN/OUT/追加と同じ高さに埋もれている。

画面全体にも同じ問題がある。

- 動画の一覧が「案件」と「編集の履歴」の2か所にある。編集の履歴は狭い左メニューの中にあって見づらい。
- 設定の置き場所が3系統ある。
- キーの意味がツールやタブで違う(S は校正では「次の行」、カットでは「分割」)。
- 同じ部品(トースト・ダイアログの見出し・ポップオーバー)がツールごとに別々に作られている。

## Solution

「開く → いま要るものだけが見える → 手がキーボードから離れない」作業机にする。

- **ホーム**(入口と案件を1つにした画面)を開くと、「次にやること」(校正待ち・パック待ち・進行中の処理)が上に数件だけ出る。押せばその作業の画面へ直接入れる。
- 画面の左上には、いつも「ホーム / スタジオ / 編集」の3つの切り替えがある。開いていた動画を引き継いで行き来できる。
- 作業の画面では、主役(映像と一覧、またはタイムライン)が画面の大半を占める。操作の入口は役割ごとに1つにする。よく使う操作にはボタンの横にキーを書き、画面の下の細い帯にいま使えるキーを出す。
- スタジオで書き出しが終わると、文字起こしが自動で始まる。ホームに「校正待ち」として並ぶので、手で次の段に渡さなくてよい。

## Experience Principles

1. **主役を大きく、道具は呼んだときだけ** — 映像・行・タイムラインが画面の大半を占める。書き出しの設定・話者・書き出し形式・上級の機能は、右の欄・「…」・畳んだ欄に入れる。「詳しい設定」を開かなくても、既定値で作業が終わるようにする。
2. **1つの操作に入口は1つ、キーは全体で同じ意味** — 同じ操作のボタンを2か所に置かない。再生系のキー(Space・J/K/L・← →・I/O)はどのツールでも同じ意味にする。1つのキーが画面によって別の意味になる状態をなくす。
3. **覚えさせずに見せる** — キーはボタンの横と下の帯に出す。前回の設定は要約して見せる(パック)。盛り上がりの山には順位と理由を書く。次にやることはホームが教える。

## Aesthetic Direction

- **Philosophy**: 落ち着いた仕事道具(quiet tool)。灰色の段階で面を分け、色は「意味」にだけ使う。紫の強調色は、主なボタン・選択中・今の行・フォーカスだけに限る。飾りの影・グラデーション・大きな角丸のカードの並びはやめる。枠線と面の濃さの差で区切る。
- **Tone**: 静か・正確・速い。何かが起きたときだけ色が出る。
- **既定のテーマ**: **明るいテーマ**(ユーザー決定)。暗いテーマの切り替えは残す。映像の周り(プレーヤーの背景)だけは、明るいテーマでも暗い灰色にして映像の色を見やすくする。
- **Reference points**: DaVinci Resolve の Cut ページ(映像が主役・下にタイムライン・道具は細い帯)、Figma の明るい UI(灰色の面・小さな文字・密度)、Linear(静かな灰色と、1色だけの強調)。
- **Anti-references**:
  - カードが並ぶ SaaS のダッシュボード
  - ネオン・ゲーミング風の配色
  - 絵文字や文字記号のアイコン(☰ ⚙ ▾ ✂)
  - 同じ画面に強調色のボタンが何個も並ぶこと
- **文字**: Segoe UI Variable(Windows に入っているので読み込みが要らず、OS の道具と同じ見た目になる)。時刻・タイムコードは Cascadia Mono と `tabular-nums` で桁をそろえる(数字の幅が変わると、再生中に文字が揺れて読みにくいため)。
- **アイコン**: SVG の線のアイコン1種類にそろえる(スタジオの今の流儀)。編集の文字記号はすべて置き換える。

## Existing Patterns

土台は今の `ui-kit/`(正本。`tools/sync_ui_kit.py` で写す)で、それを広げる形にする。作り替えはしない。
ルールは `docs/ui-guidelines.md`(用語集・ヘッダー・ボタン3種・札は押せない・一覧・段階的に見せる)を引き続き守る。変える所は下の「guidelines の改訂」に書く。

- **Typography**:
  - 今: `--font`(Segoe UI Variable Text)、`--font-display`、`--mono`(Cascadia Mono)。大きさは `--fs-xs 11.5` / `sm 12.5` / `md 14` / `lg 16` / `xl 20`。
  - 変更: 作業画面の本文は `--fs-sm`〜`--fs-md` を使う(詰める)。ホームと設定は `--fs-md`。
- **Colors**: 明暗2テーマのトークン `--bg / --panel{,-2,-3} / --line{,-2,-strong} / --ink{,-2,-3,-4} / --accent #5a46e0 / ok・warn・danger・info(+soft・ink)/ c-*`
  - 明るいテーマは、背景 `--bg` と面 `--panel` の差を少し広げる。
  - `--accent-soft` の使い道を「選択中」だけに絞る。
  - 新しいトークンを足す: `--stage-bg`(プレーヤーの周り。両テーマで暗い)と `--playhead`(再生位置の赤)。
  - 編集の CSS にじかに書いた色(#fff×22・#000×19 など)は、すべてトークンに置き換える。
- **Spacing**: `--sp-1..6`(4〜32px)、`--ctl-h 34 / --ctl-h-sm 28`、`--header-h 52`。作業画面は `--ctl-h-sm` と `--sp-1..3` を中心に詰める。ホームは `--sp-3..5`。
- **Components**(ui-kit にあるもの): `btn(primary/ghost/danger/small)`・`card`・`pill`・`badge`・`notice`・`errbar`・`toast`・`bar`・`ui-tabs`・`ui-seg`・`ui-menu`・`ui-listbar`・`ui-group`・`ui-next`・`ui-term`・`ui-skel`・`ui-spin`・`ui-krow`。JS は `UIKit.theme/tools/life/report/win/fmt`。
- **技術の前提**: 素の JS、ビルドなし、CSP `script-src 'self'`(インラインのスクリプトは不可)。画面の部品は相対パスで読む。この前提は変えない。

## Key Interactions

### 共通の再生キー(全ツール・全タブで同じ意味。ユーザー決定: 再生系だけ統一)

| キー | 意味 | 今との違い |
| --- | --- | --- |
| Space | 再生・停止 | スタジオの K 再生も残す(K は下の「止める」と同じ扱い) |
| J / K / L | 1秒戻る / 止める / 再生(もう一度押すと速く) | 校正のタブにも入れる |
| ← / → | 1秒戻る/進む。Shift つきで5秒 | 校正の Q/E(±3秒)とスタジオの ±5/10秒をこれにそろえる |
| , / . | 1コマ(1フレーム)戻る/進む。カットで区間の端を選んでいるときは、その端を1コマ動かす | 1フレーム = 動画の1枚の絵。60fps なら 1/60 秒 |
| I / O | 始まり / 終わりの印 | スタジオの IN/OUT とカットの I/O を同じキーにする |

### 同じキーが別の意味になる所をなくす(校正のキーを減らす案。ユーザー決定: キーの数を減らす)

- 行の移動を S/W から **↓/↑** に変える。これで S は「分割」(カット)だけの意味になる。
- 未校正への移動は D/A から **Shift+↓/↑** に変える。要確認への移動は F のまま。
- **やめるキー**:
  - Q・E(← → にまとめる)
  - B(自動で再生の切り替え。設定へ移す)
  - Tab(入力欄に入る・抜けるの切り替え。T と Esc と重複)
  - Ctrl+Enter(R と重複)
- **残すキー**:
  - Shift+Space(校正済みにして次へ)
  - T(文字を直す)・Esc
  - R(この行をもう一度聞く)
  - 1〜9・0(話者)
  - X / C / V(音のメモ)
  - N(行を追加)・Z を2回(行を削除)・Ctrl+Z(元に戻す)
  - G(左のメニュー)・?(キー操作の一覧)・Alt+1/2/3(タブ)

これは `transcribe-tool/AGENTS.md`「画面の設計で決めたこと」にある「単体キー」の決まりの変更になる。単体キーの方針は保つ(Shift が要るのは Shift+Space と Shift+↓/↑ だけ)。

### 画面ごとの流れ

- **ホーム**:
  - 開くと「次にやること」が上に出る。1件を押すと、その作業の画面・タブへ直接入る(例: 校正待ち → 編集の 1 校正、パック待ち → 3 パック)。
  - 進行中の処理は小さな進み具合の棒で出す。
  - 一覧の「まとめて実行」は、選んだ案件に対して範囲を選んで実行する(今の機能と同じ)。
- **校正**:
  - 行を選ぶと、その行が映像の上に字幕として出る。再生すると、再生位置にあたる行に字幕が切り替わる。
  - Shift+Space で校正済みにして次の行へ移る。キーを押すと、画面の下の帯の該当するキーが一瞬光る(何が起きたかが見える)。
- **カット**:
  - ホイールで拡大すると、マウスの位置を中心に広がる。
  - ミニマップの枠をドラッグすると、見る範囲が移る。
  - 端に近づくと光り、ドラッグすると吸い付く(Alt で吸い付かない。今と同じ)。
  - 端を選んでいる間は、下のキーの帯が「, . 1コマ / Shift で大きく / Esc 選択を外す」に変わる。
- **パック**:
  - 「作る」を押すと、その場で進み具合の棒が出る。できたら「フォルダを開く」と「Resolve での手順」が出る。
  - 設定を変えて作ると、次からはそれが「前回の設定」になる。
- **スタジオの確認**:
  - 山の札を押すと、その山の少し前へ移る。
  - 今をマーク①〜⑤を押すと、マークの一覧の先頭に追加され、タイムラインにも帯が出る。
  - 右の書き出しの欄は、開いたまま確認の作業を続けられる(書き出しの欄は映像に重ねず、横に並べる)。
- **保存と失敗**:
  - 保存の状態はヘッダーの1か所で出す。
  - 失敗は、問題が起きた場所の近くに「何が起きたか+どうすればいいか」で出す。原文は畳んで添える。

## Responsive Behavior

- **最優先は PC の全画面(1440〜1920px)**(ユーザー決定)。作業画面はこの幅で主役が最大になるように配置する。
- 1280px: 右の欄(スタジオの書き出し・パックの設定)は、映像に重ねる引き出しに変わる。
- 1024px: 編集の左メニューは重ねる引き出しになる(今の 720px の決まりを 1024px まで広げる)。
- 390px: 既存のルール「横にはみ出さない・文字が縦に割れない」だけを守る(最低限)。作業画面をスマホで使いやすくする最適化はしない。

## Accessibility Requirements

- 文字のコントラストは 4.5:1 以上(両テーマ)。状態の札は `--*-ink` を使う。
- フォーカスの輪(`--ring`)を消さない。キーボードだけで全部の操作ができる。
- 単体キーは、入力欄・select・contenteditable にフォーカスがあるときは効かない(今と同じ)。
- `ui-drawer`・`ui-dialog` は開いたらフォーカスを中に移し、Esc で閉じ、閉じたら開いたボタンへフォーカスを戻す。`aria-modal` をつける。
- 映像の上の字幕とキーの帯は飾り扱い(`aria-hidden`)にする。同じ情報は一覧と `ui-keys` から読み上げられるようにする。
- 押せる部品は 28px 以上。タイムラインの端の当たり判定は、見た目より広くする。
- 動き(光る・ずっと点滅)は `prefers-reduced-motion` で止める。ずっと点滅する表示は作らない。

## Heuristics applied(段階2。NN/g の10原則のうち、この見直しで特に効くもの)

- **#6 記憶より認識**:
  - 課題: キーが覚えられない。前回のパックの設定を毎回見直している。
  - 対応: ボタンの横のキー・下の帯・前回の設定の要約・山の順位と理由。
- **#4 一貫性と標準**:
  - 課題: S の二重の意味・シークの幅の違い・二重実装の部品・文字記号のアイコン。
  - 対応: 共通の再生キー、ui-kit への部品の昇格、SVG のアイコン1種類。
- **#8 美的でミニマル**:
  - 課題: スタジオの確認のボタン約60種・編集の左メニューの設定約30項目・4段のタイムライン。
  - 対応: 右の欄・「…」・畳む・タイムラインを3段に。
- **#1 システム状態の可視化**:
  - 課題: どの行を再生しているか分からない。書き出しから先の状況が見えない。
  - 対応: 映像の上の字幕・ホームの「次にやること」と進み具合・点滅しないジョブの札。
- **#7 柔軟性と効率**: 単体キーの体系は保つ。書き出しのあと自動で文字起こし。パックはワンクリック。ホイールでズーム。
- **#3 ユーザーの制御と自由**: カットの元に戻す/やり直す、行の削除の2回押し、`ui-dialog` の取り消しは今と同じに保つ。書き出しの欄を開いても作業は止まらない。

## guidelines の改訂(実装と同じ時期に `docs/ui-guidelines.md` へ入れる)

- **§2 ヘッダー**: 左から、`ui-appnav`(ホーム/スタジオ/編集)→ タブ → 右寄せで [ツールの操作] → [キー操作] → [⚙設定] → [テーマ]。「入口」リンクと「他のツール」メニューはなくす。
- **§1 用語集**: 「入口」を「ホーム」に置き換える。README・画面の文言も合わせる。
- **新しい節「キー」**: 共通の再生キーの表と、「1つのキーは全体で1つの意味」の決まり。
- **新しい節「右の欄」**: 設定や書き出しのような、主作業と並べて使う道具は `ui-drawer` に入れる。

## 実装の順番(ユーザー決定)

1. **共通**:
   - ui-kit に `ui-appnav`・`ui-drawer`・`ui-dialog`・`ui-pop`・`ui-toast`・`ui-keybar`・`ui-kbd`・`ui-miniprogress`・`ui-settings` を足す。
   - トークンを改訂し、共通の再生キーの処理を入れ、SVG のアイコンを用意する。
2. **編集 1 校正**: 映像の欄の整理・字幕を重ねる・「…」へのまとめ・キーの変更・左メニューの縮小。
3. **編集 2 カット・3 パック**: 3段のタイムライン・ミニマップ・ホイール・端の当たり判定・パックの要約とワンクリック。
4. **スタジオ**: ③ の書き出しを右の欄へ・今をマーク①〜⑤を主役に・盛り上がりのグラフを大きく+山の札・④ コラボを設定へ・書き出しのあとの自動の文字起こし。
5. **ホーム**: 入口と案件を1つにする・次にやること・紐づかない文字起こしも一覧へ・起動の管理を「詳しく」へ。

各段が終わるたびに、その段の画面の e2e とユーザーの実機確認を行う。全部が大まかにできたら、段階3(`/frontend-design` → `/baseline-ui` → `/design-review`)に入る。

## Out of Scope

- ホロカラー(WinForms)。色と言葉を合わせるのは、あとで別に行う。
- サーバー・API・データ形式の変更。例外は次の2つ。
  - **山の順位と理由**: 画面がすでに受け取っている `S.series` の audio / chat / comments から、画面の側で計算する。API は変えない。
  - **書き出しのあとの自動の文字起こし**: `autorun` の既存の仕組みを使う範囲で含む。
- グラフの系列を保存して、いつでも出せるようにすること。今回は含めない(ユーザーが選ばなかった)。グラフは今と同じく解析の直後だけ出る。
- スマホ向けの最適化。
- 暗いテーマを既定にすること。
- pywebview(統合計画 7-4)や窓の形の判断。
- 文字起こしの認識の精度・カット位置の精度などの機能の改善(追加機能の一覧で別に進める)。
- 作業画面の技術の入れ替え(フレームワーク・ビルドの導入)。
