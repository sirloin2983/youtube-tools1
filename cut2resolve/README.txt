cut2resolve v0.9.1(画面つき)
==================================================

切り抜いた動画に「カット」と「字幕」を入れて、DaVinci Resolve(以下 Resolve)で続きを編集できる形(パック)にして渡すツールです。
動画そのものは作り直さず、「どこを残すか」の指示(EDL)と、カット後の時刻に直した字幕(SRT)を作ります。
  EDL … 編集ソフトどうしでカットの位置を受け渡すための、昔からある文字のファイル。Resolve の「読み込み → タイムライン」で読めます。
すべてこのパソコンの中で処理し、動画や字幕を外部に送りません。


■ 準備
  - Python 3(https://www.python.org/downloads/ 。インストール時に「Add python.exe to PATH」にチェック)
  - ffmpeg / ffprobe(文字起こしツール・切り抜きスタジオと同じもの)
  - 画面(serve.py)はリポジトリのフォルダのまま使う(隣の ytt_core フォルダの共通部品を使う。cut2resolve のフォルダだけ取り出すと画面は起動しない。コマンドの cut2resolve.py は単体でも動く)


■ 起動(画面)
  リポジトリ直下の start-all.bat(入口)をダブルクリック → 入口の画面の「cut2resolve」の「開く」で http://localhost:8700/cut2resolve/ が開きます。
  終了は入口の「すべて終了」か、黒い画面を閉じる。準備と起動の全体はリポジトリ直下の README.txt。
  切り抜きスタジオの「Resolve 用に渡す」、文字起こしツールの「cut2resolve で開く」からも開けます(入力欄が埋まった状態で開き、自動では実行しません)。
  ※ このフォルダの start.bat・start.command での単独起動は 2026-09-26 にやめました(コマンドの cut2resolve.py はそのまま使えます)。


■ 画面の使い方
  1. 入力
     - 動画(必須): パスを貼り付けます。エクスプローラーでファイルを Shift+右クリック →「パスのコピー」。
       ブラウザにドロップしても動画の場所はブラウザから分からないため、動画はパスで指定します。
     - 字幕(SRT/VTT)・文字起こし(.transcript.json)・残す区間(.cut-plan.json): パスを貼るか、枠にドロップ。
       ドロップしたものは作業用フォルダ(%LOCALAPPDATA%\youtube-tools\cut2resolve\work\uploads)に写して使います(起動のたびに消えます)。
     - 「読み込む」で中身を確かめます(解像度・fps・長さ・開始タイムコード・字幕の件数)。
  2. カットの決め方(どれか1つ)
     ① 無音で自動 … 話していない所を削ります。BGM やゲーム音がずっと鳴っている動画ではほとんど切れないことがあります。
        切れすぎるときは「無音とみなす音量」を下げる(-40 など)、切れないときは上げる(-30 など)。
     ② 残す区間 … スタジオの採用区間(cut-plan)か、文字起こしで「カット済」にしなかった行を残します。
        前後の余白(秒)は、長い区間(スタジオの採用区間)なら 10 秒、文字起こしの行なら 0 秒が既定です。
     ③ 時刻リスト … 残す(または削る)区間を手で書きます。例: 0:05-0:12 / 1:02.5-1:30 / CSV の「開始,終了」
     「試算する」で、残す・削る区間をタイムラインに表示し、合計の長さを出します(ファイルはまだ作りません)。
     「カット後の見え方」をオンにすると、削る区間を飛ばして再生します(ブラウザで再生できる形式の動画だけ)。
  3. 書き出し
     - 出力フォルダ(空欄なら動画の隣の「<動画名>_pack」)に、EDL・カット後の字幕 SRT・友人へ.txt・cut-plan.json を作ります。
     - 任意: 粗編集の動画(mp4。EDL が通らないときの代わり)・元動画のコピー(フォルダごと友人に送れる)・補助の FCPXML(Resolve では未確認)。
     - 「Text+ パック」は、元の動画を再圧縮せずに media/ へコピーし、Resolve の中で実行する Lua スクリプトを同梱します。
       スクリプトは開いているプロジェクトにカット済みタイムラインと Text+ 字幕を追加します(プロジェクトは作らず、設定も変えません)。
       「置き先のプロジェクト」で fps(30/60)と向き(縦 1080x1920 / 横 1920x1080)を選びます。既定は 30fps・縦。動画の容量分が追加で必要です。
     - 動画を入れるパック(Text+ パック・元動画のコピー)では、切り抜きスタジオの「前後の余白つき素材」(動画の隣の
       <動画名>.edit.json と <動画名>_edit.mp4)があれば、元の動画の代わりにそれを入れます。Resolve でクリップの端を
       前後へ(ふつう10秒まで)延ばせます。区間は余白の分だけ後ろにずらして書くので、カットと字幕の位置は同じです。
       試算・画面のタイムラインは元の動画のままです。使わないときはコマンドの --no-edit-media。
     - すでにファイルがあるときは、上書きしてよいか確認が出ます。
     - 終わったら「フォルダを開く」「友人へ.txt の中身」で確認できます。


■ Resolve での読み込み(友人へ.txt にも同じ手順が入ります)
  1. 元動画をメディアプールに入れる
  2. ファイル → 読み込み → タイムライン → EDL を選ぶ(クリップ名で動画と結び付きます)
  3. 字幕: ファイル → 読み込み → 字幕 で SRT を入れ、タイムラインにドラッグ
  ※ 縦動画(Shorts)はタイムラインの解像度を 1080x1920 にしてください。
  Text+ 用パックを選んだ場合は、出力内の「Text+の使い方.txt」に沿って登録し、fps・解像度が合うテストプロジェクトで実行してください。


■ コマンドで使う(従来どおり)
  カットリスト(.txt)だけで切るとき: python cut2resolve.py 動画.mp4 カットリスト.txt [字幕.srt](出力は <動画名>_pack/。以前のシンプル版 cut2resolve_simple.bat は 2026-09-26 に廃止)
  cut2resolve.bat に動画・字幕などをドロップ(フル版。無音カット+粗編集つき)
  python cut2resolve.py --help / python auto_cut.py --help で全オプション
  Text+ パックは python cut2resolve.py 動画.mp4 字幕.srt --textplus で作成できます(--textplus-fps 60 / --textplus-size 1920x1080 で置き先を変更)。
  スタジオの余白つき素材を使わないときは --no-edit-media。
  出力先にファイルがあるときは止まります。上書きは --force。


■ 受け渡しの形式
  docs/pipeline.md(リポジトリ直下)を参照。youtube-tools-transcript/v1・youtube-tools-cut-plan/v1 を読みます。


■ 注意
  - 可変フレームレート(VFR)の動画は EDL の時刻がずれることがあります(警告が出ます)。
  - AV1 / H.265 / 10bit の動画は無料版の Resolve で再生できないことがあります。
  - 画面のサーバーは 127.0.0.1(このパソコン)からだけ使えます。配信する動画は入力に指定したものと、作った粗編集の動画だけです。
  - ログ: %LOCALAPPDATA%\youtube-tools\cut2resolve\work\serve.log(2026-09-26 まではこのフォルダの work\ の中)


■ v0.9.1 の変更点(2026-09-26・共通の画面部品の更新)
  - 共通の画面部品(ui-kit v2)に更新。画面で起きたエラーを入口の記録(client-errors.jsonl)に残し、入口の「窓で開く(試用)」の窓の中では
    「新しいタブで開く」リンクを窓(外のサイトはいつものブラウザ)で開く。cut2resolve の機能は変わらない

■ v0.9.0 の変更点(2026-09-26・まとめて実行・単独起動の廃止)
  - API の spec に preset "transcript-rows" を足した。文字起こしの行だけを残す規則(pack.TRANSCRIPT_ROWS。文字起こしツールの Resolve パッケージと同じ)で
    区間を決める(他の指定は使わない)。入口の「まとめて実行」がこれで Text+ パックを作る。同じ名前のパックがあるときは作らない(上書きしない)
  - このフォルダの start.bat・start.command をやめた(push.bat で消える)。起動はリポジトリ直下の start-all.bat だけ

■ v0.8.0 の変更点(2026-09-26・重い処理の同時実行の上限)
  - パックの作成は、他のツールの重い処理(スタジオの解析・書き出し、文字起こし)と合わせて同時に 2 つまでにした(入口の中で動くとき。
    ytt_core/jobs.py)。順番待ちの間は「他のツールの処理が終わるのを待っています」と出て、中止もできる。上限は環境変数 YTT_MAX_HEAVY_JOBS(1〜8)
  - 入口の「案件」の画面が、切り抜きの隣の <名前>_pack フォルダを見て「パックを作ったか」を表示する(読むだけ)

■ v0.7.0 の変更点(2026-09-26・作業データをリポジトリの外へ)
  - 画面の作業用フォルダ(ドロップしたファイルの一時置き場・ログ)を %LOCALAPPDATA%\youtube-tools\cut2resolve\work に変えた。
    中身は一時的なものだけなので、以前の work フォルダからは写さない(以前の work は消してよい)
  - 実行中のポートの共有(.runtime)・/api/siblings・Host/Origin の検査を、自分の写しから共通部品 ytt_core に切り替えた(動きは同じ)

■ v0.6.0 の変更点(2026-09-26・文字起こしツールの Resolve パッケージと一本化)
  - 文字起こしツールの「Resolveパッケージ(zip)」は、このツールの Text+ パックを作るようになった(pack.py が唯一の実装)。
    文字起こしの行を残すときの規則は pack.TRANSCRIPT_ROWS(行の時間だけ・短い行も残す・1フレームの隙間はつなぐ)。
    同じ入力から同じ中身になることは tools/test_resolve_pack_contract.py が確かめる。詳しくは docs/resolve-pack-unification.md
  - 切り抜きスタジオの前後の余白つき素材(.edit.json)を、動画を入れるパックで使う(上の「3. 書き出し」)
  - 時刻をフレームに直すときの丸めを四捨五入(0.5 は大きい方へ)にした。以前は Python の round(偶数への丸め)で、
    30fps の 0.15 秒(4.5 フレーム)が 4、0.25 秒(7.5 フレーム)が 8 と、ちょうど半フレームの時刻が上下ばらばらに丸まっていた
    (1フレームずれることがあった)。文字起こしツールと同じ規則

■ v0.5.0 の変更点(2026-09-25・入口への取り込み)
  - 入口(start-all.bat)の中の /cut2resolve/ で動けるようにした(統合計画の段階3-2。app/mount.py)。ファイルの場所・start.bat はそのまま
  - 画面の部品は相対パスで読み、API・動画の URL は app.js の BASE(画面の場所)を前に付ける
  - 入口の中で動くときは、書き込み系の操作に合言葉(X-YTT-Token。入口が画面に入れる)が要る。CSP はこれまでと同じ(script-src 'self')
  - 入口の中で動いている間に start.bat を押すと、2つ目は立てずに入口の中の画面を開く
  - 入口の「すべて終了」では、動いている書き出しを取り消してから終わる
  - 入口の中で動くときは、入力欄の前回の値(ブラウザの保存)は単独で使っていたときの値とは別になる(アドレスが違うため)
  - テスト: python e2e_ui.py --mounted(入口に取り込んだ形で画面を通す)。単独の python e2e_ui.py もこれまでどおり

■ v0.4.0 の変更点
  - Text+ スクリプトはプロジェクトを作らず、設定も変えない(スクリプトが API で作ったプロジェクトで編集ページの音が割れたため)。
    開いているプロジェクトの fps・解像度が「置き先」と違えば、何もせずに止まる
  - 動画とタイムラインの fps が違っても字幕の位置が合う(60fps の動画を 30fps のタイムラインに置く)。字幕は実際に置かれたクリップの位置から数える
  - 結果を画面に出す: 成功は CUT_TextPlus の先頭の緑のマーカー、失敗は「C2R_エラー_理由」のタイムライン(スクリプトの出力が見えない環境があるため)
  - 置き先の fps・解像度を選べる(画面・コマンド)。Text+の使い方.txt にプロジェクトの作り方(縦のときは「最短辺をマッチ: 他をクロップ」)を記載
  - テスト: 生成した Lua を Resolve の API の偽物(resolve_lua_mock.lua)の上で実行して位置・止まり方を確認(Lua がある環境のみ)
  - Text+ パックでは「友人へ.txt」を Text+ の手順書(友人向け。プロジェクトの作り方・登録・実行・編集・困ったとき)にし、
    EDL の手順書は「予備_EDLで開く手順.txt」にした(手順書が2つあって迷わないように)
  - Text+ 字幕の見た目: 黄色い文字 + 黒いふち。フォントは Resolve のフォント一覧から、Windows 標準の日本語フォント
    (游ゴシック・メイリオ・ＭＳ ゴシックなど)のうち実際にあるものを選ぶ(名前の決め打ちは実機で Font Not Found になった)。
    候補と色は resolve_textplus.py の TEXT_STYLE。選んだ書体と選び方はマーカーのメモに出る
