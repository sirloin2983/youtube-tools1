==========================================================
  切り抜き依頼(RequestSender) v2.8.0
==========================================================
切り抜いてほしい配信の URL や、切り抜いた動画を「送る」ボタンで送るだけのアプリです。
配信中・配信前のライブ配信を送ると、配信を見ながら自動で切り抜いて 1 本ずつ届けてもらえます(ベータ)。
「① 全自動」で送ったものは、できあがったパックを「受け取る」のタブで受け取れます。
送り先は、このアプリを渡してくれた人の Dropbox です(あなたの Dropbox のアカウントやお金は要りません)。
インストールは要りません(Windows 10 / 11 にはじめから入っている .NET Framework で動きます)。

【はじめに(最初に1回)】
  1. 受け取った RequestSender.zip を右クリック →「すべて展開」。できた RequestSender フォルダを、消さない場所(例: ドキュメント)に置く
     (RequestSender.exe・config.json・members.json は、同じフォルダに入れたままにしてください)
  2. RequestSender.exe をダブルクリック
     「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」
     (インターネットで受け取った、署名の無いアプリに出る確認です。最初の1回だけ)
  3. 「右クリックの『送る』でも送れるようにしますか?」と聞かれます。「はい」にすると、
     動画のファイルを右クリック →「送る」→「切り抜き依頼」で、その動画を入れた状態で開きます
     (Windows 11 は右クリック →「その他のオプションを確認」の中の「送る」)

【使い方】
  窓の上の「送る」「受け取る」で画面を切り替えます。右上の4つの色の札で、配色を選べます(次に開いたときも同じ配色です)。
  「送る」は 左 =「01 送るもの」(配信の URL / 動画ファイル / ライブ配信)、右 =「02 仕上げ方」「03 配信者・メモ」、下 = 送る内容の要約と「送る」ボタン です。
  数の − / + (切り抜く数・映像トラックの数・届け方・配信者の数・重み・ライブ配信の設定)は、押し続けると続けて動きます。

  ■ 配信を切り抜いてもらう(左の「配信の URL」)
    - YouTube の配信・動画の URL を欄に貼る。配信の題名が下に出ます(貼り間違いに気づけます。確かめられた題名には色の付いた ✓)
      使える形: https://www.youtube.com/watch?v=… / https://youtu.be/… / …/live/… / …/shorts/…
      何行かまとめて貼ると、配信が増えます(「+ 配信を足す」でも増やせます。1回に 10 本まで)
    - 「切り抜く数」(1〜10): その配信から切り抜く数の合計です
    - 区間(開始 〜 終了): 切り抜いてほしい所の時刻を入れます。入れなくてもかまいません
        ・区間が「切り抜く数」より少ないときは、足りない分を PC が自動で(見どころを)選びます。「指定 1 + 自動 2」のように出ます
        ・指定した所だけでよいときは、「切り抜く数」を区間の数と同じにします(「指定 2 + 自動 0(指定した所だけ)」)。このときは速く終わります
        ・区間の前後 2 秒は、PC が自動で足します(頭の一言が欠けないように)。1つの区間は 60 分まで・1本の配信に 10 個まで
    - 時刻の入れ方(「:」は打ちません)
        ・欄を選んで、数字だけ打つ: 12345 → 1:23:45(時 1 桁 → 分 2 桁 → 秒 2 桁 の順に進みます)。1時間より前は 0 から: 02345 → 0:23:45
        ・← → で 時・分・秒 のどこを触るか選べます(クリックでも)。選んだ所は数字で打ち直せます
        ・↑ ↓ で、選んだ所を 1 ずつ動かせます(Shift を押しながらだと 10 ずつ)
        ・YouTube で動画を止めて、動画の上で右クリック →「現在の時刻の動画の URL をコピー」→ 時刻の欄で Ctrl+V でも入ります
          (時刻の欄を右クリック →「貼り付け」でも同じです)
          (URL の欄が空なら、URL も一緒に入ります。この URL を URL の欄に貼ると、最初の区間の開始に時刻が入ります)
        ・「+30秒」「+1分」「+3分」「+5分」: 終了を「開始からその長さ」にします
        ・BackSpace = 選んだ所を 0 に / Delete = 欄を空に。10 時間より後の位置は、「時」を選んで ↑ か、URL の貼り付けで入れます
        ・終了が開始より前のときなどは、その場で赤くなって、下に理由が出ます
  ■ 切り抜いた動画を送る(左の「動画ファイル」)
    - 動画のファイル(.mp4 .mov .mkv .webm .m4v)を欄へドラッグ(いくつでも)。「ファイルを選ぶ…」でもよい
    - 配信者(名前と字幕の色)は、右の「03 配信者・メモ」に入れます(配信の URL のときと同じ欄。入れなくてもよい)
  ■ 両方いっぺんに入れて送っても大丈夫です(中で2つの依頼に分けて送ります)
  ■ ライブ配信を切り抜いてもらう(左の「ライブ配信」。v2.8.0・ベータ)
    - 配信中か配信前(待機所)の YouTube の URL を 1 本貼る。題名が下に出ます(配信の URL のときと同じ)
    - 送り先の PC が配信を録画しながら見どころを見つけ、切り抜けしだい 1 本ずつ「受け取る」に届けます(① 全自動のパック)。
      もう終わった配信の URL なら、ふつうの ① 全自動の依頼になります(切り抜く数は送り先の PC の設定)
    - ライブ配信の依頼は 1 回に 1 本だけです。配信の URL・動画ファイルの欄に何か入っているときは送れません(どちらかを空にしてから送る)
    - URL を入れている間、仕上げ方は ① 全自動に決まります(カット・映像トラックの数・配信者・メモは使えます。見どころの重みと届け方は使いません)。
      URL を消すと、前に選んでいた仕上げ方に戻ります
    - ライブ配信の設定(ベータ。試しながら変えてください。最後に使った値を次も使います)
        ・感度(高 / 普通 / 低。はじめは普通): 盛り上がりをどれだけ拾うか。高いほど候補が増えます(外れも増えます)
        ・1 時間の本数(1〜30。はじめは 6): 1 時間の配信から切り抜く候補の上限
        ・切り抜きの長さ(10〜120 秒。はじめは 45): 1 本の長さ。盛り上がった所を中心に切ります
        ・自動で採用するまでの待ち(1〜60 分。はじめは 5): 候補が出てから、送り先の PC が自動で切り抜くまでの時間。長いほど送り先の人が見て外せます
        ・前後の余白(0〜5 秒。はじめは 2): 切り抜きの前後に足す秒数(頭の一言が欠けないように)
        ・配信が終わったあと、アーカイブからも追加する(はじめはオン): 配信中に見逃した所も、配信後にアーカイブを見直して届けます
    - 外れた切り抜きは、「受け取る」で「要らない」にしてください(送り先の人に伝わり、検出の改善に使われます)
  ■ 02 仕上げ方(PC でどこまでやるか。送るたびに選ぶ。アプリを開いたときはいつも ①)
    - ① 全自動(パックまで作って届ける): PC が DaVinci Resolve のパックまで作ります。
        字幕の校正前のパックが「受け取る」に届きます(配信の長さによっては何時間もかかります)
    - 届け方(v2.8.0。「02 仕上げ方」の見出しの右。① のときだけ。はじめは「1 本ずつ」。次も同じ値)
        ・1 本ずつ: 切り抜きが 1 本できるごとに届きます
        ・n 本ごと(2〜10): n 本の組で届きます。組のまとめ動画(n 本をつなげた小さい動画)を見てから、1 本ずつ「受け取る」か「要らない」を選べます
    - ② 軽く確認(文字起こしまで): 送り先の人が字幕を直してから仕上げます
    - ③ 全部人が行う(解析まで): 送り先の人が切り抜く所から決めます(このときは「切り抜く数」と区間は使いません)
    - カット(① のときだけ): 「しない」(はじめの値)か「無音を削る」(しゃべっていない所を削ったパックにする)
    - 映像トラックの数(① のときだけ。1〜5): V1〜V数 に同じ動画、いちばん上に字幕
    - 見どころの重みを指定する: 入れると、自動で選ぶ分の見どころの選び方(音声・チャット・コメントの重み。0.0〜3.0)を変えられます。
        数字が大きいほど重く見ます(1.0 が ふつう・0 は使わない)。外しておけば PC の設定のままです
  ■ 03 配信者・メモ(v2.1.0 から。前の「話す人」と、動画の側にあった「配信者」を1つにまとめた)
    - 「配信者の数」(指定しない / 1〜10)を選ぶと、その人数分の行が出ます。1 行 = 番号 + 名前 + 字幕の色。動画と URL の両方にかかります
        ・名前: 右の ▾ を押すと、メンバーの一覧から選べます。打つと候補が絞られます。一覧に無い名前も打てます(60 文字まで)。空でもよい
        ・色: 字幕の色を 6 桁のカラーコード(# なし。例: FF00AA)で入れます。16 進の文字(0〜9・A〜F)だけ打てて、小文字は大文字になり、
          「#ff00aa」を貼っても「FF00AA」に直ります。6 桁そろうと、横に色の見本が出ます。空でもよい
        ・色が空のとき: 名前がメンバーの一覧にあれば「メンバーカラー」(その人の色)・一覧に無い名前なら「色なし」と、横に出ます。色を入れるとその色が先です(メンバーでも)
        ・色だけ入れて名前が空の行・色が 6 桁そろっていない行は、「送る」を押すと止まって、その欄が赤くなり、下に理由が出ます
    - 人数を入れると、PC が話者を分けて名前を付けます(分からない人は「話者1」などのまま)。何も入れないときは今までどおり(話者は分けない・字幕の色は配信のチャンネル名から)
    - 1 人目に名前を入れると、その人が配信者として字幕の色に使われます(URL の依頼にも付きます)。名前なしで人数だけでもかまいません
    - 人数が多くて右の列に入りきらないときは、行の欄の中でスクロールします(メモの欄は下に出たまま)
    - メモ: 送り先の人へのひとこと(自動の処理には使いません)
  ■ 送る
    - 下の帯に、いま送る内容が1行で出ています(例: 配信 1 本(指定 1 + 自動 2)・① 全自動・カットしない・トラック 1・1 本ずつ。
      ライブ配信なら「ライブ配信(配信中に自動で切り抜き → 1 本ずつ届く)・感度 普通・1 時間 6 本 …」。長いときはマウスを重ねると全部出ます)
    - 「送る」を押す(Ctrl+Enter でも送れます。どの欄にいても)。誤りがあれば、その欄が赤くなって下に理由が出ます。大きな動画は時間がかかります(「やめる」で止められます)
    - 「送りました ✓」が出れば届いています。② ③ は送り先の人から返事は来ません
    - カット・映像トラックの数・届け方・切り抜く数・重み・ライブ配信の設定・配色・窓の大きさは、次に開いたときも同じです(仕上げ方だけは毎回 ①)
    - 同じ配信を、区間や仕上げ方を変えて送り直せます(PC は前の解析などを使い回します)

  ■ 受け取る(① で送ったもの)
    - 上の「受け取る」のタブを開くと、届いたものの一覧が出ます(新しいものが上)。「更新」で見直します
      種類「パック」= できあがったもの / 「組」= 何本かのパックとまとめ動画のまとまり(v2.8.0)/ 「失敗」= 自動でうまくいかなかった知らせ
    - アプリを開いている間は、3 分ごとに届いたものを確かめます。届くと、上の「受け取る」に数(●2 など)が出て、
      ほかの窓を使っているときはタスクバーのボタンが数回光ります(窓が前に出たり、音が鳴ったりはしません)
    - パックは 1 本ずつ届きます。1 本ずつのパックにも、中の切り抜きの小さい動画(まとめ動画)が付いてきます。
      届け方を「n 本ごと」にして送った依頼は、n 本の「組」で届きます(v2.8.0):
        ・一覧に組の行「<題> 1-5(5 本)」が出て、そのすぐ下に 1 本ずつの行「├ 1. <題>」が並びます(題の終わりの「1-5」= その依頼の 1 本目から 5 本目)
        ・組の行を選ぶと: 「受け取る(5 本)」= この組の残りを全部受け取る(本数と合計の大きさの確認が出ます)/ 「要らない(5 本)」= この組の残りを全部要らない /
          「まとめ動画を見る」= 組の 5 本をつなげたまとめ動画
        ・1 本ずつの行を選ぶと: 今までどおり、その 1 本だけ「受け取る」「要らない」。「まとめ動画を見る」は組のまとめ動画を、その本の頭から再生します
        ・組の最後の 1 本を受け取る・要らないにすると、組の行も消えます。受け取った・要らないにした本があると「(残り 3 / 5 本)」と出ます
      パックを選ぶと、下に 大きさ・届いた日時・まとめ動画のあり / なし が出ます(同じ依頼のパックがほかにも届いていれば、その本数も。組の本なら何本目か)
    - 流れ: 「まとめ動画を見る」で中身を先に見る → 要るものは「受け取る」/ 要らないものは「要らない」
    - 「まとめ動画を見る」: パックを選んで押すと、中の切り抜きをつなげた小さい動画(480p・等速)が、このアプリの小さい窓で再生されます。
      まとめ動画は、届いたものを調べたとき(開いたとき・「更新」・アプリを開いている間の 3 分ごと)に裏で先に取ってきてあるので、すぐ見られます
      (取っている途中なら、取れしだい開きます。300MB を超える大きいものだけは、押したときに取ってきます)。
      窓の中: 「再生 / 一時停止」・下のつまみで好きな所へ・Space で再生 / 一時停止・← → で 5 秒戻る / 進む・Esc で閉じる。
      窓の [受け取る] [要らない] で、そのまま受け取る・要らないにできます。この窓で再生できない PC では「外部のプレイヤーで開く」で、いつものプレイヤーで見られます。
      切り抜きごとに、左上に「1/5 題」のような番号と題がずっと出ます(字幕は入っていません)。見終えた写しは、受け取った・要らないにしたときに消えます
    - 組のまとめ動画の窓(v2.8.0): 右に 1 本ずつの一覧が出ます(いま再生している本が明るくなります)。
        ・題を押すと、その本の頭へ飛びます。左の四角(チェック)は、はじめは全部入っています。要らない本はチェックを外します(キーなら Space)
        ・下の「チェックした 3 本を受け取る(残り 2 本は要らない)」を押すと、確認の窓に本数と題が出て、「OK」で
          外した本を要らないにしてから(送り先の人に伝わります)、チェックした本を古い順に受け取ります。「閉じる」は何もしません
    - 「受け取る」: 選んだパックを受け取ります(ダブルクリックでもよい)。数 GB のことがあるので時間がかかります。
      保存先ははじめ「ダウンロード\切り抜き依頼」。「変える…」で選び直せます(次からも使います)
    - 「すべて受け取る(n 本)」: 届いているパックを古い順に 1 本ずつ、まとめて受け取ります(押すと本数と合計の大きさの確認が出ます)。
      終わると「n 本すべて受け取りました ✓」。受け取れなかったものがあれば題が出るので、「更新」のあと もう一度「すべて受け取る」を押してください
    - 「やめる」: 受け取っている途中(まとめ動画を取ってきている途中も)だけ出ます。押すと止まります(受け取り終えたものはそのまま。途中だったファイルは消します)
    - 「要らない」: 選んだパックを受け取らずに消します(送り先の Dropbox から消え、もう受け取れません。消す前に確認が出ます)。
      要らなかったことは送り先の人に伝わります(送り先の PC がその切り抜きを片付け、「誤検出」として検出の改善に使います)
    - 受け取ったパックは、自分で「すべて展開」しなくても、保存先にフォルダとして開いた形で置かれます(zip は消します)
        ・1 本ずつのパック(組の中の本も)→ 「<題>_pack」のフォルダ(まとめ動画は入っていません。受け取る前に見るためのものなので)
        ・前の届け方(送り先の PC が何本かを 1 つの zip にまとめていたころ)の zip → zip と同じ名前のフォルダ(名前の終わりが「<題> 1-5」)。中に 1 本ずつの「<題>_pack」のフォルダが並びます
        ・「<題>_pack」の中に 動画・字幕(.srt)・DaVinci Resolve 用のファイルが並びます。同じ名前のフォルダがすでにあれば「(2)」を付けます
      ちゃんと保存できたことを確かめたあと、送り先の Dropbox と一覧から消えます(一覧に残るのは、まだ受け取っていないものだけ。もう一度は受け取れません)。
      「受け取りました ✓」が出たら「フォルダを開く」で、最後に受け取ったフォルダが開きます
    - 「失敗」: 選ぶと下に理由が出ます。送り先の人に伝えるか、「② 軽く確認」か「③ 全部人が行う」で送り直してください。
      読み終えたら「消す」を押すと一覧から消えます(パックを選んでいるときに「要らない」になっているボタンです。消す前に確認が出ます)
    - こんな文が出たら
        ・「まだ届いたものはありません」: まだできていません。しばらくしてから「更新」
        ・「受け取りましたが、展開できませんでした」: zip はそのまま保存先にあります(右クリック →「すべて展開」で開けます)
        ・「受け取りましたが、Dropbox から消せませんでした」: 保存はできています。「更新」するとまた出るので、そのときにもう一度「受け取る」を押せば消えます
    - zip のまま置きたいとき(ふつうは要りません): %LOCALAPPDATA%\RequestSender\settings.json に "extractZip": false を書きます

【うまくいかないとき】
  - 「config.json が見つかりません」: RequestSender.exe と同じフォルダに config.json があるか確かめる
  - 「鍵が使えなくなっています」: 送り先の人に新しい config.json をもらって、今のものと入れ替える
  - 「インターネットにつながりません」: つながっているか確かめて、もう一度「送る」
  - 「Dropbox の空きが足りません」: 送り先の人に伝えてください
  - 途中で失敗したときは、送れたものが画面に出ます。残りだけもう一度送ってください
  - 「受け取るには新しい鍵が要ります」: 前の版の鍵(config.json)は送るだけの鍵です。送り先の人に新しい config.json をもらって入れ替える
  - 「保存先の空きが足りません」: ディスクを空けるか、「変える…」で別のドライブを選ぶ(受け取るには、zip とその中身の 2 つ分の空きが要ります)
  - 記録: %LOCALAPPDATA%\RequestSender\request-sender.log(困ったらこのファイルを送り先の人に見せる。鍵は書いていません)

【config.json について(大事)】
  config.json は、送り先の Dropbox の「このアプリ専用のフォルダ」にだけファイルを置いたり読んだりできる鍵です。
  他の人に渡したり、ネットに上げたりしないでください。なくしたり漏れたりしたら、送り先の人に伝えてください(鍵を無効にして作り直します)。

【やめるとき】
  RequestSender フォルダを消すだけです。右クリックの「送る」に出したときは、
  エクスプローラーのアドレス欄に shell:sendto と入れて開き、「切り抜き依頼」を消してください。


==========================================================
  ここから下は、アプリを渡す人(PC で受け取る人)向け
==========================================================
友人の PC → Dropbox の API → 自分の Dropbox の「アプリ」フォルダ → 同期 → PC のホームが見て自動で文字起こし、という流れです。
設計: docs/spec/friend-intake.md

【鍵を作る(最初に1回)】
  1. https://www.dropbox.com/developers/apps →「Create app」
     - Choose an API: Scoped access
     - Choose the type of access: App folder(アプリ専用のフォルダだけ。Dropbox の他のファイルは読めない・書けない)
     - Name: 例「切り抜き依頼」(この名前がフォルダの名前になる。Dropbox 全体で重ならない名前が必要)
  2. できたアプリの「Permissions」タブで次の3つにチェック →「Submit」(ほかは付けない)
       files.content.write(送る・受け取ったあとに消す)・files.content.read(受け取る)・files.metadata.read(受け取るものの一覧)
     権限を変えたら、鍵は作り直す(前に作った鍵には新しい権限は付かない)
  3. 「Settings」タブの App key を控える。App secret は使わない(PKCE という方式なので secret なしで鍵を作れる)
  4. リポジトリ直下で:  python dev\dropbox_auth.py <App key>
     表示された URL をブラウザで開いて「許可」→ 出てきたコードを貼る → friend-apps\request-sender\config.json ができる
     (URL で上の3つの権限を頼む。足りない・余計な権限が付いたら [注意] が出るので、Permissions を直して作り直す)
     (鍵の値は画面に出しません。config.json は .gitignore と push.bat の検査でコミットされないようにしてある)
  5. friend-apps\request-sender\build.bat → dist\RequestSender.zip(exe・README.txt・members.json・config.json)を友人に渡す
     zip には鍵が入っているので、人に見られない方法で渡す

【届く場所】
  自分の Dropbox の「アプリ\<アプリの名前>\」(英語の Dropbox では「Apps\<アプリの名前>\」)。
  PC のホームがこのフォルダを見張る(Dropbox のデスクトップアプリで同期しておく)。
  - 動画: <id>__<元の名前>.mp4 など(名前がぶつかると Dropbox が「 (1)」などを付ける。依頼の JSON の files には実際の名前が入る)
  - 依頼: <id>.request.json(いつも最後に送る。これが届いた = そろった、の合図)
    id は yyyyMMdd-HHmmss-<16進 6 桁>。形:
      {"v":1,"kind":"video","id":"…","flow":"auto","files":["…__名前.mp4"],"streamer":"さくらみこ","memo":"…","sentAt":"2026-10-01T12:00:00+09:00"}
      {"v":1,"kind":"url","id":"…","flow":"auto","items":[{"url":"https://www.youtube.com/watch?v=xxxxxxxxxxx","top":3,"ranges":[{"start":5025,"end":5110}]}],"streamer":"さくらみこ","memo":"…","sentAt":"…"}
      {"v":1,"kind":"live","id":"…","flow":"auto","url":"https://www.youtube.com/watch?v=xxxxxxxxxxx","streamer":"","memo":"","videoTracks":1,"cut":"none",
       "live":{"sens":"normal","perHour":6,"length":45,"waitMin":5,"pad":2,"afterStream":true},"sentAt":"…"}
    items[].top(1〜10)= その配信から切り抜く数の合計。v2.0.0 から配信ごと(v1.4.0 までは全部の配信で同じ値)。区間があるときは区間の数以上
    items[].ranges(v2.0.0 から。区間を入れたときだけ・① ② のときだけ): 区間の一覧(10 個まで)。start・end は秒の整数(余白を足す前の、友人が入れた値)。
      区間が top に足りない分は PC が自動で埋める。前後 2 秒の余白は PC が足す
    cut(v2.0.0 から。① 全自動のときだけ。動画・URL の両方): "none" = カットしない / "silence" = 無音を削る。videoTracks の後
    weights(v2.0.0 から。URL の依頼で「見どころの重みを指定する」を入れたときだけ): {"audio":1.0,"chat":1.0,"comments":0.7}(0.0〜3.0)。cut の後・sentAt の前
    streamer(動画の依頼は v1.0.0 から・URL の依頼は v2.1.0 から): 配信者の 1 人目の名前。動画の依頼は、名前が無ければ空文字 ""。
      URL の依頼は、1 人目の名前があるときだけ書く(無ければキーごと無い = PC がチャンネル名から決める)。URL の依頼では items の後・memo の前
    speakers(v1.3.0 から。人数を選んだときだけ。選ばないとキーごと無い): "speakers":{"count":3,"names":["名前","名前"],"people":[{"name":"名前","style":{"color":"FF00AA"}},{"name":"名前"}]}
      count = 配信者の数(1〜10)。names = 友人が入れた名前(空は除く・前後の空白なし・重複なし・1つ60文字まで・count 以下。0 個のこともある。古い PC のために今までどおり書く)。
      people(v2.1.0 から。名前のある行が 1 つでもあるときだけ): 名前のある行だけ・入力の順(重複なし)。style は色を入れた行だけ(キーごと省く)。
        style.color = 字幕の色。# なし・大文字の 16 進 6 桁("FF00AA")。アプリは 6 桁そろったものだけ送る。受け取る側でも 6 桁だけに検査すること(画面・Lua に入る)。
        あとで字幕の見た目(フォントなど)を足すときは、style に鍵を足す。知らない鍵は読み飛ばしてよい(古い PC は people ごと読まなくても names で今までどおり動く)
      動画・URL のどちらの依頼にも、memo と sentAt の間に入る。PC はこれで話者を count 人に分け、names を覚えている声と照らして名前を付ける
    videoTracks(v1.4.0 から。① 全自動のときだけ。1〜5・既定 1。②③ はキーごと無い): "videoTracks":3(speakers の後・sentAt の前)。
      PC が作る Resolve のパックの映像トラックの数(V1〜V数 に同じ動画(V2 から上は映像だけ)・字幕はいちばん上)
    flow(v1.1.0 から): "auto" = ① 全自動(パックまで)/ "check" = ② 文字起こしまで / "manual" = ③ 解析まで。
      1回の「送る」の動画と URL の両方に同じ値が付く。v1.0.0 の依頼には flow が無い
    deliverBatch(v2.8.0。届け方。① 全自動の url・video の依頼だけ・1〜10 だけ。sentAt の直前): 1 = 1 本ずつ / n = n 本の組(まとめ動画 1 本 + 1 本ずつの zip + .group.json)。
      無いとき(v2.7.0 までのアプリ・②③)は PC の設定(ホームの intake.deliverBatch)。設計 docs/spec/friend-intake.md の 2-16
    kind "live"(v2.8.0。ライブ配信の依頼。設計 2-15): url 1 本(正規化した watch?v=)・flow は "auto" 固定・streamer はいつも書く(無ければ "")。
      speakers・videoTracks・cut は URL の依頼と同じ。live = 友人のベータの設定: sens(high / normal / low)・perHour(1〜30)・length(10〜120 秒)・
      waitMin(1〜60 分)・pad(0〜5 秒)・afterStream(真偽)。アプリは範囲の外を既定にして送る(受ける側も範囲の外・無い鍵は既定に)。weights・deliverBatch は書かない(いつも 1 本ずつ)。
      配信の URL・動画と一緒には送らない(1 回の「送る」で 1 件)
    動画と URL を一度に送ると、依頼は2つ(id も2つ)になる
  - 返すもの(PC が置く。友人のプログラムの「受け取る」が一覧にする): アプリのフォルダの「出力\」
      <依頼の id>__<題>.zip         … DaVinci Resolve のパック(① で作ったもの。中は <題>_pack\ が 1 つ)
      <zip の名前>.preview.mp4      … zip の隣のまとめ動画(等速・480p・字幕なし・各クリップに「i/N 題」の札)。zip より先に置く
      <依頼の id>__<題> 1-5.preview.mp4 / .group.json … 組(v2.8.0。2-16): 組のまとめ動画 → 1 本ずつの zip → 最後に .group.json の順に置く。
          .group.json = {"v":1,"title":"<題>","range":"1-5","preview":"<組のまとめ動画の名前>","packs":[{"n":1,"zip":"<zip の名前>","title":"<題>","previewStart":0.0,"duration":48.2}, …],"sentAt":"…"}
      <依頼の id>__<題> 1-5.zip     … 前の届け方(ホーム 0.45〜0.46)の、n 本を 1 つにまとめたパック(中は <題>_pack\ が n 個)
      <依頼の id>__<題>.失敗.txt    … ① の自動の処理が失敗した理由(UTF-8・BOM つき・短く。64KB を超えた分は読まない)
    友人のプログラムは、.preview.mp4 を同じ名前の zip に結びつけて一覧には出さない(相手の zip が無いものは出さず、消しもしない)。
    v2.8.0 からは .group.json(64KB まで)を読み、書かれた名前の zip(一覧にあるものだけ)を組に、preview の名前のまとめ動画を組に結びつける。
    zip が 1 本も届いていない組・読めない .group.json は出さない(消さない)。組の最後の 1 本を受け取った・要らないにしたら .group.json と組のまとめ動画も消す。
    previewStart が null(PC が長さを測れなかった)の本は、小窓の一覧でその本へ飛べない(チェックはできる)。
    受け取り終えたパック・「要らない」としたパック(隣の .preview.mp4 も)・読み終えて「消す」を押された失敗の知らせを、ここから消す(files/delete_v2)。
    そのため 出力\ は友人が受け取るたびに空いていく(自分では消さなくてよい)。.zip・.失敗.txt・.preview.mp4・.group.json 以外(フォルダ・途中のファイル)は一覧に出さない。
    受け取った zip は友人の保存先に展開する: 中身が 1 つのフォルダならそのフォルダを直下に、そうでなければ zip の名前のフォルダに(同じ名前は「(2)」)。
    中の名前に ..・ドライブ名・使えない文字があれば展開を断って zip のまま残す。
    書き終えてから置く(途中の名前で書いて最後に名前を変える)と、書きかけのものが一覧に出ない。
    同じ名前で置き直すと、友人の側でまた一覧に出る(消えていれば新しいものとして出る)

【v1.0.0 から上げるとき(鍵の作り直しが要る)】
  v1.0.0 の鍵は files.content.write だけなので、「受け取る」が使えない(画面に「新しい鍵が要ります」と出る)。
  1. App console の Permissions で files.content.read・files.metadata.read にもチェック →「Submit」
  2. python dev\dropbox_auth.py <App key> をやり直す(config.json を作り直す)
  3. friend-apps\request-sender\build.bat → dist\RequestSender.zip を友人に渡し直す(友人は exe と config.json を入れ替える)
  古い鍵は https://www.dropbox.com/account/connected_apps で切ってよい(新しい鍵は同じアプリなので、切ると新しい鍵も無効になる点に注意。
  切るなら先に切ってから 2 をやる)

【鍵を無効にする(漏れた・友人に使わせるのをやめる)】
  https://www.dropbox.com/account/connected_apps でアプリの接続を切る(Disconnect)。
  またはアプリの設定(developers/apps)でアプリごと消す。新しく渡すときは「鍵を作る」の 4〜5 をやり直す。

【開発】
  - C# 5・WinForms。Windows に入っている .NET Framework 4 の csc で作る(ホロカラーと同じ形。build.bat)
  - src\Core.cs(URL の読み取り・id・JSON・配信者の色の整え方と検査・分け方・「出力」の名前の読み取り・手元の記録)/ TimeCore.cs(時刻の読み書き・時刻の欄の状態・区間・カット・重み・題名・覚える設定)/
    Dropbox.cs(API)/ Sending.cs(1回の送信)/ Receiving.cs(一覧・受け取り・展開・まとめ動画・消す)/ Theme.cs(配色とフォント)/ Controls.cs(自分で描く部品)/ TimeBox.cs(時刻の欄)/
    StreamCard.cs(配信のカード・区間の行・ライブ配信の欄 LiveCard・題名の問い合わせ)/ MainForm.cs(画面・送る)/ MainForm.Receive.cs(画面・受け取る・組)/
    Preview.cs(まとめ動画を裏で取る順番と再生の小窓・組の小窓の 1 本ずつの一覧)/
    Program.cs(起動・「送る」のショートカット・画面の確認・小窓の再生の確かめ --probe-preview <mp4> <out.txt> [--theme X]。
    環境変数 REQUEST_SENDER_PROBE_GROUP=1 で組の小窓(1 本ずつの一覧つき・2 本目の頭から)・REQUEST_SENDER_PROBE_PNG=<png> で見た目も撮る)
  - 2.8.0 の部品: LiveSettings(TimeCore.cs。ライブ配信の設定の範囲と既定・JSON の live)・DeliverBatch(Core.cs。届け方)・RequestJson.Live・
    GroupInfo / GroupPack(Core.cs。.group.json の読み取りと名前の検査)・OutputFolder.Arrange(組の行と 1 本ずつの行の並び)・GroupsDone(組の最後の 1 本まで片付けたか)・
    Receiving.FinishGroups(.group.json と組のまとめ動画を消す)・DiscardAll(何本かをまとめて要らない)
  - まとめ動画の小窓は WPF の MediaElement を ElementHost で埋め込む(PresentationCore など。.NET Framework 4 に同梱なので追加のインストールは要らない。build.bat が参照する)
  - ホロカラーと共通の部品: ..\common\Json.cs(JSON の読み取り)・Log.cs(記録)。build.bat が src と一緒にコンパイルする
  - 手元の記録: %LOCALAPPDATA%\RequestSender\ の settings.json(保存先・覚える設定 = カット・映像トラックの数・切り抜く数・重み・配色・窓の大きさ・
    届け方 deliverBatch・ライブ配信の設定 live(v2.8.0。壊れた値・範囲の外は既定)。
    extractZip は画面に無く、false を書いたときだけ zip のまま)・request-sender.log。まとめ動画は %TEMP%\RequestSender\previews に取ってくる(同じ大きさのものがあれば取り直さない)
  - 通信するのは Dropbox の API と、配信の題名を出すための YouTube の oEmbed(https://www.youtube.com/oembed。配信の ID だけを渡す)だけ
  - 画面の確認: build\RequestSender.exe --screenshot <png> [--theme A|B|C|D] [--tab send|video|live|receive] [--sample] [--size 900x620] [--select <行>]
      [--state manual|weights|many|speakers|strict|busy|done|focus|receiving]
    (窓を画像に保存して終わる。通信しない・設定を書かない・「送る」のショートカットを触らない。
     --tab live はライブ配信の欄の見本。--tab receive --sample は 組(5 本)+ 1 本の zip + 失敗の知らせ。--select で選ぶ行(0 から。例: 2 = 組の 2 本目)。
     --state receiving は「受け取る」の「すべて受け取る」の途中。環境変数 REQUEST_SENDER_SHOT_MANY=1 で「受け取る」の見本に 13 本足す)
  - 設計: docs\spec\friend-intake.md の 2-10(画面の全面見直し・時刻の欄・配色)・2-6(PC 側)・2-12(すべて受け取る・展開)・2-13(まとめて届ける・まとめ動画)・
    2-15(ライブ配信の依頼)・2-16(組での届け方)
  - 時刻の欄の使い回し: 動きは TimeCore.cs の TimeEdit(画面に依らない・テストあり)、画面は TimeBox.cs(Theme.cs と Controls.cs の ThemedMenu を使う)。
    YouTube の URL の貼り付けは TimeBox.AcceptYouTubeUrl = true の欄だけ(既定はオフ)。Web の画面用は ui-kit の UIKit.timebox(同じ動き。src\ui-kit\README.md の v11)
  - テスト: build.bat が tests\CoreTests.cs を作って流す(通信はしない)
  - メンバーの一覧は ..\holo-colors\members.json(friend-apps\holo-colors\members.json)を写す(build.bat)
